# 主干审查报告

## 当前结论

Ordinary 后端主干已经完成清洁断代，可以作为后续基础能力开发的唯一生产路径。当前真实链路是：

```text
request-handler
  -> ordinary-routes
  -> OrdinaryAgentFeature
  -> OpenAI Agents SDK adapter
  -> ToolCenter
  -> ordinary-run/v3
  -> one-way Panel read-model
```

旧 BasicAgent、Desktop session、Panel run job、应用层 Underground、`MinimalRuntime` 和旧 Ordinary routes 已删除。`createPanelRuntime()` 是唯一生产组合根，负责装配 `OrdinaryAgentFeature` 与 `MultiAgentFeature`。

## 已经可信的边界

### 运行与状态

- Ordinary 是唯一默认工作方式；Multi-Agent 只能由用户显式进入。
- `OrdinaryAgentFeature` 独占 command/query/event、运行状态、确认 continuation、repository 和 read-model。
- OpenAI Agents SDK 负责机械模型-工具循环，不拥有完成语义、业务状态或持久化。
- 模型不再请求工具时才正常完成；确认等待、取消、provider 失败、上下文阻塞和崩溃恢复保持真实状态。

### 上下文与持久化

- `ordinary-run/v3` 原子保存 run 出生事实、status、`canonicalMessages`、工具事实、usage 和 timeline。
- `ordinary-conversation/v1` 只保存分支、标题、置顶和删除事实。
- 上一条可见 lineage 的 `canonicalMessages` 是跨轮模型历史的唯一来源。
- Panel conversation、SSE、工具活动与 WorkView 都是单向投影，不能反向拼装模型历史。
- 旧 RuntimeDatabase、sidecar、旧 snapshot 和开发期失效数据不迁移、不双读、不回填。

### 工具与确认

- ToolCenter 是统一执行入口，但 SDK adapter 在调用它之前仍按本轮 `allowedTools` 强制裁剪。
- 每个工具结果先由 Ordinary feature 持久化为 canonical 事实，再返回模型。
- provider `callId` 与应用 `factId` 分离，避免父/子或并行调用串用权限与结果。
- 已完成工具在确认恢复时不重复执行；拒绝、取消和失败以真实工具结果回到模型。

### Sub-Agent

- Sub-Agent 只暴露 SDK 原生 `call_sub_agent` 与 `spawn_sub_agent` AgentTool。
- nested Agent 只能使用父 run 已授权且当前可执行的工具，并强制排除所有 Sub-Agent AgentTool。
- 完整结果直接交回父模型；不维护独立 runner、事件、trace、持久化或 read-model。

### Multi-Agent 隔离

- Multi-Agent 继续通过 `/api/deep/*` 拥有 manager、TaskBoard、scheduler、child、synthesis、store 与 read-model。
- Deep 的 `AgentTurnRuntime` 不进入 Ordinary 主链。
- `domain/underground/agent-fabric` 中有效的 run-tree 契约仍由 Deep 使用；这不代表旧应用层 Underground 或 `/api/underground/*` 仍存在。

## 仍需守住的风险

### UI 尚未完全收口

Agent 集群 beta 开关、独立侧栏入口、持久化 mode、Deep DTO 与独立数据分区仍存在。它们是统一 Workbench 下的迁移事实，不能被误写成两个产品，也不能提前声称 UI 已合并。

### 结构门不能替代行为测试

依赖测试应保护唯一组合根、feature ownership 和 neutral dependency direction，但不得锁定旧 facade、文件名或源码字符串。Ordinary 的完成、确认、取消、失败、恢复、工具事实顺序和 canonical history 必须由行为测试保护。

### 不得重新引入兼容复杂度

开发期旧数据可以废弃。后续不得为了读取旧字节恢复 BasicAgent facade、旧 snapshot parser、RuntimeDatabase 双读、Panel 状态回填或 Sub-Agent trace 链。

## 后续开发原则

- 新能力先确定 Ordinary、Multi-Agent、Sub-Agent 或 neutral owner。
- Ordinary 新能力必须覆盖输入契约、AgentLoop、工具/确认、feature state、repository、read-model 和行为测试的完整纵向 slice。
- provider 私有对象只能停留在 adapter，不能进入 feature state 或公开 API。
- 模型正文、工具结果和错误不能被展示摘要覆盖。
- 只有两个真实稳定消费者需要同一机械语义时才提取共享能力。

当前结论不是“所有问题已解决”，而是默认生产主链、事实所有权和恢复来源已经统一。下一阶段可以在这条主干上打磨模型接入、工具质量、上下文和真实任务表现，不应继续重建运行时。
