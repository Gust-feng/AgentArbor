# 命名、边界与开发顺序

## 工程保护边界，模型负责判断

普通 Agent 的根边界是：

- 模型负责：目标理解、是否继续、工具选择、结果综合、停止时机。
- 工程负责：权限、命令确认、预算、上下文维护、执行边界、恢复、审计。

要求：

- 不用工程逻辑替模型决定“现在该停了”“应该继续搜索”“应该改走 deep”。
- 不用 schema、关键词、固定阶段或模板语句承担 Agent 语义判断。
- 允许模型在清晰边界内自然行动。

禁止事项：

- 用工程状态机代替普通 Agent 的行动判断。
- 用 UI copy、fallback 文案或 guard 逻辑偷偷决定任务方向。
- 看到模型偶尔不稳，就不断往普通路径里塞更多硬编码策略。

## deep 是长期能力边界，不是当前默认路径

普通 Agent 主干必须和 deep 长期方向兼容，但不能被 deep 概念污染。

要求：

- 保留未来多 Agent / deep / Plan / Aboveground 的长期方向。
- 当前默认入口始终是普通 `agent`。
- 普通路径不展示 deep 入口、不自动升级、不提前包装 deep 术语。
- 多 Agent 扩展必须复用普通 Agent 已稳定的基础设施和定义层。

禁止事项：

- 把普通编辑、一次工具循环、helper、adapter 或状态更新包装成 deep 概念。
- 为了兼容未来 deep，先把普通路径做重。
- 让未来架构名词反过来污染当前默认产品语义。

## 开发顺序

后续普通 Agent 主干开发，默认按以下顺序推进：

1. 先固定默认运行方式与唯一主循环。
2. 再固化 `AgentDefinition`。
3. 再收口工具的 `assemble / model / execute` 三层边界。
4. 再优化工具结果回灌和默认用户视图。
5. 最后再在这套主干上扩展多 Agent、deep 和长期能力建设。

禁止跳过前两步，直接扩展多 Agent、更多工具或更复杂前端编排。
