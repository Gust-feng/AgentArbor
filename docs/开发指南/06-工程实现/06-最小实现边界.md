# 最小实现边界

## 当前产品主线

AgentArbor 当前最小正式闭环是：

```text
Workbench
  -> Ordinary Agent（默认）
      -> OpenAI Agents SDK model loop
      -> ToolCenter / confirmation
      -> ordinary-run/v2
      -> one-way read-model
```

Multi-Agent 是同一 Workbench 下的显式功能，继续通过 `/api/deep/*` 使用 manager、TaskBoard、scheduler、child 和 parent synthesis。Task Soil、Plan、Aboveground、Fruits、Governance 和 Global Soil 是按真实需求出生的长期模块，不是每次普通请求的必经链路，也不是当前最小验收前提。

## Ordinary 一致性边界

Ordinary 的业务事实只由 `OrdinaryAgentFeature` 拥有：

- `ordinary-run/v2` snapshot 原子保存 run 出生事实、status、`canonicalMessages`、工具事实、usage 和 timeline。
- `ordinary-conversation/v1` control document 保存 conversation 分支、标题、置顶和删除事实。
- 上一条可见 lineage 的 `canonicalMessages` 是下一轮模型历史的唯一来源。
- Panel conversation、SSE、工具活动和 WorkView 都是单向投影，不能写回状态或重建模型历史。

旧 RuntimeDatabase、raw `run.json`、sidecar event/tool-call、旧 snapshot 和开发期缺失版本的数据不读取、不迁移、不双写。该 snapshot 不是 Event Sourcing，也不要求抽象通用 journal 或 repository。

## 最小运行闭环

普通提交必须真实经过：

1. `request-handler` 与 `ordinary-routes` 解析请求。
2. `OrdinaryAgentFeature` 冻结本轮模型、工具、Skill、MCP、工作区和权限事实。
3. OpenAI Agents SDK adapter 执行模型-工具-模型循环。
4. ToolCenter 执行获准工具；命令类动作通过确认边界。
5. 每个工具结果先持久化为 canonical 事实，再返回模型。
6. 模型不再请求工具时形成正常完成；失败、取消、确认等待和上下文阻塞保持各自状态。
7. 后端从 feature state 生成 read-model，Panel 只消费该投影。

Sub-Agent 只以 SDK 原生 `call_sub_agent` / `spawn_sub_agent` AgentTool 扩展该循环。nested Agent 复用父 run 的工具执行与确认边界，不能递归，不创建独立 runner、trace、repository 或 read-model。

## 最小验收

Ordinary 最小闭环必须证明：

- `/api/conversations` 是普通提交入口，旧 Desktop/Underground API 不参与。
- 完成、确认、拒绝、取消、provider 失败、崩溃恢复和历史恢复状态真实。
- OpenAI Responses 与 OpenAI-compatible Chat 共用同一 Ordinary feature/AgentLoop 契约。
- 工具只在本轮 `allowedTools` 内可见并可执行，工具事实在返回模型前持久化。
- provider `callId` 与应用 `factId` 分离。
- `canonicalMessages` 保留模型实际消费的 user/assistant/tool 顺序和允许持久化的 OpenAI Responses continuation。
- 旧格式数据明确拒绝，不通过 UI 或当前配置猜测修复。
- read-model 与 SSE 不成为第二套业务状态。
- Sub-Agent 权限只收窄、禁止递归、完整返回结果并复用父 run 确认。

Multi-Agent 的独立最小验收继续覆盖启动、child 调度、纠正、停止、综合和历史恢复；它不能读取 Ordinary store、canonical messages 或 read-model。

## 明确不做

- universal Run API、统一业务状态或跨 feature workflow engine。
- DI 框架、全局 service locator、Event Sourcing 或跨模块事务。
- 为开发期旧数据建设兼容 facade、迁移、双读或双写。
- 把 Multi-Agent 状态转换为 Ordinary 状态。
- 把长期 Plan/Governance 能力提前写进普通请求主线。
- 为 Sub-Agent 自建批量协议、续读状态、runner、trace 或独立生命周期。

## 验证门

```text
pnpm build:node
pnpm typecheck:panel
pnpm build:panel
pnpm test:panel
pnpm test
git diff --check
```

真实 OpenAI 验证使用 `pnpm smoke:real-ai`。它必须启动正式 Panel、提交 `/api/conversations`，并且只在 Ordinary 正常完成、至少一个工具事实已经持久化且 provider usage 有效时成功；进入 `approval_needed` 必须立即输出诊断并失败，不能等待成超时。该 smoke 不能调用已删除的 demo 或旧运行链。
