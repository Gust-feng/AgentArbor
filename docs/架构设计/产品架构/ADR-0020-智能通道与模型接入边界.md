# ADR-0020: 智能通道与模型接入边界

日期：2026-05-02

状态：Accepted

## 决策

AgentArbor 采用“智能通道”作为所有模型能力的统一接入边界。智能通道是横切能力，不是概念树节点；它服务 Soil、Underground Center、Aboveground Center、Verification、Fruits 和 Governance，但不能替代这些层的事实源、状态机、约束门或治理门。

概念树主线保持不变：

```text
Soil
  -> Underground Center
  -> .agentarbor
  -> Aboveground Center
  -> Fruits
  -> Governance
  -> Soil
```

智能通道横跨这条主线：

```text
Model Provider
  -> Provider Adapter
  -> Intelligence Channel
  -> AgentArbor domain / app caller
  -> Deterministic validation
  -> EventLog / Handoff / Plan / Governance
```

任何需要调用外部或本地模型的功能，都必须通过智能通道。Underground Center、Aboveground Center、Verification、Governance、CLI、未来 UI 或其他应用入口都不得直接绑定 OpenAI、Anthropic、Gemini、Qwen、Ollama、vLLM 或其他 provider SDK。

## 定位

智能通道负责把“需要模型参与”的请求转化为可审计、可替换、可失败、可观测的模型调用。它不负责决定最终事实，也不负责写入长期资产。

智能通道至少承担：

- 统一 `ModelRequest`、`ModelResponse`、`ModelUsage`、`ModelCallRef`。
- 约束请求目的、输入范围、输出契约、预算和敏感信息边界。
- 把 provider 差异隔离在 adapter 中。
- 记录清洗后的模型调用事件，支撑 Observation Snapshot 和后续审计。
- 在 provider 失败、超时、输出不合约或成本越界时给出确定性失败结果。
- 将模型输出标记为候选、草案、解释或证据建议，而不是系统事实。

## 与概念树的关系

| 使用方 | 可以通过智能通道获得 | 不能让模型直接拥有 |
| --- | --- | --- |
| Underground Center | 目标结构化建议、候选方向、反例、风险提示、证据搜索建议 | Direction Handoff 状态、收束裁决、用户升级门 |
| `.agentarbor` | 可以引用已收束后采纳的模型产出来源 | 不能保存未验证模型原文作为方向事实 |
| Aboveground Center | Growth Plan 草案、任务切片建议、上下文拓扑建议 | Growth Plan 版本事实、Workflow IR 状态转移 |
| Verification | 失败原因解释、测试补充建议、LLM-as-judge 候选意见 | hard constraint 通过结论、验收事实 |
| Governance | 能力候选归纳、退役建议、风险解释 | Capability Asset 晋升、权限扩大、导出裁决 |

## Provider Adapter 边界

Provider adapter 只做外部供应商到内部模型契约的转换。它可以处理：

- 供应商鉴权。
- 请求字段映射。
- 响应字段映射。
- token / cost / latency 用量归一化。
- provider-specific 错误映射。
- 流式输出到内部事件的转换。

Provider adapter 不能定义：

- AgentArbor 领域模型。
- Direction Handoff、Growth Plan、Workflow IR 或 Governance 的业务语义。
- 约束是否通过。
- 资产是否进入 Soil。
- 子 agent 是否成熟或可脱离。

## 事实源边界

模型输出默认是不可信输入。它只有经过相应层的确定性处理后，才能进入正式材料：

- 进入 Underground Center 前是 `candidate` 或 `proposal`。
- 进入 Direction Handoff 前必须被 Convergence Judge / Handoff Steward 采纳、合并或转写为引用。
- 进入 Aboveground Center 前必须来自 approved Direction Handoff Package。
- 进入 Verification 前必须被转成可执行检查、证据引用或人工可审查说明。
- 进入 Governance 前必须保留来源、版本、适用范围、风险和权限边界。

EventLog 记录模型调用发生过、使用了什么通道、产生了什么引用和验证状态；它不能把未验证的模型正文当作系统事实。

## 事件与观测

智能通道必须为未来前端工作台提供可观测性。最低事件包括：

- `model.requested`：记录调用目的、调用方、trace、预算、输出契约和清洗后的输入引用。
- `model.completed`：记录 provider、model、usage、finish reason、输出引用和结构化校验状态。
- `model.failed`：记录失败类型、可重试性、降级策略和错误引用。

这些事件必须避免泄露密钥、完整敏感 prompt、用户隐私、未授权 Soil 内容或供应商原始错误中的敏感字段。

Observation Snapshot 可以展示模型调用状态、用量、失败原因和输出引用，但不能成为 EventLog、Direction Handoff、Growth Plan、Run Memory 或 Soil 之外的新事实源。

## 失败与降级

模型调用失败时，系统必须显式处理，不得静默伪造成功：

- Underground Center 可以回退到确定性规则、进入 `awaiting_user` 或 `stopped`。
- Aboveground Center 可以保留草案缺口、请求用户确认或等待后续 Nutrient Request。
- Verification / Governance 可以把模型意见标记为缺失，而不能把缺失意见解释为通过。
- Provider 超时、输出不合约、成本越界或安全策略命中，必须形成可观测失败状态。

## 密钥与权限

- API key、provider token、base URL 凭证和组织级配置只能通过运行环境或安全配置注入。
- EventLog、Snapshot、Direction Handoff Package、Run Memory、Experience Candidate 和 Soil 都不能保存密钥。
- 模型请求必须携带调用目的和权限边界，不能把全量 Soil、全量任务历史或未授权资产直接塞入 prompt。
- Provider 输出可能包含 prompt injection、误导性建议或权限诱导，必须按不可信输入处理。

## 后果

- 后续真实 AI 接入先实现智能通道最小内核，再接具体 provider adapter。
- 任何直接在 Underground、Aboveground、Verification、Governance 或 app 层调用 provider SDK 的实现都违反架构边界。
- AI 能力可以加速目标理解、候选生成、解释和建议，但不能削弱 Direction Handoff validation、约束工程、状态机、EventLog、Verification 和 Governance。
- 多 provider、降级、观测、成本控制和供应商替换都有统一入口，不再在各业务模块中分散实现。
