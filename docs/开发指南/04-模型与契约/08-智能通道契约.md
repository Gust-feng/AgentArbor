# 智能通道契约

智能通道是 AgentArbor 调用模型的统一契约。它不是新的事实源，也不是产品节点；它让模型能力以可审计、可替换、可失败和可观测的方式服务各层。

所有真实模型调用必须通过智能通道或 `AgentTurnRuntime`。领域模块、应用编排、CLI、Desktop Shell 和测试入口都不能直接绑定 provider SDK、外部 LLM SDK 或 provider adapter；应用组合根只能负责装配 provider adapter 和智能通道，不能把 provider-specific 字段泄漏给业务流程。

AgentArbor 的智能通道是原生协议适配层，不采用 Vercel AI SDK、OpenAI SDK、LangChain、Anthropic SDK、Gemini SDK 或其他外部 LLM SDK 作为核心依赖。首个真实协议目标是 `openai_compatible_chat_completions`，通过 Node global `fetch` 映射到 `/v1/chat/completions`；后续可扩展其他协议，但这些协议在本轮只保留边界。

## 核心对象

### ModelRequest

`ModelRequest` 描述一次模型调用的内部请求。它必须说明调用目的、调用方、输出契约、约束和预算。

```ts
interface ModelRequest {
  requestId: string;
  traceId: string;
  callerRef: string;
  purpose:
    | "intent_profile"
    | "rootlet_candidate"
    | "counterfactual"
    | "parent_synthesis"
    | "convergence_decision"
    | "plan_draft"
    | "execution_draft"
    | "verification_advice"
    | "governance_advice";
  inputRefs: string[];
  sanitizedMessages: ModelMessage[];
  outputContract: ModelOutputContract;
  constraintRefs: ConstraintRef[];
  budget: ModelBudget;
  sensitivity: "public" | "internal" | "restricted";
  requestedAt: string;
}
```

`sanitizedMessages` 只保存已清洗、已授权进入模型上下文的内容。未授权 Global Soil 内容、密钥、完整运行私密材料和平台凭证不能进入请求。

### ModelResponse

`ModelResponse` 描述 provider 返回后经过智能通道归一化的结果。

```ts
interface ModelResponse {
  responseId: string;
  requestId: string;
  providerId: string;
  model: string;
  status: "completed" | "failed" | "cancelled";
  outputKind: "candidate" | "draft" | "explanation" | "evidence_suggestion";
  structuredOutput?: unknown;
  textOutputRef?: ArtifactRef;
  usage?: ModelUsage;
  finishReason?: "stop" | "length" | "tool_call" | "content_filter" | "error";
  validation: ModelOutputValidationResult;
  completedAt: string;
}
```

`structuredOutput` 仍然只是单次模型产出。它必须先进入调用方或父层 agent 的候选池、收束判断、Plan 草案或治理建议流程，再接受确定性边界守卫；不能由 provider response 直接写入 Plan、Workflow IR、Run Memory 或 Global Soil。

### ModelUsage

`ModelUsage` 归一化 provider 用量，供成本、审计和观测使用。

```ts
interface ModelUsage {
  inputTokens?: number;
  outputTokens?: number;
  totalTokens?: number;
  estimatedCostUsd?: number;
  latencyMs?: number;
}
```

用量字段可以缺失，但不能伪造。provider 不返回的字段应保持空值，并在观测层显示为 unknown。

### ModelCallRef

`ModelCallRef` 是正式材料引用模型调用的方式。

```ts
interface ModelCallRef {
  requestId: string;
  responseId?: string;
  providerId?: string;
  model?: string;
  outputKind: "candidate" | "draft" | "explanation" | "evidence_suggestion";
  eventRefs: string[];
  validationStatus: "pending" | "passed" | "failed";
}
```

Plan、ExecutionPlan、Verification Result 或 Governance Review 可以引用 `ModelCallRef`，但不能把未验证模型正文当成事实复制进去。

## 接口边界

### ModelProvider

`ModelProvider` 是 provider adapter 的最小接口。它只处理供应商协议差异。

```ts
interface ModelProvider {
  providerId: string;
  complete(request: ModelRequest): Promise<ModelResponse>;
}
```

Provider adapter 不能读取或写入 Global Soil、Plan Package、Fruits、Governance Registry 或任务状态机。

Provider adapter 必须把供应商响应归一化为 `ModelResponse`，不能把原始 provider response 结构泄漏到 Underground、Aboveground、Verification、Governance 或 Observation Panel。

### IntelligenceChannel

`IntelligenceChannel` 是业务层唯一能调用的模型入口。

```ts
interface IntelligenceChannel {
  request(request: ModelRequest): Promise<ModelResponse>;
  validateResponse(request: ModelRequest, response: ModelResponse): ModelOutputValidationResult;
}
```

智能通道负责：

- 校验请求是否带有目的、预算、输出契约和授权上下文。
- 发布模型调用事件。
- 调用合适的 provider adapter。
- 归一化 provider 响应。
- 执行输出契约校验。
- 返回可失败结果，而不是抛给业务层自行猜测。

## 事件契约

智能通道最低必须发布以下事件：

| 事件 | 触发时机 | 最低字段 |
| --- | --- | --- |
| `model.requested` | 请求通过通道校验并准备调用 provider | `requestId`、`traceId`、`purpose`、`callerRef`、`providerId`、`model`、`budget`、`inputRefs` |
| `model.completed` | provider 返回且响应归一化完成 | `requestId`、`responseId`、`usage`、`finishReason`、`outputKind`、`validationStatus` |
| `model.failed` | provider 失败、超时、输出不合约或预算越界 | `requestId`、`failureKind`、`retryable`、`fallback`、`sanitizedErrorRef` |

事件不得包含：

- API key、access token 或 provider 凭证。
- 未清洗完整 prompt。
- 未授权 Global Soil 内容。
- 用户隐私正文。
- provider 原始错误中的敏感字段。

## 配置边界

首个真实 provider 接入可以使用环境变量：

```text
AGENTARBOR_MODEL_API_KEY
AGENTARBOR_MODEL_NAME
AGENTARBOR_MODEL_BASE_URL
```

规则：

- `AGENTARBOR_MODEL_API_KEY` 只由 provider adapter 读取。
- `AGENTARBOR_MODEL_NAME` 是运行配置，不是代码常量。
- `AGENTARBOR_MODEL_BASE_URL` 仅用于兼容网关或自托管 OpenAI-compatible endpoint。
- 环境变量不得写入 EventLog、Snapshot、Plan Package、Run Memory、Experience Candidate 或 Global Soil。

## 验证规则

- 模型输出必须匹配 `outputContract`；不匹配时返回 failed 或 validation failed。
- 单次 AI 输出只能进入候选池、草案或建议层；进入正式材料前必须通过父层 agent 收束，并通过调用方的确定性边界验证。
- `openai_compatible_chat_completions` adapter 只能在显式配置 provider 时发起网络请求；默认 demo 和测试必须使用 fake/stub runtime，不触发真实网络。
- 如果运行环境没有 global `fetch`，且调用方没有注入测试 fetch，adapter 必须返回清晰的 provider configuration failure，不添加 polyfill。
- hard constraint 不能被模型输出覆盖。
- Path Bias 只能影响模型请求的偏好和排序提示，不能覆盖约束。
- LLM-as-judge 只能作为 Verification / Governance 的建议输入，不能单独决定通过。

## 首个接入范围

首个真实模型接入应围绕 Underground Cognitive Runtime 的 AI 驱动主线推进：

- Intent Core 可以请求目标结构化建议，并把结果作为 GoalIntentProfile 候选进入后续守卫。
- Rootlet 可以请求候选方向、风险、证据建议或反例。
- Parent Synthesis 和 Convergence 可以通过统一 AgentTurnRuntime 请求收束判断，但推荐、合并、淘汰、用户澄清或停止决策必须回到正式 convergence 结果，并接受 hard constraint、预算、状态机和引用一致性验证。
- Handoff / Plan Steward 可以使用上层 agent 叙事组织 Plan，但只能打包已收束、已验证的候选。

工程边界不得替 agent 思考：`outputContract`、parser、visibleOutput、validation、budget 和 permission 只负责裁剪、校验、脱敏、失败归一和引用边界；不得把这些机制写成目标理解、候选排序、工具选择或收束裁决的主逻辑。

Aboveground、Verification、Governance 的真实模型调用应在智能通道和 AgentTurnRuntime 稳定后逐步接入。
