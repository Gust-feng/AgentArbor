# 智能体组织、集群与果实

## 智能体组织

AgentArbor 中的智能体组织来自 Direction Handoff、Growth Plan、Workflow IR 和运行时证据，不来自预设角色表。

设计智能体时必须先回答：

- 它承担的是地下成形、地上计划、执行、验证、沉淀还是交付职责。
- 它需要哪些输入。
- 它产出什么结构化交付物。
- 它可以使用哪些能力。
- 它不能做什么。
- 它的结果如何验证。
- 它和其他 agent 如何通过 MessageBus、Router 和状态机交接。

## 生命周期

```text
临时职责
  -> 临时 agent
  -> EventLog / Artifact / Verification
  -> Nutrient Request / Growth Plan Revision
  -> Run Memory
  -> Experience Candidate
  -> Capability Asset
  -> 注册内部 agent
  -> Fruit
  -> 可脱离子 agent
  -> 退役或再演化
```

## 成熟度模型

智能体和能力资产按成熟度分层治理：

| 等级 | 名称 | 形态 | 复用能力 | 是否可脱离母体 |
| --- | --- | --- | --- | --- |
| L0 | 运行痕迹 | EventLog、Artifact、Checkpoint、Verification | 否 | 否 |
| L1 | Run Memory | 单次运行经验摘要 | 弱复用 | 否 |
| L2 | Experience Candidate | 可复用经验候选 | 可评估 | 否 |
| L3 | Capability Asset | 已治理能力、工作流片段、验证规则或内部 agent | 强复用 | 可进入审查 |
| L4 | Fruit | 独立 AgentApp、能力包或子 agent | 可复用 | 是 |

晋升必须有证据：

- L0 到 L1：运行链路可回放，验证结果明确。
- L1 到 L2：经验具备可复用条件、不适用条件和证据来源。
- L2 到 L3：多次复用或强验证成立，有权限边界、版本和维护责任。
- L3 到 L4：用户或外部系统明确需要脱离，且安装测试、文档、安全审查、回滚预案全部通过。

## 果实条件

agent 成为果实前，必须满足：

- 有真实任务来源。
- 有清晰输入输出。
- 有最小权限声明。
- 有依赖说明。
- 有验证记录。
- 有版本。
- 有谱系。
- 有退役策略。

## 不能做的事

不能因为某个角色在文档里被命名，就把它当作已经存在的 agent。不能把 Codex custom subagent、OpenCode agent 或 Agent Skills 文件直接视为 AgentArbor 原生子 agent。不能把一次 Run Memory 直接当成 Capability Asset。
