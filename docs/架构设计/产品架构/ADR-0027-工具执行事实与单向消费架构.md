# ADR-0027: 工具执行事实与单向消费架构

日期：2026-05-14

状态：Accepted

## 背景

历史工具链曾同时携带执行结果、模型投影、UI display、envelope、跨层调用计数和多份摘要。同一个调用被执行层、事件层、持久化层和 Panel 重复加工，取消也可能被折叠成失败。项目处于开发期，因此这些旧结构已经清洁断代，不迁移旧 runtime JSON，不保留 deprecated alias 或旧字段读取。

## 决策

`ToolCallResult` 是中性工具执行的唯一结果事实：

```text
ToolCenter -> ToolCallResult
                    |
                    +-> owning feature canonical facts
                    +-> model view
                    +-> feature-owned event/read-model
```

`completed / failed / cancelled / approval_required` 互斥。ToolCenter 负责执行、权限、命令确认和结果归一化；不拥有 Agent 轮次、业务状态、跨 feature 事件、仓储或 UI display。调用 feature 必须先接受工具事实，再把同一事实映射给模型、事件和 Panel。

## 功能归属

- Ordinary 把工具 requested、结果、确认和取消写入 `ordinary-run/v2` canonical facts；live、replay、conversation history 和 Panel projection 都从这份 feature 状态单向派生。
- Multi-Agent 将 `ToolCallResult` 映射到自己的 Deep child/run facts、事件和 file stores，不读取 Ordinary 工具事实。
- Sub-Agent 是 Ordinary 的 SDK AgentTool。调用与完整结果形成 Ordinary 标准工具事实，不发布 `sub_agent.*` 事件，不建立专用 trace store、continuation store 或 read-model。
- provider `callId` 与应用 `factId` 分离；外部 id 不承担 feature 幂等或持久化身份。

禁止建设跨 feature 的统一工具生命周期 reducer、RuntimeDatabase tool-call 表或全局业务事件。中性事实可以复用，业务恢复规则不能复用。

## 结果形状

- input/output 只接受 JSON-safe `ToolFactValue`。
- 模型正文在 `none / text / json` 中选择一种表达；不得把同一完整 output 同时复制到 text、JSON、summary 和 envelope。
- error、error facts、duration、confirmation 和 continuation 必须保留原始状态；交付失败不得抹掉工具是否已经产生副作用。
- `ToolDisplayProjection` 属于 Panel/Observation read-model，只能从 feature-owned facts 派生，不能写回 ToolCallResult、feature state 或 repository。

## 有界读取与 continuation

通用 ToolCenter 只读取输出顶层明确的 `continuation / continuations`，不从任意 `nextInput`、`nextOffset` 或第三方 `structuredContent` 猜测可执行续读。

- `read_file / list_dir / grep_files` 返回当前有界事实和下一位置。模型需要更多内容时，用下一位置再次调用原工具。
- MCP 规范没有通用 continuation；MCP `content[]` 与 `structuredContent` 原样保留，除非 producer 明确定义 canonical continuation。
- 真实分页、offset ceiling 或副作用请求无法安全重放时，返回明确失败，不能构造会重放 POST/PUT/DELETE 的 synthetic continuation。

当单次序列化结果超过内联边界时，Host-owned 进程内 `ToolOutputStore` 可以保存当前完整结果并返回预览、`tool-output://` 引用和 `read_tool_output` 输入。它只是 feature-owned run 可用的 live transport：

- 不重新执行原工具。
- 引用必须标记 `continuationAvailability: "live_only"`。
- 完整内容不进入 Ordinary 或 Deep 持久化 snapshot；进程重启、TTL 或容量回收后明确 not found。
- 无法保存完整结果时，completed 转为 delivery failure，并保留 `sourceExecutionStatus` 与 `doNotBlindlyRetry`；failed/cancelled/approval 保留自身语义。

## MCP 与附件

MCP adapter 只保留服务端 `content[]` 与可选 JSON 对象 `structuredContent` 的单份语义事实。只有 text 可解析 JSON 且与 `structuredContent` 深度完全相等时，才删除精确镜像；其他内容完整保留。`isError=true` 映射为正式失败。

图片、音频和文件通过带外附件进入模型请求，JSON 只保存 MIME、文件名/URI、byte length 和附件索引。adapter 必须保持来源角色并执行各协议的媒体能力与预算；不支持的媒体明确失败，不能静默删除或把 audio 伪装成 file。附件字节不进入 feature 持久化上下文。

## 工具与补丁

工具 producer 返回客观执行事实，不返回 `canonicalResult / display` 等派生结构。`edit_file` 使用成熟 `diff` 库生成唯一 canonical unified diff；模型事实、事件和 Panel 只能消费这份补丁，不能各自重建不同 diff。

## 依赖规则

- ToolCenter、adapter 和 kernel 不依赖 Ordinary、Deep 或 Panel。
- feature repository 不依赖 Panel UI 类型，不保存 display/envelope 历史副本。
- 工具调用预算和停止判断属于调用 Agent loop。
- 工具定义、冻结可见性和可执行范围在 run 出生时确定；运行中配置变化只影响新 run。
- 用户确认、取消和资源释放必须贯穿 AgentLoop、ToolCenter 与 owning feature，不能由 UI 文案推导。

## 后果

- 工具结果只在一个 owner 中成为业务事实，其他层单向消费。
- Ordinary、Multi-Agent 和未来 feature 可以共享执行机械能力，同时保持独立状态和恢复语义。
- 开发期旧事件、旧 projection/envelope、旧 Sub-Agent trace 和旧 RuntimeDatabase 记录直接失效。
- 新增 continuation 必须有真实 producer、明确生命周期和可执行读取路径；不能为了潜在需求保存额外历史数据。
