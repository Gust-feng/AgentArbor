# AgentArbor 愿景

## 1. 定位

AgentArbor 是一个基于 Git 演化的 AgentApp 孕育、开发、维护、分化与重生平台。

它不是一个让人搭 Bot 的工具，也不是一个让 AI 帮人写代码的助手。它的目标更深：

> 把用户的目标转化为一个可运行、可验证、可追溯、可继续演化的多 Agent 系统。

AgentArbor 的产物不是“一段代码”或“一组 Prompt”，而是一个拥有目标、文档、能力、Agent 组织、测试、日志、Git 历史与演化谱系的 AgentApp 工程。

## 2. 核心隐喻

AgentArbor 的隐喻不是工厂，而是树。

- 目标是种子。
- 文档是基因。
- Agent 是枝条。
- 能力是器官。
- Git 是年轮。
- 测试是自然选择。
- 治理是边界。
- 反思是意识。
- 分化是生命力。
- 重生是勇气。
- 用户是园丁。

这个隐喻不是装饰。它决定了 AgentArbor 的产品哲学：软件不是一次性吐出来的，而是在时间、反馈和约束中生长出来的。

## 3. 为什么不是固定工作流平台

固定工作流平台的逻辑是：先定义流程，然后让系统按流程执行。

AgentArbor 的逻辑相反：先理解目标，再根据目标和当前状态动态生成阶段、任务、Agent 组织和能力配置。工作流可以存在，但它只是某一轮自主迭代里的临时形态，而不是系统的统治者。

AgentArbor 的目标是：

> 目标不变，路径可变；方向可修正，历史不抹除。

## 4. 为什么 Git 是核心

Git 在 AgentArbor 中不只是版本管理工具，而是 AgentApp 的时间结构。

每一次 commit 都应该有理由：

- 为什么做这次修改？
- 哪个 Agent 触发？
- 它对应哪个目标或验收条件？
- 测试结果如何？
- 是否引入技术债？
- 是否影响未来演化？

Git branch 也不只是代码分支，而是 AgentApp 的分化路径。一个项目可以成长出企业版、轻量版、实验版、重生版，每个版本都有自己的血缘关系。

## 5. AgentArbor 最终要实现什么

完整形态的 AgentArbor 应当支持：

1. 从用户目标孕育 AgentApp。
2. 生成完整文档、计划、架构和验收标准。
3. 动态组织多个 Agent 执行开发。
4. 自动测试、审查、修复并提交 Git。
5. 持续维护已生成的 AgentApp。
6. 在用户改变方向时重新规划。
7. 在新需求与旧主线冲突时分化版本。
8. 在旧架构无法支撑目标时进入重生模式。
9. 通过 MCP、skills、`.agent`、插件等能力系统持续获得新能力。
10. 在所有自主动作中保留治理、边界和可追溯性。

## 6. 一句话愿景

AgentArbor 是一个让 AgentApp 拥有出生、成长、修剪、分化与重生能力的软件生命平台。
