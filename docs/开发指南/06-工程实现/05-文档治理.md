# 文档治理

## 文档分层

- `docs/开发指南/`：稳定开发口径。
- `docs/任务看板/`：历史 Trellis 任务态势快照，不再从 `.trellis/tasks/` 派生当前任务，也不是计划源数据。
- `docs/研究资料/`：研究报告、基础资料和长期参考材料。
- `docs/架构设计/`：长期架构决策、协议边界、工作区结构、当前产品架构和历史植物学架构资料。

## 吸收规则

研究资料和架构设计进入开发指南前必须被转化为稳定结论。不能把整篇原始材料直接挪进开发指南。历史经验、推进记录、阶段计划、会话沉淀、草案包和准备包不保留在活跃文档树。

## 索引规则

任何新增、移动或删除文档，都必须同步检查：

- 当前目录 `README.md`。
- `docs/README.md`。
- 根 `README.md`。
- `AGENTS.md` 中的开发入口。
- `.trellis/spec/guides/agentarbor-governance-guide.md` 中仍有参考价值的治理口径，但不得覆盖 `AGENTS.md`、当前开发指南和用户最新指令。

## 命名规则

目录名、文件名和正文默认使用简体中文。`README.md` 是目录索引文件的保留例外。
