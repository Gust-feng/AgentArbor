# 核心模块

## Seed Cluster

把用户提示词中的 Imagination 转化为 Seed Packet。它负责前置成像、目标拆解、非目标边界、假设缺口、最小化搜索、反驳风险、可选方向和用户确认。

Seed Cluster 不启动正式执行，不生成 Growth Plan，不创建长期资产。

## Goal Kernel

保存目标、约束、状态、验收标准、风险、暂停点、分支点和变更记录。Goal Kernel 是目标事实源，不是执行 agent。

## Soil Store

保存受治理的 Capability Asset、历史运行索引、验证规则、权限策略、失败模式、偏好和长期资料。任何进入土壤的资产都必须经过 Governance Gate。

## Root System

负责持续地下探索和吸收。Root System 读取 Seed Packet、Soil Store、Run Memory、Experience Candidate、Path Bias 和 Capability Asset，输出版本化 Root Brief。

Root System 支持：

- Initial Rooting：生成 Root Brief v1。
- Lateral Rooting：局部补探并生成补充版本。
- Deep Rooting：整体重探并给出计划重估建议。

Root System 不能直接生成最终 Growth Plan，不能直接执行任务，也不能绕过权限策略。

## Root Crown Cluster

根颈固定核心集群，负责汇总多个根系方向的探索结果，审计证据、识别冲突、反局部最优，并形成 Root Brief。

Root Crown Cluster 建议包含：

- Root Synthesizer。
- Evidence Auditor。
- Path Bias Analyst。
- Root Critic。

## Core Control Cluster

主干固定核心集群，读取 Root Brief，制定和修订 Growth Plan，必要时触发 Root Callback。

Core Control Cluster 建议包含：

- Trunk Synthesizer：最强模型主综合。
- Plan Critic：反审查。
- Risk Governor：风险、权限、成本和不可逆动作检查。
- Growth Recorder：记录决策、偏离和沉淀策略。

## Workflow IR Builder

把 Growth Plan 转换成可执行、可暂停、可恢复、可验证的 Workflow IR。Workflow IR 必须包含任务依赖、输入输出、失败处理、验证门、Root Callback 点和沉淀节点。

## Branch / Leaf Runtime

负责运行 Workflow IR，创建任务工作区，调度临时 agent，记录事件，处理暂停、恢复和失败。

运行时第一阶段必须先建立内部骨架：

- `ArborMessage`：AgentArbor 内部消息母语。
- `MessageBus`：消息接收、校验、路由、权限检查、事件记录、重试和回放。
- `Router / Coordinator`：根据任务状态、能力、权限和失败记录选择执行者。
- `AgentRegistry`：记录可调度智能体及其能力、状态和生命周期。
- `ArtifactStore`：记录产物来源、版本、验证状态和复用状态。
- `EventLog`：记录可回放事件链，作为验证、回流、谱系和演化依据。

内部智能体不能互相私聊，必须通过 MessageBus、Router 和状态机协作。外部协议进入系统前，必须先被 adapter 翻译为 AgentArbor 内部消息。

## Flower Verification / Acceptance

Flower Verification 负责测试、检查、证据收集和成熟度判断。Acceptance 判断用户目标是否真正满足。

两者必须分离：

- Verification 判断产物是否正确、格式是否合规、测试是否通过。
- Acceptance 判断交付是否满足用户目标和治理边界。

Flower Cluster 可以触发 Root Callback，但不能自行修订 Growth Plan。

## Run Memory Store

负责从 EventLog、Artifact、Verification 和 Acceptance 中形成 Run Memory。它记录实际路径、成功模式、失败模式、Root Callback、Growth Plan Revision、偏离原因和下一次可参考的线索。

## Experience Candidate Store

负责保存可复用经验候选。候选不能自动进入土壤，必须等待治理门判断。

## Path Bias Index

负责把已验证路径转化为下一次任务可检索的路径倾向。Root System 发现 Path Bias，Core Control Cluster 决定是否采用。

## Lineage Registry

记录 Seed Packet、Root Brief 版本、Growth Plan 版本、Workflow IR、Branch / Leaf Runtime、AgentApp、能力、验证结果、果实和导出包之间的来源关系。

## Evolution & Governance

负责经验候选识别、晋升、版本、导出、修剪、退役和风险隔离。任何长期资产出生都必须经过这一层。

## Adapter Layer

负责 Codex、OpenCode、Agent Skills、MCP、模型供应商、工具协议和外部平台的格式转换。适配层不能反向污染核心模型。

架构原则是“内核自研，协议兼容”：

```text
外部协议 -> Adapter -> ArborMessage
ArborMessage -> Adapter -> 外部协议
```
