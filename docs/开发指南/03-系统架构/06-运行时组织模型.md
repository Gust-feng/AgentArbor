# 运行时组织模型

## 组织形态

AgentArbor 运行时根据 Growth Plan 选择组织形态，而不是预设固定角色表。

| 形态 | 适用场景 | 输出 |
| --- | --- | --- |
| Underground Center | 用户目标需要成形、证据探索、约束确认或养料供给 | 方向交接包版本、Nutrient Patch |
| Constraint Engineering | 目标、非目标、权限、成本、技术边界或验收门需要工程化 | Constraint、ConstraintRef |
| single agent | 目标简单、风险低、验证清楚 | Artifact、Verification、Run Memory |
| sub-agent tree | 任务天然分解为父子上下文和递归子任务 | Artifact、Verification、Run Memory |
| shared team cluster | 多 agent 需要共享事实池、共同推进和状态同步 | Artifact、Verification、Run Memory |
| competitive team cluster | 需要多方案竞争、反审查或高风险验证 | 对比证据、推荐方案、Verification |
| fruit run | 已有成熟能力可独立承担 | Fruit 输出和运行记录 |

## 决策顺序

```text
Soil
  -> Underground Center
  -> .agentarbor direction handoff
  -> Aboveground Center
  -> Growth Plan
  -> Workflow IR
  -> Router
  -> Aboveground Growth
  -> Verification
  -> Fruits
  -> Governance
  -> Soil
```

Aboveground Center 必须决定：

- 是否采用 Path Bias。
- 是否复用 Capability Asset。
- 哪些 ConstraintRef 必须进入 Growth Plan、Workflow IR、TaskSpec 和 Verification。
- 是否需要 single agent、sub-agent tree、shared team cluster 或 competitive team cluster。
- 哪些节点需要 Verification 和 Acceptance。
- 哪些结果需要形成 Run Memory 或 Experience Candidate。
- 哪些失败、未知项或目标变化需要向 Underground Center 发起 Nutrient Request。

## 状态和通信

运行时状态必须由状态机驱动。agent 之间不能私下通信。

允许：

- 通过 MessageBus 发送同步请求。
- 通过 Router 分配任务。
- 通过 EventLog 记录状态变更。
- 通过 ArtifactStore 保存产物。

禁止：

- agent 私下绕过消息系统调用另一个 agent。
- 用聊天内容替代结构化交付物。
- 用历史 Path Bias 替代本次验证。
- 用 Path Bias 覆盖 hard constraint。
- 用自然语言约束说明替代 ConstraintRef。
- 用平台适配文件替代 AgentArbor 原生运行语义。
- 用地下中枢替代执行层。
- 用一次方向交接包锁死后续运行。
