# 目标驱动元循环

## 元循环

AgentArbor 的最小稳定循环是：

```text
用户提示词 / Imagination
  -> Seed Cluster 前置成像
  -> Seed Packet
  -> User Approval Gate
  -> Soil
  -> Initial Rooting
  -> Root Brief v1
  -> Core Control Cluster
  -> Growth Plan v1
  -> Workflow IR
  -> Branch / Leaf 执行
  -> Verification / Acceptance
  -> Root Callback / Re-rooting
  -> Run Memory
  -> Experience Candidate
  -> Path Bias
  -> Capability Asset / Fruit / Retire
```

这个循环必须比任何单个平台 agent 格式更基础。平台 agent 只是执行或导出结果之一。

Path Bias 表示后续相似任务对已验证路径的自然倾向。它使系统不会每次从零开始，也不会把历史流程当成不可改变的模板。

## 目标内核职责

目标内核至少保存：

- 用户原始目标。
- 澄清后的目标。
- 非目标。
- 约束。
- 验收标准。
- 风险等级。
- 输入资产范围。
- 当前状态。
- 暂停点和恢复点。
- 变更记录。
- 完成或失败判定。

## 状态要求

目标不能只存在于聊天上下文里。实现时必须把目标表达为可存储、可恢复、可比较的数据结构。

基础状态包括：

- `draft`：目标尚未澄清。
- `imaging`：Seed Cluster 正在前置成像。
- `seed_ready`：Seed Packet 已形成，等待用户确认。
- `ready`：Seed Packet 已通过 User Approval Gate。
- `exploring`：Root System 正在初始生根或补探。
- `planned`：已经形成 Growth Plan 和 Workflow IR。
- `running`：任务正在执行。
- `blocked`：需要人工决策、权限或外部输入。
- `re_rooting`：已触发 Root Callback，等待新的 Root Brief 版本或无需重探证据。
- `revising`：Core Control Cluster 正在基于新 Root Brief 修订 Growth Plan。
- `verifying`：进入验证阶段。
- `completed`：通过验收。
- `failed`：未通过验收并保留失败证据。
- `archived`：关闭并保留谱系和 Run Memory。

## 验收原则

目标是否完成，不能由执行 agent 自我宣布。必须由验证结果、用户确认、测试证据或明确规则共同决定。
