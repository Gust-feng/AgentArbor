# 模块划分

未来 `src/` 建议围绕原生概念树组织领域模块，同时把消息、状态机、事件、权限和产物等横切内核放在明确边界内。源码布局采用 `domain / kernel / adapters / app` 四层，不把概念树节点平铺成根级工程目录：

```text
src/
  domain/
    soil/
    underground/
    agentarbor/
    aboveground/
    fruits/
    governance/
    lineage/
    intelligence/
  kernel/
    messages/
    state-machine/
    events/
    permissions/
    artifacts/
    intelligence/
  adapters/
    intelligence/
  app/
```

## 职责边界

- `domain/soil`：长期事实、Capability Asset、Path Bias、稳定约束、治理规则、历史证据和失败模式。
- `domain/underground`：需求成形、约束提取、证据探索、方向综合、用户升级确认、Nutrient Request 处理和 Nutrient Patch 生成。
- `domain/agentarbor`：`.agentarbor` 方向交接包的读写契约、版本、引用校验和 Growth Entry；不保存最终资产。
- `domain/aboveground`：Growth Plan、Workflow IR、Context Topology、任务切片、运行组织选择、计划修订和验证门编排。
- `domain/fruits`：交付物、AgentApp、能力包、可脱离子 agent 候选、Run Memory 和 Experience Candidate。
- `domain/governance`：果实成熟度评估、权限审查、谱系归因、版本、导出、退役和入土裁决。
- `domain/lineage`：方向交接包、Growth Plan、Workflow IR、执行组织、产物、验证和入土结果之间的谱系。
- `domain/intelligence`：智能通道领域契约、模型调用目的、输出类型、`ModelCallRef` 和模型产出引用规则；它是横切契约，不是概念树节点。
- `kernel/messages`：ArborMessage、MessageBus、Router 和跨模块消息协议。
- `kernel/state-machine`：运行阶段、状态转移和 Growth Plan Revision 状态机制。
- `kernel/events`：EventLog、事件发布、事件订阅和审计轨迹。
- `kernel/permissions`：权限声明、授权检查、用户升级确认和高风险动作门。
- `kernel/artifacts`：ArtifactStore、产物引用、校验摘要和临时运行材料索引。
- `kernel/intelligence`：智能通道实现、请求校验、输出契约校验、模型调用事件、失败策略和 provider registry；它不能保存业务事实。
- `adapters/intelligence`：OpenAI-compatible、Anthropic、Gemini、Qwen、Ollama/vLLM 或其他 provider adapter；只有这一层可以直接处理供应商协议和凭证。
- `adapters`：Codex、OpenCode、Agent Skills、MCP、模型、工具和外部平台适配。
- `app`：工作台界面、应用服务编排、CLI 或未来 API 入口。

## 横切规则

- `domain/` 保存 AgentArbor 产品语义和概念树规则；它不能依赖具体平台 adapter。
- `kernel/` 可以被 `domain/`、`app/` 和 `adapters/` 复用，但不能保存业务事实，也不能替代 Soil、`.agentarbor` 或 Governance。
- `adapters` 只能转换格式，不能定义核心领域模型。
- `app` 只能通过正式服务或应用层接口读写，不能直接写 Soil、`.agentarbor` 或治理注册表。
- `domain/agentarbor` 只能引用 Soil 中的稳定资产，不能复制 Soil 内容形成第二事实源。
- `domain/fruits` 不能直接写 `domain/soil`；必须经过 `domain/governance`。
- `domain/aboveground` 可以向 `domain/underground` 发起 Nutrient Request，但不能自建方向探索集群，也不能静默改写方向交接包。
- `domain/underground` 可以读取 `domain/soil` 和写 `.agentarbor`，不能创建最终果实。
- 任何运行流程需要模型能力时，只能依赖智能通道契约或注入的 `IntelligenceChannel`；应用组合根可以装配 provider adapter，但不能让领域层、kernel 或业务编排直接读取 provider 环境变量或调用 provider SDK。

## 禁止穿透

`app` 不能直接写注册表；adapter 不能定义核心模型；地上运行不能绕过 `kernel/permissions`；临时任务不能直接写长期能力资产；果实不能绕过治理进入土壤；领域层、kernel 和业务编排不能直接导入模型供应商 SDK。
