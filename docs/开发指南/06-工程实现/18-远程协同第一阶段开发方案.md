# 远程协同第一阶段开发方案

## 目标

第一阶段在同一仓库交付四部分：

1. 可作为 Linux 进程运行的 AgentArbor Remote Service，装配 Identity、Relay 与 Content Vault；
2. 由唯一桌面 Host Composition Root 装配的 Remote Collaboration connector；
3. Android 9+ Capacitor 客户端与可安装 debug APK；
4. 桌面与移动端的 Content Vault V1 同步客户端。

源码、协议和 APK 构建先在本地完成；公网更新和 Android 真机联调在用户授权部署验证后进行。实时协同边界以 [ADR-0034](../../架构设计/产品架构/ADR-0034-远程协同与选择性同步架构.md) 为准，受管内容持久同步以 [ADR-0035](../../架构设计/产品架构/ADR-0035-ContentVault与受管内容同步架构.md) 为准。

## 模块所有权

`src/app/remote-collaboration/` 拥有：

- `remote-collaboration/v1` Ordinary wire schema 和 Zod 校验；
- desktop connector 的显式启动、自动重连、本地 outbox/inbox、接收确认和 command result；
- live-only delta 合并、Ordinary 命令幂等、Relay WebSocket adapter 和定向行为测试。

`src/app/content-vault/` 拥有：

- `content-vault/v1` 资源、mutation、change、usage 和错误契约；
- 按账户隔离的 SQLite repository、CAS、mutation 幂等、删除墓碑、cursor 和配额；
- HTTP adapter 和 repository/route 行为测试。

`src/app/content-vault-sync/` 拥有桌面同步 outbox、cursor、资源时钟、冲突和 contributor 调度。它通过 Host 注入的 Space、Personal Knowledge、Workbench Assets、Agent Notes 与 Managed Content contributor ports 工作，不能读取这些 feature 的 store。

远程服务入口只装配 Identity、Relay、Content Vault 和环境配置，不装配 Agent runtime。`src/app/mobile-ui/` 分别拥有 realtime client/cache 与 Vault client/cache，并共享 Secure Storage 设备凭据 adapter。`android/` 是 Capacitor 生成并纳入维护的原生外壳。

Remote Collaboration 只通过公开 Ordinary facade 工作。Content Vault Sync 只通过内容 feature 的 contributor facade 工作。两者都不调用 Panel `/api/*`，不读取其他 feature 的 repository 或 SQLite 表。Agent Notes contributor 在 V1 只投影全局笔记；工作区笔记的本地身份仍是 `workspaceRoot`，在建立逻辑工作区 ID 前不得同步。

## 配置边界

Remote Service 读取：

- `AGENTARBOR_RELAY_HOST`
- `AGENTARBOR_RELAY_PORT`
- `AGENTARBOR_RELAY_DATABASE`
- `AGENTARBOR_RELAY_INVITE_CODES`
- `AGENTARBOR_RELAY_ALLOW_OPEN_SIGNUP`，当前默认 `true`；显式设为 `false` 可恢复邀请码门禁
- `AGENTARBOR_VAULT_DATABASE`
- `AGENTARBOR_VAULT_ACCOUNT_BYTES`，默认 `157286400`
- `AGENTARBOR_VAULT_MAX_RESOURCES`，默认 `50000`

桌面 Panel 与移动端都通过 `VITE_AGENTARBOR_RELAY_URL` 在构建时注入官方服务地址；普通界面不显示也不允许修改。第一阶段不提供自托管入口，未来只通过独立高级配置开放。`.env.example` 只能使用 `https://relay.example.com`；正式域名、IP、邀请码、token、数据库路径和服务器凭据不得硬编码或提交。

官方桌面安装包必须由发布环境注入配置后再打包：

```powershell
$env:VITE_AGENTARBOR_RELAY_URL='https://relay.example.com'
pnpm dist:desktop:win
```

官方部署当前默认开放账户创建，桌面端不要求邀请码。邀请码表、哈希存储和关闭开放注册的开关继续保留；显式设置 `AGENTARBOR_RELAY_ALLOW_OPEN_SIGNUP=false` 后，邀请码仍只用于创建账户与首台桌面设备。每账户限一台桌面和一台手机，手机 token 在桌面批准前不可用，撤销后 Relay 与 Vault 都必须立即拒绝。

开放创建只取消产品邀请码门禁，不等于取消基础设施保护。公网长期运行前仍需在部署层补齐注册接口速率限制、磁盘容量监控和全局用量告警；在这些边界未落地前，`AGENTARBOR_RELAY_ALLOW_OPEN_SIGNUP=false` 是保留的紧急收口开关。

桌面批准手机后自动启动本次 Relay 连接，但后续应用启动仍保留显式“运行连接”。Content Vault 的 HTTPS 同步生命周期只依赖有效账户 binding 与设备 token，不依赖 WSS 是否在线；Relay 的 `vault.changed` 只携带 cursor 并负责唤醒。手机提交新会话而 Space 尚未进入桌面投影时，Host 通过注入 Remote Collaboration adapter 的窄同步函数拉取 Vault 后复查，不能让 Remote feature 读取 Vault repository，也不为此扩张 `remote-collaboration/v1`。

## 服务端数据与 API

Identity SQLite 只拥有账户、邀请码、设备和配对表。Relay 只维护进程内 socket、presence 与 pending receipt，重启后为零。对话、消息、命令和 AI 输出在任何服务端数据库中都必须为零。

Content Vault 使用独立数据库，只拥有 `vault_resources`、`vault_changes`、`vault_mutations` 和账户 usage 投影。它可以保存 ADR-0035 白名单内的 Space、知识、资产、全局 Agent Note 与受管文本文件，不能保存 Conversation/run；工作区 Agent Note 暂不进入 V1 Vault。

HTTP 根路径不提供网页。正式入口为：

- `GET /v1/health`
- 账户、handle、配对、设备列表与撤销接口
- `GET /v1/connect` 的 WebSocket upgrade
- `POST /v1/vault/mutations`
- `GET /v1/vault/changes`
- `GET /v1/vault/snapshot`
- `GET /v1/vault/resources/:kind/:id`
- `GET /v1/vault/usage`

旧 `/health`、根 `/` 和 `/v1/sync/*` 均返回 404。Vault API 与 Relay 共用设备 bearer token，但通过窄 authenticator port 获取账户事实。

## Ordinary 在线协议

所有帧携带 `protocolVersion: "remote-collaboration/v1"`。Relay 只在内存保存在线 socket 和等待接收确认的投递身份：

- 目标离线返回 `peer_offline`，发送端保留本地 outbox；
- 目标收到后返回 `message.received`，发送端才移除可靠 outbox 项；
- 桌面 inbox 按稳定 `commandId` 去重，Ordinary 消息复用其作为 `submissionId`；
- `command.result` 明确返回 `applied | conflict | failed`；
- `run.delta` 以 `24ms` 窗口合并，只在 socket 健康时 best-effort 在线发送，不写 desktop outbox；正式投影由 `run.snapshot` 覆盖；
- 可靠 outbox 对同一连接的 `clientMessageId` 只允许一个 in-flight submit，`message.received` 删除后立即补充发送窗口，断线后才允许重发；
- `conversation.index` 同步全部索引，`conversation.page.request` 按需返回最近或更早的最多 50 条正文。

WebSocket 单帧上限约 1.1 MiB，慢消费者超过发送缓冲上限时断开。不能通过无限放大帧或 Relay 内存队列解决内容聚合。

## Vault V1 同步协议

Space、知识、资产、全局 Agent Note 与受管文件不作为 Relay command/event 传输，统一使用 `content-vault/v1` mutation/change：

- mutation 使用稳定 `mutationId`、`baseRevision`、完整 payload 与 SHA-256；
- 新建以 `baseRevision: 0` 提交，更新和删除必须基于当前 revision；
- 删除生成墓碑，旧设备不能用新建语义复活；
- change 以账户级 cursor 分页；本地业务 apply 与同步元数据都成功后才推进 cursor；
- Vault 成功写入后通过同一 WebSocket 向其他在线设备发送只含 cursor 的 `vault.changed`，设备立即用 HTTPS 拉取正文；10 秒轮询只作漏通知兜底；
- CAS 冲突保持为 durable conflict，不自动 LWW、CRDT 或覆盖；
- 未装配 contributor 的远端 kind 必须形成 durable `remote_apply_failed`，禁止静默越过 cursor；
- 文本编辑跟随桌面当前 `500ms` autosave，待发送的同资源连续修改只保留最新完整版本。

桌面和手机都可以在对端离线时提交内容 mutation；落到桌面本地数据时仍必须通过 owning feature command。Space 引用只允许 `asset_folder`、`workbench_asset` 的路径无关投影，软件受管目录另以 `managed_root` 和 `managed_file` 表达；文件路径必须相对且不能越界，绝对路径与 `workspaceRoot` 不进入 Vault。Knowledge page 只投影有同步正文支撑的 Personal Note 与 Markdown/code material，二进制材料和目录导入的关系元数据保持本地。手机只对 Personal Note、全局 Agent Note 和受管文本文件展示删除；Space 与 Workbench Asset 在 owner 提供完整删除语义前不允许产生远端墓碑。

第一阶段每账户 active content 最大 150 MiB、每个 inline 文本资源最大 5 MiB、每批最多 100 个 mutation/4 MiB、最多 50,000 个 active resource。首次快照固定 change cursor 并使用资源身份键集分页，随后通过 change feed 补齐快照期间的并发变更。二进制 blob 不属于第一阶段。

## 本地存储

- Identity SQLite：账户与设备控制面。
- Vault SQLite：白名单资源 current revision、change log、mutation 幂等事实与 usage。
- Desktop connector store：桌面 binding、Ordinary outbox/inbox 和 command result。
- Desktop Vault Sync store：resource clock、cursor、outbox 与 conflict。
- Desktop token：宿主凭据存储，不写普通配置或日志。
- Mobile IndexedDB realtime stores：binding、pairing、Ordinary outbox、接收去重与对话展示缓存。
- Mobile IndexedDB vault stores：resource、cursor、mutation outbox 与 conflict。
- Mobile token：Android Secure Storage；浏览器开发环境只使用 localStorage fallback。

手机对话缓存不是桌面业务恢复源。退出或撤销设备时必须清除 token、binding、两个 outbox、回执、cursor、conflict 和缓存；桌面本地业务内容不因退出云账户而删除。

## Android 构建

当前配置：

- 包名：`dev.gustfeng.agentarbor`
- `minSdkVersion = 28`
- `compileSdkVersion = 36`
- `targetSdkVersion = 36`
- `allowBackup = false`

构建命令：

```powershell
$env:VITE_AGENTARBOR_RELAY_URL='https://relay.example.com'
pnpm mobile:android:debug
```

正式地址只在构建环境中注入。APK 使用当前 AgentArbor 图标、系统 Secure Storage 和相机二维码扫描；浏览器 URL 不是产品入口。

## 验证

提交前至少执行：

```powershell
pnpm build:node
node --test dist/app/remote-collaboration/*.test.js dist/app/content-vault/*.test.js
pnpm typecheck:mobile
pnpm test:mobile
pnpm typecheck:panel
pnpm build:panel
pnpm build:mobile
git diff --check
```

定向测试必须覆盖账户激活、handle 唯一修改、批准前 token 不可用、撤销、设备限制、peer offline、接收确认、重复 Ordinary 命令、delta burst/迟到终态、Vault cursor 通知、CAS、mutation 幂等、墓碑、cursor 分页、未装配 contributor 冲突、配额、账户隔离、路径越界，以及 Relay 重启后 Conversation 内容为零。

公网验证至少覆盖 TLS、反向代理 WebSocket/HTTPS、API-only 根路径、systemd 重启和 Android 网络切换。当前服务器上的其他业务端口不得修改；部署只更新独立 Remote Service 与对应反向代理路径。
