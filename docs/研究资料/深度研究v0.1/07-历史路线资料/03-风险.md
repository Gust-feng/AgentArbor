# 风险分析

## 1. 愿景过大

风险：AgentArbor 完整形态过大，容易失控。

应对：MVP 只证明自主迭代闭环，不一开始做完整生态。

## 2. 工作流模板化

风险：为了方便实现，系统被写成固定流程。

应对：固定 Meta Loop，不固定 Workflow Graph。

## 3. Agent 官僚化

风险：Agent 过多、层级过深、互相转述。

应对：保持 Root → Phase Lead → Worker 三层结构。

## 4. 自主性变成失控

风险：AI 执行危险操作或偏离用户目标。

应对：Governance System + 用户确认点 + 事件日志。

## 5. 局部最优与技术债

风险：短期可跑，长期难维护。

应对：CriticAgent、技术债账本、架构不变量、未来压力测试。

## 6. UI 先行掩盖内核薄弱

风险：界面漂亮但系统不真。

应对：先实现后端闭环，再做 UI 展示。

## 7. 能力系统过早复杂

风险：MCP、skills、plugins 全都做，拖垮第一版。

应对：先做 capability registry，再逐步扩展 MCP 和插件。

## 8. 重生功能滥用

风险：系统遇到难题就推倒重来。

应对：Rebirth 必须有提案、证据、用户确认和继承清单。

## 9. 用户信任问题

风险：用户不知道系统为什么这样做。

应对：每次行动都可解释，每次 commit 都有理由，每次演化都有文档。
