# 通信机制

## 定位

通信机制保证地下中枢、方向交接包、地上中枢、地上生长、验证、果实和治理之间只通过可记录、可回放、可验证的消息协作。

## 核心对象

- `ArborMessage`：内部消息母语。
- `MessageBus`：消息接收、校验、权限检查、路由和事件记录。
- `Router`：根据任务状态、能力和权限选择接收方。
- `EventLog`：可回放事件链。
- `ArtifactStore`：产物引用和版本。

## 事件链

```text
goal.received -> Underground Center
Underground Center -> direction_handoff.completed -> .agentarbor
.agentarbor -> direction_handoff.approved -> Aboveground Center
Aboveground Center -> growth_plan.completed -> Router
Router -> task.assigned -> Aboveground Growth
Aboveground Growth -> artifact.produced -> Verification
Verification -> verification.completed -> Aboveground Center / Fruits
Aboveground Center / Verification / Governance -> nutrient_request.requested -> Underground Center
Underground Center -> nutrient_patch.supplied -> Aboveground Center
Fruits -> governance.review.requested -> Governance
Governance -> capability_asset.accepted -> Soil
```

## 请求响应

需要同步响应的场景可以使用请求响应语义，例如验证请求、Nutrient Request 或人工确认请求。但这仍是 MessageBus 上的消息：

```text
request -> accepted -> working -> completed / failed / blocked
```

## 禁止事项

- agent 之间不私聊。
- 不用聊天上下文替代消息。
- 不绕过权限检查传文件。
- 不绕过 EventLog 直接改状态。
- 不让外部协议消息直接进入核心状态机。

## 可追溯性

- 每条消息必须有 `traceId`。
- Artifact、Verification、Run Memory、Nutrient Request、Nutrient Patch、Growth Plan Revision 和 Governance 决策必须能通过 EventLog 找到来源。
- 外部平台消息必须先被 adapter 转换为 ArborMessage。
