# 兼容路径隔离

## 当前结论

AgentArbor 处于开发期，Ordinary 不承担旧本地数据兼容。旧 BasicAgent、Desktop session、Panel run job、应用层 Underground、`MinimalRuntime`、旧 Sub-Agent runner 与 `/api/underground/*` 已删除，不能通过 facade、双读、双写或字段回填重新进入正式路径。

Multi-Agent 仍通过 `/api/deep/*` 提供正式功能，并继续使用 `domain/underground/agent-fabric` 中有效的 run-tree 领域契约。保留这些领域契约不代表保留旧应用层 Underground，也不是 Ordinary 的兼容入口。

## Ordinary 唯一恢复事实

Ordinary 只读取 feature-owned repository 中的：

- `ordinary-run/v2` snapshot：run 出生事实、status、`canonicalMessages`、工具事实、usage 与 timeline。
- `ordinary-conversation/v1` control document：对话分支、标题、置顶与删除事实。

`canonicalMessages` 是跨轮模型上下文的唯一表示。Panel conversation、SSE、工具活动、WorkView 和其他 UI read-model 都由 snapshot 单向投影，不能反向拼装模型历史。

旧 snapshot、raw `run.json`、sidecar event/tool-call、旧 RuntimeDatabase、旧独立模型上下文记录以及缺失当前 schema/version 的数据直接视为失效数据。不迁移、不回填、不双读，也不使用当前 Host 配置修补历史事实。

## 默认普通路径禁止事项

默认 Ordinary 路径不得：

- 重新引入 `/api/desktop/runs`、`/work-session`、`workSession` alias 或旧 conversation/run route。
- 重新引入 `desktop_chat`、`work_session_*` purpose 或 intent gate 自动路由。
- 从 Canvas、Panel stream event、可见对话或当前配置推导 run 状态、完成语义、能力快照或模型历史。
- 为读取开发期旧数据增加 deprecated facade、fallback parser、schema 猜测、双读或双写。
- 让 Deep 的 store、run tree、事件或 read-model 成为 Ordinary 的恢复来源。

## 新代码判断标准

新增代码必须直接进入当前 owner：

- Ordinary command/query/event、snapshot 与 read-model 归 `OrdinaryAgentFeature`。
- Multi-Agent manager、TaskBoard、scheduler、child、synthesis 与 run tree 归 `MultiAgentFeature`。
- 模型 provider、工具执行、确认和上下文机械算法通过中性端口注入。
- HTTP/SSE route 只做协议适配，不创建第二套 runtime、store 或恢复逻辑。

如果某项实现只有“旧数据可能存在”这一理由，就不应保留。需要诊断旧字节时使用一次性离线工具，不能把兼容分支放回生产主链。
