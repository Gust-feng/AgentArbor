# 枝层（Branch System）- 动态分支执行集群

## 职责

枝层负责把 Growth Plan 和 Workflow IR 转化为可执行的任务组织。它不是最终决策层，而是动态分支执行集群的协调结构。

## 输入与输出

| 项目 | 内容 |
| --- | --- |
| 输入 | Growth Plan、Workflow IR、任务依赖、权限边界、可用能力 |
| 输出 | 任务分配、进度事件、Artifact、阻塞报告、Root Callback Request、验证请求 |

## 分支 agent 集群

Branch System 可以按任务临时组建多个分支集群：

- Feature Branch Cluster：实现某个功能或阶段。
- Research Branch Cluster：限定范围的技术验证或事实补充。
- Repair Branch Cluster：处理验证失败后的局部修复。
- Integration Branch Cluster：整合多个叶层产物。

分支集群是动态任务集群。任务结束后，它们应解散、沉淀为 Experience Candidate，或在治理门后晋升为 Capability Asset。

## 协调规则

- 通过 Router 接收任务。
- 通过 MessageBus 与 Core Control、Leaf 和 Flower 协作。
- 通过 EventLog 记录状态变更。
- 不修改 Growth Plan；只能提出阻塞、偏离、Root Callback 或修订建议。
- 不直接写入 Soil。

## Root Callback 触发

Branch Agent 遇到以下情况时，应请求 Root Callback：

- 任务输入不足。
- 关键假设与执行证据冲突。
- Path Bias 在当前任务中失效。
- 权限、成本或外部依赖前提不成立。
- 局部失败无法通过普通修复解决。
