# 愿景

## 长期愿景

AgentArbor 要成为目标驱动的 Agent / AgentApp 孕育与演化平台。

用户不应该反复从零组织提示词、工具、上下文、角色和工程目录。用户给出的提示词首先是一种 Imagination。Seed Cluster 把这个想象前置成像为可审阅的 Seed Packet，并在 User Approval Gate 之后种入 Soil。Root System 随后初始生根，形成 Root Brief；Core Control Cluster 作为主干固定核心，读取根系证据，制定 Growth Plan 与 Workflow IR，调度 Branch / Leaf / Flower 完成执行、验证和交付。运行中如果发现信息不足、验证失败、Path Bias 失效或目标变化，Core Control Cluster 可以发起 Root Callback，让根系继续 Lateral Rooting 或 Deep Rooting，再修订 Root Brief 与 Growth Plan。

随着真实任务重复发生，系统应识别哪些做法稳定有效，哪些能力值得保留，哪些 agent 具备独立承担一类任务的条件。第二次相似任务不应从零开始，也不应机械复刻第一次流程，而应通过 Path Bias 自然倾向于上一轮已经验证过的有效路径。成熟的子 agent 最终可以成为“果实”：它从母体孕育而来，但在通过治理门后可以脱离母体，携带最小权限、明确契约、版本、评估记录和撤回路径独立运行。

## 不是短期生成器

AgentArbor 不是把一句话变成一堆文件的脚手架。单次生成只能证明系统会写文件，不能证明系统能长期生长能力。

AgentArbor 的长期价值来自四件事：

- 目标不丢失：目标、约束、决策、变更和验收标准可以持续追踪。
- 执行可观察：执行过程、工具调用、资产使用和产物变化可以审计。
- 结果可验证：任务结果必须有证据、测试或人工确认。
- 运行有沉淀：每次任务都留下 Run Memory，并按证据生成 Experience Candidate 和 Path Bias。
- 能力可演化：重复成功的模式可以被治理、复用、导出和修剪。

## 植物隐喻的实际含义

植物隐喻不是装饰，它用于约束职责：

- Soil 表示固定资产、历史证据、能力资产、约束和治理规则。
- Seed 表示从用户想象中成像出的启动种子包，未经用户确认不能种入土壤。
- Root System 表示持续地下探索与吸收系统，负责初始生根、侧根扩展和深根重探。
- Root Crown Cluster 表示根颈固定核心，负责汇总根须和根系探索结果，输出版本化 Root Brief。
- Core Control Cluster 表示主干固定核心，负责综合决策、制定和修订 Growth Plan，并触发 Root Callback。
- Branch / Leaf 表示运行组织和具体执行单元。
- Flower 表示验证、评审、成熟度判断和交付前确认。
- Fruit 表示成熟交付物、可复用 AgentApp、能力包或可脱离子 agent。
- Ring 表示 EventLog、Run Memory 和 Experience Candidate 的聚合视图，用于观察系统怎样生长。

任何把 Seed Cluster 写成执行层、把 Root System 写成一次性前置调研、把 Core Control Cluster 写成单点万能 agent、或把 Fruit 写成未经治理的普通输出的设计都必须修正。Root Brief 必须版本化；Growth Plan 必须引用具体 Root Brief 版本，并能在 Root Callback 后形成 Growth Plan Revision。
