# 工作流示例

## 示例目标

用户希望生成一个“竞品价格监控 AgentApp”，每天抓取公开价格页，发现价格变化后生成报告。

## Phase 1：Underground Center 方向成形

```text
用户目标
  -> Intent Core 固定目标、非目标和验收标准
  -> Growth Governor 限定探索方向、深度、预算和停止条件
  -> 临时根须集群分别探索抓取方案、风险、Soil 资产适配和外部事实
  -> Constraint Sentinel 提取权限、频率、站点规则、数据安全和人工确认约束
  -> Evidence Ledger 记录 Soil 引用、失败模式、外部事实和可信度
  -> Convergence Judge 比较、合并、淘汰候选方向
  -> Handoff Steward 组装方向交接包
```

输出 `.agentarbor` Direction Handoff：

```text
.agentarbor/
  direction.md
  options.json
  decision-record.md
  constraints.json
  soil-refs.json
  evidence-index.md
  risk-register.md
  open-questions.md
  escalation-rules.md
  growth-entry.json
  handoff.meta.json
```

## Phase 2：Aboveground Center 制定计划

```text
Aboveground Center
├── 读取 Direction Handoff
├── 判断是否采用已有 Path Bias
├── 制定 Growth Plan v1
├── 生成 Workflow IR
└── 定义 Nutrient Request 触发条件
```

Growth Plan v1 包含：

- 公开页面抓取。
- 数据清洗。
- 差异检测。
- 报告生成。
- 验证规则。
- 沉淀策略。

## Phase 3：Aboveground Growth 执行

```text
Router
├── 分配抓取任务
├── 分配清洗任务
├── 分配报告任务
└── 记录 EventLog
```

执行个体只能按 ConstraintRef 和权限声明访问网络、文件和工具。

## Phase 4：Verification 与 Nutrient Request

如果验证发现：

- 页面结构变化。
- 站点阻断。
- 数据字段缺失。
- 用户目标要求变化。

则触发：

```text
Nutrient Request
  -> Underground Center 供给 Nutrient Patch 或进行方向再成形
  -> 新 Direction Handoff 版本或无需补充证据
  -> Aboveground Center 形成 Growth Plan Revision
```

## Phase 5：Fruits 与 Governance

运行完成后形成：

```text
Artifact / Report
  -> Fruit Candidate
  -> Run Memory
  -> Experience Candidate
  -> Governance Review
  -> Path Bias / Capability Asset / Retire
  -> Soil
```

## 示例价值

| 机制 | 作用 |
| --- | --- |
| 地下成形 | 目标、约束、风险和证据先进入方向交接包 |
| 方向交接 | `.agentarbor` 让地上中枢接管方向，不复制 Soil |
| 地上计划 | Growth Plan 与 Workflow IR 明确执行、验证和养料请求点 |
| 验证保障 | Verification 不只验收结果，也能发现上游事实错误 |
| 资产治理 | 只有经过治理的经验和能力才能进入 Soil |
