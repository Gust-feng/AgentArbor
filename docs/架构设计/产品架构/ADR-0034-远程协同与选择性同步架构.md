# ADR-0034：远程协同与选择性同步架构

## 状态

已接受，并被 ADR-0035、ADR-0036 部分取代。Conversation、run、命令、确认与 AI 输出继续遵循本 ADR 的零持久化 Relay；Space、知识、资产、Agent Notes 和受管文件改由独立 Content Vault 持久同步；移动端 Conversation 归属与信息架构以 ADR-0036 为准。公网更新、域名解析和真机联调仍属于部署验证阶段。

## 背景

AgentArbor 需要让同一个用户从手机继续桌面 Ordinary 对话、查看运行状态、处理待确认动作，并同步软件自己拥有的 Space、笔记、Workbench Assets 和受管文件。它不是远程桌面，也不镜像电脑磁盘。若同步整个 runtime、工作区路径或 feature 私有数据库，会破坏模块所有权，并让云端错误地成为第二个 Agent runtime。

用户已确认：

- 手机和电脑属于同一个用户，配对成功后持续互信，直到电脑撤销手机权限；
- 账户创建门禁是 Remote Identity 的部署策略；当前发布阶段开放创建，邀请模式启用时邀请码只用于首次创建账户和桌面凭据，不作为长期登录凭据；
- 手机输入六位配对码或扫描二维码，电脑点击一次“允许连接”；
- 手机可发送 Ordinary 消息、取消运行，并作出 `approve_once / deny / guidance` 决定；
- 手机可查看全部对话索引，正文按需获取最近 50 条并保存在手机；
- Relay 不保存任何对话、命令或 AI 输出；软件自有内容的持久同步由 ADR-0035 的独立 Content Vault 负责；
- 暂不做端到端加密，公网部署仍必须使用 TLS。

## 决策

### 1. 三端职责

```text
Android 9+ APK <──WSS/HTTPS──> Linux Remote Service <──WSS/HTTPS──> Desktop Connector
                                      │                              │
                         Identity / Relay / Vault                    ▼
                                           Ordinary / Space / Knowledge /
                                           Managed Content / Workbench Assets / Agent Notes
```

- **桌面端**是 Ordinary 执行、确认 continuation 和 AgentArbor 本地数据的唯一权威。用户每次启动应用后显式点击“运行连接”，当前进程内断线后自动重连。
- **Remote Identity**拥有账户、邀请码哈希、设备、配对会话、撤销状态和最后在线时间。
- **Relay**只拥有在线 socket、presence、尚未确认的进程内投递身份和 receipt。它不装配模型、工具、Ordinary 或业务内容仓储。
- **Content Vault**只拥有白名单受管资源的 revision、mutation 幂等、change cursor、墓碑和配额，不保存 Conversation、run、命令或确认。
- **手机端**是同一用户的轻客户端，在 IndexedDB 保存展示缓存与 outbox，在 Android Secure Storage 保存设备 token；它不推断或伪造 Ordinary 终态。
- **Remote Collaboration feature**只拥有 Ordinary 远程协议、桌面连接生命周期、本地 outbox/inbox 和命令幂等。受管内容同步与冲突归 ADR-0035 的 Content Vault Sync。

### 2. 账户、配对与信任

1. 当前发布阶段可直接创建账户和首台桌面设备；邀请模式启用时，邀请码在账户创建事务中原子消费。
2. Relay 为账户生成不可变内部 UUID 和唯一 `handle`，用户可修改 `handle`，UUID 不变。
3. 桌面创建短时配对会话并展示六位码和二维码。二维码只包含 Relay 地址与配对码。
4. 手机加入后获得自己的设备 token，但该 token 在桌面批准前不可连接。
5. 桌面核对设备名与配对码后点击一次批准，手机随后可连接。
6. 电脑可撤销手机；设备 token 立即失效。桌面退出账户后本地凭据被删除，再次使用必须重新创建账户；邀请模式启用时仍需新的邀请码。

第一阶段每个账户只允许一台桌面和一台手机。邀请模式启用时，邀请码、配对码和账户 token 是三种不同生命周期的凭据，不能互相替代；开放创建只跳过邀请码门禁，不放松设备配对和批准。配对完成后两端按同一用户互信，不对每条普通同步命令增加第二套审批；危险本地动作仍经过 Ordinary 既有确认边界。

### 3. 内容边界

允许在两台在线设备之间实时协同：

- 全部 Ordinary 对话索引；
- 按需请求的对话正文页、当前运行状态、AI 文本增量和确认请求；
- 手机提交的命令、确认决定以及桌面返回的 `command.result`。

允许通过 Content Vault 持久同步并在电脑离线时读取：

- Space 元数据及不依赖本地路径的 `asset_folder`、`workbench_asset` 引用；
- 由 `managed_root` 表达的软件受管根元数据；
- AgentArbor 创建的受管根目录及其相对路径内文本文件；
- Personal Knowledge、软件维护笔记与知识关系元数据；
- Workbench Assets 的 Markdown/code 可编辑文本与元数据；
- 全局 Agent Note。工作区 Agent Note 在逻辑工作区 ID 出生前保持本地。

禁止同步：

- `local_file`、`workspace_folder` 及它们引用的外部内容；
- 外部磁盘绝对路径、工作区根路径和目录扫描结果；
- API Key、模型/provider 配置、Skills、MCP 与命令环境配置；
- reasoning、完整工具输出、stdout/stderr；
- 整个 `runtime/`、SQLite 文件、Pi Session 原始历史或任一 feature 私有仓储。

确认投影可以包含让同一用户作出决定所需的命令、风险、影响资源和本地路径，但只在线转发并保存在用户设备中。

### 4. Conversation 零持久化与在线语义

- `remote-collaboration/v1` 通过 WSS 传递 Ordinary 命令、确认、对话索引/正文和 AI 增量。受管内容使用独立 `content-vault/v1` HTTPS 契约。
- Relay 数据库不创建内容表，不保存消息正文、索引、快照或文件。进程内只保留在线 socket 与尚未收到确认的投递身份，进程退出即丢失。
- 目标设备离线时 Relay 立即返回 `peer_offline`。命令继续留在发送设备本地 outbox，双方重新在线后重发。
- `message.received` 只表示目标设备已接收；`command.result` 才表示业务层 `applied | conflict | failed`。
- 每个可重试命令携带稳定 `commandId`。桌面 inbox 去重；远程 Ordinary 消息复用 `commandId` 作为 `submissionId`。
- AI 增量按 24ms 短窗口合并且是 live-only，不进入可靠 outbox；正式 `run.snapshot`、`conversation.index` 和 `conversation.page` 覆盖手机展示投影，避免终态后继续回放积压字符。
- 对话正文默认每页最多 50 条。Space、知识、资产、全局 Agent Note 和受管文本不进入 WebSocket 内容事件，统一通过 `content-vault/v1` 的 HTTPS mutation/change/snapshot API 传输。
- Vault 成功写入后，Remote Service 可以通过现有 WebSocket 向同账户其他在线设备发送只含 change cursor 的 `vault.changed` 通知；设备仍通过 Vault HTTP 拉取正文，10 秒轮询只作漏通知兜底。

Relay 不提供电脑离线时的对话浏览能力。Content Vault 可以在电脑离线时提供受管内容。官方模式和未来自托管模式使用同一服务组合与协议。

### 5. 冲突与数据所有权

- 所有 Vault mutation 使用稳定 `mutationId`、`baseRevision` 与完整 payload；服务端按 revision/contentHash CAS，版本不一致时返回当前资源并形成可见冲突。
- Space 创建和引用写入使用稳定逻辑 ID；重试同一 mutation 返回既有结果。
- `managed_file` 只接受受管根下相对路径并拒绝 `..` 越界；外部 `local_file` 与 `workspace_folder` 永不进入 Vault。
- 对话和审批是桌面权威的命令/投影流，不做双主合并。
- 手机本地缓存不是恢复桌面 Ordinary、Space、Notes 或 Assets 的权威来源。

### 6. 移动端产品面

本节的全局对话索引、任务抽屉与底部主导航方案已被 ADR-0036 取代，仅保留 Capacitor、Android 版本、主题语义和构建配置事实。

移动端使用 Capacitor 8 封装同一 React UI，包名为 `dev.gustfeng.agentarbor`，最低 API 28，目标 API 36。正式首屏左上角只有三横任务入口，底部导航为“首页、知识库、我的”：

- 首页只保留输入框与单列 Space；Space 内展示输入、最近对话和受管内容；
- 任务索引放入三横抽屉，进入任务后使用完整对话界面，历史正文按需分页；
- 待确认动作突出影响和主要决定，原始细节按需展开；
- 知识库承载软件维护笔记、可编辑资产、知识条目与全局 Agent 笔记；
- 我的承载账户、设备和撤销操作；
- 离线、连接中、软键盘、安全区、窄屏和深浅色都有明确状态。

界面直接复用 AgentArbor 工作台的暖灰画布、克制表面、薰衣草品牌强调色与既有语义状态色，并使用当前 AgentArbor 图标、圆角、密度和交互语言。APK 构建时通过 `VITE_AGENTARBOR_RELAY_URL` 注入默认 Relay 地址，源码不硬编码正式域名。

### 7. Relay 对外表面

Relay 是 API 服务，不是网站。`/` 与旧 `/health` 返回 404，健康检查位于 `/v1/health`，WebSocket 位于 `/v1/connect`。反向代理只应暴露 `/v1/*`，真实域名、IP、邀请码和凭据不进入源码或提交。

## 不采用

- Relay 长期保存对话、Space、笔记或文件：内容必须进入独立 Content Vault；Conversation 永不进入两者的持久层。
- 同步整个 runtime 或各 feature SQLite 表：破坏所有权且协议不可演进。
- 让 Relay 运行第二套 Ordinary/工具循环：会产生双主执行和确认 continuation 分裂。
- 同步电脑工作区或任意用户文件夹：超出 AgentArbor 自有数据边界。
- 首版使用 CRDT：单用户两设备使用 CAS 更简单、清楚、可测。
- 继续以 PWA 作为正式移动交付：Secure Storage、二维码扫描和 APK 分发已经是当前真实需求。
- 把邀请码作为永久登录 token：一旦泄露无法按设备撤销，也混淆账户创建和设备身份。

## 后果

- Relay 容量与隐私风险显著降低，但电脑离线时手机只能查看自己的缓存，不能从服务器补取新正文。
- 两端必须维护本地 outbox、接收去重和展示缓存；不宣称跨进程 exactly-once。
- 没有 E2E 意味着 Relay 进程可在转发瞬间读取正文；TLS 保护传输，未来 E2E 需要独立密钥生命周期 ADR。
- 原生 APK 带来 Android 工具链和插件维护成本，但换取系统凭据存储、二维码扫描及后续后台能力的稳定基础。
