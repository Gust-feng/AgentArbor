# 模块划分

未来 `src/` 建议按职责组织：

```text
src/
  core/
  goals/
  assets/
  capabilities/
  workflows/
  runtime/
  verification/
  governance/
  lineage/
  adapters/
  ui/
```

## 职责边界

- `core`：通用类型、错误、状态机和领域契约。
- `goals`：目标内核、目标状态和变更记录。
- `assets`：本地资产授权、索引和上下文选择。
- `capabilities`：能力清单、依赖、权限和可用性。
- `workflows`：Workflow IR、计划转换和任务图。
- `runtime`：任务工作区、执行、暂停、恢复和事件记录。
- `verification`：测试、检查、验收和证据管理。
- `governance`：能力晋升、导出、修剪和退役。
- `lineage`：谱系记录、分支、合并和来源追踪。
- `adapters`：Codex、OpenCode、模型、工具和外部平台适配。
- `ui`：工作台界面。

## 禁止穿透

UI 不能直接写注册表；adapter 不能定义核心模型；runtime 不能绕过权限层；临时任务不能直接写长期能力资产。
