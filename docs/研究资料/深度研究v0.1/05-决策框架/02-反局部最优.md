# 避免局部最优与技术债

## 1. 问题

AI 开发最容易陷入局部最优：

- 当前测试过了，但架构变差；
- 当前功能实现了，但未来扩展变难；
- 当前代码能跑，但文档和目标偏离；
- 当前 Agent 自我肯定，缺少反对声音。

## 2. 多方案竞争

关键节点不允许只有一个方案。

AgentArbor 应生成多个方案：

- 快速 MVP 方案；
- 长期架构方案；
- 低风险方案；
- 高扩展方案；
- 最小依赖方案。

然后由 CriticAgent、ArchitectAgent、TestStrategyAgent 评估。

## 3. 反对者 Agent

CriticAgent 必须问：

- 这个方案会在哪里失败？
- 后续三阶段是否会被卡住？
- 测试怎么落？
- 技术栈是否过度复杂？
- 模块边界是否清晰？
- 是否有更简单方案？

## 4. 技术债账本

每个 AgentApp 应维护：

```text
docs/debt/technical_debt.md
```

记录：

- 债务描述；
- 来源；
- 严重程度；
- 影响范围；
- 偿还建议；
- 是否阻塞未来阶段。

## 5. 架构不变量

定义不可破坏的架构规则。

例如：

- core 不依赖 UI；
- workflow 不直接调用模型供应商；
- tool call 必须经过 capability router；
- Git 操作必须经过 GitAgent；
- 能力安装必须经过 Governance。

## 6. 未来压力测试

每次关键架构决策前问：

- 如果要支持 Python AgentApp 怎么办？
- 如果要接 MCP 怎么办？
- 如果要桌面版怎么办？
- 如果要企业版怎么办？
- 如果用户改变方向怎么办？
- 如果当前模块被分化怎么办？

## 7. 分支实验

高风险方案不直接进 main。

应创建 experiment branch，成功再合并，失败保留经验。

## 8. 关键结论

避免局部最优不是靠“更聪明的模型”，而是靠反对机制、验证机制、债务账本和未来压力测试。
