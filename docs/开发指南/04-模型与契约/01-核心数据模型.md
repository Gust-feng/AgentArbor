# 核心数据模型

## arbor.json

`arbor.json` 是 AgentApp 或导出资产的入口描述文件。第一阶段可以先作为草案设计，不提前塞进 `.agentarbor/`。

建议字段：

```json
{
  "schemaVersion": "0.1",
  "kind": "agentapp",
  "name": "",
  "goal": {},
  "seedPacket": {},
  "rootBriefVersions": [],
  "growthPlanVersions": [],
  "workflow": "",
  "runtime": {},
  "capabilities": [],
  "rootCallbacks": [],
  "runMemory": [],
  "pathBias": [],
  "lineage": {},
  "exports": []
}
```

## Seed Packet

Seed Packet 必须描述：

- 来源 Imagination。
- 目标成像。
- 非目标与边界。
- 假设与缺失信息。
- 最小化搜索结果。
- 反驳与风险。
- 可选方向。
- 用户决策记录。
- 启动建议。
- `handoff-to-root`。
- 版本和确认状态。

## Goal

目标对象必须包含：

- 原始目标。
- 澄清目标。
- 非目标。
- 约束。
- 验收标准。
- 风险。
- 当前状态。
- 变更记录。

## Root Brief

Root Brief 必须描述：

- 来源 Seed Packet。
- 版本号。
- 触发模式：Initial Rooting、Lateral Rooting 或 Deep Rooting。
- 探索范围。
- 可复用 Soil 资产。
- 相似 Run Memory。
- 相关 Experience Candidate。
- Path Bias。
- 未知项。
- 约束和风险。
- 可选方向。
- 推荐方向。
- 证据来源。

## Growth Plan

Growth Plan 必须描述：

- 来源 Root Brief 版本。
- 计划版本号。
- 选定方向。
- 是否采用 Path Bias。
- Workflow IR 摘要。
- 运行组织形态。
- 任务列表。
- 复用策略。
- 沉淀策略。
- 验证和验收门。
- Root Callback 触发点。

## Growth Plan Revision

Growth Plan Revision 必须描述：

- 来源 Growth Plan 版本。
- 来源 Root Brief 版本。
- 修订原因。
- 影响范围。
- 决策：继续、回退、分叉或停止。
- 新 Workflow IR 或变更摘要。

## Agent Manifest

Agent 清单必须包含：

- 名称。
- 职责。
- 输入。
- 输出。
- 可用能力。
- 权限边界。
- 协作关系。
- 验证要求。
- 生命周期状态。

## Capability Asset

能力资产必须包含：

- 能力名称。
- 能力类型。
- 输入输出。
- 依赖。
- 权限。
- 适用范围。
- 来源。
- 验证记录。
- 版本。
- 退役策略。

## Root Callback

Root Callback 必须描述：

- 触发者。
- 触发原因。
- 关联 Growth Plan 版本。
- 关联任务、分支或验证报告。
- 建议模式：Lateral Rooting 或 Deep Rooting。
- 输出 Root Brief 版本，或无需重探的证据。

## Run Memory

Run Memory 必须描述：

- 来源目标和任务。
- 来源 Growth Plan。
- 参与 agent、Branch System、Leaf Agents 或 Flower Cluster。
- 实际路径。
- Root Callback 与 Growth Plan Revision。
- 产物引用。
- 验证证据。
- 偏离原因。
- 成功模式。
- 失败模式。
- 下一次可参考线索。

## Experience Candidate

Experience Candidate 必须描述：

- 来源 Run Memory。
- 可复用经验。
- 适用目标类型。
- 前置条件。
- 必须保留的验证门。
- 不适用条件。
- 置信度。
- 治理状态。

## Path Bias

Path Bias 必须描述：

- 来源 Experience Candidate 或 Capability Asset。
- 适用目标类型。
- 推荐节点和能力组合。
- 必须保留的验证门。
- 已知失败模式。
- 不适用条件。
- 置信度。

## Ring Memory

Ring Memory 必须描述：

- 聚合的 EventLog 范围。
- 聚合的 Run Memory 范围。
- 聚合的 Experience Candidate 范围。
- Root Callback 和 Growth Plan Revision 趋势。
- 生长趋势。
- 重复失败模式。
- 可修剪资产。

Ring Memory 只能作为聚合视图，不能替代 EventLog、Run Memory 或治理记录。

## Lineage Record

谱系记录必须描述：

- Seed Packet。
- Root Brief 版本。
- Growth Plan 版本。
- Workflow IR。
- 参与 agent。
- 使用能力。
- Root Callback。
- 关键决策。
- 验证证据。
- 派生资产。
- 分支和合并关系。
