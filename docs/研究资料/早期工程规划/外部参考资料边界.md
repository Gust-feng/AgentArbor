# 外部参考资料边界

## 1. 结论

外部 Agent 工程资料不属于 AgentArbor 项目的范畴。

它只能作为参考来源，不能作为本项目的主架构、产品定位、生成物标准或长期路线。

如果需要借鉴，必须满足其中一种方式：

1. 将确实需要的文件复制到本项目内，并标明其参考性质。
2. 将其思想沉淀为本项目自己的参考文档。

当前采用第二种方式：

```text
docs/04-参考沉淀/Agent工程基础原则.md
```

## 2. 不能做什么

不得在 AgentArbor 的核心规划中持续依赖外部目录。

不得把外部模板等同于 AgentArbor 的最终标准。

不得让外部工程框架反向决定 AgentArbor 的灵魂、隐喻、生命周期模型和演化机制。

不得在主文档中写成“吸收某框架作为项目基础”。

## 3. 可以参考什么

外部 Agent 工程资料中可以参考的只是基础工程经验：

* 单个 Agent 项目可以拆分为声明、Prompt、Schema、工具绑定、权限、测试、评测。
* Prompt、Schema、工具、权限和测试应一起版本化。
* Agent 项目应保持薄，公共运行时能力不应复制到每个 Agent。
* 多 Agent 不能只有角色名，还必须有输入、输出、权限和工作流位置。
* 权限不能只写在 Prompt 里，运行时也要能检查或验证。
* 文档、配置、注册表和运行时不应形成多个事实源。

这些原则已沉淀到：

```text
docs/04-参考沉淀/Agent工程基础原则.md
```

## 4. 与 AgentArbor 的关系

AgentArbor 的上层问题是：

> 一个自然语言目标如何长成可运行、可验证、可追溯、可继续演化的 AgentApp？

外部 Agent 工程资料解决的是更低层的问题：

> 一个 Agent 项目如何组织 Prompt、Schema、工具、权限和测试？

低层参考可以帮助减少工程混乱，但不能定义高层系统。

## 5. 当前模板说明

当前 `templates/agent-project/` 是初始参考模板。

它只用于早期工程占位和结构启发，不代表 AgentArbor 的最终生成标准。

后续模板应服从 AgentArbor 自己的核心对象：

```text
ArborSpec
GoalSpec
AgentApp
WorkflowIR
AgentManifest
CapabilitySpec
ValidationResult
LineageRecord
```
