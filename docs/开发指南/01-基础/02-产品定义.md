# 产品定义

## 一句话定义

AgentArbor 是目标驱动的问题解决与经验积累平台。它以 `Soil -> Underground Center -> .agentarbor -> Aboveground Center -> Fruits -> Governance -> Soil` 为原生概念树，把用户问题经过地下中枢的理解、探索、裁决和方向成形，交给地上中枢执行解决，并把每次解决问题的有效路径、能力和判断沉淀为受治理的长期资产。

## 用户获得什么

用户提出一个问题或场景，系统逐步形成：

1. 目标内核与约束：问题澄清、非目标、验收标准、风险、约束和变更记录。
2. Soil 读取结果：可用能力资产、历史运行、Path Bias、治理规则和权限边界。
3. Direction Handoff：地下中枢经过多方向探索和交叉裁决后形成的方向交接包，描述"这个问题如何解决"——包含方案、证据索引、约束引用、风险登记和 Growth Entry。
4. Growth Plan：地上中枢形成执行入口，并在 Nutrient Patch 后可修订。
5. 执行与交付：按 Workflow IR 推进的解决方案执行和验证。
6. 运行沉淀：Run Memory → Experience Candidate → Path Bias → 通过治理后入土的 Capability Asset。
7. 谱系记录：来源问题、解决过程、版本、分支和演化记录。

## 核心产品对象

### 目标内核

目标是驱动一切的入口。它不是一个转瞬即逝的聊天消息，而是可存储、可恢复、可追踪的状态机。目标从 `draft` 开始，经 Underground 成形后进入 `direction_ready`，经 Aboveground 计划化后 `planned`，执行中 `running`，最终 `completed` 或 `failed`。

### Underground Center

地下中枢是问题的理解与探索层。它不直接执行，也不制定执行计划。它的职责是：把用户问题分解为可探索的方向，启动临时根须集群做多角度调研（方向、风险、证据、约束、反驳），交叉裁决后收敛为 `.agentarbor` 方向交接包。用户只在必要时确认。

### .agentarbor 方向交接包

从地下中枢到地上中枢的方向交接层。它描述一个问题的解决方案：主方向、备选方向、约束映射、证据索引、风险登记、待确认项和地上执行入口。它不是最终资产，不复制 Soil。

### Aboveground Center

地上中枢读取方向交接包，制定 Growth Plan、Workflow IR 和验证门。它的职责是把"问题如何解决"转化为可执行的计划——不是"设计一个 Agent"，是"组织一次解决问题的执行"。

### Growth Plan

地上中枢的决策输出。它引用具体 Direction Handoff 版本，明确执行策略、约束分发和修订规则，支持基于 Nutrient Patch 的 Growth Plan Revision。

### 约束工程

约束从 Soil → Underground → .agentarbor → Aboveground → Fruits → Governance → Soil 全程可追踪。Hard constraint 可阻断行动；soft constraint 允许带证据偏离；preference 只影响 Path Bias 和方案排序。

### Path Bias

Path Bias 是相似问题对已验证解决路径的自然倾向。它帮助系统不每次从零开始，但不强制复刻——当新问题的约束、权限或上下文与历史冲突时，系统必须允许选择新路径并记录偏离原因。

### 能力资产

能力资产是经过治理后入土的长期复用资产。可以是工具适配器、工作流片段、验证规则、提示词模板或成熟的独立运行时。Run Memory 和 Experience Candidate 不能直接等同能力资产。

### Fruits

Fruits 是每次问题解决后的产物集合：交付物、运行报告、Experience Candidate、Run Memory。绝大多数 Fruits 作为经验沉淀而非独立 agent。仅在极少数场景（问题需要长期独立调度运行时）才产出可脱离的 AgentApp 果实。

### 子 agent 果实（进阶场景）

子 agent 果实是能力资产中极少数的成熟形态。它必须来自多次验证、具备清晰输入输出、最小权限、版本、评估证据和退役路径。它是能力积累的自然结果，不是每轮任务的目标。子 agent 脱离母体时不能默认继承母体的密钥、资产图或历史任务。

## 价值判断

AgentArbor 的价值由以下指标衡量：

- 问题能否被持续追踪和解决。
- 地下中枢的探索和裁决是否真正深入（不是模板填充）。
- 执行是否可观察、可暂停、可恢复。
- 每次运行是否形成 Run Memory、Experience Candidate 和 Path Bias。
- 类似问题再次出现时是否显著更快、更好。
- 能力是否能被治理后复用。
- 失败、重复、过时能力是否能被修剪。
