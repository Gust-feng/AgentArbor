# 模块划分

未来 `src/` 建议围绕功能闭环组织领域模块，同时把消息、状态机、事件、权限、模型和产物等横切内核放在明确边界内。源码布局采用 `domain / kernel / adapters / app` 四层，但模块所有权优先按功能闭环判断，横向分层只是实现手段：

```text
src/
  domain/
    soil/
    task-soil/
    underground/
    plan/
    aboveground/
    fruits/
    governance/
    lineage/
    intelligence/
    runtime-database/
  kernel/
    messages/
    state-machine/
    events/
    permissions/
    artifacts/
    intelligence/
    tools/
  adapters/
    intelligence/
    runtime-database/
    tools/
  app/
    config-center/
    agent-definitions/
    capability-center/
    capability-policy.ts
    app-update/
    model-runtime/
    tool-projection/
    task-soil/
    basic-agent-runtime/
    desktop/
    underground/
    aboveground/
    panel-conversation/
    panel-read-model/
    panel/
    panel-ui/
```

## 职责边界

- `domain/soil`：Global Soil，保存长期偏好、Capability Asset、Path Bias、稳定约束、治理规则、历史证据和失败模式。
- `domain/task-soil`：Task Soil，保存当前任务目标、文件/网页/项目引用、临时约束、权限边界和本轮运行材料。
- `domain/underground`：目标成形、多路探索、动态派生、父层综合、用户澄清、Nutrient Request 处理和 Nutrient Patch / Plan vNext 生成。
- `domain/plan`：Plan / Plan Package 的读写契约、版本、引用校验、validation result 和执行入口；`.agentarbor` 只是其可能的存储目录形态。
- `domain/aboveground`：执行计划、Workflow IR、任务切片、工具动作、执行组织选择、验证门编排和 Plan Revision。
- `domain/fruits`：交付物、运行报告、Run Memory、Experience Candidate 和能力候选。
- `domain/governance`：候选成熟度评估、权限审查、谱系归因、版本、导出、退役和入土裁决。
- `domain/lineage`：Task Soil、Plan、Nutrient Patch、执行记录、产物、验证和入土结果之间的谱系。
- `domain/intelligence`：智能通道领域契约、模型调用目的、输出类型、`ModelCallRef` 和模型产出引用规则；它是横切契约，不是业务节点。
- `domain/runtime-database`：Lite / Full 共用的运行记录契约，表达 Workspace、Run、Event、ToolCall、ModelCall 和 Artifact 的安全持久化记录；业务层依赖该端口，不依赖具体本地文件、PGlite 或 PostgreSQL 实现。
- `kernel/messages`：ArborMessage、MessageBus、Router 和跨模块消息协议。
- `kernel/state-machine`：运行阶段、状态转移和 Plan Revision 状态机制。
- `kernel/events`：EventLog、事件发布、事件订阅和审计轨迹。
- `kernel/permissions`：权限声明、授权检查和必要命令确认。
- `kernel/artifacts`：ArtifactStore、产物引用、校验摘要和临时运行材料索引。
- `kernel/intelligence`：模型运行时、请求校验、输出契约校验、模型调用事件、失败策略和 provider registry；它不能保存业务事实。
- `kernel/tools`：工具执行边界、工具权限、预算、结果归一化、`ToolResultEnvelope` 和共享本地执行策略；它可以处理 URL、路径、命令确认和工具结果结构，但不能替 agent 决定任务方向。
- `adapters/intelligence`：当前只实现 OpenAI 格式 provider adapter；只有这一层可以直接处理供应商协议、OpenAI 官方 SDK 对象和凭证。后续 Anthropic、Gemini、Qwen、Ollama/vLLM 或其他 provider 必须作为新增 adapter 接入，不能反向改变内部智能通道契约。
- `adapters/runtime-database`：RuntimeDatabase 的可替换本地存储实现；当前可用文件系统运行投影验证 appHome / runHome 和运行记录边界，后续可替换为 PGlite 或 PostgreSQL + pgvector。
- `adapters/tools`：MCP、浏览器、文件、搜索、终端或外部工具协议适配。MCP 接入必须通过 MCP 官方 SDK 管理 client/session、tool/resource/prompt 列表、调用、取消、进度和错误归一化；不能手写一套并行协议解析替代官方 SDK。
- `app/config-center`：统一保存本地配置，包括模型 profiles、模型能力 override、工具启用状态、Skills 状态入口、MCP server 配置和工作目录；密钥只能进入 secret store，普通 settings 只保存 `secretRef` 与配置元数据。
- `app/agent-definitions`：普通 AgentDefinition 的运行引用、语义 hash、注册表、内置目录和 turn policy / capability runtime 转换模块；它消费 `agent-prompts` 的定义资产，但不拥有 prompt 正文拆分，也不拥有 ToolCenter、run tool boundary 或 Panel server 路由。顶层历史 `app/agent-definition-*.ts` 只能作为兼容 facade 存在。
- `app/capability-center`：在创建 Basic Agent run 时把配置、模型能力目录、工具 registry、Skills 元数据、MCP 配置目录和工作区摘要解析成 `BasicAgentCapabilitySnapshot`；快照只保存配置引用、能力目录和运行入口事实，不复制 secret store、raw provider response 或 live runtime 引用。
- `app/capability-policy`：在每次 run 创建时把 `BasicAgentCapabilitySnapshot`、Task Soil 权限边界、运行模式和平台策略裁剪成 `RunCapabilityResolution`；CapabilityCenter 负责“有什么”，policy 负责“本轮能看见和能尝试什么”。
- `app/app-update`：应用更新检查、Electron autoUpdater 适配和产品版本读取模块；它不拥有 Panel config route 或 Desktop Shell 启动流程，顶层历史 `app/app-update-service.ts`、`app/electron-app-update-service.ts` 和 `app/product-info.ts` 只能作为兼容 facade 存在。
- `app/model-runtime`：模型运行时应用入口，负责把 Context Pack、模型能力和工具 schema 组合为 `ModelRuntimeRequestPlan`，统一处理 strict schema、并行工具策略、stream / cancel 和失败归一；Basic Agent、deep mode 和未来 Aboveground 不能各自拼 provider-specific payload。
- `app/tool-projection`：工具结果到模型可见事实、UI 展示、诊断引用和续读 continuation 的应用层投影模块；它拥有 `safe-projection`、工具显示归一化、命令文本提取、安全预览和 continuation 计算等支撑实现，可以消费 `kernel/tools` 的 envelope 能力和 app 内普通文案 helper，但不能被 Panel UI 摘要、配置中心或具体工具 adapter 反向定义。顶层历史 `app/safe-projection.ts`、`app/command-text.ts`、`app/safe-tool-preview.ts`、`app/tool-display-normalization.ts` 和 `app/tool-result-continuation.ts` 只能作为兼容 facade 存在，新的实现和测试必须归入该模块。
- `app/task-soil`：Desktop Shell / Panel 任务上下文输入的应用层支撑模块，负责解析 Desktop Task Soil 输入、本地/上传/网页上下文附件预览、工作区摘要和可直接传给模型的文件输入附件；它消费 `domain/task-soil` / `domain/soil` / Basic Agent 上下文契约，但不拥有 Basic Agent 主运行循环、Panel server 路由、ToolCenter、provider adapter 或 deep 编排。顶层历史 `app/task-soil-workspace.ts`、`app/context-attachments.ts`、`app/desktop-agent-model-input-files.ts` 和 `app/workspace-folder-summary.ts` 只能作为兼容 facade 存在，新的实现和测试必须归入该模块。
- `app/basic-agent-runtime`：当前 Desktop Basic Agent 的应用内核，拥有 run lifecycle、BasicAgentRun 运行投影、RunEvent replay、确认续跑、取消状态、工具目录接线、Context Ledger 和 Context Pack 入口；Panel、SSE、HTTP 和未来桌面壳都只能消费它的契约，不能各自派生运行事实。
- `app/desktop`：Desktop Shell、Electron 桌面壳支持模块、启动动画、preload、窗口控制、本地偏好和桌面入口；当前基础 Agent 路线通过 `app/basic-agent-runtime` 组合模型、工具、技能和上下文能力。
- `app/underground`：Underground Cognitive Runtime 的应用编排和内置 agent specs；它是未来 deep / Agent 集群能力边界，不是普通 Agent 的默认升级目标。
- `app/aboveground`：Aboveground Execution Runtime 的应用编排和执行入口；只有消费 approved Plan 或等价 deep 交接对象时才使用该语义。
- `app/panel-conversation`：Panel conversation 的会话 store、运行记录映射、conversation read-model、刷新策略、响应模型投影和 conversation display list；它负责会话层聚合，不拥有 Basic Agent 运行事实，也不替代 Panel server 路由或 Panel UI 组件。
- `app/panel-read-model`：Observation Panel 的只读投影模块，负责把 BasicAgentRun、RunEvent、模型调用、工具显示、确认和 conversation 缓存整理为 UI / Panel server 可消费的 transcript、activity 和 run read-model；它不是运行状态事实源，也不能反向解析 raw provider response 或 live runtime 对象。
- `app/panel`：Observation Panel 的 API、SSE、静态文件托管、兼容响应和诊断详情组装；它不是 Basic Agent run 状态事实源。
- `app/panel-ui`：Panel 工作台前端静态资产，负责消费 BasicAgentRun、RunEvent、结构化工具展示和上下文摘要；不能解析 raw prompt、provider response 或 live runtime 对象来还原状态。
- `app/testing`：跨 app 测试共享的 fixture、stub response 和测试辅助材料；只能被测试或测试辅助资产依赖，生产运行路径不能导入这里的 OpenAI / provider fixture。

## 横切规则

- `domain/` 保存 AgentArbor 产品语义；它不能依赖具体平台 adapter。
- `kernel/` 可以被 `domain/`、`app/` 和 `adapters/` 复用，但不能保存业务事实，也不能替代 Task Soil、Plan、Fruits 或 Governance。
- `adapters` 只能转换格式，不能定义核心领域模型。
- `app` 只能通过正式服务或应用层接口读写，不能直接写 Global Soil 或治理注册表。
- `domain/plan` 只能引用 Global Soil 中的稳定资产，不能复制 Global Soil 内容形成第二事实源。
- `domain/fruits` 不能直接写 `domain/soil`；必须经过 `domain/governance`。
- `domain/aboveground` 可以向 `domain/underground` 发起 Nutrient Request，但不能自建方向探索集群，也不能静默改写 Plan。
- `domain/underground` 可以读取 Task Soil 和 Global Soil 引用，可以写 Plan / Nutrient Patch，不能创建最终果实。
- 任何运行流程需要模型能力时，只能依赖智能通道契约或注入的 `AgentTurnRuntime` / `IntelligenceChannel`；应用组合根可以装配 provider adapter，但不能让领域层、kernel 或业务编排直接读取 provider 环境变量或调用 provider SDK。
- 工具权限必须按 `AgentRunContext` 的有效权限裁剪，不能只看 agent role 或 prompt。
- 运行记录必须通过 RuntimeDatabase 契约保存运行投影：Run、Event、ToolCall、ModelCall 和 Artifact 记录保存摘要、refs、状态、时间、模型可见输出、工具可见结果和失败信息，但不能保存 live runtime/store 引用或 provider SDK 原始对象。
- 模型上下文窗口、输出 token 上限、工具调用、结构化输出、流式输出和稳定性必须通过协议基线、内置模型能力目录和用户 override 解析，不能写死在 panel UI、prompt helper 或 agent loop 中；未命中内置模型目录时使用用户所选协议的基线能力，不能把自定义 OpenAI-compatible / Responses 模型视为未知异常或默认关闭工具调用。
- Desktop Basic Agent 当前实现必须以 `BasicAgentRunExecutor` 和 `BasicAgentContextPack` 为入口：运行状态、事件 replay、确认决策、取消、工具目录和模型上下文不能由 `panel-server.ts`、UI 文本解析或旧 desktop detail store 重新实现第二套事实源。
- 命名必须匹配职责：普通文件编辑、状态更新、helper、adapter、formatter 和单次工具调用不能命名为 agent、Plan、Handoff 或 atomic mutation；`atomic` 只用于真正有全成功/全失败、失败不落盘、回滚或一致性边界的场景。

## `src/app` 顶层收敛规则

当前 `src/app` 已经承载默认普通 Agent、Panel、配置中心、工具中心、模型运行时、Skills、子 Agent 和 Agent 集群 beta 等多个功能闭环。后续开发必须把实现和测试放入拥有职责的功能目录，不能继续把大文件堆在 `src/app` 顶层。

`src/app` 顶层只允许三类文件长期存在：

- 应用组合根、启动入口和跨模块小契约，例如 `panel.ts`、`runtime.ts`、`agents.ts`、`desktop-agent-session.ts`。
- 暂时保留的兼容 facade，例如 `config-center.ts`、`safe-projection.ts`；facade 只能 re-export 目标模块，不能重新承载实现。
- 正在迁移中的历史文件；新增或大改时必须先判断归属模块，并优先把测试一起迁入同一功能目录。

Panel 相关测试按职责归属：

- `src/app/panel-structure-tests/` 保存跨 Panel UI / Panel server / app projection 的静态结构测试和测试读取工具；这类测试验证源码组织、文案边界、组件职责和结构约束，不属于生产 Panel UI 或 Panel server 模块。
- `src/app/testing/` 保存跨 app 测试共享的 OpenAI / provider fixture；这类测试夹具不属于生产模块，不能继续以 `panel-*` 名称堆在 `src/app` 顶层，也不能被生产代码依赖。
- `src/app/panel-server/integration-tests/` 保存 Panel server HTTP / SSE / conversation / desktop run / deep route / MCP / skill service 集成测试，以及只服务这些测试的 Panel server 测试工具；这类测试资产归 Panel server 所有，不能继续堆在 `src/app` 顶层。
- `src/app/panel-conversation/` 保存 Panel conversation store、conversation projection、response model、summary refresh 和 conversation display list；Panel server 与 Panel UI 只能消费这里的 conversation 契约，不能在各自目录重新维护一套 conversation 状态或展示列表规则。
- `src/app/desktop/` 保存桌面壳启动几何、主题、本地偏好、窗口控制、launcher 和 preload 支持文件；`panel-desktop.ts` 这类 Electron 启动入口可以继续留在顶层，但不能再把同类支撑实现散落回根目录。
- `src/app/panel-read-model/run/` 保存 run stream、run transcript、run tracking、run status、live run buffer、run projection patch、run observation state 和 run read-model facade 等 Panel 只读投影；`panel-run-jobs.ts` 这类内存 job store 不属于该目录，不能和 read-model 混成一个职责。
- `src/app/panel-read-model/transcript/` 保存 transcript、activity、模型调用、工具显示、确认节点、transcript cache 和 live transcript overlay / materialization 等 Panel 只读投影；Panel UI 和 Panel server 只能消费这些投影契约，不能在各自目录重新拼装 transcript 事实。
- `src/app/panel-read-model/assistant/` 保存 assistant 消息可见文本、失败拆分、消息结构、工作流 display、timeline collapse、assistant workline、稳定性和 run output 等只读投影；conversation、transcript 和 Panel UI 可以消费这些契约，但不能把同类 projection 重新放回 `src/app` 顶层。

迁移优先级：

1. 配置中心、工具结果投影、Panel server、Panel UI 结构测试这类已有明确 owner 的文件优先归位。
2. 普通 Agent 主循环、Capability、ToolCenter、Sub-agent 等跨模型能力边界的文件必须按垂直闭环迁移，迁移时同步验证模型可见事实、工具 continuation、确认和 run read-model。
3. deep / Underground 相关文件只在显式 Agent 集群工作中迁移，不能因为普通路径瘦身而顺手改变 deep 编排语义。

结构测试必须守住已完成的归位：当一个顶层实现被移动到功能目录后，顶层只能保留兼容 facade；对应测试必须跟随功能目录，不能再新增同名顶层测试。

已归位到 `panel-read-model` 的支撑模块必须继续留在对应 owner 下：`panel-read-model/run/` 承载 live run buffer、run projection patch 和 run observation state；`panel-read-model/transcript/` 承载 transcript cache 和 live transcript overlay / materialization；`panel-read-model/assistant/` 承载 assistant workline 和 timeline collapse display policy。Panel UI 前端支撑模块必须继续留在 `src/app/panel-ui/src/`：streaming text、transcript windowing、chat active projection/view、run capability state、deep sidebar selection 和 deep transcript split 这类 helper 都属于 Panel UI 自身闭环；对应的纯 Node 测试放在 `src/app/panel-ui/tests/`，继续由 Panel UI 自己拥有。旧的 `panel-ui-*` 顶层文件名只能作为历史迁移来源，不能作为新增实现位置。

## 禁止穿透

`app` 不能直接写注册表；adapter 不能定义核心模型；地上运行不能绕过 `kernel/permissions`；临时任务不能直接写长期能力资产；果实不能绕过治理进入土壤；领域层、kernel 和业务编排不能直接导入模型供应商 SDK 或 MCP SDK。
