# 工作流中间表示

## 目的

Workflow IR 是 AgentArbor 的工作流中间表示。它让计划不只存在于自然语言中，而能被运行时执行、暂停、恢复、检查和分叉。

## 最小结构

Workflow IR 至少包含：

- workflow id。
- 目标引用。
- 节点列表。
- 依赖关系。
- 输入输出。
- 执行条件。
- 权限要求。
- 验证门。
- 失败处理。
- 暂停点。
- 恢复信息。
- Path Bias 输入。
- 收获输出。

## 节点类型

第一阶段建议支持：

- `clarify`：澄清目标或需求。
- `research`：读取资料、检索上下文、形成证据。
- `design`：设计 agent、能力、工作流或工程结构。
- `generate`：生成代码、配置、文档或测试。
- `execute`：执行命令、工具或任务。
- `verify`：运行检查、测试或人工验收。
- `memory`：收集本次运行的 Run Memory、Experience Candidate 和 Path Bias。
- `govern`：判断能力晋升、导出或修剪。

## 运行约束

Workflow IR 不能绕过权限系统。任何节点访问文件、命令、网络、密钥或外部服务，都必须声明权限并被运行时检查。

Workflow IR 可以接收 Growth Plan 中采用的 Path Bias，但不能被 Path Bias 强制锁死。执行前必须重新比较本次目标、约束、上下文、权限和验证要求；如果历史路径不适用，运行时必须允许偏离，并记录偏离原因。

## Path Bias

Path Bias 是 Growth Plan 传入 Workflow IR 的历史倾向输入。它帮助系统在相似任务中更快形成候选工作流，但它不是模板复刻。

Path Bias 至少应表达：

- 来源 Run Memory 或 Experience Candidate。
- 适用目标类型。
- 前置条件。
- 推荐节点顺序。
- 推荐能力组合。
- 必须保留的验证门。
- 已知失败模式。
- 不适用条件。
- 本次是否采纳以及采纳理由。

## 收获输出

每次 Workflow IR 运行结束时都必须产生运行沉淀。运行沉淀至少应包括本次实际路径、关键偏离、产物引用、验证结果、失败模式、权限结论、Run Memory、Experience Candidate 和下一次可参考的 Path Bias。

## 验证门

验证门必须是显式节点或显式条件。没有验证门的工作流，只能算草稿，不能用于生成长期资产或导出子 agent。
