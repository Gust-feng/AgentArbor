# ADR-0012: 植物学融合架构资料

## Status

Accepted as historical architecture material, amended by [ADR-0022](ADR-0022-AgentArbor桌面通用Agent与双运行时架构.md).

## Context

AgentArbor 采用“固定骨架 + 动态发育 + 分层通信”的融合方向。`植物学融合架构/` 把这个方向展开为 Soil、Underground Center、`.agentarbor`、Aboveground Center、Aboveground Growth、Fruits 和 Governance 的概念树。

## Decision

AgentArbor 保留植物学融合架构作为当前产品架构资料，并以 ADR-0018 的原生概念树为统一语义：

| 层级 | 当前语义 |
| --- | --- |
| Soil | 固定资产、能力资产、治理规则、历史证据和失败模式 |
| Underground Center | 需求成形、证据探索、方向综合和养料供给 |
| `.agentarbor` | Direction Handoff、ConstraintRef、Soil 引用、证据索引和 Growth Entry |
| Aboveground Center | 制定和修订 Growth Plan 与 Workflow IR |
| Aboveground Growth | 运行协调结构与最小执行单元 |
| Verification | 验证、评审和成熟度判断 |
| Fruits | 成熟交付物、AgentApp、能力包、Run Memory 或 Experience Candidate |
| Governance | 晋升、拒绝、退役、权限和入土裁决 |

研究结构必须映射到当前命名：

| 研究结构 | 当前处理规则 |
| --- | --- |
| 目标治理层 | 其治理和目标约束思想进入 Underground Center、Aboveground Center、Verification 和 Governance。 |
| 阶段管理层 | 保留为 Aboveground Center 的计划、调度和修订职责。 |
| 能力执行层 | 执行和资产吸收职责分别进入 Aboveground Growth、Verification、Fruits 和 Soil。 |

`.agentarbor/` 采用增量填充策略：

- 可以为空，直到方向交接包契约稳定并出现真实任务出生依据。
- 不提前创建固定完整 agent、workflow、memory 或 schema 列表。
- 每个新增方向交接包材料必须有对应任务授权、方向依据、约束引用、证据引用和资产引用。
- `.agentarbor/` 只引用 Soil 中的固定资产，不复制资产本体，也不作为最终资产仓库。

## Consequences

- 当前正式运行主线以 ADR-0018 为准。
- 后续实现骨架层前，先完成方向交接包、Growth Plan、Workflow IR、Nutrient Request、Nutrient Patch、Growth Plan Revision、Run Memory、Experience Candidate、Capability Asset 和 Path Bias 的接口对齐。
- 研究资料保留，但必须通过 ADR-0018 的原生概念树进入当前架构入口。
- `.agentarbor/` 当前为空是合理状态，不代表产品层缺失；它等待按真实出生依据增量生成方向交接包材料。
