# ADR-0027：工具执行事实与单向消费架构

## 状态

已采纳，适用于 `0.1.x` 开发主线。

## 背景

历史工具链同时携带执行结果、模型投影、UI display、envelope 和 broker 调用计数，导致执行层、模型层、事件层、持久化层和 Panel 互相读取对方的派生字段。同一调用可能由多个消费者重复推导状态，取消也曾被折叠成失败。这些兼容结构削弱了模块边界，并使 live、replay 与持久化难以证明一致。

项目仍处于开发期，因此本轮选择清洁断代，不迁移旧本地 runtime JSON，也不保留 deprecated alias、兼容 facade 或旧字段读取分支。

## 决策

工具执行的唯一权威结果是 `ToolCallResult`：

```text
ToolCenter -> ToolCallResult
                 |
                 +-> model ToolResult
                 +-> append-only tool events
                 +-> tool-call read-model -> Panel
                 +-> runtime factual records
```

`ToolCallResult` 只包含 `callId / toolName / input / output / status / error / errorDomain / errorFacts / durationMs / confirmationRequest`。ToolCenter 负责权限、输入、确认、取消、执行和事实归一化，不拥有调用预算，不生成模型内容、展示对象或持久化对象。

`input / output` 使用 `ToolFactValue`：只允许 JSON 可表达的 `null / string / finite number / boolean / array / plain object`。`undefined` 对象字段被显式省略；循环引用、`BigInt`、函数、symbol、非有限数字和 class instance 必须在工具边界明确失败，不能依赖 `JSON.stringify` 静默丢字段或改变事实。ToolCenter 同时归一化调用输入与 executor 输出。

模型边界通过 kernel 纯函数把 `ToolCallResult` 转换为 `ToolResult`。`ToolResult` 的正文是排他联合，只能是 `none / text / json` 之一；同一完整结果不得同时写入文本正文和结构化正文，也不得再套一层 `agentContent / modelResult / envelope`。模型消息只携带下一步判断所需的状态、单份正文与错误事实；`callId / toolName` 使用消息协议已有字段，不在正文内重复序列化，耗时等观察事实留在事件和 read-model。

工具附件使用带外 `ModelMessage.attachments` 进入下一轮模型请求，JSON 正文只保留附件元数据，不能复制 base64。工具调用预算只属于 Agent loop。

continuation 是工具输出顶层的显式契约，只读取 `continuation` 或 `continuations`，不按 `nextStartChar / nextOffset / rawContentRef` 等历史字段递归猜测。小结果完整返回且不附带从头重读的冗余 continuation；大结果由 producer 返回首段、截断事实和从未读位置开始的可执行 `nextInput/ref`。真实分页/offset ceiling 或无法安全重放副作用请求时，producer 必须返回明确失败事实，不能返回 `completed + truncated` 的不可续读结果或会重放副作用的 synthetic continuation。超过共享 transport budget 而没有 continuation 的结果必须明确失败，不能用更大的特例预算掩盖不可恢复输出。

MCP adapter 只保留服务端原生 `content[]` 与可选 `structuredContent`，不再生成 `summary / mcpResult / result` 三份包装。只允许一种无损去重：某个 text part 必须能解析为 JSON，且解析值与 `structuredContent` 深度完全相等，才能删除这份精确镜像；解析失败、近似相同、只包含部分字段或正文不同都必须完整保留。MCP adapter 不再次执行 JSON-safe 归一化，最终 executor output 仍由 ToolCenter 统一归一化。`isError=true` 映射为正式 failed `ToolCallResult`，图片字节带外传给模型，不支持的二进制必须明确标记且不得塞回 JSON。

工具生命周期事件固定为 `tool.requested / tool.completed / tool.failed / tool.cancelled`，确认等待使用 `user_approval.requested`。`completed / failed / cancelled` 是互斥终态。事件只保存一次有界事实快照：requested 保存 input，终态保存 output/error/duration，不在每个阶段重复完整 input；错误、错误事实和顶层 continuation(s) 必须保留。统一 reducer 从 append-only event entries 生成 tool-call facts：重复事件幂等，首个终态不可被后续 requested、approval 或其他终态覆盖，缺少 requested 时仍可恢复终态事实，但 input 可以为空。

`ToolDisplayProjection` 属于 Observation/Panel read-model。Panel summary、preview 和 display 只能从调用事实派生，不写回事件、ToolCallResult 或 runtime database。持久化的生命周期 event payload 是唯一可重放工具事实；`RuntimeToolCallRecord` 只作为 callId/终态/错误/引用/时间索引，不复制 input/output。Sub-Agent trace 只保存 request/response refs、usage、状态、tool-call refs 和单份 `fullOutput` continuation owner，不保存累计模型 messages、逐轮 response 正文、工具 input 或 display。

## 兼容与数据

删除 `ToolSafeProjection`、`ToolResultEnvelope`、`projection`、`envelope`、`resetCallCount`、`getCallCount`、内部 `run_command` alias 和字段猜测式 continuation。旧 JSON 的多余字段不会被读取；旧 snapshot 若缺少当前 Ordinary/Multi-Agent 出生事实或无法满足新契约，视为开发期失效数据，可以清理本地 runtime 目录后重新运行。

## 约束

- adapter 和 ToolCenter 不得依赖或生产 Observation/Panel display 类型。
- kernel 不得依赖 app。
- runtime database 不得依赖 Panel UI 类型或保存 display/envelope 历史副本。
- live、replay、conversation history 和持久化视图必须复用同一事件归约语义。
- 工具 producer 不得返回 `canonicalResult / display`，不得把同一正文同时放入多个等价字段。
- continuation 必须能由当前工具集合实际执行；纯诊断引用不能冒充可恢复 continuation。
- 新功能不得建立第二套 projection 中心或以兼容名恢复已删除契约。

## 影响

收益是事实所有权唯一、状态归约可测试、模型能力不被 UI 摘要削弱，并降低 Panel、持久化和子 Agent 对执行内部的耦合。代价是旧开发期运行历史不保证可读；这是本次断代的明确选择。
