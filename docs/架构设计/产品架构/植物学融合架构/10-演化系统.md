# 演化系统

## 定位

演化系统负责根据验证结果、运行证据、养料供给、债务情况和用户决策，决定系统是继续、回退、分叉、停止、沉淀还是孕育果实。

演化不是让执行层随意改方向。所有方向变化都必须回到 Aboveground Center 的 Growth Plan Revision 或 Governance Gate。

## 演化类型

| 类型 | 触发 | 决策 |
| --- | --- | --- |
| Patch | 问题局部、影响面小 | 保持 Growth Plan，局部修复 |
| Revision | 假设、约束或验证证据发生变化 | Growth Plan Revision |
| Branch | 需要并行方向或产品分化 | 新 Growth Plan 或新 Fruit |
| Stop | 成本、权限、目标或安全边界不成立 | 停止并记录证据 |
| Fruit | 结果成熟且可复用或可脱离 | 进入 Fruits / Governance |
| Retire | 能力过期、失败或被替代 | 降级、归档或删除 |

## 决策链路

```text
Verification / EventLog / Fruit
  -> Nutrient Request / Nutrient Patch / No-Patch Evidence
  -> Growth Plan Revision
  -> Governance Decision
  -> Run Memory / Experience Candidate / Path Bias
```

## 修订必须记录

- 相关 Direction Handoff 版本。
- 相关 Growth Plan 版本。
- 是否触发 Nutrient Request。
- 变更原因和影响范围。
- 继续、回退、分叉或停止决策。
- 新的 Workflow IR 或差异。

## 禁止事项

- 不让执行个体静默改方向。
- 不用 Path Bias 掩盖新证据。
- 不把单次成功直接晋升为 Capability Asset 或 Fruit。
- 不让 Fruit 绕过 Governance。
