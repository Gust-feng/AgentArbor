# 通信机制

## 概述

AgentArbor 内部通信统一通过 MessageBus、Router、状态机和 EventLog 组织。同步请求可以存在，但必须表现为可记录、可重试、可审计的内部消息。

## 核心组件

| 组件 | 职责 |
| --- | --- |
| ArborMessage | 内部消息母语 |
| MessageBus | 接收、校验、记录、路由、重试和回放 |
| Router | 根据状态、能力、权限和计划分配接收者 |
| State Machine | 控制任务生命周期和合法状态转换 |
| EventLog | 保存可回放通信和状态证据 |

## 层级通信

```text
Seed Cluster -> seed_packet.completed -> User Approval Gate
User Approval Gate -> user_approval.received -> Soil
Root System -> root_brief.completed -> Core Control Cluster
Core Control Cluster -> growth_plan.completed -> Router
Router -> task.assigned -> Branch / Leaf
Branch / Leaf -> artifact.produced -> Flower Cluster
Flower Cluster -> verification.completed -> Core Control Cluster / Memory Writer
Core Control Cluster / Branch / Flower -> root_callback.requested -> Root System
Root System -> root_callback.completed -> Core Control Cluster
Memory Writer -> run_memory.captured -> Governance
Governance -> capability_asset.accepted -> Soil
```

## 同步请求

需要同步响应的场景可以使用请求响应语义，例如验证请求、Root Callback 或人工确认请求。但这仍是 MessageBus 上的消息：

```text
request message -> MessageBus -> Router -> handler -> response message -> EventLog
```

这样可以同时保留可靠性、可观察性和可恢复能力。

## 禁止事项

- agent 不能绕过 MessageBus 调用另一个 agent。
- agent 不能把聊天文本当作系统状态。
- Router 不能跳过权限检查。
- 状态机不能被执行者私自推进。
- 外部协议不能直接成为内部事实源。

## 可靠性规则

- 所有关键消息必须有 `traceId`。
- 高风险动作必须有审批消息。
- 失败消息必须可回放。
- Artifact、Verification、Run Memory、Root Callback、Growth Plan Revision 和 Governance 决策必须能通过 EventLog 找到来源。
