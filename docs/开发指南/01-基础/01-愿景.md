# 愿景

## 长期愿景

AgentArbor 要成为目标驱动的 Agent / AgentApp 孕育与演化平台。

用户不应该反复从零组织提示词、工具、上下文、角色和工程目录。用户给出的目标首先进入 Soil 环境，由 Underground Center 结合土壤事实、约束、证据和必要的用户确认形成 `.agentarbor` 方向交接包。Aboveground Center 读取交接包，制定 Growth Plan、Workflow IR、上下文拓扑、执行组织、验证门和修订机制。地上生长组织完成执行、验证和交付，形成 Fruits；Fruits 必须经过 Governance，才能以 Capability Asset、Path Bias、长期约束或验证证据回流 Soil。

随着真实任务重复发生，系统应识别哪些做法稳定有效，哪些能力值得保留，哪些 agent 具备独立承担一类任务的条件。第二次相似任务不应从零开始，也不应机械复刻第一次流程，而应通过 Path Bias 自然倾向于上一轮已经验证过的有效路径。成熟的子 agent 最终可以成为果实：它从母体孕育而来，但在通过治理门后可以脱离母体，携带最小权限、明确契约、版本、评估记录和撤回路径独立运行。

## 不是短期生成器

AgentArbor 不是把一句话变成一堆文件的脚手架。单次生成只能证明系统会写文件，不能证明系统能长期生长能力。

AgentArbor 的长期价值来自六件事：

- 目标不丢失：目标、约束、决策、变更和验收标准可以持续追踪。
- 执行可观察：执行过程、工具调用、资产使用和产物变化可以审计。
- 结果可验证：任务结果必须有证据、测试或人工确认。
- 运行有沉淀：每次任务都留下 Run Memory，并按证据生成 Experience Candidate 和 Path Bias。
- 能力可演化：重复成功的模式可以被治理、复用、导出和修剪。
- 约束可执行：hard constraint、soft constraint 和 preference 可以被分发、验证和沉淀。

## 植物隐喻的实际含义

植物隐喻不是装饰，它用于约束职责：

- Soil 表示固定资产、历史证据、能力资产、约束和治理规则。
- Underground Center 表示地下中枢，负责需求成形、证据探索、方向综合和养料供给。
- `.agentarbor` 表示方向交接包，用于从地下中枢向地上中枢传递方向、约束、证据和 Growth Entry。
- Aboveground Center 表示地上中枢，负责计划、上下文拓扑、运行组织、验证门和修订机制。
- Aboveground Growth 表示地上执行、协作、验证反馈和产物提交。
- Fruit 表示成熟交付物、可复用 AgentApp、能力包或可脱离子 agent。
- Governance 表示果实入土前的评估、权限、谱系、版本和退役裁决。
- Ring 表示 EventLog、Run Memory 和 Experience Candidate 的聚合视图，用于观察系统怎样生长。

任何把地下中枢写成执行层、把 `.agentarbor` 写成最终资产仓库、把地上中枢写成单点万能 agent、把地上组织写成方向探索组织、把约束写成不可执行备注、或把 Fruit 写成未经治理的普通输出的设计都必须修正。Direction Handoff 必须版本化；Growth Plan 必须引用具体 Direction Handoff 版本，并能基于 Nutrient Patch 形成 Growth Plan Revision。
