# 生成工程规范

## 1. 目标

本文定义 AgentArbor 生成出来的 Agent 工程应该具备的最小结构。

目标不是一次性覆盖所有 Agent 场景，而是建立稳定格式，让 Code Review、Research、论文阅读、文件整理等场景都能逐步扩展。

## 2. 生成工程分两级

AgentArbor 的生成物不是单个 Agent 文件，而是一个应用级工程。

```text
Agent App
  ├─ Workflow
  ├─ Agent Project 1
  ├─ Agent Project 2
  ├─ Samples
  ├─ Outputs
  └─ README
```

其中每个 Agent Project 使用 `templates/agent-project/` 的标准结构。

## 3. 应用级工程结构

建议第一版生成结构：

```text
generated/<project-id>/
  manifest.yaml
  workflow.yaml
  agents/
    <agent-id>/
      agent.yaml
      manifest.yaml
      prompts/
        system.md
        task.md
      schemas/
        input.schema.json
        output.schema.json
      tools/
        bindings.yaml
      policies/
        permissions.yaml
      memory/
        memory.yaml
      tests/
        smoke.test.yaml
      evals/
        smoke.eval.yaml
      src/
        README.md
  samples/
    sample_task.yaml
  artifacts/
    .gitkeep
  outputs/
    .gitkeep
  logs/
    .gitkeep
  README.md
```

如果后续生成某种语言的可运行工程，应通过 `runtime.yaml` 明确声明运行剖面，而不是让 AgentArbor 默认绑定某个语言运行时。

```text
runtime.yaml
providers.example.yaml
secrets.example.env
```

## 4. 应用级 manifest

应用级 `manifest.yaml` 负责声明整个生成工程。

草案：

```yaml
schema_version: agent.app/v1
id: generated_app_id
name: Generated Agent App
template: code_review
created_at: 2026-04-27
version: 0.1.0

entry:
  workflow: workflow.yaml
  sample_task: samples/sample_task.yaml

agents:
  - id: diff_reader
    path: agents/diff_reader/agent.yaml
  - id: code_reviewer
    path: agents/code_reviewer/agent.yaml

outputs:
  directory: outputs
  expected:
    - outputs/report.md
```

## 5. WorkflowSpec

`workflow.yaml` 负责描述多 Agent 的执行顺序。

草案：

```yaml
schema_version: agent.workflow/v1
id: main
name: Main Workflow
entry: read_input

steps:
  - id: read_input
    agent: diff_reader
    input: samples/sample_task.yaml
    output: artifacts/diff_summary.json
    on_failure: stop

  - id: review
    agent: code_reviewer
    input: artifacts/diff_summary.json
    output: artifacts/findings.json
    on_failure: stop

  - id: write_report
    agent: report_writer
    input: artifacts/findings.json
    output: outputs/report.md
    on_failure: stop

final_output: outputs/report.md
```

第一版可以顺序执行，不必实现复杂 DAG。

## 6. 单 Agent 标准

每个 Agent 必须包含：

```text
agent.yaml
manifest.yaml
prompts/system.md
prompts/task.md
schemas/input.schema.json
schemas/output.schema.json
tools/bindings.yaml
policies/permissions.yaml
memory/memory.yaml
tests/smoke.test.yaml
evals/smoke.eval.yaml
```

这些文件已经由 `templates/agent-project/` 提供初始模板。

## 7. 权限原则

默认权限应为 deny。

第一版至少区分：

```text
filesystem.read
filesystem.write
network.access
tools.allow
secrets.access
human_approval.required_for
```

Code Review 场景中：

* DiffReader 可以读 sample diff。
* CodeReviewer 不应该写文件。
* ReportWriter 可以写 outputs。
* 默认不允许联网。

Research 场景中：

* Researcher 可以读离线资料源。
* 如果启用 WebSearch，必须在工具绑定里显式声明。
* Writer 可以写 outputs。

## 8. 测试和评测

每个生成工程必须包含 sample task。

每个 Agent 至少包含 smoke test。

应用级验证至少检查：

* manifest 存在。
* workflow 存在。
* workflow 中引用的 agent 都存在。
* 每个 agent 的 schema/prompt/tool/policy 文件存在。
* sample task 存在。
* 运行后 final output 存在。
* 输出文件包含必要章节。

## 9. Code Review 模板预期

第一优先级模板。

推荐 Agent：

```text
DiffReaderAgent
CodeReviewAgent
RiskRankAgent
ReportWriterAgent
```

推荐输出：

```text
outputs/review_report.md
```

报告至少包含：

```text
摘要
主要风险
具体发现
风险等级
建议修改
剩余不确定点
```

## 10. Research 模板预期

第二优先级模板。

推荐 Agent：

```text
PlannerAgent
ResearchAgent
CompareAgent
CriticAgent
ReportWriterAgent
```

推荐输出：

```text
outputs/research_report.md
```

报告至少包含：

```text
调研目标
资料来源
对比维度
主要发现
风险和限制
结论
```

## 11. 验证结果

运行验证输出 `ValidationResult`。

草案：

```yaml
schema_version: agent.validation/v1
project_id: generated_app_id
project_path: generated/generated_app_id
manifest_valid: true
workflow_valid: true
agents_valid: true
sample_task_found: true
run_succeeded: true
final_output_found: true
final_output: outputs/report.md
errors: []
warnings: []
```

## 12. 规范底线

生成工程必须满足：

1. 不是只有 Prompt。
2. 不是只有 README。
3. 不是只有平台内部配置。
4. 必须有 Agent 声明。
5. 必须有输入输出 Schema。
6. 必须有工具绑定。
7. 必须有权限策略。
8. 必须有 sample task。
9. 必须有可验证输出。
10. 必须能被导出和复现。
