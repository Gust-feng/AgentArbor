# ADR-0036：路径依赖（程序性记忆）系统

日期：2026-08-10

状态：已接受，当前生产实现已落地

关联：

- ADR-0033：模型自主笔记记忆架构
- ADR-0035：Conversation 双资源 owner 与统一运行作用域
- CURRENT_RUNTIME_MODE.md

## 1. 决策摘要

AgentArbor 建立一个统一的产品级记忆入口，但不建设一个吞掉所有业务事实的万能记忆管理器。

记忆由多个有明确所有权的 feature 组成：

| 记忆类型 | 记录内容 | 当前 owner |
| --- | --- | --- |
| 声明性记忆 | 用户偏好、项目事实、工作约定和稳定知识 | AgentNotesFeature |
| 路径依赖 | 可复用的任务方法、适用条件、验证方式和失败边界 | PathDependencyFeature |

Workbench Panel 的“记忆”只是上述 feature 的组合查询和管理投影。普通 Agent 的运行事实、记忆读取引用和使用记录仍由 OrdinaryAgentFeature 持有。

路径依赖是记忆的一种程序性类型，不是历史 PathMemory 的改名，也不恢复 PathMemory 或 ExperienceCandidate 的自动采集链路。

本文定义当前生产架构。`PathDependencyFeature`、记忆搜索/读取/引用/保存工具和 Memory Center 已由唯一 Composition Root 装配；运行细节仍以 `CURRENT_RUNTIME_MODE.md` 为准。

## 2. 背景与问题

ADR-0033 使模型可以通过 NoteWrite 自主保存 Markdown 笔记，解决了“模型完全看不到记忆”的问题。但现有 Agent Notes 仍有边界：

- 笔记以作用域全文为主要组织单位，不适合大量可独立检索的经验条目；
- 项目事实、用户偏好和复杂任务方法容易混在同一正文中；
- 启动时全文注入不能随着经验数量无限增长；
- 历史路径身份笔记不会猜测迁移；当前实现已改用稳定 owner 身份，旧目录只保留为不可见历史数据。

历史 PathMemory / ExperienceCandidate 记录的是运行流水和治理实验。它们已经从生产组合根卸载，不作为新路径依赖的来源或兼容实现。

本 ADR 要解决的是：模型完成一次复杂任务后，可以主动保存一条可复用的方法论；以后遇到类似任务时，模型先看到有限目录，再按需读取完整方法论，并自行判断是否采用。

## 3. 记忆模型与模块边界

### 3.1 产品模型

Memory Center 提供以下视图。管理查询可以显式选择已登记且未删除的 Space 或 Workspace；服务端通过 feature facade 校验选择，不接受任意未验证 ownerId：

- 全局记忆；
- 当前 Space 记忆；
- 当前 Workspace 记忆；
- 路径依赖；
- 后续可能增加的其他记忆类型。

Space 和 Workspace 在 Panel 中可以作为同级的“空间记忆”展示，但内部必须保留不同的 owner 类型。

### 3.2 Feature 所有权

AgentNotesFeature 拥有声明性记忆的写入、查询、版本和用户编辑边界。

PathDependencyFeature 拥有路径依赖的契约、存储、查询、写入、更新和删除边界。

OrdinaryAgentFeature 拥有：

- Run 中实际读取了哪些记忆；
- 模型明确声明采用了哪些记忆；
- 这些引用发生在哪个 memory revision；
- 引用事实的持久化和投影。

Panel、HTTP route 和 UI 只能调用公开 query/command/event facade，不能读取 feature 的 store，也不能自行推导记忆使用事实。

只共享必要的机械契约，例如 owner、memory id、revision、搜索结果和来源引用；不抽取 universal MemoryManager、全局业务状态或跨 feature 事务。

## 4. 作用域

### 4.1 稳定 owner

目标作用域是以下判别联合：

~~~text
global
spaceId
workspaceId
~~~

持久化和权限判断使用稳定身份，不使用 workspaceRoot、路径哈希或当前进程 cwd 作为记忆 owner。

Conversation 创建时只有一个直接 owner，语义遵循 ADR-0035：

- Space Conversation 默认可见全局记忆和当前 Space 记忆；
- Workspace Conversation 默认可见全局记忆和当前 Workspace 记忆；
- Space 引用的 Workspace 不会自动把两套记忆合并；
- 跨作用域复制、提升或引用必须是显式动作。

模型运行工具只能在当前 Run 冻结的 capability scope 内选择 global 或 current direct owner，不能提交任意 spaceId、workspaceId 或路径来扩大访问范围。Memory Center 的显式管理选择不改变这一模型运行边界。

### 4.2 Space 与 Workspace 的产品含义

Space 是 AgentArbor 内部维护的语义工作场景，可以拥有自己的软件资产、Conversation 和工作约定，也可以引用多个 Workspace。

Workspace 是用户文件系统中的真实文件夹或仓库，可以被多个 Space 引用。它承载与仓库本身不可分离的知识，例如构建方式、目录约定和项目特有的解决方法。

因此：

- “客户 A 的交付检查清单”属于 Space；
- “这个仓库必须使用 pnpm”属于 Workspace；
- “用户偏好中文和简洁回答”属于 global。

UI 可以把 Space 和 Workspace 平铺展示，但不能为了简化界面而在存储层合并二者。

## 5. 路径依赖的内容边界

路径依赖保存的是模型提炼后的方法论，不是客观运行日志。

一条路径依赖至少应能回答：

1. 这类任务或问题是什么；
2. 核心解决思路为什么有效；
3. 适用的前提和范围是什么；
4. 如何判断方法确实奏效；
5. 常见失败边界和不适用情况是什么。

推荐的方法论组织方式是：

- 问题；
- 核心思路；
- 适用条件；
- 验证方式；
- 失败边界；
- 可选的补充知识。

这些是写作指引，不是要求模型机械填满固定模板。

明确禁止：

- 保存完整工具调用流水；
- 保存完整 transcript 或工具输出；
- 保存一次任务的绝对路径、临时 URL、密钥和环境偶然值；
- 把方法论变成下一次必须盲目重放的脚本。

方法论可以描述某类工具或关键技术的选择依据，但应保留判断和适用边界，而不是记录上一次 Run 的逐步执行序列。

### 5.1 最小记录事实

| 字段 | 作用 |
| --- | --- |
| id | 稳定的记忆身份 |
| owner | global、spaceId 或 workspaceId |
| title | 可识别的短标题 |
| methodology | 方法论正文 |
| sourceRunRefs | 产生该方法论的 Run 来源 |
| verification | not_recorded 或 observed（模型侧观察状态，不代表用户确认） |
| evidenceRefs | 可追溯证据引用，不复制 transcript 或工具正文 |
| revision | 并发更新，以及 Run 读取/采用时绑定的版本 |
| contentVersion | 正文内容哈希 |
| createdAt、updatedAt | 生命周期信息 |
| createdBy | agent 或 user |
| tags | 可选检索标签 |

verification 和 evidenceRefs 只表达来源事实，不是工程对方法论质量的自动评分。没有明确来源时使用 not_recorded；工程不得因为关键词、工具数量或模型措辞自行把状态升级为已验证。

## 6. 模型可见性与工具

### 6.1 渐进式披露

新 Run 的记忆可见性采用三层：

1. Run birth 注入有界的 active 记忆目录。目录只包含 id、类型、作用域、标题、适用提示、revision 和必要的短摘录；
2. Agent 通过 MemorySearch 在当前授权作用域内查找候选；
3. Agent 通过 MemoryRead 读取完整正文、来源引用、验证状态和 revision。

路径依赖不能在启动时全量注入。首期目录最多 16 条 / 2,000 tokens，搜索最多 8 条 / 1,500 tokens，完整读取最多 8,000 tokens；tokenizer 随冻结 Run 模型选择，未知模型使用公开 fallback。目录或搜索超限只停止增加完整候选卡片；完整读取超限明确失败且不产生 read 事实，不能用摘要伪装为完整正文。完整正文只有在模型主动读取后才进入当前上下文。

现有 Agent Notes 的全文启动注入在迁移期继续保留，避免能力倒退。它不是新路径依赖的注入范式；当 Notes 也完成条目化和 owner 迁移后，再统一收口。

### 6.2 工具边界

建议的读取工具是跨记忆类型的中性机械能力：

- MemorySearch：按当前授权 scope、类型、标题、标签或正文索引返回有界候选；
- MemoryRead：按不透明 memory id 和 revision 返回完整记忆事实。

写入工具保留 feature 语义：

- NoteWrite：更新声明性笔记；
- PathDependencySave：创建或更新路径依赖，更新必须携带 expectedRevision；
- 其他记忆类型以后按真实需求增加，不预先制造通用写入器。

模型决定何时搜索、读取、保存、更新和删除；工程只守权限、版本、大小、来源引用和持久化一致性，不用关键词规则代替模型判断。

初期不引入向量数据库。关键词、标签和可重建的文本索引足以验证核心价值。

## 7. 引用与使用事实

“记忆出现在目录中”不等于被引用，“模型提到了标题”也不等于被使用。

定义三类事实：

| 事实 | 产生条件 | 含义 |
| --- | --- | --- |
| exposure | 目录或搜索结果向模型展示 | 模型有机会看到 |
| read | MemoryRead 成功返回完整正文 | 本 Run 明确读取了该版本 |
| applied/use | 模型调用轻量 MemoryReference，明确声明采用 | 本 Run 主动把该版本作为方法依据 |

MemorySearch 不计引用次数。MemoryRead 形成 Ordinary run 的可追溯读取事实。MemoryReference 不修改记忆正文，只记录 memory id、revision、runId、时间和可选说明。

Panel 的引用列表、读取次数和使用次数都从 Ordinary 的事实投影计算：

- 读取次数统计 read 事实；
- 使用次数统计 applied/use 事实；
- 不扫描模型回复文本；
- 不通过标题关键词猜测引用；
- 不让 Panel 直接调用 PathDependencyFeature.commands.recordUsage。

如果记忆随后被用户删除，历史 Run 仍保留引用的 id、标题快照和 revision；正文按“不参与备份、删除即删除”的产品政策返回不可用，不伪造恢复内容。

## 8. 持久化、版本与删除

每条路径依赖需要稳定 id、owner、revision、内容版本、创建来源和更新时间。

更新、删除和用户编辑必须遵循 expectedRevision/CAS。内容哈希用于识别正文版本，不能替代并发修订号。

当前产品政策：

- 路径依赖不参与 Workbench 备份；
- 用户删除是直接删除，不进入回收站；
- 删除 Space 或 Workspace 时，直接删除该 owner 下的路径依赖；
- 全局记忆不受 owner 删除影响；
- 删除后的历史引用只保留最小来源快照，不保留可恢复正文；
- 旧 PathMemory / ExperienceCandidate 数据不迁移、不导入。

这些是有意接受的数据丢失边界，必须在 UI 和错误结果中如实表达。

## 9. Panel 入口

Panel 左侧增加独立的“记忆”入口，不放在设置页，也不复用 Personal Knowledge 的 brain 视图。

Memory Center 首期应展示真实可查询的记忆事实：

- 全局记忆；
- 当前 Space 或 Workspace 的记忆；
- 路径依赖；
- 来源 Run、revision、读取/使用统计；
- 编辑、删除和冲突提示。

引用详情可以从记忆页或 Run 活动投影打开。是否在模型正文旁显示徽标，只能建立在明确的 MemoryReference 事实之上，不能修改或重新解析模型正式回答。

## 10. Dream 的边界

Dream、后台空闲总结和自动生成记忆不属于本 ADR 的当前实现范围。

未来若出生 Dream feature，它必须：

- 读取 Ordinary 的公开稳定事实端口；
- 生成带 sourceRefs 的 draft；
- 不直接覆盖或激活现有 active 记忆；
- 拥有自己的队列、预算、取消、幂等和失败诊断；
- 通过单独 ADR 决定何时被采用。

本 ADR 不为 Dream 提前实现队列、状态或后台调度器。

## 11. 当前实现与后续出生条件

以下基础工作已在当前生产实现中完成：

1. 定义统一的 Memory owner facade，把 Agent Notes 的路径作用域迁移到稳定 global、spaceId、workspaceId；
2. 保持现有 Notes 全文注入兼容，并让路径依赖目录随 run birth 的冻结 AgentDefinition 一起确定；
3. 建立 PathDependencyFeature 的独立契约、仓储、CAS 和公开 query/command；
4. 接入 MemorySearch、MemoryRead 和 PathDependencySave；
5. 建立 Ordinary 的 read 与 applied/use 事实投影；
6. 在后端契约稳定后接入左侧 Memory Center；
7. 通过确定性契约验证 owner 隔离、CAS、完整读取、删除后历史事实和预算边界；模型质量仍需以重复任务评测验证是否减少无意义探索、是否错误复用和是否超过上下文预算。

历史 PathMemory / ExperienceCandidate 只保留为孤儿实验和历史参考，不作为迁移输入。

未来 Dream、向量检索、Path Bias 或 Governance/Global Soil 回流必须在真实需求出生后分别定义契约、所有权、预算、取消和失败事实；不得从本 ADR 的历史 PathMemory 链路自动恢复。

## 12. 非目标

当前不做：

- 自动 Dream 总结；
- 全量路径依赖启动注入；
- 原始工具流水回放；
- 向量数据库或不可解释的自动相关度路由；
- 跨 Space/Workspace 的隐式记忆继承；
- 方法论市场、共享和导出；
- Workbench 备份；
- 通过回复文本启发式生成引用事实；
- 为记忆建立第二个 Ordinary runner 或平行业务状态。

## 13. 后果与验收判断

正面后果：

- 复杂任务的解决方法可以被模型主动保存和复用；
- 方法论不被一次性工具流水锁死；
- 记忆来源、版本和使用事实可追溯；
- Space、Workspace 和 global 的边界清晰；
- 面板可以独立管理记忆，不污染 Personal Knowledge。

主要代价：

- Agent Notes owner 身份迁移带来的实现和兼容成本；
- MemorySearch、MemoryRead 和引用事实会增加新的契约；
- 不参与备份和直接删除会带来不可恢复的数据损失；
- 方法论质量仍依赖模型判断，工程不替模型决定内容价值。

当前实现的持续验收事实包括：

- 同一条记忆在不同 owner 间隔离；
- owner 重挂载不导致记忆漂移；
- Run 能复现当时读取的 id 和 revision；
- 删除后历史引用诚实显示不可用；
- Search/Read 的结果不丢失完整正文；
- 使用次数不依赖回复文本猜测；
- 重复任务相较无记忆基线确实减少无效探索。
