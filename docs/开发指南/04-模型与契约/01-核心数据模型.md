# 核心数据模型

## TaskSoil

TaskSoil 是当前任务上下文容器。它必须描述：

- 来源用户任务。
- 文件、项目、网页和外部资料引用。
- 临时约束、权限边界和验收要求。
- 可读取的 Global Soil 引用。
- 本轮运行材料和恢复点。

TaskSoil 是临时土壤，不能直接写入 Global Soil。

## Plan

Plan 是地下到地上的产品级交接对象。它必须描述：

- 来源任务和 Task Soil 引用。
- 目标、非目标、验收门和边界。
- 假设、缺失信息、风险和升级条件。
- Global Soil 引用、可复用能力、历史证据和失败模式。
- ConstraintRef 与候选约束状态。
- 可选方向、适用条件、不适用条件、推荐方向和证据来源。
- 方向裁决、合并、淘汰、反驳和风险登记。
- child/rootlet 输出的来源引用与父层 synthesis / convergence 记录。
- execution entry。
- 版本和有效状态。

Plan 不是长期资产，也不是执行成果。单个 child/rootlet 的原始输出不能直接成为 Plan 中的事实、约束或方向依据。

## PlanPackage

PlanPackage 是 Plan 的可持久化形态。它可以保存在内存、显式输出目录或未来 `.agentarbor/` 目录下。

PlanPackage 必须包含：

- Plan 主体。
- refs 索引。
- validation result。
- manifest。

`.agentarbor` 只是 PlanPackage 的存储形态或目录名，不是独立产品节点。

## Goal

目标对象必须包含：

- 原始任务。
- 澄清目标。
- 非目标。
- ConstraintRef。
- 验收标准。
- 风险。
- 当前状态。
- 变更记录。

## ExecutionPlan

ExecutionPlan 是 Aboveground 从 Plan 派生的执行入口。它必须描述：

- 来源 Plan 版本。
- 选定方向。
- 是否采用 Path Bias。
- Workflow IR 摘要。
- 执行组织形态。
- 任务列表。
- 约束采用与分发。
- 复用策略。
- 沉淀策略。
- 验证和验收门。
- Nutrient Request 触发点。

## PlanRevision

PlanRevision 必须描述：

- 来源 Plan 版本。
- Nutrient Patch 或 Plan vNext。
- 修订原因。
- 影响范围。
- 决策：继续、回退、分叉或停止。
- 新 Workflow IR 或变更摘要。

## AgentSpec

AgentSpec 必须包含：

- 名称。
- 职责。
- 输入。
- 输出契约。
- 静态能力上限。
- 工具权限上限。
- 预算。
- 协作关系。
- 验证要求。
- 生命周期状态。

本轮实际能力由 `AgentSpec`、父层动态授权、`AgentRunContext` 和 `ToolCenter / Guard` 共同裁剪。

## Constraint

Constraint 必须描述：

- 来源。
- 类型。
- 等级：hard、soft 或 preference。
- 约束内容。
- 责任方。
- 适用范围。
- 证据引用。
- 执行门。
- 冲突处理策略。
- 当前状态。

ConstraintRef 必须描述：

- 约束 ID。
- 在当前对象中的要求等级。
- 当前执行门。

## Capability Asset

能力资产必须包含：

- 能力名称。
- 能力类型。
- 输入输出。
- 依赖。
- 权限。
- 适用范围。
- 来源。
- 验证记录。
- 版本。
- 退役策略。

## Nutrient Request / Nutrient Patch

Nutrient Request 必须描述：

- 触发者。
- 触发原因。
- 关联 Plan 版本。
- 关联执行任务、验证报告或治理报告。
- 养料类型：证据、Global Soil 资产、外部事实、约束细节、上下文或能力线索。
- 阻塞等级。
- 当前假设。
- 缺口说明。

Nutrient Patch 必须描述：

- 来源 Nutrient Request。
- 补充的 EvidenceRef、SoilRef、ConstraintRef、FactRef、Context Supplement 或 Capability Hint。
- child/rootlet 输出引用与父层 synthesis / convergence 记录。
- 对当前假设的判断。
- 对执行的影响。
- 输出 Plan vNext，或无需补充的证据。

## PathDependency（当前程序性记忆契约）

PathDependency 是 `PathDependencyFeature` 拥有的可复用任务方法论，不是一次 Run 的工具流水或历史 PathMemory 的改名。它只属于稳定的 `global`、`spaceId` 或 `workspaceId` owner；Run 仅能使用其 capability snapshot 已冻结的 global + 当前 Conversation owner 作用域。

每条记录至少包含：

- 稳定 `id`、owner、title、methodology、tags。
- `sourceRunRefs`、`evidenceRefs` 与 `verification`（`not_recorded` 或 `observed`；验证状态只表示模型侧观察，不代表用户确认）。
- `revision`、`contentVersion`、createdAt、updatedAt 与 createdBy。

模型通过 `PathDependencySave` 显式创建或携带 expectedRevision 更新；更新与删除遵循 CAS。新 Run 只得到有预算的目录，不全量注入 methodology 正文；模型自行决定是否使用 `MemorySearch` 发现候选、`MemoryRead` 读取完整版本，以及 `MemoryReference` 声明采用。成功读取和明确采用都由 OrdinaryAgentFeature 记录为 Run 事实，不能由 Panel 或回复文本推断。

Memory Center 是 Agent Notes 与 PathDependency 的组合管理投影，不改变各 feature 的所有权；它可显式选择已登记且未删除的 Space / Workspace，经 feature facade 校验后查询全局和所选 owner 记忆，不接受任意 ownerId。该管理选择不扩张模型运行工具只能使用 global + 当前 frozen direct owner 的边界。当前不包含自动采集、Dream、向量检索、Path Bias 或 Governance。

## 历史路径记忆实验

PathMemory、Experience Candidate、Path Bias、Ring Memory 和 Lineage Record 的旧定义不属于当前开发契约；它们既不定义新的路径依赖，也不是生产运行的输入。历史实验的完整材料只保留在 [ADR-0032](../../架构设计/产品架构/ADR-0032-路径记忆与长期记忆回流架构.md) 与孤儿源码中。新实现只能遵循上文的 PathDependency 契约以及 ADR-0036，不能复用旧字段或自动采集流程。
