# AgentArbor 当前规划总入口

本文回答一个问题：

> AgentArbor 到底为什么存在，以及现在应该按什么方向开发？

## 1. 根本判断

AgentArbor 不应该为了比赛而开发。

比赛可以是一个阶段性展示窗口，但不能成为项目的灵魂、边界和架构来源。AgentArbor 的核心价值必须先独立成立：即使没有比赛，它也应该是一个值得长期生长的系统。

当前统一定位：

> AgentArbor 是一个让自然语言目标长成可运行、可验证、可追溯、可继续演化 AgentApp 的平台。

它不是普通 Agent 应用，不是 Prompt 生成器，也不是 Dify/FastGPT/Coze 的替代品。

它真正关心的是：

```text
一个目标如何出生
如何形成计划
如何组织 Agent 和能力
如何生成可运行工程
如何验证结果
如何记录历史
如何在反馈中修剪、分化或重生
```

## 2. 项目的灵魂

AgentArbor 的隐喻不是工厂，而是树。

* 目标是种子。
* 文档是基因。
* Agent 是枝条。
* 能力是器官。
* Git 是年轮。
* 测试是自然选择。
* 治理是边界。
* 反思是意识。
* 分化是生命力。
* 重生是勇气。
* 用户是园丁。

这个隐喻不是宣传语，而是工程约束：

* 生成不是结束，验证才决定是否保留。
* 计划不是圣旨，只是当前假设。
* 历史不能抹掉，只能被覆盖、标记、分化或重生。
* Agent 不能只会执行，还必须会怀疑。
* 局部能跑不等于全局健康。

## 3. 资料地位

当前项目里有四类资料，它们地位不同。

### 3.1 深度研究：精神内核和长期方向

```text
docs/02-研究资料/deep-research-report.md
docs/02-研究资料/deep-research-v0.1/
```

这两份资料最接近 AgentArbor 的灵魂。它们定义了目标驱动、Git 年轮、验证、演化、治理、分化和重生等关键思想。

它们不是必须一次性实现的范围，但它们决定项目长期不能长歪。

### 3.2 开发计划书：早期叙事和产品表达

```text
docs/00-总览/项目计划书.md
```

它适合保留为早期产品叙事、场景说明和对外表达基础。

但后续规划不能只停留在“生成 Agent 工程”，需要逐步升级为“孕育 AgentApp 生命周期”。

### 3.3 比赛资料：外部约束和展示机会

```text
docs/90-外部资料/比赛资料/比赛信息.md
```

比赛不是项目目标，只是外部展示机会。

它可以影响提交材料、演示节奏和阶段性取舍，但不能决定 AgentArbor 是什么。

### 3.4 外部工程参考：只能先沉淀再使用

外部的 Agent 工程参考资料不属于本项目范畴。

如果需要借鉴，必须先在项目内沉淀为自己的参考文档或复制必要模板，不能让项目文档持续依赖外部目录。

当前已沉淀为：

```text
docs/04-参考沉淀/Agent工程基础原则.md
```

该文档只提供基础工程参考，不能决定 AgentArbor 的灵魂、主架构或长期路线。

## 4. 当前主线

当前主线应从“工程生成器”升级为“AgentApp 孕育系统”的最小闭环：

```text
自然语言目标
  -> arbor.json
  -> 目标和约束澄清
  -> 阶段计划
  -> Workflow IR / 动态任务图
  -> Agent 组织和能力声明
  -> 生成 AgentApp 工程
  -> sample task / 测试 / 验证
  -> 修复或悬停
  -> 日志 / 谱系 / 可选 Git commit
  -> 导出可继续演化的 AgentApp
```

## 5. 第一版目标

第一版不证明 AgentArbor 无所不能。

第一版只证明：

> 一个目标可以被 AgentArbor 转化为带有文档、Agent 组织、工作流、验证、日志和演化入口的可运行 AgentApp。

第一版必须有：

* `arbor.json`
* 目标文档
* 阶段计划
* Agent 组织
* Workflow IR
* 能力和权限声明
* sample task
* 验证结果
* 运行日志
* 可导出工程

第一版暂不做：

* 完整插件市场
* 完整 MCP broker
* 完整 Rebirth 自动执行
* 企业级治理
* 大规模多 Agent 并发
* 长期自治维护
* 复杂拖拽工作流编辑器

## 6. 下一步

建议下一步不是继续扩写比赛材料，而是整理 AgentArbor 自己的核心规格：

1. 定义 `arbor.json`。
2. 定义 AgentApp 标准目录。
3. 定义 Workflow IR。
4. 定义最小 Agent Manifest。
5. 定义验证结果格式。
6. 定义第一版生成闭环。
7. 再选择一个最适合展示“生命系统”的 AgentApp 示例。

Code Review、Research、论文阅读都只是候选示例，不是项目本体。
