# 工作台界面

## 界面目标

AgentArbor Desktop 不是营销首页，也不是单纯调试面板。它是桌面通用 Agent 的工作台：用户提交任务、绑定工作区上下文、查看判断、证据、结果和待确认事项。

用户只面对一个工作会话入口，不应该被迫理解 Underground / Aboveground、Task Soil、Plan Package、Agent Run Tree、provider 等内部术语。这些内部细节只进入设置、诊断或开发者详情。

工作台必须先像本地桌面 Root Agent 一样可用。用户可以随意提问、闲聊、询问模型身份、让系统解释概念或处理小请求，也可以直接交给它需要查证、读取授权材料、等待确认并产出结果的本地任务；默认路径是普通工具型 Root Agent 会话，直接由 LLM 决定回答、查证、读取授权上下文、请求确认或给出用户指导。工程层不得用关键词、长度或固定规则自动升级模式；它只负责空输入、配置、schema、预算、权限和脱敏边界。

复杂方向成形使用显式入口。用户切换到“深度模式”后，系统才进入 Underground Cognitive Runtime，读取授权上下文、调用工具、多路探索、派生 child/rootlet agent、父层综合并形成收束结果。当前阶段深度模式只开发到地下组织 / Plan 边界，不进入 Aboveground 执行，也不把每个复杂输入都包装成通用 Work Session。界面的基本节奏是“默认普通 Agent 就能工作，用户选择深度模式时才展开地下组织过程”，而不是把内部流程默认铺在首屏。

同一会话必须支持连续对话。发送新消息只能追加新的用户回合和助手回合，不能清空已有 transcript；后续请求应把最近可见对话按原 `user` / `assistant` 角色作为独立模型消息传给后端，并保证当前用户输入仍是最后一条 user message。

## 工作台结构

```text
桌面工作台
  - 会话导航：新对话、技能、工具、设置、最近对话、需要确认的任务
  - 主工作区：持续对话 / 显式深度模式、轻量活动、结果块、证据、下一步
  - 输入区：底部常驻任务输入，折叠高级上下文和权限
  - 工作上下文：待办、当前上下文、证据、近期活动，默认进入详情或按需展开
  - 开发者详情抽屉：诊断、Agents、设置、调试投影
```

### 会话导航

承接新对话、技能、工具、设置、最近对话，以及正在运行或需要确认的任务。Routines / 例行任务必须等真实调度器出生后再进入可见导航，当前不能展示假入口。左侧导航不能把内部架构层级做成产品菜单，也不应在底部常驻“本地工作”这类说明块。空态下它应更像会话列表，而不是任务管理系统。

### 主工作区

主工作区服务用户完成任务，形态是持续工作会话流，而不是“表单 + 文档预览”或工程监控台。它展示：

- 当前任务理解和状态。
- 普通问题的直接回答。
- 运行中的轻量活动笔记。
- 已执行动作、已读材料和阶段性判断。
- 需要用户授权、拒绝或补充指导的待确认事项。
- 报告、草稿、成果或失败说明，作为会话中的可审阅产物出现。
- 关键发现。
- 证据引用。
- 风险和不确定性。
- 下一步。

主工作区解释“这个结果为什么合理”，不展示完整内部运行过程。
完成态应优先呈现产物本身，例如报告预览、文件摘要、表格或补丁预览；不应把最终结果降级成一组等权状态卡。
若本轮只是普通问答，完成态只展示回答、必要的不确定性和可继续追问方向，不展示空报告或假产物。

### 输入区

输入区默认常驻在主工作区底部，首屏只保留任务输入、发送和必要的轻量状态/模式入口。模型选择、测试模式、上下文引用、权限引用、附件/文件能力和工具设置默认折叠到高级输入、设置或详情入口中，不能占据首屏注意力。

### 右侧上下文栏

工作上下文服务普通用户的浅层监督，但不再作为空态和普通问答的默认首屏结构。它只在真实工作会话需要时按需展开，或进入详情抽屉的概览区。它展示：

- 待办：需要用户判断、授权或补充的信息。
- 当前上下文：本轮任务引用的文件、网页、项目或短摘要。
- 证据：支持当前结果的文件、网页、引用或输出摘要。
- 近期活动：人类可读的工作进度，例如正在阅读上下文、整理证据、生成报告。

成果预览必须留在主工作区的会话结果块中，不能放到上下文栏抢主视觉。工作上下文不是固定流程图，也不是架构监控卡片墙。

### 开发者详情抽屉

诊断、Agents 和设置解释“系统如何形成这个结果”。它们可以展示：

- 模型配置边界和失败摘要。
- 输出契约、模型 / 工具 refs 和安全 trace。
- agent 运行树、child 输出摘要和父层综合。
- budget、permission、调试 JSON 的安全投影。

开发者详情不展示 raw prompt、raw provider response、raw tool output、hidden reasoning、密钥或 token。

## 三层解释结构

普通用户默认看到：结论、关键发现、证据、不确定性和下一步。

用户展开当前结果时看到：为什么这样判断、为什么暂不选另一个方向、主要风险、还缺什么、相关活动摘要。

开发者打开详情时看到：agent run tree、child 摘要、父层 synthesis、模型和工具 refs、budget、trace 和安全 reasoningTrace 投影。

用户追问“为什么推荐方案 A 而不是方案 B”时，应先在主工作区对应结果处获得解释摘要，再选择是否打开开发者详情查看完整监督 trace。

## 界面边界

UI 不能直接绕过权限层访问本地资产，不能直接写长期能力注册表，也不能把平台适配格式展示成 AgentArbor 原生事实。
