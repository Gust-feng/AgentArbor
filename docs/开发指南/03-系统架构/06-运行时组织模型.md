# 运行时组织模型

## 组织形态

AgentArbor 运行时根据 Task Soil、Plan 和执行风险选择组织形态，而不是预设固定角色表。

| 形态 | 适用场景 | 输出 |
| --- | --- | --- |
| Underground Cognitive Runtime | 用户目标需要成形、证据探索、约束确认、动态派生或养料供给 | Plan、Nutrient Patch、Plan vNext、停止依据 |
| Agent Fabric child/rootlet | 需要局部调研、风险识别、证据补充、约束提取或反事实检查 | 局部材料、证据 refs、不确定性、失败条件 |
| Aboveground Execution Runtime | 已有 Plan，需要执行和验证 | Artifact、Verification、Run Memory |
| single execution agent | 任务简单、风险低、验证清楚 | Artifact、Verification、Run Memory |
| sub-agent execution tree | 执行任务天然分解为父子上下文 | Artifact、Verification、Run Memory |
| shared execution cluster | 多 agent 需要共享事实池和协作状态 | Artifact、Verification、Run Memory |
| competitive execution cluster | 需要多方案竞争、反审查或高风险验证 | 对比证据、推荐方案、Verification |
| governed capability run | 已有成熟能力可独立承担 | Fruit 输出和运行记录 |

MVP 阶段只要求地下 Agent Fabric 一层 child，地上执行可以先从 single execution agent 或简单工具链开始。

## 决策顺序

```text
Desktop Shell
  -> Task Soil
  -> Underground Cognitive Runtime
  -> Plan
  -> Aboveground Execution Runtime
  -> Verification
  -> Fruits
  -> Governance Pipeline
  -> Global Soil
```

Underground 必须决定：

- 是否需要派生 child/rootlet。
- 是否继续探索、等待、打断、追问用户或停止。
- 哪些 child outputs 被采纳、合并、降权、驳回或保留为未知。
- 方向是否足够成立并可形成 Plan。

Aboveground 必须决定：

- 是否采用 Path Bias。
- 是否复用 Capability Asset。
- 哪些 hard constraint 阻断行动，哪些 soft constraint 允许偏离但必须解释，哪些 preference 只用于排序。
- 是否采用 single agent、sub-agent tree、shared cluster 或 competitive cluster。
- 哪些节点需要 Verification 和 Acceptance。
- 哪些失败、未知项或目标变化需要向 Underground 发起 Nutrient Request。
- 哪些结果需要形成 Run Memory 或 Experience Candidate。

## 状态和通信

运行时状态必须由状态机、EventLog 和 Trace 驱动。agent 之间不能私下通信。

允许：

- 通过 Mailbox 接收上游材料。
- 通过 Agent Fabric 派生受控 child。
- 通过 ToolCenter 执行当前上下文允许的工具。
- 通过 EventLog 记录状态变更。
- 通过 ArtifactStore 保存产物。

禁止：

- agent 私下绕过消息系统调用另一个 agent。
- 用聊天内容替代结构化交付物。
- 用历史 Path Bias 替代本次验证。
- 用 Path Bias 覆盖 hard constraint。
- 用自然语言约束说明替代可执行约束引用。
- 用平台适配文件替代 AgentArbor 原生运行语义。
- 用地上执行替代地下方向成形。
- 用一次 Plan 锁死后续运行。
