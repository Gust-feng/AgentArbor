# 路径依赖（程序性记忆）开发指南

状态：已落地的生产实现边界。ADR-0036 的早期实施状态文字尚未同步，不以其旧状态描述覆盖当前运行事实。

本文只定义实现边界和验收口径，不替代 [ADR-0036：路径依赖（程序性记忆）系统](../../架构设计/产品架构/ADR-0036-路径依赖方法论记忆系统.md)，也不恢复历史 PathMemory / ExperienceCandidate。

## 1. 功能定位

路径依赖是记忆系统中的程序性记忆。它保存模型提炼出的可复用任务方法，让模型在类似任务中减少重复探索。

它不是：

- 运行日志；
- 工具调用回放；
- transcript 归档；
- 自动生成的总结；
- 固定工作流或必须执行的脚本。

方法论可以说明技术选择和关键参数的判断依据，但不能保存一次 Run 的原始工具流水、临时路径、密钥、用户私有 URL 或盲目重放指令。

推荐正文能够说明：

- 问题；
- 核心思路；
- 适用条件；
- 验证方式；
- 失败边界；
- 可选补充知识。

这些是模型写作提示，不是要求确定性解析的模板。

## 2. 功能所有权

| 行为 | owner |
| --- | --- |
| 创建、更新、读取、删除路径依赖 | PathDependencyFeature |
| Run birth 的记忆目录组装 | Ordinary 与记忆 feature 的公开 query port |
| MemorySearch / MemoryRead 的机械执行 | 中性工具执行能力；业务查询仍回到对应 feature |
| 本 Run 读取、引用和使用事实 | OrdinaryAgentFeature |
| Panel 列表、详情、编辑和删除 | Panel HTTP/UI adapter，通过 feature facade |
| 具体 feature 装配与资源释放 | 唯一 Composition Root |

禁止：

- route 或 UI 直接读取路径依赖仓储；
- PathDependencyFeature 创建平行 Agent runner、Run 状态或 SSE 终态；
- Panel 根据回复文本猜测“模型使用了哪条记忆”；
- 新建 universal MemoryManager、全局 service locator 或跨 feature 业务事务；
- 导入历史 PathMemory / ExperienceCandidate 作为新路径依赖。

## 3. owner 与作用域

路径依赖只能属于：

- global：用户跨项目可复用的方法；
- spaceId：某个语义工作场景的经验；
- workspaceId：某个真实文件夹或仓库的经验。

Conversation 的直接 owner 由 ADR-0035 冻结。Run 只能读取和写入其 capability snapshot 授权的作用域：

- Space Conversation：global + 当前 Space；
- Workspace Conversation：global + 当前 Workspace。

Space 引用 Workspace 不构成自动记忆继承。需要跨作用域复用时，必须显式复制或提升。

持久化不能使用 workspaceRoot、路径哈希或临时 cwd。Space 和 Workspace 必须保留独立的类型和身份，即使 Panel 将它们作为同级“空间记忆”展示。

Agent Notes 已迁移到稳定的 global + Conversation owner（Space / Workspace）身份；路径键只保留为未导入的旧目录，不能猜测归属或自动恢复。路径依赖实现必须复用同一 owner 契约。

## 4. 路径依赖记录

每条记录至少需要：

| 字段 | 作用 |
| --- | --- |
| id | 稳定的记忆身份 |
| owner | global、spaceId 或 workspaceId |
| title | 可识别的短标题 |
| methodology | 方法论正文 |
| sourceRunRefs | 产生该方法论的 Run 来源 |
| verification | not_recorded、observed 或 user_confirmed |
| evidenceRefs | 可追溯证据引用，不复制 transcript 或工具正文 |
| revision | 并发更新和 Run-born 快照 |
| contentVersion | 正文内容哈希 |
| createdAt、updatedAt | 生命周期信息 |
| createdBy | agent 或 user |
| tags | 可选检索标签 |

写入规则：

- Agent 明确调用 PathDependencySave 后，记录进入 active；
- 用户可以直接编辑或删除；
- 更新和删除必须携带 expectedRevision；
- 内容哈希不能替代并发修订号；
- verification 只表示来源事实，不是工程自动评分；
- 当前不实现 Dream 的 draft、stale 或 retired 状态；
- Dream 将来若出生，必须由独立 ADR 定义 draft 和激活流程。

## 5. 渐进式披露

新 Run 不全量注入路径依赖正文。

### 第一步：有界目录

Run birth 只提供当前授权范围内的有限目录卡片：

- id；
- 类型；
- owner；
- 标题；
- 适用提示；
- revision；
- 很短的可选摘录。

目录有明确条数和 token 预算。目录不代表模型已经采用该记忆。

### 第二步：搜索

MemorySearch 负责在授权 scope 内按标题、标签和可重建文本索引返回有界候选。初期不引入向量数据库，也不把关键词路由写成强制业务流程。

### 第三步：读取

MemoryRead 按不透明 id 和 revision 返回完整正文、来源、验证信息和适用边界。结果必须保留完整事实；超出上下文时使用真实可继续读取的证据契约，不能返回失效摘要或死引用。

现有 Notes 全文注入作为迁移兼容路径保留，直到条目化记忆的召回能力经过验证。

## 6. 引用与使用记录

以下事实必须区分：

- exposure：目录或搜索结果展示过；
- read/reference：MemoryRead 成功返回过完整正文；
- applied/use：模型明确调用 MemoryReference，声明本 Run 采用了该版本。

规则：

- MemorySearch 不增加引用或使用次数；
- MemoryRead 产生 Ordinary 的读取事实，绑定 runId、memoryId、revision 和时间；
- MemoryReference 只记录采用事实，不修改记忆正文；
- 统计从 Ordinary 事实投影生成，PathDependencyFeature 不提供任意 id 的 recordUsage 命令；
- Panel 不扫描助手正文，不用标题关键词推断引用；
- 删除记忆后，历史 Run 保留最小来源快照，正文显示不可用。

首次实现可以先展示“本 Run 读取的记忆”和“累计读取次数”；“使用次数”必须只来自明确的 MemoryReference，不能把读取冒充采用。

## 7. Panel Memory Center

左侧增加独立“记忆”入口。不要复用 Personal Knowledge 的 brain，也不要把路径依赖塞进设置页。

首期页面至少需要：

- 全局记忆；
- 可显式选择的、已登记且未删除的 Space / Workspace 记忆；
- 路径依赖列表；
- 作用域、来源 Run、revision、读取/使用统计；
- 查看完整正文；
- 编辑、删除和版本冲突提示。

引用详情从记忆页或 Run 活动投影打开。只有存在明确 MemoryReference 事实时，才允许额外显示引用徽标；不能改写正式模型回答，也不能通过解析 Markdown 生成业务事实。

Memory Center 可以显式选择已登记且未删除的 Space / Workspace；服务端必须通过 feature facade 校验该选择，不能信任请求体中的任意 ownerId、ownerKind 或路径。此管理查询不改变模型运行工具只能使用 global + 当前 frozen direct owner 的 scope。

## 8. 持久化与删除

路径依赖是 feature-owned durable state，但当前产品明确：

- 不参与 Workbench 备份；
- 用户删除直接删除；
- Space 或 Workspace 删除时直接删除其 owner 记忆；
- global 记忆不受 owner 删除影响；
- 删除不可撤销，UI 和错误结果必须明确说明；
- 历史 Run 的引用事实不随正文删除而消失。

仓储需要单写者或等价的串行化边界、原子写入、显式版本和可诊断失败。单纯 rename 只能防文件损坏，不能替代 CAS。

## 9. 工具与模型边界

建议的工具职责：

- MemorySearch：发现候选；
- MemoryRead：读取完整记忆；
- PathDependencySave：保存或按 revision 更新方法论；
- MemoryReference：记录模型明确采用的记忆版本。

模型自主决定是否搜索、读取、保存和引用。工程只负责：

- 当前 Run 的冻结权限；
- scope 派生；
- 输入 schema；
- 大小和版本；
- 来源引用；
- 结果完整性；
- 取消和失败事实。

Sub-Agent 如果继承记忆能力，只能继承父 Ordinary Run 已冻结的目录、scope 和版本；不得自行扩大 owner、建立新仓储或产生平行引用事实。

## 10. 实施顺序

### 已落地：统一记忆 owner

- 定义 global、spaceId、workspaceId 的公开 owner facade；
- 保持 Agent Notes 的稳定 owner 契约，并为 Memory Center 复用同一作用域解析；
- 保留现有 Notes 全文注入；
- 为 Run birth 保存 memory id/revision/injection hash 所需的最小事实。

### 已落地：路径依赖 feature

- 实现 PathDependencyFeature、仓储、CAS 和删除；
- 接入 PathDependencySave；
- 接入 MemorySearch / MemoryRead；
- 保证完整正文、来源和错误事实可读取。

### 已落地：Ordinary 引用事实

- 记录 MemoryRead；
- 增加 MemoryReference；
- 从 Ordinary read-model 生成读取和使用统计；
- 验证删除后历史引用仍诚实。

### 已落地：Memory Center

- 后端公开 query/command facade；
- Panel 左侧记忆入口；
- 全局、Space、Workspace 和路径依赖视图；
- 编辑、删除、冲突和来源详情。

Dream 不属于当前实现；若未来出生，仍须作为独立 feature 和独立 ADR 决定。

## 11. 验收门

确定性契约至少覆盖：

- global、Space、Workspace 隔离；
- Workspace 重挂载后记忆不随路径漂移；
- 当前 Run 不能伪造 foreign owner；
- CAS 冲突不会静默覆盖；
- Run 能复现当时读取的 memory id 和 revision；
- MemoryRead 返回完整正文或诚实失败；
- 删除后历史引用显示不可用；
- read/use 统计不依赖回复关键词；
- Search 和目录有明确预算；
- 取消不会留下半写入或重复引用事实。

模型质量另做重复任务评测：

- 保存方法论后，相似任务是否减少无效探索；
- 是否出现错误跨场景复用；
- 方法论是否比单纯 Notes 更有帮助；
- 不同模型对保存、搜索、读取和引用的行为差异。

变更实现时，至少运行对应的 Node 构建、Panel 类型检查、Panel 构建和文档 diff 检查；不得因本指南预先创建 Dream、向量、Path Bias 或 Governance 功能。

## 12. 明确不做

当前不做：

- Dream 后台总结；
- 全量路径依赖启动注入；
- 原始工具序列采集或回放；
- 向量数据库；
- 跨 Space/Workspace 隐式继承；
- 备份、回收站和恢复；
- 回复文本启发式引用；
- 第二套 Agent runner 或全局记忆状态。
