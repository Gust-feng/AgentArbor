# 智能体应用孕育闭环

## 基本路径

AgentApp 孕育闭环是 AgentArbor 第一阶段必须证明的产品路径：

```text
自然语言场景 / Imagination
  -> Seed Cluster
  -> Seed Packet
  -> User Approval Gate
  -> Soil
  -> Root System
  -> Root Brief vN
  -> Core Control Cluster
  -> Growth Plan vN
  -> Workflow IR
  -> Branch / Leaf
  -> 工程生成
  -> Flower 验证
  -> Root Callback / Growth Plan Revision
  -> Run Memory
  -> Experience Candidate
  -> Path Bias
  -> 文档与谱系
  -> 可导出 AgentApp 或 Fruit
```

## 保留早期计划书的正确部分

早期计划书有三个值得保留的判断：

- 用户应该能从业务场景或自然语言目标开始，而不是从框架配置开始。
- 系统应该生成可运行、可修改、可测试、可部署的智能体应用工程，而不是只输出说明文档。
- 生成结果必须包括智能体分工、工具、工作流、提示词、配置、测试和文档。

## 需要修正的部分

早期方向如果停留在“生成垂直 Agent 应用”，会把 AgentArbor 压扁成脚手架。当前方向必须补上：

- 目标内核：目标持续存在并驱动后续状态。
- Seed Packet：用户想象必须先经过前置成像、反驳、最小化搜索和确认。
- Root Brief：根系探索必须先看清资产、历史和风险，并支持运行期版本化修订。
- Growth Plan：Core Control Cluster 必须形成执行前计划入口，并在 Root Callback 后可修订。
- Workflow IR：工作流可暂停、恢复、分叉和验证。
- Branch / Leaf：任务由有边界、有交付物、有生命周期的协作单元推进。
- 验证系统：生成结果必须经过检查。
- 运行沉淀：每次任务必须产生 Run Memory、Experience Candidate 和 Path Bias。
- 谱系系统：AgentApp、能力和子 agent 的来源必须可追踪。
- 治理系统：能力进入长期资产前必须经过评估。

## 智能体应用的出生条件

一个智能体应用不能只因为目录生成成功就算出生。至少要满足：

- 有明确目标和非目标。
- 有经过用户确认的 Seed Packet。
- 有版本化 Root Brief 和引用它的 Growth Plan。
- 有运行组织的职责边界。
- 有能力与权限声明。
- 有 Workflow IR 或等价任务图。
- 有可运行工程结构。
- 有测试或验收样例。
- 有 Run Memory、Experience Candidate 和 Path Bias。
- 有文档入口。
- 有谱系记录。
