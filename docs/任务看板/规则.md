# 历史看板规则

## 定位

`docs/任务看板/` 是历史态势看板资产，不是当前计划源数据。它解决的是“早期 Trellis 看板如何被保留和冻结”的问题，而不是“当前任务状态在哪里存储”的问题。

源数据边界：

- `.trellis/tasks/` 是历史任务材料，不再保存当前任务真实状态、当前指针或生命周期。
- `docs/任务看板/` 保存历史说明，不再从 Trellis 派生当前视图。
- `docs/开发指南/` 保存稳定产品和开发口径。
- `docs/研究资料/` 与 `docs/架构设计/` 保存思想来源、研究材料和长期结构性判断。

## 文件职责

- `README.md`：目录入口，只说明历史看板怎么看、边界是什么、哪些文件负责什么。
- `看板.md`：冻结视图，说明旧 Trellis 看板为何不再作为当前任务源。
- `规则.md`：维护协议，约束历史看板不得恢复为第二套计划系统。

除非看板规模已经明显影响阅读，不新增其他文件。即便需要新增，也只能新增阶段级摘要，不能按任务一事一文件扩张。

## 冻结规则

- 不再维护“当前任务”“前置任务”“未来方向”三层 Trellis 视图。
- 不再链接 `.trellis/tasks/*/prd.md` 或 `.trellis/tasks/*/task.json` 作为当前依据。
- 不按任务创建独立看板文件。
- 不把详细 PRD、进展日志、经验库或归档资料复制进看板。
- 如果历史说明已经无法提供价值，应删除或进一步压缩，而不是扩写。

## 更新时机

只在以下情况更新本目录：

- 需要澄清 `.trellis/tasks` 已退出当前开发流程。
- 当前事实源改变了历史看板的边界说明。
- 文件索引或链接需要修正。

## 更新流程

1. 检查 `README.md`、`看板.md`、`规则.md` 的链接。
2. 保持本目录只说明历史边界。
3. 如目录职责或入口发生变化，同步更新 `docs/README.md`、`AGENTS.md` 和相关治理指南。

## 禁止事项

- 不创建根目录 `Plan/`、`Plans/`、`plans/` 或 `PLANS.md`。
- 不让看板成为第二套任务状态。
- 不按任务新建看板文件。
- 不把未来方向写成已承诺任务。
- 不复制完整 PRD、会话记录或沉淀经验。
- 不再从看板修改或刷新 Trellis 任务状态。
