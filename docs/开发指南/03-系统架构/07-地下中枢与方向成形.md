# 地下中枢与方向成形

## 定位

Underground Center 是 AgentArbor 的地下中枢。它把用户想象、土壤事实、约束、风险和证据整理成地上可接管的方向交接包。

地下中枢不属于地上执行组织。它不执行正式任务，不写长期资产，不生成 Growth Plan。

地下中枢采用地下辐射生长模型：中枢组织稳定存在，围绕用户想象向外生成临时探索根须集群，再把多方案、多证据、多约束和多风险收束为 `.agentarbor` 方向交接包。

## 输入与输出

输入包括：

- 用户原始目标、背景和补充信息。
- Soil 中的长期事实、Capability Asset、Path Bias、治理规则和失败模式。
- 初始约束、偏好、权限、成本、时间、安全和验收要求。
- 外部事实核验结果和内部证据。

输出是 `.agentarbor` 方向交接包：

```text
.agentarbor/
  direction.md
  options.json
  decision-record.md
  constraints.json
  soil-refs.json
  evidence-index.md
  risk-register.md
  open-questions.md
  escalation-rules.md
  growth-entry.json
  handoff.meta.json
```

## 中枢固定职责

地下中枢是固定低自由度集群，至少包含：

| 成员 | 职责 |
| --- | --- |
| Intent Core | 维护用户想象、目标原像、非目标和验收边界 |
| Growth Governor | 决定探索方向、探索深度、预算和停止条件 |
| Constraint Sentinel | 守住权限、成本、安全、技术和人工确认边界 |
| Evidence Ledger | 管理证据、来源、可信度、时间点和可追溯关系 |
| Convergence Judge | 比较多方案，决定保留、合并、淘汰或升级给用户 |
| Handoff Steward | 组装 `.agentarbor` 方向交接包 |

## 动态派生 Agent Fabric

地下中枢可以按任务动态派生临时 child agent。派生 agent 与固定核心 agent 使用同一套能力内核：`AgentLoop` 负责 observe / reason / act / guard / reflect / decide_next，`AgentTurnRuntime` 负责模型与工具多轮回合，`WorkspaceView` 和 `Mailbox` 提供隔离上下文，Guard 只守权限、预算、schema、hard constraint、脱敏和包结构。

派生运行时必须显式记录：

- `AgentSpec`：派生 agent 的协议、prompt ref、output contract、工具权限和预算。
- `DelegationDecision`：父层 agent 为什么派生、等待、继续、停止或请求收束。
- `ChildAgentRun`：子 agent 的运行状态、输入 refs、输出 refs、证据 refs、失败条件和不确定性。
- `AgentRunTree`：一次地下运行的父子关系和状态树。
- `ParentSynthesisResult`：父层对 child/rootlet 材料的综合结果。

`ChildAgentRun` 不等于长期 Agent 资产。它只是当前地下运行内的临时能力，不自动进入 Soil，不自动成为 Capability Asset，也不继承母体运行时权限、密钥、历史任务或注册表写权限。

## 辐射根须集群

地下中枢可以按任务需要生成临时探索根须集群。根须集群不是长期 agent，也不是地上执行组织；它们只为方向成形和养料供给服务。

| 根须集群 | 触发场景 | 交付物 |
| --- | --- | --- |
| Option Cluster | 存在多个可行方向 | 候选方向、取舍、适用条件 |
| Risk Cluster | 成本、失败、合规或维护风险不清 | 风险登记、失败模式、阻断项 |
| Asset Fit Cluster | 需要判断 Soil 资产是否适配 | Soil 引用、适配条件、不适用条件 |
| Evidence Cluster | 需要外部事实、环境事实或依赖事实 | EvidenceRef、FactRef、可信度 |
| Constraint Cluster | 方向需要映射为可执行约束 | Constraint / ConstraintRef 候选 |
| Counterfactual Cluster | 需要反驳方向或识别局部最优 | why-not、反例、替代方向 |

根须集群必须有明确输入、预算、输出和退场条件。它们不能直接制定 Growth Plan，不能调度地上生长，也不能把运行产物写入 Soil。

单个探索 agent 或单个根须集群的调研输出只能作为 `Observation`、`Evidence Candidate` 或 `Claim Candidate`。这些候选材料必须先进入地下中枢候选池，由负责该根须集群的汇总/裁决 agent，或 Convergence Judge / Handoff Steward 完成交叉校验、去重、来源归因和冲突裁决后，才能进入 `direction.md`、`options.json`、`decision-record.md`、`risk-register.md`、Nutrient Patch 或其他正式交接材料。

在 Agent Fabric 主线下，根须集群的局部产物必须先回到父层 `ParentSynthesisResult`，再进入 Convergence Judge 的保留 / 合并 / 淘汰 / 继续探索 / 询问用户 / 停止裁决。禁止单个 rootlet output、单个搜索结果或单个模型回复绕过父层综合进入 `.agentarbor`。

## 方向收束

地下中枢必须记录多个候选方向，而不是默认只产出单一结论。收束时必须说明：

- 保留哪个主方向。
- 哪些方向被合并。
- 哪些方向被淘汰。
- 哪些冲突需要用户确认。
- 哪些备选方向可以作为未来地上中枢的参考。
- 哪些候选观察、候选证据或候选主张被采纳、合并、驳回或保留为未知项，以及来源归因。

收束结果写入 `direction.md`、`options.json`、`decision-record.md` 和 `risk-register.md`。

## 生长预算

地下辐射生长必须受控。每次方向成形或养料供给都必须定义：

- 最大探索方向数。
- 每个方向最大探索深度。
- 最大外部事实查询数。
- 最大成本或时间预算。
- 是否允许询问用户。
- 是否允许触发更深一层探索。
- 停止条件。

预算耗尽后，地下中枢必须收束为 `.agentarbor`、Nutrient Patch、用户升级确认，或明确停止依据。系统不能因为持续探索而无限推迟方向交接。

## 用户确认循环

```text
User Imagination
  -> Underground Center
  -> Radial Exploration
  -> Cross-Critique
  -> Convergence
  -> Direction Draft
  -> User Review when needed
  -> .agentarbor Direction Handoff
```

用户只在必要处确认。当地下中枢已经拥有足够目标、约束、权限和证据时，应直接形成方向交接包；当目标冲突、权限不清、关键事实缺失、高风险动作或长期治理冲突出现时，必须升级给用户。

## 禁止事项

- 不生成 Growth Plan。
- 不调度地上生长组织。
- 不创建 Capability Asset。
- 不把方向交接包当长期事实源。
- 不把候选约束自动变成长期约束。
- 不把单个探索 agent 的原始调研输出直接写入正式方向或养料交接材料。
- 不绕过用户确认门执行高风险动作。
- 不把 Soil 内容复制进 `.agentarbor` 形成第二事实源。
