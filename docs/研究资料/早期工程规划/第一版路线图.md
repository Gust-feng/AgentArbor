# 第一版路线图

## 1. 当前阶段

当前处于开发前期规划阶段。

此阶段不是为了赶比赛，也不是为了堆功能，而是为了稳定 AgentArbor 自己的第一条生命闭环。

需要先稳定：

```text
项目灵魂
目标模型
AgentApp 契约
Workflow IR
验证闭环
谱系记录
最小可运行生成物
```

## 2. 第一版目标

第一版不证明 AgentArbor 无所不能。

第一版只证明：

> 一个自然语言目标可以被 AgentArbor 孕育成一个可运行、可验证、可追溯、可继续演化的 AgentApp 原型。

第一版的主流程：

```text
输入目标
  -> 生成 arbor.json
  -> 生成目标文档和阶段计划
  -> 生成 Workflow IR
  -> 生成 Agent 组织和能力声明
  -> 生成 AgentApp 工程
  -> 运行 sample task / 测试
  -> 失败则 Repair 或 Suspend
  -> 成功则写入日志和谱系
  -> 导出 AgentApp
```

## 3. 第一阶段：核心规格

目标：

* 定义 `arbor.json`。
* 定义 AgentApp 标准目录。
* 定义 Workflow IR。
* 定义 Agent Manifest。
* 定义 Capability / Permission 声明。
* 定义 ValidationResult。
* 定义 LineageRecord。

完成标准：

* 能用固定数据生成一个最小 AgentApp 目录。
* 目录中包含目标、计划、Agent、工作流、样例任务、验证结果和 README。
* 不接 AI 也能完成一次确定性生成。

## 4. 第二阶段：生成闭环

目标：

* 输入一段自然语言目标。
* 生成结构化目标和 `arbor.json`。
* 生成阶段计划和 Workflow IR。
* 生成 AgentApp 工程。
* 运行最小验证。

完成标准：

* 生成结果不是只有 Prompt。
* 生成结果能被用户打开、理解、运行和复现。
* 验证失败时能给出 Repair 或 Suspend 状态。

## 5. 第三阶段：第一个 AgentApp 示例

第一版可以选择一个示例，但示例不是项目本体。

候选：

* Code Review AgentApp
* Research AgentApp
* 论文阅读 AgentApp
* 文件整理 AgentApp

选择标准：

* 是否最能体现目标到 AgentApp 的生长过程。
* 是否能展示验证与修复。
* 是否能展示 Agent 组织和能力声明。
* 是否能展示日志、谱系和可继续演化。

不要因为外部展示方便就牺牲项目本质。

## 6. 第四阶段：验证、日志和谱系

目标：

* 实现最小 RuntimeValidator。
* 写入 `validation-result`。
* 生成运行日志。
* 生成 `docs/lineage.md`。
* 可选生成 Git commit。

完成标准：

* 每次生成都有可追踪结果。
* 用户能知道为什么生成这些文件。
* 用户能知道验证通过或失败的原因。
* 后续迭代可以读取旧状态继续。

## 7. 第五阶段：Workbench 原型

UI 不是主角，Workbench 是观察窗口。

第一版 UI 只需要展示：

```text
目标
arbor.json
阶段计划
Workflow IR
Agent 组织
能力声明
验证结果
日志
输出文件
导出入口
```

Workbench 不应该把系统变成固定表单或拖拽平台。它要让用户看到 AgentApp 如何生长。

## 8. 外部展示

比赛可以作为外部展示机会，但不是开发目的。

如果需要参赛，提交材料应从项目自身能力中自然抽取：

* 项目愿景
* AgentApp 生成演示
* 验证结果
* 日志和谱系
* 源代码和运行说明
* AI 工具使用说明

不能为了比赛修改项目灵魂。

## 9. 第一版明确不做

第一版不做：

* 完整插件市场。
* 完整 MCP broker。
* 企业级权限系统。
* 完整 Rebirth 自动执行。
* 大规模多 Agent 并发。
* 长期自治维护。
* 复杂拖拽式工作流编辑器。
* 生产级 EventBus / Outbox / DLQ / ReplayEngine。

这些可以进入长期路线，但不进入第一条生命闭环。
