# 工作台界面

## 界面目标

AgentArbor Desktop 是一个统一任务工作台。用户提交任务、绑定工作区上下文、查看 Agent 动作、处理确认并获得结果，不需要先理解 Ordinary、DeepRuntime、TaskBoard、Plan、provider 或 run tree。

默认 Ordinary Agent 必须能直接完成问答、文件工作、资料查证和工具任务。Multi-Agent 只有在用户显式选择“深入协作”时进入；不能用关键词、文本长度、文件数量或模型推断自动升级。

## 目标结构

```text
Workbench
  - 侧栏：新任务、统一历史、待确认、设置
  - 主区域：当前 Ordinary 或 Multi-Agent surface
  - 输入区：消息、附件、轻量选项、单次“深入协作”动作
  - 详情：上下文、工具事实、运行诊断和按需协作记录
```

Workbench Shell 只管理 surface 导航与展示组合。Ordinary surface 与 Multi-Agent surface 分别拥有 controller、SSE/poll cursor、busy、confirmation 和 view projection。切换 surface 或任务后，旧订阅回调必须失效，不能修改当前视图。

## 当前实现必须诚实

UI 收口尚未完成。当前版本仍然：

- 默认启动进入普通 Agent。
- 当前 release availability 暂时隐藏“Agent 集群（beta）”设置开关与侧栏按钮。
- `MultiAgentWorkspace` 与进入 controller 仍作为内部实现保留，但当前没有产品入口。
- 前端仍存在持久化全局 Agent mode 和 Ordinary/Deep 两套历史选择逻辑。
- Multi-Agent 使用 `/api/deep/*`、独立 conversation/run、SSE/poll 和 Deep read-model。

这些是迁移前的真实行为。目标文案不能声称侧栏按钮、全局 mode 或独立数据已经移除；实现也不能为了视觉统一把 Deep 状态改写成 Ordinary 状态。

## Surface 边界

### Ordinary surface

负责：

- 连续 conversation 和 transcript。
- 模型流式正文、工具活动和确认卡。
- 取消、恢复、失败和完成展示。
- Ordinary run view 与 Sub-Agent 内联运行视图。

Ordinary 前端只消费 Ordinary 后端 read-model，不从 raw provider response、工具文本或 Deep event 猜测状态。

### Multi-Agent surface

负责：

- intake、协作运行与终态续聊。
- child 调度、父层综合和纠正/停止/继续的用户可见投影。
- Deep conversation、run view、历史与协作记录。

默认主视觉保持接近自然对话：展示助手回复、动态协作进展、探索结果和综合结论。runId、API path、raw event type、完整 run tree 与长材料只进入按需详情。

### Shell

Shell 只保存当前选中的判别 surface 和展示 summary，例如：

```text
ActiveWorkbenchSurface = ordinary(conversationId) | multiAgent(conversationId/runId)
WorkbenchItemSummary = ordinary(...) | multiAgent(...)
```

这两个类型不进入后端业务状态或持久化。Shell 不共享 busy、confirmation、cursor、active run、conversation 或 controller。

## 统一历史

侧栏按 `updatedAt` 统一展示 Ordinary conversation 与 Multi-Agent task summary。每一项保留 `kind` 和原始 feature id，选择后交给对应 surface 恢复。

统一历史不意味着：

- 合并两类 store。
- 把 Deep conversation 转换成 Ordinary conversation。
- 新增 `/api/work`、`WorkAggregate` 或统一 Run API。
- 由前端拼接两类业务状态。

## 输入区

输入区默认常驻在主区域底部，首屏只保留消息、发送、附件和轻量选项。模型、思考强度、上下文和权限细节按需展开。

目标入口中的“深入协作”是本次提交的显式动作：

- 不写入持久化全局 AgentMode。
- 不改变下一次提交的默认 Ordinary 行为。
- beta 开关只控制动作是否可用。
- 一次提交只能进入一种 feature command，不能同时启动 Ordinary 与 Multi-Agent。

## 主区域与活动

主区域使用线性 Agent 工作流，而不是卡片墙或工程监控台。它可以展示：

- 自然语言回答与阶段性输出。
- 轻量活动轨迹与工具事实。
- 待确认、拒绝、补充指导和失败。
- 文件、网页、产物与 continuation 引用。
- Multi-Agent 的协作进展、探索材料和父层综合。

UI 摘要只能是附加展示字段，不能覆盖模型正文、工具输出、错误、stdout/stderr、文件内容或模型继续工作需要的 continuation。

## 设置与详情

设置页承接模型服务、基础能力、MCP、工作目录和确认边界。当前不展示 Agent 集群 beta 开关；设置页不作为工具启动器，也不通过全局规则替模型决定工具路径。

详情抽屉可以展示模型/工具 refs、Ordinary 运行活动、Deep run tree、child 摘要、parent synthesis、budget 和 permission。Sub-Agent 只作为父 Ordinary 的 AgentTool 活动展示，不从已删除的专用 trace 重建详情。不得展示 secret、raw provider HTTP、未声明可见的内部推理或用前端猜测出的业务事实。

## 思考与失败展示

只有 provider 明确返回可展示 reasoning summary/content 时，界面才展示该阶段；不能伪造思考链。`approval_required`、`out_of_fuel`、`context_overflow`、取消、provider error 和 runtime error 必须保留各自语义，不能为了统一 UI 都改成 completed 或普通失败文案。

## 验收

- 默认提交走 Ordinary。
- “深入协作”只影响本次提交。
- 两类历史按更新时间排序且保留判别 identity。
- 切换 surface 后旧 SSE/poll 回调不能污染当前 surface。
- Ordinary 与 Multi-Agent 分别消费自己的后端 read-model。
- UI 摘要不替代模型或工具事实。
- 当前 beta 侧栏入口已由 release availability 隐藏，并由“旧偏好不能重新开启入口、启动不请求 Deep 历史”的行为测试保护；内部 surface 的正式收口仍需上述切换隔离测试。
