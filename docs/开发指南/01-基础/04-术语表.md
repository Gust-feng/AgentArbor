# 术语表

## Soil（土壤）

土壤是固定资产与治理层，保存经过治理的能力资产、历史运行证据、可检索资料、约束、权限策略、失败模式和长期偏好。临时运行记录不能直接进入土壤。

## Imagination（想象）

想象是用户提示词中的原始目标图景。它可能含混、跳跃、缺少边界和验证条件，因此不能直接进入正式运行。

## Seed Cluster（前置成像集群）

Seed Cluster 是启动门。它负责理解、拆解、反驳、最小化搜索、风险识别和用户确认，把 Imagination 转化为 Seed Packet。它不属于地下 Root System，也不属于地上执行组织。

## Seed Packet（种子包）

Seed Packet 是前置成像输出，建议采用文件夹形态。它记录用户原始想象、目标成像、非目标、假设、最小化搜索、反驳风险、可选方向、用户决策和交给 Root System 的 handoff。

## User Approval Gate（用户确认门）

用户确认门决定 Seed Packet 是否可以种入 Soil。未经确认的 Seed Packet 不能启动 Root System。

## Root Cluster（根系探索集群）

Root Cluster 是 Root System 内部的动态探索集群，不再是完整根系系统的同义词。它围绕目标向多个方向探索土壤中的资产、相似运行、外部事实、未知项、约束、风险和可选路径，并把证据交给 Root Crown Cluster 汇总。Root Cluster 不是最终计划者，也不是执行层。

## Root System（根系系统）

Root System 是持续地下生命系统。它包含 Initial Rooting、Lateral Rooting 和 Deep Rooting，不会在生成第一版 Root Brief 后停止。

## Root Continuity（根系连续性）

根系连续性表示 Root System 在运行期持续存在。地上组织遇到问题时，可以通过 Root Callback 请求地下组织继续补探。

## Root Callback（根系回调）

Root Callback 是地上组织回调地下组织的机制。它由 Core Control Cluster、Branch Agent 或 Flower Cluster 发起，用于信息不足、验证失败、Path Bias 失效、目标变化或关键假设被证伪等场景。

## Lateral Rooting（侧根扩展）

侧根扩展是局部补探模式，用于某个分支、某个工具、某个数据源或某个验证失败原因不清楚时。

## Deep Rooting（深根重探）

深根重探是整体重估模式，用于 Growth Plan 的核心前提可能错误时。它可能导致 Growth Plan Revision、分叉、回退或停止。

## Root Brief（根系简报）

Root Brief 是根系探索输出，不是最终执行计划。它必须版本化，至少包含目标理解、可复用资产、相似运行、Path Bias、未知项、约束、风险、可选方向和推荐方向。

## Core Control Cluster（核心控制集群）

Core Control Cluster 是主干固定核心集群。它读取 Root Brief，决定是否采用 Path Bias，选择方向，制定和修订 Growth Plan，并在必要时触发 Root Callback。

## Trunk Synthesis（主干综合）

Trunk Synthesis 是 Core Control Cluster 中的主综合职责。它可以由最强模型承担，但不能成为单点万能 agent，必须受计划反审查、风险治理和记录职责制衡。

## Growth Plan（生长计划）

Growth Plan 是执行前计划入口。它至少包含目标、选定方向、Workflow IR、运行组织形态、任务列表、复用策略和沉淀策略。

## Growth Plan Revision（生长计划修订）

Growth Plan Revision 是基于新 Root Brief 版本修订计划的机制。它必须记录修订原因、影响范围、继续、回退、分叉或停止决策。

## Workflow IR（工作流中间表示）

Workflow IR 用于表达任务图、依赖、状态、输入输出、恢复点、失败处理和验证门。它由 Growth Plan 派生，不能绕过 Core Control Cluster。

## Branch / Leaf Runtime（枝叶运行组织）

Branch / Leaf Runtime 是按 Growth Plan 和 Workflow IR 组建的执行组织。它包含枝层协调、叶层执行和花层验证协作，但所有消息必须经过 MessageBus、Router 和状态机。

## Run Memory（运行记忆）

Run Memory 是单次运行后的经验摘要，来自 EventLog、Artifact、Verification 和 Acceptance 结果。它用于帮助下一次相似任务理解上一轮实际发生了什么。

## Experience Candidate（经验候选）

Experience Candidate 是从 Run Memory 中提取的可复用经验候选。它不能直接写入土壤，必须经过验证、去重、适用范围确认和治理门。

## Capability Asset（能力资产）

Capability Asset 是经过治理后进入土壤的正式能力资产。它必须有来源、输入输出契约、权限边界、版本、验证记录、适用范围和退役路径。

## Path Bias（路径倾向）

Path Bias 是历史运行对新任务的路径牵引。第二次遇到相似任务时，系统不会强行复刻上一次流程，但会天然倾向于参考上一次有效路径。Root System 负责发现，Core Control Cluster 负责决定是否采用。

## Ring Memory（年轮记忆）

Ring Memory 是 EventLog、Run Memory 和 Experience Candidate 的聚合视图，用于观察系统如何在多次运行中生长。它不是新的平行事实源。

## AgentApp（智能体应用）

围绕目标形成的可运行智能体应用。它包含目标、运行时集群、能力声明、工作流、配置、工程目录、测试、文档和运行记录。

## Fruit（果实）

果实是成熟能力的可交付形态，可以是可复用模板、AgentApp、工作流包、工具组合或可脱离子 agent。果实必须经过治理门。

## Governance Gate（治理门）

治理门决定 Experience Candidate 是否可以成为 Capability Asset，Fruit 是否可以脱离母体运行，以及过时资产是否需要修剪或退役。

## Adapter（适配器）

适配器连接外部平台、模型、工具或协议。适配器负责格式转换，不负责定义 AgentArbor 核心产品语义。
