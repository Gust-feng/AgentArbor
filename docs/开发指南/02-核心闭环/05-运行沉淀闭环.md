# 运行沉淀闭环

## 定位

运行沉淀闭环回答一个核心问题：AgentArbor 完成一次任务后，系统到底收获了什么。

沉淀不是最后写一段总结，也不是把所有输出直接保存为长期资产。沉淀必须从可回放事件和验证证据开始，逐级形成 Run Memory、Experience Candidate、Path Bias 和 Capability Asset。

## 基本链路

```text
EventLog / Artifact / Verification / Acceptance
  -> Fruits
  -> Run Memory
  -> Experience Candidate
  -> Path Bias
  -> Governance Gate
  -> Capability Asset / Fruit / Retire
  -> Soil / Ring Memory
```

## Run Memory

Run Memory 是单次运行后的经验摘要。它必须来自真实运行证据，不能来自事后想象。

最小内容：

- 来源目标和任务。
- 来源 Direction Handoff 与 Growth Plan。
- 实际执行路径。
- 参与的地上生长组织、验证组织和关键 agent。
- 使用的能力和资产。
- 产物引用。
- 验证结果。
- 偏离 Growth Plan 的原因。
- Nutrient Request、Nutrient Patch 和 Growth Plan Revision。
- 成功模式、失败模式和风险。
- 对下一次相似任务有价值的观察。

Run Memory 不等于长期记忆。它只是一次运行的结构化经验摘要。

## Experience Candidate

Experience Candidate 是从 Run Memory 中提取出的可复用经验候选。

它必须回答：

- 哪类目标可复用。
- 复用前需要满足哪些前提。
- 哪些步骤、能力、验证门值得保留。
- 哪些失败模式必须避免。
- 哪些场景不能复用。
- 置信度来自什么证据。

Experience Candidate 不能直接进入土壤。它需要经过验证、去重、适用范围确认和治理门。

## Path Bias

Path Bias 是 Experience Candidate 对下一次相似任务的路径牵引。它不强制复刻历史路径，而是让 Underground Center 在探索时优先看见已验证路径，让 Aboveground Center 在决策时显式判断是否采用。

Path Bias 必须保留偏离空间：当新的目标、约束、权限、上下文或验证要求与历史路径冲突时，Growth Plan 必须允许选择新路径，并把偏离原因写入新的 Run Memory。

## Capability Asset

Capability Asset 是经过治理后进入土壤的正式资产。它可以是工作流片段、验证规则、工具适配、提示模板、AgentApp 模板、固定内部 agent 或可脱离子 agent。

晋升要求：

- 有真实运行来源。
- 有可复现输入输出。
- 有验证证据。
- 有权限边界。
- 有适用范围和不适用条件。
- 有版本和退役路径。

## 硬规则

- 凡运行必留 EventLog。
- 凡交付必有 Verification 或 Acceptance 结果。
- 凡沉淀必先形成 Run Memory。
- 凡复用必标记 Experience Candidate。
- 凡入土必经过 Governance Gate。
- 凡成为果实必有脱离边界和撤回路径。
- 凡触发 Nutrient Request 必须记录原因、输入证据、Nutrient Patch、输出 Direction Handoff 版本或无需补充证据。
