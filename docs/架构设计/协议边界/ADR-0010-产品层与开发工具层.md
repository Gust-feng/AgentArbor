# ADR-0010: 产品运行层与开发工具层分离

## Status

Accepted, amended by [ADR-0022](../产品架构/ADR-0022-AgentArbor桌面通用Agent与双运行时架构.md) and [ADR-0028](../产品架构/ADR-0028-AgentArbor统一Workbench与功能模块化单体架构.md).

## Context

AgentArbor 同时存在两类工作：

- 开发 AgentArbor 仓库本身。
- 定义未来 AgentArbor 产品 runtime 应该如何识别、生成、编排和治理 agent。

前一类工作使用 Codex 官方兼容能力：`AGENTS.md`、`.agents/skills/`、`.codex/agents/*.toml` 和 `docs/` 的开发记录。后一类工作使用 AgentArbor 自己的产品协议。当前产品边界由 ADR-0028 定义为单一 Workbench：Ordinary Agent 默认工作，Multi-Agent 是显式功能，Sub-Agent 是 Ordinary 的工具；长期 Soil、Plan、Aboveground 和 Governance 能力按真实需求出生，不是每次请求必经链路。

开发工具层如果直接承载产品层 agent、workflow、memory 或 schema，会让产品规格被工具能力反向塑形。`.agentarbor` 在当前口径下只是 Plan Package 的实现/存储形态或目录名；最终资产经 Fruits 和 Governance Pipeline 进入 Global Soil。

## Decision

AgentArbor 固定区分两层：

1. **开发工具层**：用于开发当前仓库。
   - `AGENTS.md` 保存 AI 执行硬规则。
   - `docs/` 保存人类可读的开发指南、任务看板、研究资料和架构设计。
   - `.agents/skills/` 保存官方 Agent Skills / Codex repo skills。
   - `.codex/agents/*.toml` 保存开发 AgentArbor 时使用的 Codex custom subagents。
2. **产品运行层 / Plan Package 层**：用于定义未来 AgentArbor 自身。
   - `.agentarbor/**` 保存 Plan Package 材料。
   - `.agentarbor/**` 只引用 Global Soil 中的固定资产，不复制资产本体。
   - `.agentarbor/**` 不是产品 agent source-of-truth、最终资产仓库或 Codex 官方索引。
   - 可脱离 agent、能力包和经验候选先进入 Fruits，再经 Governance Pipeline 才能沉淀到 Global Soil。

当同一能力同时出现在两层时，必须按用途区分：

- Codex 开发工具层可以适配、验证、预演产品能力。
- AgentArbor 产品运行层可以吸收开发过程中被验证的结构性知识。
- 开发工具层不能替代产品运行层。
- 产品运行层不能被当前 Codex 工具能力压缩。

## Consequences

- `.codex/agents/*.toml` 是开发 AgentArbor 的 Codex 标准配置，但不是 AgentArbor 产品 agent 源数据。
- `.agentarbor` 必须从当前产品 ADR 和 Plan Package 契约出发，不按当前开发工具的可用角色做删减。
- 当前开发 AgentArbor 本体的人类可读入口是 `docs/开发指南/`；研究和架构材料分别保存在 `docs/研究资料/` 与 `docs/架构设计/`。`.agentarbor/` 是 Plan Package 存储形态，不承担当前文档工作区职责。
- 当前产品架构以 `docs/架构设计/产品架构/ADR-0028-AgentArbor统一Workbench与功能模块化单体架构.md` 为正式事实源。
- 后续新增 agent 时，先判断问题属于开发工具适配输出、运行期候选果实还是治理后的 Soil 能力资产，再选择 `.codex/agents/`、Fruits 或 Soil。
- 任何文档、skill 或 ADR 如果把两层混用，必须标记为过时或用新的 ADR 修正。
