# 最小实现边界

## 第一阶段目标

第一阶段应证明 AgentArbor 可以从用户目标孕育一个最小 AgentApp，并完成验证和谱系记录。

同时，第一阶段必须证明系统不是一次性生成器：运行结束后要形成 Run Memory，并让下一次相似任务能读取 Path Bias。

## 最小路径

```text
Soil
  -> Underground Center 形成 Direction Handoff
  -> .agentarbor 方向交接包
  -> Aboveground Center 形成 Growth Plan
  -> 生成 Workflow IR
  -> Aboveground Growth 执行样例任务
  -> Verification
  -> Fruits
  -> Governance
  -> Run Memory / Experience Candidate / Path Bias
  -> Soil
```

## 第一阶段骨架

第一阶段不要从“写很多智能体”开始。必须先让消息、状态、注册、产物和事件跑通。

最小实现顺序：

```text
1. ArborMessage
2. Constraint / ConstraintRef
3. DirectionHandoff
4. AgentManifest
5. TaskState
6. GrowthPlan
7. WorkflowIR
8. NutrientRequest / NutrientPatch
9. GrowthPlanRevision
10. BaseAgent
11. InMemoryMessageBus
12. InMemoryAgentRegistry
13. InMemoryEventLog
14. InMemoryArtifactStore
15. SimpleRouter
16. 最小 demo
```

最小 demo 必须证明：

```text
用户目标
  -> goal.received
  -> UndergroundAnalyzer 生成 direction_handoff.completed
  -> .agentarbor 方向交接包可读取
  -> AbovegroundPlanner 生成 growth_plan.completed
  -> Workflow IR 生成 task.created
  -> Router 根据 requiredCapabilities 分配 WorkerAgent
  -> WorkerAgent 生成 artifact.produced
  -> Verification 运行
  -> 可选 nutrient_request.requested / nutrient_patch.supplied / growth_plan.revised
  -> 生成 Fruit 候选
  -> Governance 判断能否入土
  -> 生成 RunMemory
  -> 生成 ExperienceCandidate
  -> 生成 PathBias
  -> EventLog 可回放全过程
```

## 暂不做

第一阶段不做：

- A2A Adapter。
- MCP Adapter。
- AG-UI Adapter。
- 完整模型调用；后续真实模型接入必须先经过智能通道，不得直接散落在领域模块。
- 完整插件市场。
- 企业多租户。
- 大规模 agent 自治网络。
- 完全自动自我修改。
- 无人值守高风险命令执行。
- 数据库持久化。
- 复杂可视化编排器。

## 必须保留的扩展口

即使第一阶段很小，也必须保留：

- 内部消息契约。
- 目标状态机。
- DirectionHandoff。
- `.agentarbor` 方向交接包读写边界。
- GrowthPlan。
- Workflow IR。
- NutrientRequest。
- NutrientPatch。
- GrowthPlanRevision。
- AgentManifest。
- Constraint / ConstraintRef。
- RunMemory。
- ExperienceCandidate。
- PathBias。
- MessageBus。
- AgentRegistry。
- ArtifactStore。
- EventLog。
- 权限声明。
- 验证门。
- 约束分发与约束验证结果。
- 谱系记录。
- 平台适配层。
- 能力晋升的治理门。

## 最小验收

第一阶段通过条件：

- 用户目标能进入系统。
- 至少两个内部智能体参与。
- 智能体只能通过 MessageBus 协作，不能绕过总线互相调用。
- 任务状态发生真实流转。
- 至少产生一个 Artifact。
- 至少形成一个 Fruit 候选。
- 至少写入完整 EventLog。
- 至少执行一次 Verification。
- 至少证明 hard constraint 可以阻断或要求确认，soft constraint 可以记录偏离，preference 只能影响方案排序。
- Nutrient Request / Patch 的触发条件、消息和结果结构已经保留，哪怕最小 demo 只走不触发路径。
- 至少写入一次 RunMemory。
- 至少生成一个 ExperienceCandidate。
- 至少形成一个可供下一次相似任务读取的 PathBias。
- EventLog 能打印或展示完整链路。
