# 模型供应商资料卡

## 1. 目标

模型供应商资料卡用于沉淀不同 AI 厂商和兼容协议的接入边界。

AgentArbor 不应在核心代码中直接绑定某个厂商 API，而应通过 `ModelProvider` 和 `ProtocolAdapter` 读取供应商资产。

## 2. 第一版优先资产

### model.openai.responses

```text
类别：ModelProvider
来源：OpenAI
接口：Responses API
优先级：P0
风险：Medium
密钥：OPENAI_API_KEY
来源链接：https://developers.openai.com/api/docs/guides/tools
当前动作：建立 ModelProfile + ToolCallNormalizer
```

AgentArbor 抽象建议：

* 作为第一版云端模型主画像。
* 统一沉淀工具调用、结构化输出、模型响应、错误分类和流式事件映射。
* 不允许业务模块直接拼接供应商请求体。

待核验：

* 当前 Responses API 的工具调用字段。
* Structured output 的严格程度和失败返回。
* Streaming 中 tool call 增量事件格式。
* 远程 MCP 或内置工具的授权边界。

### model.openai.chat_compatible

```text
类别：ModelProvider
来源：OpenAI-compatible ecosystem
接口：Chat Completions
优先级：P0
风险：Medium
密钥：provider API key
来源链接：https://developers.openai.com/api/docs/guides/function-calling
当前动作：做兼容性测试矩阵
```

AgentArbor 抽象建议：

* 作为 DeepSeek、Ollama、vLLM、部分代理网关的兼容入口。
* 必须用兼容性矩阵记录每个供应商对 tool calling、streaming、JSON schema 的支持差异。
* 默认不假设“OpenAI-compatible”就完全兼容。

待核验：

* 每个兼容供应商的 tool call 字段差异。
* 错误码和重试语义。
* 是否支持严格 JSON schema。
* 是否支持本地无密钥运行。

## 3. P1 候选资产

```text
model.anthropic.messages
model.google.gemini
model.deepseek.api
model.qwen.dashscope
model.gateway.litellm
```

第一版可以先保留为候选，不进入默认主链路。

准入条件：

* 完成 ProviderProfile。
* 完成 ToolCallNormalizer。
* 完成至少一个 ReplayProvider 样例。
* 完成错误分类和限流策略。
* 完成最小 live eval。

## 4. 统一 ProviderProfile 草案

```yaml
schema_version: agentarbor.provider-profile/v0.1
id: model.openai.responses
status: draft
provider: OpenAI
protocol: responses
auth:
  type: api_key
  env: OPENAI_API_KEY
capabilities:
  streaming: unknown
  tool_calling: unknown
  structured_output: unknown
  vision: unknown
  embedding: unknown
normalizers:
  tool_call: protocol.openai.responses
  structured_output: protocol.openai.structured_output
testing:
  default: replay
  live_requires_explicit_approval: true
```

## 5. 设计底线

* 模型供应商只通过 Adapter 接入。
* 默认测试不依赖真实密钥。
* 外部模型调用必须可记录成本、错误和重试。
* AgentApp 生成时必须快照使用的 ProviderProfile 版本。
