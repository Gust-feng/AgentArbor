# 干层（Core Control Cluster）- 主干固定核心

## 职责

干层是 Core Control Cluster。它承接 Root Brief，汇总根系探索结果，制定 Growth Plan，并把计划转化为 Workflow IR。它也负责在运行期根据 Root Callback 输出修订 Growth Plan。

干层不是执行层，也不是单个万能 agent。它应是低自由度固定核心集群，用强模型承担综合判断，同时用反驳、计划审查、验证门和版本记录抵抗单点认知失败。

## 核心职责

| 角色 | 职责 |
| --- | --- |
| Trunk Synthesis | 汇总 Root Brief、Path Bias、土壤资产和约束 |
| Planner | 选择方向、制定 Growth Plan、生成 Workflow IR |
| Critic | 对 Growth Plan 做对抗性评审，检查局部最优、权限风险和验证缺口 |
| Revision Controller | 处理 Root Callback 后的 Growth Plan Revision |
| Sedimentation Planner | 决定运行结束后哪些内容进入 Run Memory、Experience Candidate 或治理门 |

这些是职责，不要求第一阶段都拆成独立长期 agent。

## Growth Plan 内容

Growth Plan 至少包含：

- 目标摘要。
- Seed Packet 引用。
- Root Brief 版本引用。
- 选定方向。
- Path Bias 决策。
- Workflow IR。
- 运行组织形态。
- 任务列表。
- 复用策略。
- 沉淀策略。
- 验证和验收门。
- Root Callback 触发条件。

## Growth Plan Revision

当 Root System 输出新的 Root Brief 版本，Core Control Cluster 必须判断：

- 继续：计划仍然有效，只需补充证据。
- 回退：现有执行路径需要回滚到某个稳定点。
- 分叉：多个方向都成立，需要限定预算做并行探索。
- 停止：核心前提不成立，继续执行会制造债务或风险。

Revision 必须记录原因、影响范围、变更任务、引用的 Root Brief 版本和最终决策。

## 工作流程

```text
1. 接收 Root Brief vN
2. 判断证据是否足够
3. 选择方向
4. 判断 Path Bias
5. 制定或修订 Growth Plan
6. 生成 Workflow IR
7. 交给 Branch System
8. 监听 Root Callback、Verification 和 Run Memory 信号
```

## 禁止事项

- 不绕过 Root Brief 直接生成计划。
- 不让 Path Bias 机械复刻历史流程。
- 不把计划写成不可验证的自然语言列表。
- 不直接执行叶层任务。
- 不用单个强模型的判断替代证据、反驳和验证门。
