## 未来方向

这些条目是方向提示，不是已启动任务。只有用户确认并创建或启动 Trellis 任务后，才进入“当前任务”。

| 方向 | 为什么重要 | 启动条件 |
| --- | --- | --- |
| repo-root `.agentarbor` 运行资产生命周期 | V0.2 只证明内存 store 和显式临时目录文件系统 store，不创建真实 repo-root `.agentarbor/` 资产；后续仍需定义真实出生条件、提交策略、读写权限和治理边界。 | 方向交接包契约稳定后，用户确认允许创建真实运行资产，并明确哪些内容进入提交基线。 |
| 地下与地上生长机制深化 | 当前架构已确立静态概念树，后续需要单独分析地下如何长出方向、地上如何长出执行组织和果实，避免把动态机制混进本轮架构迁移。 | 当前原生概念树架构提交后，用户确认进入动态生长机制专题。 |
| Nutrient Request 与 Growth Plan Revision | 地上执行遇到养料不足或验证失败时，需要能向地下中枢请求养料并修订计划。 | 设计最小 runtime 状态机或 Workflow IR 时。 |
| Constraint / ConstraintRef 深化 | 首个最小运行内核会证明 hard constraint 阻断或确认门；后续还需要把软约束偏离、preference 排序和治理沉淀做成更完整机制。 | 最小内存闭环通过后，用户确认进入约束执行与验证细化。 |
| Fruit 与 Capability Asset 治理 | 子 agent 是否能脱离母体，取决于成熟、验证、权限收敛和谱系记录。 | 开始定义能力资产注册、导出、退役和权限边界。 |
