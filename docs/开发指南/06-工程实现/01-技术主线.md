# 技术主线

## 默认方向

当前默认实现路线是桌面基础 Agent 与基础设施优先。普通桌面会话先稳定消息输入、连续对话、模型工具循环、工具安全元数据、Windows 写入/执行确认、事件重放、RuntimeDatabase 安全 read-model、Skills 元数据发现和用户友好工作台；地下/地上组织、Plan Package、Governance、Routines、可见 deep 入口和多 agent 团队模式只作为未来能力边界保留，不进入默认首屏、普通会话文案或本轮后端改动。

实现以 TypeScript 自研架构为主：

- 语言：TypeScript。
- 本地服务：Node.js。
- 持久化：本地嵌入式数据库优先。
- 前端：TypeScript Web 技术栈。
- 测试：单元测试、集成测试、任务样例测试、安全边界测试。
- 外部系统：通过 adapter 接入。

## 实现原则

- 先稳定基础 Agent 运行闭环，再考虑是否重启地下/地上高级组织。
- 普通模式和未来深入模式共享基础设施，但普通模式不得自动升级、调用或展示 Underground / child-agent / Plan 组织语义。
- 当前不做可见 deep 入口，不主动改动 deep 后端；未来 deep 项目必须由用户重新明确启动。
- 先保证权限、确认、验证和安全投影，再扩展自动化。
- 先让 ToolCenter、RunEvent、RuntimeDatabase 和 Skills 契约成为共享基础设施，再做 MCP 管理器、Routines 或团队 agent。
- 普通 HTTP/SSE/面板/会话投影永不暴露 raw prompt、raw provider response、raw tool output、stdout/stderr、文件正文、secret、token 或未经验证模型输出。
- 先证明可恢复、可审计、可取消、可确认的桌面 Agent 运行，再谈 Governance 回流和能力资产出生。

## 不提前引入

除非进入明确实现阶段，否则不引入包管理器、构建系统、运行时代码或测试框架。
