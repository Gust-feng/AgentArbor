# 兼容路径隔离

## 为什么要隔离

AgentArbor 当前代码中仍保留了一些具有明确 owner 的 Legacy Underground 运行语义和未来 deep 能力基础。它们可以服务显式功能或后续迁移，但“旧本地记录可能存在”本身不是长期保留 Ordinary 兼容入口的理由。

但它们也不能污染默认普通 Agent。默认普通 `agent` 的主线必须保持朴素：单一主循环、后端 run facts、后端工具边界、前端 read-model 展示。

## 当前可保留的显式 Legacy 形态

以下内容可以存在，但只能由 Legacy Underground / deep 明确拥有：

- `work_session_canvas`：历史 work session 记录形态。
- `underground_deep_canvas`：显式 deep 或历史 deep replay 形态。
- `direction_handoff.*`：deep / handoff 历史或显式路径事件。
- `agent.child.*`、`agent.parent_synthesis.*`：未来 Agent 集群和历史 deep replay 事件。
- `work_session_*` model purpose：Legacy Underground 的显式运行 purpose，不能作为默认普通 AgentDefinition 的执行 purpose。
- 已删除 `desktop_intent_gate` / `desktop.intent_gate.v1`：当前没有生产者，旧开发期 transcript/model call 不再兼容读取；默认入口不得重新引入 intent gate 模型路由器，也不能用工程规则自动把普通请求升级为 work session / deep。

这些路径必须被命名和测试为显式 Legacy / deep 路径。新增普通入口、普通 UI、普通 run view 和普通持久化恢复不应依赖它们。

## 已清理的 Ordinary 兼容入口

- `/api/basic-agent/runs/:runId/work-session` 及其 `workSession` 响应别名没有生产客户端，已经删除；普通调用方统一读取 `/api/basic-agent/runs/:runId/view` 或 conversation `currentRun` 中的 `workView`。
- `desktop_chat` purpose、`desktop.chat.*` 输出契约和 `createDesktopChatCanvas` read-model alias 没有当前 producer，已经从类型、模型流、回放与 fake provider 中删除。
- 以上入口不提供 deprecated alias、旧 snapshot 分支或本地数据迁移。开发期旧记录不满足当前契约时应清理本地 runtime 目录。

## 默认普通路径禁止事项

默认普通 Agent 路径不得：

- 重新引入 `/work-session` 或 `workSession` alias 恢复普通 run 视图。
- 从 `workSession` alias 拼装当前工作视图。
- 在默认 UI 首屏展示 deep、rootlet、handoff、convergence、child agent 等内部或未来态术语。
- 把 `work_session_*` purpose 的模型输出混入普通 `desktop_agent` 的 live stream。
- 重新引入 intent gate 模型调用、prompt 或 fake provider 输出，让工程或模型路由器替普通 Agent 判断是否升级到旧 work session。
- 用旧 canvas、旧 job 字段或当前配置覆盖 run 创建时冻结的 `AgentDefinition`、`capabilitySnapshot`、`capabilityResolution`、`informationAccess`。
- 在切换到另一个 run 且后端未返回能力事实时，继续展示上一轮 run 的工具能力或 AgentDefinition 信息。

## Ordinary 不保留旧记录回退

当前项目处于 `0.1.x` 开发期，Ordinary snapshot 必须完整保存 run 出生事实与可重放事实。缺少 `capabilitySnapshot`、`informationAccess`、`agentDefinitionRef`，或工具事件缺少当前事实 payload 的旧记录直接视为失效数据；读取接口返回稳定的 snapshot 失效错误，用户可以清理本地 runtime 目录后重新运行。恢复只读取 canonical `run`、runtime `events`、`confirmations` 和存在时的 `contextLedger`；`BasicAgentRun`、Panel stream events、WorkView 和 Canvas 都从这些事实投影，不另行持久化为恢复缓存。

禁止用以下方式“修复”失效记录：

- 用 Host 当前模型、工具、Skill、MCP、工作区或信息访问配置覆盖历史 run。
- 从当前 pending confirmation、model call、runtime event 或 UI 状态反推并补造缺失的 Ordinary 事件和终态。
- 用旧 `responseModel`、旧 canvas、旧 alias 或上一帧其他 run 的能力事实拼出新 read-model。
- 双读新旧字段、在写入时双写旧格式，或以 deprecated facade 延长内部调用入口。

显式 Legacy Underground 仍由其 owning feature 读取自己的历史数据；这不是 Ordinary 的兼容入口，也不能成为新代码继续生产旧格式的理由。

## 后续新增代码的判断标准

新增代码如果满足任一条件，就不应放入默认普通路径：

- 需要解释 deep、handoff、rootlet、child agent 或 Plan 才能说明它的职责。
- 需要从历史 canvas 结构反推普通 run 状态。
- 需要由前端判断工具可见性、AgentDefinition 或完成语义。
- 需要用当前全局配置修正已经创建的 run facts。

如果确实需要保留，应放在清楚的 compat / legacy / explicit deep 边界里，并补测试证明默认普通路径不会调用它。
