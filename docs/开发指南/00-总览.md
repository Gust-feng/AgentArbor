# 总览

## 本指南解决什么问题

本指南给 AgentArbor 后续实现提供统一口径。它回答四个问题：

1. AgentArbor 到底是什么。
2. AgentArbor 要用什么核心闭环证明价值。
3. 系统边界、数据契约、Agent 生命周期和平台适配如何分层。
4. 第一阶段实现边界是什么，什么算通过验收。

## 产品主线

AgentArbor 的产品主线是：

```text
Soil
  -> Underground Center
  -> .agentarbor
  -> Aboveground Center
  -> Fruits
  -> Governance
  -> Soil
```

这条主线采用原生概念树语义：土壤承载固定事实、长期资产、治理规则和历史证据；地下中枢把用户问题经过多方向探索和交叉裁决成形为 `.agentarbor` 方向交接包；地上中枢把方向交接包转成 Growth Plan、Workflow IR、执行组织、验证门和修订机制；果实在治理后才允许回流土壤。

当前产品架构事实源是 [ADR-0018-AgentArbor原生概念树架构](../架构设计/产品架构/ADR-0018-AgentArbor原生概念树架构.md)。开发指南只展开该 ADR 的当前实现口径。

## 当前稳定结论

- AgentArbor 面向的是问题的理解、探索、解决与经验积累。AgentApp 只是 Fruits 中一种可选形态，不是产品主线。
- 本地优先是底座，不是全部产品定义。
- Soil 是固定资产与治理土壤，保存长期事实、能力资产、历史证据、失败模式、治理规则和稳定约束。
- Underground Center 是地下中枢，负责需求成形、用户确认、约束提取、证据探索、方向综合和运行期养料供给。
- `.agentarbor` 是方向交接包，负责从地下中枢向地上中枢传递问题解决方案、ConstraintRef、Soil 引用、证据索引、升级规则和 Growth Entry。
- Aboveground Center 是地上中枢，负责 Growth Plan、Workflow IR、Context Topology、执行组织、验证门和计划修订。
- Fruits 是交付物、运行报告、能力包、Experience Candidate 和 Run Memory 的候选区。AgentApp 只在极少数需要长期独立调度运行的场景下作为 Fruits 的一种形态产出。Fruits 不是 Soil。
- Governance 是果实入土前的治理门，负责评估、权限、版本、谱系、导出和退役。
- Run Memory 是单次运行后的经验摘要，Experience Candidate 是可复用候选，Capability Asset 才是进入 Soil 的正式资产。
- Path Bias 是后续相似任务对已验证路径的自然倾向，不是流程复刻。
- Path Bias 只能影响偏好和方案排序，不能覆盖 hard constraint。
- 智能通道是模型能力的横切接入层。Underground Center、Aboveground Center、Verification、Governance 和未来工作台都只能通过智能通道调用模型；provider adapter 不能反向决定 AgentArbor 产品语义。
- 子 agent 果实是能力积累到一定程度的自然产物，不是每轮任务的目标。它必须经过治理，携带最小权限、明确契约和退役路径才能脱离母体。
- `.agentarbor/` 是未来运行时方向交接包层，只在契约稳定并有真实出生依据时增量创建。
- `.agents/`、`.codex/`、`.opencode/` 是当前开发和平台适配层，不能反向决定产品语义。
