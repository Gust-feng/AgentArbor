# ADR-0016: 需求成形与持续养料供给架构

## 状态

已采纳为历史语义材料，当前产品事实源为 [ADR-0022](ADR-0022-AgentArbor桌面通用Agent与双运行时架构.md)。本 ADR 保存需求成形与持续养料供给的结构原则。

## 背景

用户的原始想法通常不是可执行任务。它可能缺少目标边界、权限、成本、安全约束、验收条件、外部事实和可复用资产适配判断。如果把它直接交给地上执行组织，系统很容易在局部执行上看似正确，却在方向、权限或长期治理上偏离。

同时，地下组织不能只在任务启动前工作一次。地上生长在执行、验证或治理中会持续暴露养料缺口：证据不足、Soil 资产不适配、外部事实变化、上下文切片不足、能力线索缺失或关键假设被证伪。此时地上组织应通过 Nutrient Request 向地下中枢请求养料，而不是自行创建方向探索集群。

## 决策

AgentArbor 采用以下需求成形与持续养料供给主线：

```text
User Imagination
  -> Underground Center
  -> Direction Handoff Package (.agentarbor)
  -> Aboveground Center
  -> Growth Plan
  -> Workflow IR
  -> Aboveground Growth / Verification / Fruits
  -> Nutrient Request / Nutrient Patch
  -> Growth Plan Revision
  -> Run Memory / Governance / Soil
```

核心定义：

| 概念 | 定义 |
| --- | --- |
| User Imagination | 用户提出的原始想法。它可能含混、跳跃、缺少边界，不能直接进入正式运行。 |
| Underground Center | 地下中枢，负责需求成形、反驳、证据探索、约束提取、Soil 检索、方向综合和养料供给。 |
| Direction Handoff Package | `.agentarbor` 方向交接包，保存方向、约束引用、证据引用、Soil 引用、风险、升级条件和 Growth Entry。 |
| User Approval Gate | 用户确认门，只在任务确认、授权边界变化、目标冲突、权限/成本/安全越界或关键事实不足时触发。 |
| Constraint Engineering | 横向约束工程，把目标、非目标、权限、成本、技术边界和验收门转化为可执行约束。 |
| Nutrient Request | 地上组织向地下中枢请求养料的运行期机制。 |
| Nutrient Patch | 地下中枢对养料请求的结构化补充。 |
| Direction Re-shaping | 当方向前提被证伪、目标变化或 Path Bias 失效时，地下中枢生成新的 Direction Handoff 版本。 |
| Aboveground Center | 地上中枢，制定和修订 Growth Plan 与 Workflow IR。 |
| Growth Plan Revision | 基于 Nutrient Patch、新 Direction Handoff 版本或无需补充证据修订 Growth Plan 的机制。 |

## Direction Handoff 形态

`.agentarbor` 方向交接包建议采用文件夹结构：

```text
.agentarbor/
  direction.md
  constraints.json
  soil-refs.json
  evidence-index.md
  open-questions.md
  escalation-rules.md
  growth-entry.json
  handoff.meta.json
```

`.agentarbor` 是方向交接包，不是 Growth Plan，不是长期资产库，也不是 Soil 的副本。它只引用 Soil 中的固定资产，不复制资产本体。

## Nutrient Request

Nutrient Request 可以由 Aboveground Center、Aboveground Growth、Verification 或 Governance 发起。触发原因包括：

- 运行中发现证据不足。
- 地上执行反复失败，需要判断失败是执行问题还是方向养料不足。
- Verification 不通过且缺少可判定证据。
- Path Bias 失效。
- Soil 中原有资产不适用或适用条件不清。
- 用户修改目标。
- 权限、成本或不可逆动作前提不成立。
- Growth Plan 的关键假设被证伪。

Nutrient Request 的输出必须是 Nutrient Patch、新 Direction Handoff 版本，或明确“无需补充”的证据。它不授权地上组织绕过 Verification、用户确认或治理门。

## 版本关系

- `Direction Handoff v1` 来自 Underground Center 的初始方向成形。
- `Direction Handoff v2+` 来自方向补充或方向再成形。
- 每个 Growth Plan 必须引用具体 Direction Handoff 版本。
- Growth Plan Revision 必须记录修订原因、影响范围、Workflow IR 变化、引用的 Nutrient Patch 或 Direction Handoff 版本，以及继续、回退、分叉或停止决策。

## 边界

- Underground Center 不是地上执行组织，不生成 Growth Plan。
- Aboveground Center 不是单个万能最强 agent，而是低自由度固定核心集群。
- Aboveground Growth 负责沿既定方向执行和提交证据，不负责重新探索方向。
- 动态任务集群负责执行扩展，固定地上中枢负责汇总、决策和抗单点认知失败。
- Nutrient Request 是补充养料，不是推倒重来。

## 影响

- 开发指南必须表达 Direction Handoff、Nutrient Request、Nutrient Patch、Growth Plan Revision 和约束工程的契约。
- 约束工程由 ADR-0017 补充，负责把目标、权限、成本、验证和治理边界转化为可执行约束。
- 植物学融合架构中的地下中枢和地上中枢必须表达持续养料供给机制。
