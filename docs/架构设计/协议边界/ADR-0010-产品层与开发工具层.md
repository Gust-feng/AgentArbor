# ADR-0010: 产品运行层与开发工具层分离

## Status

Accepted.

## Context

AgentArbor 同时存在两类工作：

- 开发 AgentArbor 仓库本身。
- 定义未来 AgentArbor 产品 runtime 应该如何识别、生成、编排和治理 agent。

前一类工作使用 Codex 官方兼容能力：`AGENTS.md`、`.agents/skills/`、`.codex/agents/*.toml` 和 `docs/` 的开发记录。后一类工作使用 AgentArbor 自己的产品协议草案：`.agentarbor/agents/`、`.agentarbor/workflows/`、`.agentarbor/registry.json`、`.agentarbor/schemas/` 和 `.agentarbor/memories/`。

此前在“开发 AgentArbor”和“设计 AgentArbor”之间切换时，`.agentarbor/agents/` 被当前 Codex 开发流程压缩：深度研究报告中的 Canopy/Trunk/Root 三层结构和 10 个产品 agent 被简化为当前开发中更容易使用的角色集合。这会让产品规格被工具能力反向塑形。

## Decision

AgentArbor 固定区分两层：

1. **开发工具层**：用于开发当前仓库。
   - `AGENTS.md` 保存 AI 执行硬规则。
   - `docs/` 保存人类可读的开发指南、任务看板、研究资料和架构设计。
   - `.agents/skills/` 保存官方 Agent Skills / Codex repo skills。
   - `.codex/agents/*.toml` 保存开发 AgentArbor 时使用的 Codex custom subagents。
2. **产品运行层 / 未来启动资产层**：用于定义未来 AgentArbor 自身。
   - `.agentarbor/**` 保存 AgentArbor runtime 原生协议草案。
   - `.agentarbor/agents/` 是产品 agent source-of-truth。
   - `.agentarbor/registry.json` 是产品 runtime registry 草案，不是 Codex 官方索引。
   - `.agentarbor/**` 是 AgentArbor 未来启动、生成、识别和治理 agent 所需的产品资产种子。

当同一能力同时出现在两层时，必须按用途区分：

- Codex 开发工具层可以适配、验证、预演产品能力。
- AgentArbor 产品运行层可以吸收开发过程中被验证的结构性知识。
- 开发工具层不能替代产品运行层。
- 产品运行层不能被当前 Codex 工具能力压缩。

## Consequences

- `.codex/agents/*.toml` 是开发 AgentArbor 的 Codex 标准配置，但不是 AgentArbor 产品 agent 源数据。
- `.agentarbor/agents/` 必须从产品研究资料和产品 ADR 出发，不按当前开发工具的可用角色做删减。
- 当前开发 AgentArbor 本体的人类可读入口是 `docs/开发指南/`；研究和架构材料分别保存在 `docs/研究资料/` 与 `docs/架构设计/`。`.agentarbor/` 是未来启动资产，不承担当前文档工作区职责。
- 旧 Canopy/Trunk/Root 与 10 个产品 agent 只作为研究输入保留，当前产品架构以 `docs/架构设计/产品架构/ADR-0015-树形语义基线与Root重定义.md` 为正式树形语义基线。
- 后续新增 agent 时，先判断问题属于开发工具层还是产品运行层，再选择 `.codex/agents/` 或 `.agentarbor/agents/`。
- 任何文档、skill 或 ADR 如果把两层混用，必须标记为过时或用新的 ADR 修正。
