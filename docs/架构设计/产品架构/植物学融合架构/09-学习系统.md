# 运行沉淀系统

## 概述

AgentArbor 不采用“等到重复任务时再总结”的方式。每次运行结束，都必须从可回放证据中形成沉淀。

## 沉淀链路

```text
EventLog
  -> Artifact
  -> Verification / Acceptance
  -> Run Memory
  -> Experience Candidate
  -> Path Bias
  -> Governance Gate
  -> Capability Asset / Fruit Record
  -> Soil
```

## Run Memory

Run Memory 是单次运行摘要，记录实际发生了什么：

- Seed Packet。
- Root Brief 版本。
- Growth Plan 版本。
- Root Callback 和 Growth Plan Revision。
- 实际路径。
- 参与 agent。
- 使用能力。
- 产物。
- 验证结果。
- 偏离原因。
- 成功模式和失败模式。

## Experience Candidate

Experience Candidate 是可复用经验候选，记录哪些做法可能在相似任务中复用。它必须包含适用条件、不适用条件、验证门和置信度。

## Path Bias

Path Bias 是候选经验对下一次相似任务的牵引。Root System 发现它，Core Control Cluster 判断是否采用、调整或拒绝。

Path Bias 不要求复刻历史流程。新的 Seed Packet、Root Brief、权限、成本、验证要求或外部事实可以推翻旧路径。

## Ring Memory

Ring Memory 是多次运行的聚合视图，用于观察：

- 哪类任务重复出现。
- 哪些 Path Bias 稳定有效。
- 哪些 Experience Candidate 应晋升。
- 哪些 Capability Asset 过期或应修剪。
- 哪些失败模式反复出现。
- 哪些 Root Callback 经常发生，说明根系或 Seed 成像不足。

Ring Memory 不保存新的事实，只聚合已有事实源。

## 评估

运行沉淀系统的质量由以下指标衡量：

- Run Memory 是否来自真实 EventLog 和验证结果。
- Experience Candidate 是否有清楚适用范围。
- Path Bias 是否保留偏离空间。
- Capability Asset 是否经过治理门。
- Ring Memory 是否没有制造平行事实源。
- Root Callback 和 Growth Plan Revision 是否可追踪。
