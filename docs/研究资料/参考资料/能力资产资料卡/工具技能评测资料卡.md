# 工具、技能与评测资料卡

## 1. 目标

工具、技能和评测是 AgentArbor 第一版能否闭环的关键。

```text
Tool = 原子动作
Skill = 方法包
Evaluator = 结果裁判
```

AgentArbor 不应该让 Agent 自由选择任意命令，而应从能力资产注册表中选择已登记能力。

## 2. P0 Tool 资产

```text
tool.git.clone
tool.git.status
tool.git.diff
tool.git.apply_patch
tool.file.read
tool.file.write
tool.file.search
tool.package.detect
tool.shell.run
tool.test.pytest
tool.test.vitest
tool.secret_scan
```

沉淀结论：

* Git 和 File 是代码型 AgentApp 的基础手脚。
* Shell 是高风险能力，必须受 CommandPolicy 管控。
* Test Runner 是“生成是否成活”的最低证据。
* Secret Scanner 必须进入发布前门禁。

## 3. P0 Skill 资产

```text
skill.repo_map
skill.requirement_parse
skill.code_repair
skill.test_failure_diagnosis
skill.diff_review
skill.security_review
skill.project_memory_extract
skill.agent_blueprint_design
```

沉淀结论：

* `code_repair` 是第一版最适合展示真实闭环的核心 Skill。
* `repo_map` 和 `requirement_parse` 是所有工程型任务的前置 Skill。
* `diff_review`、`security_review` 和 `test_failure_diagnosis` 负责让 Agent 不只会改，还会解释和修正。
* Skill 必须包含输入、输出、所需工具、权限、验收规则和样例。

## 4. P0 Evaluator 资产

```text
eval.build
eval.unit_tests
eval.diff_scope
eval.requirement_match
eval.secrets
```

沉淀结论：

* Build 和 Unit Test 是确定性评测。
* Diff Scope 用于防止越界修改。
* Requirement Match 可以用 LLM-as-judge，但必须引用证据。
* Secrets 检测必须覆盖 diff、log、outputs。

## 5. 第一版闭环建议

```text
Repository Mapping
  -> Requirement Parsing
  -> Code Repair
  -> Build Evaluator
  -> Unit Test Evaluator
  -> Diff Scope Evaluator
  -> Secret Leakage Evaluator
  -> Diff Review
  -> Human Approval Gate
```

这个闭环足够证明 AgentArbor 不是只生成文件，而是能生成、运行、测试、审查和沉淀结果。
