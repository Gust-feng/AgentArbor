# 人工智能与确定性边界

## 统一入口

所有 AI 调用必须通过智能通道。Underground Center、Aboveground Center、Verification、Governance、CLI、未来 UI 和测试 fixture 都不能直接调用 OpenAI、Anthropic、Gemini、Qwen、Ollama、vLLM 或其他 provider SDK、外部 LLM SDK 或 provider adapter。

智能通道负责统一 `ModelRequest`、`ModelResponse`、`ModelUsage`、`ModelCallRef`、模型调用事件、输出契约校验、失败状态和 provider adapter。具体 provider 只能放在 adapter 层，不能反向定义 AgentArbor 的领域模型。

本阶段模型接入采用 AgentArbor 原生协议适配，不引入 Vercel AI SDK、OpenAI SDK、LangChain、Anthropic SDK、Gemini SDK 或其他外部 LLM SDK。首个真实协议实现为 `openai_compatible_chat_completions`，使用 Node global `fetch` 或测试注入 fetch 直接映射 HTTP 协议；默认 demo 不配置 provider 时不得触发真实网络。

## AI 可以负责什么

AI 可以参与：

- Underground Center 的目标结构化建议、方向候选、风险提示、反例和证据探索建议。
- 目标澄清问题的草拟。
- Aboveground Center 的计划建议、任务切片建议、上下文拓扑建议和工作流草案。
- Path Bias 候选建议。
- 提示词、文档、代码或配置草案。
- 失败原因解释和修复建议。
- 能力候选、退役建议和治理解释。
- Nutrient Request 和 Growth Plan Revision 建议。

单个模型调用、单个 rootlet 输出、工具结果和搜索结果只能被标记为候选、草案、解释或证据建议。它们不能直接成为 Direction Handoff、Growth Plan、Workflow IR、Verification Result、Run Memory、Experience Candidate、Capability Asset、Path Bias 或 Soil 的事实；必须先进入父层 agent 的汇总、质疑、交叉验证、裁决或澄清流程，再接受确定性边界守卫。

## 确定性系统必须负责什么

确定性系统必须负责：

- 数据结构校验。
- 模型请求授权、预算、敏感信息和输出契约校验。
- Direction Handoff 状态与用户确认门。
- Direction Handoff 版本关系。
- Growth Plan Revision 版本关系。
- Constraint / ConstraintRef 分发、阻断和偏离记录。
- 权限判断。
- 状态转换。
- 文件写入边界。
- 命令执行边界。
- 测试运行。
- EventLog 写入和回放。
- Run Memory 写入规则。
- Experience Candidate 晋升规则。
- Path Bias 写入和读取规则。
- Nutrient Request / Patch 写入和读取规则。
- 谱系记录。
- 版本管理。
- 导出打包。

确定性系统不负责替代 agent 的语义判断。目标理解、方案探索、工具选择、候选综合、收束理由和交接叙事应由对应层的 agent 主线完成；确定性代码只阻断越界行为、标记 fallback / failed 状态、保存可审计证据并验证正式材料结构。

禁止工程边界替 Agent 思考：不得用关键词表、状态迁移、schema 校验、validation 错误码、固定 fallback 文案或文件契约来决定“用户真正要什么”“哪个候选更好”“是否该继续探索”“该调用什么工具”或“方向如何综合”。这些只能作为 agent 决策后的守卫和证据。

## 模型调用事件

智能通道必须发布模型调用事件：

- `model.requested`：调用目的、调用方、预算、输出契约和清洗后的输入引用。
- `model.completed`：provider、model、usage、finish reason、输出类型、结构化校验结果和输出引用。
- `model.failed`：失败类型、是否可重试、降级策略和清洗后的错误引用。

EventLog 和 Observation Snapshot 只能记录清洗后的模型调用摘要和引用，不能保存 API key、token、完整敏感 prompt、未授权 Soil 内容、用户隐私正文或 provider 原始敏感错误。

## 失败策略

AI 调用失败不能被解释为成功：

- 目标理解失败时，Underground Center 可以把确定性 fallback 标记为低置信度候选交给父层收束，或进入 `awaiting_user` / `stopped`。
- 候选生成失败时，rootlet 可以记录失败候选或减少候选数量，但不能伪造 accepted candidate。
- 计划建议失败时，Aboveground Center 必须保留缺口或请求补充，不能跳过 Growth Plan validation。
- LLM-as-judge 缺失时，Verification / Governance 只能记录建议缺失，不能自动通过。

## 核心原则

下层 LLM / rootlet / subagent 可以提出内容，不能单独拥有最终事实。上层中枢 agent 可以承担运行级综合、裁决和交接判断，但任何长期资产、子 agent 脱离、权限扩大、导出、删除、约束放行、Direction Handoff 批准或治理晋升，都必须经过确定性边界检查和必要的人类确认。
