# 状态机

## 概述

状态机定义 Seed、Root、Plan、Run、Callback、Memory 的合法转换。所有关键状态变化必须通过 MessageBus、Router 和 EventLog 记录。

## 核心状态

| 状态 | 层级 | 说明 | 退出条件 |
| --- | --- | --- | --- |
| Dormant | 系统 | 等待用户想象 | 收到 Imagination |
| Imaging | Seed | Seed Cluster 前置成像 | Seed Packet 形成 |
| Awaiting Approval | Seed | 等待用户确认 | 用户批准、修改或拒绝 |
| Seeded | Soil | Seed Packet 种入 Soil | Initial Rooting 开始 |
| Rooting | Root | Initial、Lateral 或 Deep Rooting | Root Brief vN 完成或无需重探 |
| Planning | Core Control | 制定或修订 Growth Plan | Growth Plan vN 完成 |
| Routing | Branch | Router 分配任务 | 任务分配完成 |
| Executing | Leaf | Leaf Agents 执行任务 | 产物完成、阻塞或失败 |
| Verifying | Flower | 验证、评审和成熟判断 | 验证通过、失败或建议 Root Callback |
| ReRooting | Root | Root Callback 后补探或重探 | 新 Root Brief 或无需重探证据 |
| Revising | Core Control | Growth Plan Revision | 继续、回退、分叉或停止决策 |
| Fruiting | Fruit | 交付或果实治理 | 交付完成或治理完成 |
| Sedimenting | Ring / Soil | 形成 Run Memory、Experience Candidate、Path Bias | 沉淀完成 |
| Archived | 系统 | 关闭并保留谱系 | 等待下次启动 |

## 主转换

```text
Dormant
  -> Imaging
  -> Awaiting Approval
  -> Seeded
  -> Rooting
  -> Planning
  -> Routing
  -> Executing
  -> Verifying
  -> Fruiting
  -> Sedimenting
  -> Archived
```

## 回调转换

```text
Executing / Verifying / Planning
  -> Root Callback Request
  -> ReRooting
  -> Root Brief vN 或 No Re-rooting Evidence
  -> Revising
  -> Routing / Executing / Fruiting / Archived
```

## 守卫规则

- `Seeded` 前必须有通过 User Approval Gate 的 Seed Packet。
- `Planning` 前必须有 Root Brief 版本。
- `Routing` 前必须有 Growth Plan 版本。
- `ReRooting` 必须由 Root Callback 触发。
- `Revising` 必须引用新的 Root Brief 版本或无需重探证据。
- `Fruiting` 必须经过 Verification 和 Acceptance。
- `Sedimenting` 必须写入 Run Memory，或记录无可沉淀内容的证据。

## 禁止事项

- 不允许执行者自行推进状态机。
- 不允许把聊天文本当成状态事实源。
- 不允许跳过 Seed、Root Brief 或 Growth Plan 直接进入执行。
- 不允许 Root Callback 绕过 Verification 或用户确认。
