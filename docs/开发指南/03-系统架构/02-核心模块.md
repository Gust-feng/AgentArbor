# 核心模块

## Desktop Shell

Desktop Shell 是用户唯一入口，负责承接任务、工作区上下文、成果展示和监督视角。它包含：

- Task Inbox：任务输入区。
- Workspace Context：文件、项目、网页和外部材料引用。
- Main Canvas：当前任务主画布，展示结果、Plan 摘要、inline evidence 和可展开解释。
- Artifact Area：文档、代码改动、原型、报告和 Plan Package。
- Observation Panel：监督面板，展示 agent run tree、child 摘要、父层 synthesis、convergence 事件、模型/工具 refs、budget 和 trace。

## Task Soil

Task Soil 是当前任务级临时土壤，保存用户目标、文件引用、项目上下文、网页材料、临时约束、权限边界和本轮运行材料。它可以引用 Global Soil 中的长期资产，但不能把本轮材料直接写入 Global Soil。

## Global Soil

Global Soil 保存受治理的 Capability Asset、长期约束、历史运行索引、验证规则、权限策略、失败模式、Path Bias 和长期资料。任何进入 Global Soil 的资产都必须经过 Governance Pipeline。

## Shared Agent Kernel

Shared Agent Kernel 是所有 agent runtime 的共同能力层：

- `AgentLoop`：observe / reason / act / guard / reflect / decide_next。
- `AgentTurnRuntime`：模型与工具多轮回合。
- `ToolCenter`：工具注册、权限裁剪、执行和结果归一化。
- `WorkspaceView`：隔离后的任务上下文视图。
- `Mailbox`：agent 间消息和材料路由。
- `Guard`：schema、预算、权限、hard constraint、脱敏和包结构边界。
- `Trace`：安全可观察事件和 reasoningTrace 投影。
- Budget / Permission boundary：运行预算和授权边界。

Shared Agent Kernel 不保存业务事实。业务语义由 Underground 和 Aboveground 运行时承担。

## Underground Cognitive Runtime

地下认知运行时负责方向智能。它采用 AI-first agent 协作主线，允许不确定、分叉、追问和停止。

建议包含：

- Center Manager：决定是否派生、等待、打断、继续探索、追问用户或停止。
- Growth Governor：建议探索预算、并行度、rootlet 类型和停止条件。
- Agent Fabric：按 `AgentSpec` 创建 child agent，执行权限、预算和上下文隔离。
- Parent Synthesis / Convergence：消费 child outputs，综合冲突材料，决定方向是否足够成立。
- Handoff / Plan Steward：组织 Plan，但不能绕过父层 convergence。

地下运行时不能调度正式执行，不能创建长期资产，不能把候选经验写入 Global Soil。

## Agent Fabric

Agent Fabric 是动态派生 child agent 的执行机制。MVP 阶段：

- 只允许一层 child agent。
- `depth = 1`。
- Center Manager 可以派生 rootlet child。
- child 不可再派生孙 agent。
- descendant output 不能直接进入 Plan，必须经过父层 synthesis / convergence。

长期可扩展到 `depth = 2+`，但必须由 `maxDepth`、`maxChildrenPerAgent`、`maxTotalChildren`、`maxBudgetPerSubtree`、`allowedDelegationKinds`、`parentSynthesisRequired` 和 `noDirectHandoffFromDescendant` 等硬约束守住边界。

## Plan Package Store

Plan 是地下到地上的产品级交接对象。Plan Package Store 保存 Plan 的可持久化形态，支持暂停恢复、版本管理、人类可读、审计复盘、跨进程消费和防 child output 直通执行。

`.agentarbor/` 是 Plan Package 的默认目录名或实现形态。它不保存最终交付物，不复制 Global Soil，不作为独立产品节点。

## Aboveground Execution Runtime

地上执行运行时读取 Plan，执行文件修改、文档生成、原型制作、工具调用和验证。它负责把“Plan 中已经成立的方向”转化为可交付成果。

建议包含：

- Execution Planner：从 Plan 生成可执行步骤和验证点。
- Runtime Coordinator：选择执行形态、分配上下文和处理失败。
- Tool Executor：通过 ToolCenter 执行文件、浏览器、MCP 或其他工具。
- Verifier：检查结果、约束和验收证据。
- Revision Controller：遇到信息不足时发起 Nutrient Request，并根据 Nutrient Patch 或 Plan vNext 决定继续、回退、分叉或停止。

## Fruits Store

保存交付物、运行报告、Run Memory、Experience Candidate 和能力候选。Fruits Store 不是 Global Soil；它只保存待治理或已交付材料。

## Governance Pipeline

负责经验候选识别、验证、归因、去重、版本化、导出、修剪、退役、权限隔离和入土裁决。任何长期资产出生都必须经过这一层。

## Lineage Registry

记录用户任务、Task Soil、Plan 版本、Nutrient Patch、执行记录、产物、验证结果、Run Memory、Experience Candidate、治理结论和 Global Soil 更新之间的来源关系。

## Intelligence Runtime

智能运行时是所有模型能力的统一横切入口。它服务地下目标理解、child/rootlet 探索、父层综合、Plan 叙事、地上执行辅助、验证建议和治理解释，但不属于任何单一业务节点。

建议包含：

- Request Contract：统一 `ModelRequest`、调用目的、预算、输出契约和敏感信息边界。
- Response Contract：统一 `ModelResponse`、`ModelUsage`、输出类型、finish reason 和结构化校验结果。
- Model Call Registry：生成 `ModelCallRef`，让正式材料只引用模型调用结果，不复制未验证模型正文。
- Event Projection：发布模型事件，供 EventLog 和 Observation Panel 消费。
- Provider Selection：选择 OpenAI-compatible、Anthropic、Gemini、Qwen、本地模型或其他 provider adapter。
- Failure Policy：把超时、鉴权失败、预算越界和输出不合约转成可观测失败，不静默伪造成功。

## Adapter Layer

负责 Codex、OpenCode、Agent Skills、MCP、模型供应商、工具协议和外部平台的格式转换。适配层不能反向污染核心模型。
