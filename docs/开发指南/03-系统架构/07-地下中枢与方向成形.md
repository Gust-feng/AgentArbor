# 地下中枢与方向成形

## 定位

Underground Cognitive Runtime 是 AgentArbor 的方向智能运行时。它把用户任务、Task Soil、Global Soil 引用、约束、风险和证据整理成地上可消费的 Plan。

地下运行时不属于地上执行组织。它不执行正式任务，不写长期资产，不生成交付物。

地下运行时采用 AI-first agent 协作模型：Center Manager 组织目标成形和动态派生，child/rootlet 做局部探索，父层 synthesis / convergence 汇总、质疑、合并、淘汰、追问或停止，Handoff / Plan Steward 组织 Plan。

## 输入与输出

输入包括：

- 用户原始任务、背景和补充信息。
- Task Soil 中的文件引用、项目上下文、网页材料、临时约束和权限边界。
- Global Soil 中的 Capability Asset、Path Bias、治理规则和失败模式引用。
- 初始约束、偏好、成本、时间、安全和验收要求。
- 外部事实核验结果和内部证据。

输出包括：

- Plan：地下到地上的产品级交接对象。
- Nutrient Patch：地上发起 Nutrient Request 后的补充材料。
- Plan vNext：方向前提变化后的新版本。
- User Clarification Request：需要用户澄清的问题。
- Stopped Result：目标冲突、预算耗尽、缺少 runtime 或 hard constraint 阻断时的停止依据。

`.agentarbor` 是 Plan Package 的存储形态，不是地下输出的产品节点名称。

## 父层固定职责

| 成员 | 职责 |
| --- | --- |
| Center Manager | 决定是否派生、等待、打断、继续探索、追问用户或停止 |
| Growth Governor | 建议探索预算、并行度、rootlet 类型和停止条件 |
| Agent Fabric | 按 `AgentSpec` 创建 child agent，执行权限、预算和上下文隔离 |
| Parent Synthesis / Convergence | 消费 child outputs，综合冲突材料，决定方向是否足够成立 |
| Handoff / Plan Steward | 组织 Plan，但不能绕过父层 convergence |

父层中枢默认不直接使用外部探索工具。父层可以读取 run tree、mailbox、trace、workspace summary 等内部观察材料。证据不足时应派 child 继续探索，而不是父层自己搜索。

## 动态派生 Agent Fabric

地下中枢可以按任务动态派生临时 child agent。派生 agent 与固定核心 agent 使用同一套能力内核：`AgentLoop` 负责 observe / reason / act / guard / reflect / decide_next，`AgentTurnRuntime` 负责模型与工具多轮回合，`WorkspaceView` 和 `Mailbox` 提供隔离上下文，Guard 只守权限、预算、schema、hard constraint 和包结构。

派生运行时必须显式记录：

- `AgentSpec`：派生 agent 的协议、prompt ref、output contract、工具权限上限和预算。
- `DelegationDecision`：父层 agent 为什么派生、等待、继续、停止或请求收束。
- `ChildAgentRun`：子 agent 的运行状态、输入 refs、输出 refs、证据 refs、失败条件和不确定性。
- `AgentRunTree`：一次地下运行的父子关系和状态树。
- `ParentSynthesisResult`：父层对 child/rootlet 材料的综合结果。

`ChildAgentRun` 不等于长期 Agent 资产。它只是当前地下运行内的临时能力，不自动进入 Global Soil，不自动成为 Capability Asset，也不继承母体运行时权限、密钥、历史任务或注册表写权限。

## 权限模型

本轮实际能力由四层相交决定：

```text
AgentSpec 静态能力上限
  ∩ Parent DelegationDecision 动态授权
  ∩ AgentRunContext 当前阶段 / 任务 / 预算 / 用户授权裁剪
  ∩ ToolCenter / Guard 强制执行
  = 本轮实际能力
```

角色只给能力上限，实际工具权限按运行上下文裁剪。同一个 rootlet 在探索阶段可以被授予 search / read，在综合阶段可以只允许 model。`ToolCenter` 最终读取 `AgentRunContext` 中的有效权限，而不是只看 agent role。

## MVP 派生边界

MVP 阶段只允许一层 child agent：

- `depth = 1`。
- Center Manager 可以派生 rootlet child。
- child 不可再派生孙 agent。
- descendant output 不能直接进入 Plan，必须经过父层 synthesis / convergence。

长期允许受控递归，但必须有 `maxDepth`、`maxChildrenPerAgent`、`maxTotalChildren`、`maxBudgetPerSubtree`、`allowedDelegationKinds`、`parentSynthesisRequired` 和 `noDirectHandoffFromDescendant` 等硬约束。

## Rootlet 类型

| Rootlet | 触发场景 | 交付物 |
| --- | --- | --- |
| option | 存在多个可行方向 | 候选方向、取舍、适用条件 |
| risk | 成本、失败、合规或维护风险不清 | 风险登记、失败模式、阻断项 |
| evidence | 需要外部事实、环境事实或依赖事实 | EvidenceRef、FactRef、可信度 |
| constraint | 方向需要映射为可执行约束 | Constraint / ConstraintRef 候选 |
| asset_fit | 需要判断 Global Soil 资产是否适配 | Soil 引用、适配条件、不适用条件 |
| counterfactual | 需要反驳方向或识别局部最优 | why-not、反例、替代方向 |

rootlet 必须有明确输入、预算、输出和退场条件。它们不能直接制定执行计划，不能调度地上执行，也不能把运行产物写入 Global Soil。

单个 rootlet 输出只能作为局部材料。它必须先进入父层 `ParentSynthesisResult`，再进入 Convergence 的保留 / 合并 / 淘汰 / 继续探索 / 询问用户 / 停止裁决。禁止单个 rootlet output、单个搜索结果或单个模型回复绕过父层综合进入 Plan。

## 方向收束

地下运行时必须记录多个候选方向，而不是默认只产出单一结论。收束时必须说明：

- 保留哪个主方向。
- 哪些方向被合并。
- 哪些方向被淘汰。
- 哪些冲突需要用户确认。
- 哪些备选方向可以作为地上执行参考。
- 哪些候选观察、候选证据或候选主张被采纳、合并、驳回或保留为未知项，以及来源归因。

收束结果进入 Plan 的决策记录、风险、不确定性、证据引用和执行入口。

## 生长预算

地下探索必须受控。每次方向成形或养料供给都必须定义：

- 最大探索方向数。
- 每个方向最大探索深度。
- 最大 child 数。
- 最大外部事实查询数。
- 最大成本或时间预算。
- 是否允许询问用户。
- 是否允许触发更深一层探索。
- 停止条件。

预算耗尽后，地下运行时必须收束为 Plan、Nutrient Patch、用户澄清请求，或明确停止依据。系统不能因为持续探索而无限推迟 Plan。

## 用户确认循环

```text
User Task
  -> Task Soil
  -> Underground Cognitive Runtime
  -> Child Exploration
  -> Parent Synthesis
  -> Convergence
  -> Plan Draft
  -> User Review when needed
  -> Plan
```

用户只在必要处确认。当地下运行时已经拥有足够目标、约束、权限和证据时，应直接形成 Plan；当目标冲突、权限不清、关键事实缺失、高风险动作或长期治理冲突出现时，必须升级给用户。

## 禁止事项

- 不执行正式任务。
- 不创建 Capability Asset。
- 不把 Plan 当长期事实源。
- 不把候选约束自动变成长期约束。
- 不把单个探索 agent 的原始调研输出直接写入 Plan 或 Nutrient Patch。
- 不绕过用户确认门执行高风险动作。
- 不把 Global Soil 内容复制进 Plan Package 形成第二事实源。
- 不在无 `AgentTurnRuntime` 时产出 approved Plan。
