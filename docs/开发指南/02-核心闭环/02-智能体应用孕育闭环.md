# 桌面任务孵化闭环

## 基本路径

AgentArbor 的第一验证环路是：桌面任务输入 -> Task Soil -> Underground 方向成形 -> Plan -> Aboveground 执行验证 -> Fruits -> Governance -> Global Soil。

```text
用户任务 / 文件 / 项目 / 网页
  -> Desktop Shell
  -> Task Soil
  -> Underground Cognitive Runtime
  -> Plan
  -> Aboveground Execution Runtime
  -> Verification / Acceptance
  -> Fruits
  -> Run Memory
  -> Experience Candidate
  -> Governance Pipeline
  -> Capability Asset / Path Bias / Soil Update
  -> Global Soil
```

用户获得的是**任务被推进到可交付结果**，以及解决路径和经验的长期沉淀。独立 agent 或 AgentApp 只是少数长期运行场景下的可选 Fruit，不是每次任务的目标。

## 产品判断

- 用户入口是任务、文件、项目或网页上下文，不是技术配置。
- Desktop Shell 是唯一产品入口；Underground 和 Aboveground 是内部 runtime。
- Underground 的职责是目标成形、多路探索、父层综合、裁决、追问或停止。
- Aboveground 的职责是按 Plan 执行和验证，不自建方向探索集群。
- Plan 描述“这个任务应该如何继续”，`.agentarbor` 只是 Plan Package 的实现/存储形态。
- Fruits 可以是文档、代码改动、研究报告、原型、运行报告、Run Memory 或 Experience Candidate。
- 经验进入长期土壤前必须经过 Governance Pipeline。

## 必须具备的结构

- Desktop Shell：承接 Task Inbox、Workspace Context、Main Canvas、Artifact Area 和 Observation Panel。
- Task Soil：当前任务的目标、引用、上下文、临时约束、权限边界和运行材料。
- Shared Agent Kernel：`AgentLoop`、`AgentTurnRuntime`、`ToolCenter`、`WorkspaceView`、`Mailbox`、`Guard`、`Trace`、预算和权限边界。
- Underground Cognitive Runtime：方向智能主线。
- Agent Fabric：按任务动态派生 child/rootlet agent，但 MVP 只允许一层 child。
- Parent Synthesis / Convergence：所有 child/rootlet 输出必须经父层综合、冲突处理和裁决。
- Plan Package：地下到地上的可持久化交接对象，支持暂停恢复、版本化、人类可读、审计和跨进程消费。
- Aboveground Execution Runtime：消费 Plan 并产出可验证成果。
- Nutrient Request：地上发现信息不足时回到地下补充探索，产出 Nutrient Patch 或 Plan vNext。
- Governance Pipeline：`Fruits / Run Trace -> Run Memory -> Experience Candidate -> Governance Pipeline -> Capability Asset / Path Bias / Soil Update`。

## MVP 边界

MVP 应证明以下最小闭环：

- 用户在 Desktop Shell 输入任务并绑定工作区材料。
- Task Soil 能被地下 runtime 消费。
- 地下 runtime 使用 fake/stub AI runtime 稳定跑通 AI 路径；无 `AgentTurnRuntime` 不允许 approved Plan。
- Agent Fabric 能派生一层 child/rootlet，child 输出不能直通 Plan。
- Plan 能被地上 runtime 消费，并产出至少一种可见成果。
- Main Canvas 展示结果级解释，Observation Panel 展示 agent 过程级监督 trace。

MVP 不做完整 IDE、完整终端代理、插件市场、多用户系统、完整能力资产治理或多层递归 Agent Fabric。

## 独立 Agent 的出生条件

独立 agent 不是产品主线。只有当任务同时满足以下条件时，才考虑产出可脱离的 agent 或 AgentApp：

- 需要长期、定时、独立运行的执行单元，例如每日监测或持续同步。
- 有明确输入输出契约、权限边界、版本和退役路径。
- 多次真实任务证明该能力稳定有效。
- 有对应 Plan、执行记录、验证证据和 Run Memory。
- Experience Candidate 已经过 Governance Pipeline 评估。

不满足上述条件的场景由 AgentArbor Desktop 直接执行、交付和沉淀，不分化独立 agent。
