# 路径倾向机制

## 定义

Path Bias 是历史运行对新任务的路径牵引。第二次遇到相似任务时，系统不会强行复刻上一次流程，但会天然倾向于参考上一次已经验证过的有效路径。

## 形成过程

```text
Run Memory
  -> Experience Candidate
  -> Path Bias
  -> Root System 发现
  -> Core Control Cluster 判断
  -> Growth Plan 采用、调整或拒绝
```

## Root System 的职责

Root System 在 Initial Rooting、Lateral Rooting 或 Deep Rooting 时，必须检索与当前目标相似的 Run Memory、Experience Candidate 和 Capability Asset，并把可用的 Path Bias 写入 Root Brief。

Root Brief 中的 Path Bias 应说明：

- 来源运行。
- 相似点。
- 推荐路径。
- 关键验证门。
- 已知失败模式。
- 不适用条件。
- 证据强度。

## Core Control Cluster 的职责

Core Control Cluster 不能被 Path Bias 绑架。Trunk Synthesis 只负责综合证据，最终是否采用由 Core Control Cluster 在 Growth Plan 中记录。它必须重新比较当前目标、约束、权限、上下文、风险和验证要求，再决定：

- 采用历史路径。
- 采用历史路径的一部分。
- 调整历史路径。
- 明确拒绝历史路径。

决定结果必须进入 Growth Plan，并在运行结束后写入 Run Memory。

如果 Path Bias 在执行或验证中失效，Branch Agent 或 Flower Cluster 可以请求 Root Callback。新的 Root Brief 版本必须说明旧路径为什么失效，以及 Growth Plan Revision 需要继续、回退、分叉还是停止。

## 禁止事项

- 禁止把 Path Bias 当模板复刻。
- 禁止用上次成功替代本次验证。
- 禁止跳过当前目标和权限判断。
- 禁止把单次成功直接晋升为 Capability Asset。
- 禁止让 Path Bias 绕过 MessageBus、Router、状态机或治理门。
