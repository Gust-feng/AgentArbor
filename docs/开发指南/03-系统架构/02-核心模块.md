# 核心模块

## Soil Store

保存受治理的 Capability Asset、长期约束、历史运行索引、验证规则、权限策略、失败模式、Path Bias 和长期资料。任何进入 Soil 的资产都必须经过 Governance。

## Underground Center

地下中枢负责需求成形、方向探索、反驳、收束和养料供给。它采用地下辐射生长模型：中枢能力保持稳定，围绕任务动态生成临时根须集群，完成多方案探索后收束为方向交接包。建议包含：

- Intent Core：维护用户想象、目标原像、非目标和验收边界。
- Growth Governor：决定探索方向、探索深度、预算和停止条件。
- Constraint Sentinel：守住权限、成本、安全、技术和人工确认边界。
- Evidence Ledger：管理证据、来源、可信度、时间点和可追溯关系。
- Convergence Judge：比较多方案，决定保留、合并、淘汰或升级给用户。
- Handoff Steward：组装 `.agentarbor` 方向交接包。

地下中枢不能生成 Growth Plan，不能调度执行，不能把候选经验写入 Soil。

## `.agentarbor` Handoff Store

保存地下中枢交给地上中枢的方向交接包。它只保存方向、候选方向、方向裁决、ConstraintRef、Soil 引用、证据索引、风险登记、未决问题、升级规则和 Growth Entry。

它禁止复制 Soil 固定资产，也禁止保存最终交付物、长期能力资产或平台适配产物。

## Aboveground Center

地上中枢读取 `.agentarbor` 方向交接包，制定和修订 Growth Plan 与 Workflow IR。建议包含：

- Growth Planner：选择方向、复用策略和运行组织形态。
- Plan Critic：反审查计划和约束冲突。
- Risk Governor：检查权限、成本、安全和不可逆动作。
- Context Topology Builder：分配共享上下文、父子裁剪上下文和执行节点 ContextPack。
- Workflow IR Builder：生成可执行、可暂停、可恢复、可验证的工作流。
- Revision Controller：根据验证失败、目标变化或 Nutrient Patch 修订计划。

## Aboveground Growth Runtime

负责运行 Workflow IR，创建任务工作区，调度 single agent、sub-agent tree、shared team cluster 或 competitive team cluster，记录事件，处理暂停、恢复和失败。

运行时第一阶段必须先建立内部骨架：

- `ArborMessage`：AgentArbor 内部消息母语。
- `MessageBus`：消息接收、校验、路由、权限检查、事件记录、重试和回放。
- `Router / Coordinator`：根据任务状态、能力、权限和失败记录选择执行者。
- `AgentRegistry`：记录可调度智能体及其能力、状态和生命周期。
- `ArtifactStore`：记录产物来源、版本、验证状态和复用状态。
- `EventLog`：记录可回放事件链，作为验证、回流、谱系和演化依据。

内部智能体不能互相私聊，必须通过 MessageBus、Router 和状态机协作。外部协议进入系统前，必须先被 adapter 翻译为 AgentArbor 内部消息。

## Verification / Maturity

负责测试、检查、约束验证、证据收集和成熟度判断。验证必须说明 hard constraint 是否满足、soft constraint 是否偏离、preference 是否只影响排序，以及是否需要 Nutrient Request、计划修订、用户确认或治理复核。

## Fruits Store

保存交付物、AgentApp、能力包、可脱离子 agent 候选、Run Memory、Experience Candidate 和其他候选沉淀。Fruits Store 不是 Soil；它只保存待治理或已交付材料。

## Governance

负责经验候选识别、晋升、版本、导出、修剪、退役、权限隔离和谱系归因。任何长期资产出生都必须经过这一层。

## Lineage Registry

记录用户目标、方向交接包版本、Growth Plan 版本、Workflow IR、地上执行组织、AgentApp、能力、验证结果、果实和导出包之间的来源关系。

## Intelligence Channel

智能通道是所有模型能力的统一横切入口。它服务地下目标理解、根须候选生成、地上计划草案、验证建议和治理解释，但不属于 Soil、Underground Center、`.agentarbor`、Aboveground Center、Fruits 或 Governance 的任何一个节点。

建议包含：

- Request Contract：统一 `ModelRequest`、调用目的、预算、输出契约和敏感信息边界。
- Response Contract：统一 `ModelResponse`、`ModelUsage`、输出类型、finish reason 和结构化校验结果。
- Model Call Registry：生成 `ModelCallRef`，让正式材料只引用模型调用结果，不复制未验证模型正文。
- Event Projection：发布 `model.requested`、`model.completed`、`model.failed`，供 EventLog 和未来 Observation Snapshot 消费。
- Provider Selection：选择 OpenAI-compatible、Anthropic、Gemini、Qwen、本地模型或其他 provider adapter。
- Failure Policy：把超时、鉴权失败、预算越界和输出不合约转成可观测失败，不静默伪造成功。

智能通道不能写 Soil，不能绕过 CandidatePool、Convergence、Handoff validation、Verification 或 Governance，也不能让 provider 私有响应成为产品事实。单次模型/rootlet/tool 输出只是未收束材料；上层中枢 agent、Convergence Judge 和 Handoff Steward 是地下语义判断主路径，确定性规则负责协议、权限、预算、hard constraint、谱系、脱敏和 package validation。

## Adapter Layer

负责 Codex、OpenCode、Agent Skills、MCP、模型供应商、工具协议和外部平台的格式转换。适配层不能反向污染核心模型。

架构原则是“内核自研，协议兼容”：

```text
外部协议 -> Adapter -> ArborMessage
ArborMessage -> Adapter -> 外部协议
```
