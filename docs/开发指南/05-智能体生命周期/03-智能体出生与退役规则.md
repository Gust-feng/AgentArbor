# 智能体出生与退役规则

## 出生原则

智能体出生必须来自真实需要，而不是来自命名冲动。

一个 agent 可以出生，必须同时满足：

- 有明确职责边界。
- 有稳定输入和输出。
- 有可验证交付物。
- 有权限边界。
- 有运行证据或强设计依据。
- 有失败处理和退役条件。
- 不会与现有 agent、Capability Asset 或 Workflow IR 重复。

## 出生路径

```text
Direction Handoff
  -> Growth Plan
  -> Run Memory
  -> Experience Candidate
  -> Capability Asset
  -> 内部 agent 候选
  -> Governance Gate
  -> 注册 agent
  -> Fruit 候选
```

Underground Center 可以在方向成形中发现可能需要某类 agent 的线索，但不得创建长期 agent。Aboveground Center 可以把它写入 Growth Plan，Aboveground Growth 可以临时组建动态执行个体，但只有 Governance Gate 可以批准长期 agent 出生。

## 禁止出生

以下情况不得创建长期 agent：

- 只有角色名称，没有输入输出。
- 只有一次成功，没有验证证据。
- 只是平台适配文件需要某个名字。
- 只是为了让目录看起来完整。
- 现有 Workflow IR、工具或 Capability Asset 已能清楚解决。
- 权限边界说不清。

## 退役规则

agent 应在以下情况下退役或降级：

- 长期未被使用。
- 被更稳定的 Capability Asset 替代。
- 权限风险高于收益。
- 验证结果反复失败。
- 适用范围已经过期。
- 维护责任不清。

退役必须记录：

- 退役原因。
- 受影响的 Growth Plan、Workflow IR 或 Fruit。
- 替代路径。
- 回滚方式。
- 谱系更新。

## 脱离母体

可脱离子 agent 是果实，不是普通资产。脱离前必须完成最小权限、安装测试、运行示例、验证报告、版本、文档、撤回路径和母体权限隔离。
