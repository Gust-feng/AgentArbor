# 学习系统

## 定位

学习系统负责把单次运行转化为下一次任务可利用的倾向和资产。它不直接把运行流水写进 Soil，而是通过证据、治理和适用范围逐步沉淀。

## 学习链路

```text
EventLog
  -> Run Memory
  -> Experience Candidate
  -> Path Bias
  -> Governance
  -> Capability Asset / Soil
```

## Run Memory

Run Memory 必须引用：

- Direction Handoff 版本。
- Growth Plan 版本。
- Workflow IR。
- Nutrient Request、Nutrient Patch 和 Growth Plan Revision。
- Artifact 与 Verification。
- 实际执行路径、偏离、成功模式和失败模式。

## Experience Candidate

Experience Candidate 是可复用经验候选。它必须说明：

- 适用目标类型。
- 前置条件。
- 必须保留的验证门。
- 不适用条件。
- 置信度和证据来源。

## Path Bias

Path Bias 是候选经验对下一次相似任务的牵引。Underground Center 发现它，Aboveground Center 判断是否采用、调整或拒绝。

Path Bias 不要求复刻历史流程。新的 Direction Handoff、ConstraintRef、权限、成本、验证要求或外部事实可以推翻历史路径。Path Bias 只能影响 preference 和方案排序，不能覆盖 hard constraint。

## Ring Memory

Ring Memory 是聚合视图，不是事实源。它可以观察：

- 哪些目标类型反复成功。
- 哪些 Fruit 经常被治理拒绝。
- 哪些 Nutrient Request 经常发生，说明地下成形、土壤资料或上下文供给不足。
- 哪些 Capability Asset 过期、重复或风险升高。

## 验证重点

- 运行链路是否可回放。
- Run Memory 是否来自真实证据。
- Experience Candidate 是否有适用和不适用条件。
- Path Bias 是否保留偏离空间。
- Nutrient Request、Nutrient Patch 和 Growth Plan Revision 是否可追踪。
