# 目标驱动元循环

## 元循环

AgentArbor 的最小稳定循环是：

```text
用户任务
  -> Desktop Shell
  -> Task Soil
  -> Underground Cognitive Runtime
  -> Plan
  -> Aboveground Execution Runtime
  -> Workflow IR / tool actions
  -> Verification / Acceptance
  -> Fruits
  -> Run Memory
  -> Experience Candidate
  -> Governance Pipeline
  -> Capability Asset / Path Bias / Retire
  -> Global Soil
```

这个循环必须比任何单个平台 agent 格式更基础。平台 agent 只是执行或导出结果之一。

Path Bias 表示后续相似任务对已验证路径的自然倾向。它使系统不会每次从零开始，也不会把历史流程当成不可改变的模板。

## 目标内核职责

目标内核至少保存：

- 用户原始任务。
- 澄清后的目标。
- 非目标。
- 约束。
- 验收标准。
- 风险等级。
- 输入资产范围。
- 当前状态。
- 暂停点和恢复点。
- 变更记录。
- 完成或失败判定。

## 状态要求

目标不能只存在于聊天上下文里。实现时必须把目标表达为可存储、可恢复、可比较的数据结构。

基础状态包括：

- `draft`：目标尚未澄清。
- `shaping`：Underground 正在成形目标、探索方向或派生 child agent。
- `plan_ready`：Plan 已形成并可供 Aboveground 接管。
- `executing`：任务正在执行。
- `blocked`：需要人工决策、权限或外部输入。
- `nourishing`：已发起 Nutrient Request，等待 Nutrient Patch、Plan vNext 或无需补充证据。
- `revising`：Aboveground 正在基于新证据修订执行路径或请求 Plan vNext。
- `verifying`：进入验证阶段。
- `fruiting`：正在形成交付物或候选沉淀。
- `governance_review`：正在判断候选经验能否入土、导出或退役。
- `completed`：通过验收。
- `failed`：未通过验收并保留失败证据。
- `archived`：关闭并保留谱系和 Run Memory。

## 验收原则

目标是否完成，不能由执行 agent 自我宣布。必须由验证结果、用户确认、测试证据或明确规则共同决定。
