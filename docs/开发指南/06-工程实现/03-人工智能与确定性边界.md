# 人工智能与确定性边界

## 模型入口

当前有两条中性模型端口：

- Ordinary：`AgentLoop -> Pi AgentHarness/Session adapter`。
- Deep manager / child / synthesis 与其他单轮消费者：`IntelligenceChannel / AgentTurnRuntime -> OpenAI protocol adapter`。

`model-runtime` 负责创建端口和解析冻结模型配置。feature、route、Panel、领域模块和测试 fixture 都不能直接绑定外部 SDK、provider adapter 或 provider 私有响应。测试需要 fake 时必须显式注入，不能打开生产 fake 分支。

生产只支持 OpenAI Responses 和 OpenAI-compatible Chat Completions。SDK/adapter 负责协议、stream、usage 与失败归一化；feature 自己拥有业务状态、事件、仓储、read-model 和完成语义。

## Agent 负责什么

Agent 负责需要语义判断的事情：

- 理解用户目标、约束和已有上下文。
- 选择工具、探索路径和工作顺序。
- 判断材料是否足够、是否继续、是否追问。
- 比较候选、处理冲突、综合结果和表达不确定性。
- Ordinary 的任务执行与最终回答。
- Multi-Agent 中 manager 的派生、审查、继续和 synthesis 决策。

模型输出、工具结果和 child 材料可以直接成为 Agent 的工作上下文，但是否成为某个 feature 的业务结论由 owning Agent/feature 决定。工程不能用关键词、固定阶段或伪工作流替 Agent 完成这些判断。

## 确定性工程负责什么

工程只守可验证边界：

- 外部输入 schema 与 provider 协议校验。
- 模型、工具和 Skill 的冻结能力边界。
- 工具权限、命令确认和工作区访问规则。
- 取消、预算、上下文容量和明确失败。
- 工具调用与结果配对、JSON-safe 事实和附件预算。
- feature 状态转换、原子持久化、事件顺序和 read-model 投影。
- 资源释放、测试、版本和审计引用。

这些规则说明“什么不能越界、如何记录、如何失败”，不能决定“用户真正要什么、该调用什么工具、哪个方案更好、是否应该继续探索”。

## 能力优先

不得以安全、摘要、脱敏、产品化文案或鲁棒性为名削弱模型：

- 普通回答、工具结果、错误、文件正文和 stdout/stderr 不得被固定摘要替换。
- UI 摘要只能是额外投影，不能覆盖模型历史或正式回答。
- 工具返回什么，canonical 上下文就保存模型实际消费的那份事实；不能从展示文本回填或猜测缺失内容。
- 有界读取工具返回当前页和下一位置，模型需要更多内容时再次调用工具；不建设替模型思考的通用“续读工作流”。
- 超大且无法内联的单次结果可以使用 `ToolOutputStore` 做 live transport，但引用失效必须明确失败，不能伪造 durable memory。

## 状态与事实

- Ordinary 使用 `ordinary-run/v5` 保存 Session refs、工具事实、状态、usage 和 timeline；模型消息由 Pi Session 保存，Panel 只消费 Ordinary read-model。
- Multi-Agent 使用自己的 Deep state、events 和 file stores，不读取 Ordinary snapshot。
- Sub-Agent 是 Ordinary AgentTool；其调用和结果只形成 Ordinary 标准工具事实。
- 中性 `ToolCallResult`、`ModelUsage` 和协议错误可以复用；业务事件、完成语义和恢复规则不能跨 feature 统一。

## 失败与取消

配置错误、provider 失败、context overflow、预算耗尽、工具交付失败、确认等待和取消都必须保留真实状态。不得：

- 把暂停、确认等待或取消投影为 completed。
- 在 provider 失败时生成固定成功回答。
- 在可见流已经输出后无身份地透明重试整轮。
- 丢失 live continuation 后伪造可恢复。
- 让 route、UI 或 adapter 根据文案重新推导业务状态。

## 命名与抽象

普通文件编辑、命令、helper、adapter、状态更新或一次模型调用使用朴素名称。只有真正做多 child 探索和父层综合时才使用 Deep/Multi-Agent 语义；只有具有稳定消费者和机械语义时才提取共享能力。

不建设 universal Run runtime、全局业务事件总线、统一状态机、工作流 DSL 或 service locator。成熟库可以替代机械实现，但不能成为第二事实源或接管 feature 状态。

## 验证原则

- 确定性契约使用正常单元/集成测试；非确定性回答质量使用 eval。
- 行为测试优先于源码字符串和固定文件名测试。
- 重要路径覆盖成功、失败、取消、确认、恢复和资源释放。
- 外部 SDK 只在 adapter 测试与显式真实 smoke 中出现；默认测试不访问真实网络。
