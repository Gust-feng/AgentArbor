# 土壤治理

## 定位

土壤是固定资产与治理层。它保存系统长期可以依赖的资产和规则，但不保存未经治理的临时输出。

土壤的质量决定树能否继续生长。如果所有运行记录都直接进入土壤，系统会很快被噪声污染；如果沉淀过严，系统又无法从真实任务中成长。

## 土壤内容

土壤可以保存：

- Capability Asset。
- 经治理的工作流片段。
- 经验证的工具、模型、MCP、插件和外部服务适配。
- 可靠的验证规则和评分规则。
- 稳定偏好、约束和权限策略。
- 经确认的失败模式。
- 可检索研究资料和架构资料。
- Fruit 的版本、谱系和退役记录。

土壤不直接保存：

- 未验证聊天内容。
- 临时任务中间文本。
- 单次运行的原始流水。
- 未归因的经验总结。
- 没有权限边界的 agent 文件。
- 平台适配层的偶然格式。
- 未经治理的 Fruit。

## 治理维度

每个进入土壤的资产至少需要记录：

- 来源：来自哪个目标、运行、证据和决策。
- 范围：适用于什么目标，不适用于什么目标。
- 信任：验证结果、人工确认和失败记录。
- 权限：可读、可写、可执行和敏感边界。
- 版本：当前版本、兼容性和迁移路径。
- 风险：误用风险、过期风险和回滚方案。
- 退役：何时修剪、降级、归档或删除。

## 反哺机制

```text
Soil
  -> Underground Center
  -> .agentarbor Direction Handoff
  -> Aboveground Center
  -> Growth Plan
  -> Aboveground Growth
  -> Fruits
  -> Governance Gate
  -> Soil
```

土壤不是被动资料夹，而是下一次任务的基础环境。Underground Center 必须从土壤开始探索；Aboveground Center 必须说明哪些土壤资产被采用、哪些被拒绝以及原因。Nutrient Request / Patch 也必须遵守同一土壤权限和治理边界。
