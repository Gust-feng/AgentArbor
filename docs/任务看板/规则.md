# 规则

## 定位

`docs/任务看板/` 是人类态势看板资产，不是计划源数据。它解决的是“我现在怎么看项目推进”的问题，而不是“任务状态在哪里存储”的问题。

源数据边界：

- `.trellis/tasks/` 保存任务真实状态、PRD、当前指针和生命周期。
- `docs/任务看板/` 保存从 Trellis 派生的人类可读投影视图。
- `docs/开发指南/` 保存稳定产品和开发口径。
- `docs/研究资料/` 与 `docs/架构设计/` 保存思想来源、研究材料和长期结构性判断。

## 文件职责

- `README.md`：目录入口，只说明怎么看、边界是什么、哪些文件负责什么。
- `看板.md`：主视图，包含前置任务、当前任务和未来方向。
- `规则.md`：维护协议，约束看板如何更新、压缩和避免变成第二套计划系统。

除非看板规模已经明显影响阅读，不新增其他文件。即便需要新增，也只能新增阶段级摘要，不能按任务一事一文件扩张。

## 三层视图

### 前置任务

前置任务只保留对当前理解有价值的关键任务。写法应压缩：

- 任务名。
- 完成结果。
- 对当前工作的意义。
- Trellis 链接。

不要复制 PRD 正文，不保存会话流水，不记录所有细节。

### 当前任务

当前任务是看板中最具体的部分，应包含：

- 当前 Trellis 指针。
- 进行中任务。
- 已完成但仍被当前指针指向的待收尾任务。
- 下一步。
- 阻塞点。
- 验收判断。
- Trellis 链接。

如果没有真正进行中的任务，应明确写出“无当前进行中任务”或“当前指针待收尾”，不能为了填满看板伪造任务。

### 未来方向

未来方向只记录未启动但值得保留的方向提示。每条最多写：

- 方向。
- 为什么重要。
- 启动条件。

未来方向不是承诺、排期或计划源。它不能替代 Trellis 任务创建，也不能在未确认时写成已启动任务。

## 压缩规则

- 一个当前任务完成后，压缩成前置任务的一行或一小段。
- 前置任务超过 7 条时，应合并为阶段摘要，并只保留关键节点。
- 阶段摘要优先写在 `看板.md` 中；只有主视图明显过长时，才允许新增一个阶段级摘要文件。
- 不按任务创建独立看板文件。
- 不把详细 PRD、进展日志、经验库或归档资料复制进看板。

## 更新时机

发生以下任一情况时刷新看板：

- 新建、启动、完成或归档 Trellis 任务。
- Trellis 当前指针变化。
- 阶段推进后，下一步发生变化。
- 用户询问当前任务、后续方向或计划状态。
- 正式开发指南或 ADR 改变了未来方向判断。

## 更新流程

1. 读取 Trellis 当前任务状态和当前指针。
2. 读取相关 `task.json` 与 `prd.md`。
3. 把当前任务写具体。
4. 把已完成关键任务压缩进前置任务。
5. 把未启动事项写成未来方向，并标明启动条件。
6. 检查 `README.md`、`看板.md`、`规则.md` 的链接。
7. 如目录职责或入口发生变化，同步更新 `docs/README.md`、`AGENTS.md` 和 Trellis 治理指南。

## 禁止事项

- 不创建根目录 `Plan/`、`Plans/`、`plans/` 或 `PLANS.md`。
- 不让看板成为 Trellis 之外的第二套任务状态。
- 不按任务新建看板文件。
- 不把未来方向写成已承诺任务。
- 不复制完整 PRD、会话记录或沉淀经验。
- 不从看板直接修改 Trellis 任务状态，除非用户明确要求。
