# 资产管理

## 概述

资产管理负责让 Experience Candidate 在治理后成为 Capability Asset，并在过期、失败或被替代时完成修剪和退役。Seed Packet、Root Brief、Growth Plan、Run Memory 和 Root Callback 记录可以作为证据来源，但不能直接等同于长期资产。

## 资产类型

| 类型 | 说明 |
| --- | --- |
| Capability Asset | 经过治理的正式能力资产 |
| Workflow Asset | 可复用工作流片段 |
| Verification Asset | 验证规则、评分规则和检查模板 |
| Tool Asset | 工具、MCP、插件和外部服务适配 |
| Agent Asset | 经过治理的内部 agent 或果实 agent |
| Policy Asset | 权限、偏好、风险和审计规则 |

## 生命周期

```text
Experience Candidate
  -> Governance Review
  -> Capability Asset
  -> Versioned Use
  -> Evaluation
  -> Update / Retire / Fruit
  -> Soil
```

## 晋升要求

- 来源 Run Memory 清楚。
- 输入输出契约清楚。
- 验证证据足够。
- 权限边界明确。
- 适用范围和不适用条件明确。
- 有版本、维护责任和退役路径。

## 退役要求

资产在以下情况下应被修剪或退役：

- 验证反复失败。
- 适用范围过期。
- 权限风险过高。
- 被更稳定资产替代。
- 使用频率长期为零。
- 维护责任不清。

## 与土壤关系

土壤只保存通过治理门的正式资产。Run Memory、Experience Candidate、Seed Packet、Root Brief 和 Root Callback 可以被检索和评审，但不能直接作为土壤固定资产使用。
