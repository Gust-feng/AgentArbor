# 智能体应用孕育闭环

## 基本路径

AgentApp 孕育闭环是 AgentArbor 第一阶段必须证明的产品路径：

```text
自然语言场景
  -> Soil
  -> Underground Center
  -> .agentarbor Direction Handoff
  -> Aboveground Center
  -> Growth Plan
  -> Workflow IR
  -> Aboveground Growth
  -> 工程生成
  -> Verification
  -> Nutrient Request / Growth Plan Revision
  -> Fruits
  -> Governance
  -> Run Memory
  -> Experience Candidate
  -> Path Bias
  -> 文档与谱系
  -> 可导出 AgentApp 或 Fruit
```

## 产品判断

AgentArbor 必须保留这些判断：

- 用户应该能从业务场景或自然语言目标开始，而不是从框架配置开始。
- 系统应该生成可运行、可修改、可测试、可部署的智能体应用工程，而不是只输出说明文档。
- 生成结果必须包括智能体分工、工具、工作流、提示词、配置、测试和文档。
- 方向交接、执行计划、验证、谱系和治理必须形成闭环。

## 必须具备的结构

如果只停留在“生成垂直 Agent 应用”，AgentArbor 会被压扁成脚手架。当前产品主线必须具备：

- 目标内核：目标持续存在并驱动后续状态。
- Direction Handoff：用户目标必须先经过地下中枢成形、反驳、证据探索和确认。
- Growth Plan：地上中枢必须形成执行前计划入口，并在 Nutrient Patch 后可修订。
- Workflow IR：工作流可暂停、恢复、分叉和验证。
- Aboveground Growth：任务由有边界、有交付物、有生命周期的协作单元推进。
- Verification：生成结果必须经过检查。
- Fruits：交付物和候选沉淀必须明确归属。
- Governance：能力进入长期资产前必须经过评估。
- 运行沉淀：每次任务必须产生 Run Memory、Experience Candidate 和 Path Bias。
- 谱系系统：AgentApp、能力和子 agent 的来源必须可追踪。

## 智能体应用的出生条件

一个智能体应用不能只因为目录生成成功就算出生。至少要满足：

- 有明确目标和非目标。
- 有 Direction Handoff。
- 有引用 Direction Handoff 的 Growth Plan。
- 有运行组织的职责边界。
- 有能力与权限声明。
- 有 Workflow IR 或等价任务图。
- 有可运行工程结构。
- 有测试或验收样例。
- 有 Run Memory、Experience Candidate 和 Path Bias。
- 有文档入口。
- 有谱系记录。
