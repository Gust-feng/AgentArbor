# 运行时组织模型

## 组织形态

AgentArbor 运行时根据 Growth Plan 选择组织形态，而不是预设固定角色表。

| 形态 | 适用场景 | 输出 |
| --- | --- | --- |
| Seed Cluster | 用户想象需要前置成像、反驳、最小化搜索和用户确认 | Seed Packet |
| 单 agent | 目标简单、风险低、验证清楚 | Artifact、Verification、Run Memory |
| Root System | 目标不清、资料多、路径选择多，或运行中需要补探 | Root Brief vN |
| Branch System | 任务需要多职责协作和阶段协调 | Artifact、Verification、Run Memory |
| 多阶段工作流 | 任务依赖复杂、需要暂停恢复 | Workflow IR 执行记录 |
| 果实运行 | 已有成熟能力可独立承担 | Fruit 输出和运行记录 |

## 决策顺序

```text
Imagination
  -> Seed Cluster
  -> Seed Packet
  -> User Approval Gate
  -> Soil
  -> Root System
  -> Root Brief vN
  -> Core Control Cluster
  -> Growth Plan vN
  -> Router
  -> Branch / Leaf
  -> Flower
  -> Root Callback / Run Memory
```

Core Control Cluster 必须决定：

- 是否采用 Path Bias。
- 是否复用 Capability Asset。
- 是否需要单 agent、集群或多阶段工作流。
- 哪些节点需要 Verification 和 Acceptance。
- 哪些结果需要形成 Run Memory 或 Experience Candidate。
- 哪些失败、未知项或目标变化需要触发 Root Callback。

## 状态和通信

运行时状态必须由状态机驱动。agent 之间不能私下通信。

允许：

- 通过 MessageBus 发送同步请求。
- 通过 Router 分配任务。
- 通过 EventLog 记录状态变更。
- 通过 ArtifactStore 保存产物。

禁止：

- agent 私下绕过消息系统调用另一个 agent。
- 用聊天内容替代结构化交付物。
- 用历史 Path Bias 替代本次验证。
- 用平台适配文件替代 AgentArbor 原生运行语义。
- 用 Seed Cluster 替代执行层。
- 用第一次 Root Brief 锁死后续运行。
