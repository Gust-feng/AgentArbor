# 移动端工作台界面

## 设计定位

移动端是桌面 Workbench 的远程协同入口，不是桌面端的缩小版，也不是聊天记录浏览器。移动端最重要的对象是对话所属的 Space；用户先进入归属，再阅读或发起对话。

Conversation 的长期 Space/Workspace owner 与迁移边界以 [ADR-0036](../../架构设计/产品架构/ADR-0036-Conversation归属与移动工作台信息架构.md) 为准。本指南只描述当前可实现的界面口径，不能用视觉占位替代尚未出生的 WorkspaceFeature。

正式信息架构固定为：

```text
首页 → Space → Conversation
                  └─ 对话内容与运行状态
Space
  ├─ 对话
  └─（未来）笔记 / 资料
```

首页只承担“选择归属并开始新对话”。不得恢复全局“最近对话”、与 Space 无关的旧文件入口或平行的主要导航。当前侧栏只保留 Space 切换、创建和设置；知识库与内容冲突入口在后续内容 surface 出生前不得出现。

## 当前移动协同阶段范围

当前阶段只交付会话闭环：选择 Space、查看该 Space 的会话、发起或继续会话、接收运行状态、处理确认、离线排队和返回归属。移动端暂不交付文件管理器、笔记编辑器、资料树、知识库浏览和内容冲突处理界面。

这不是删除内容能力。Space、Personal Knowledge、受管文本和 Content Vault 的后端契约、同步投影与持久化继续保留，未来内容界面应复用这些公开端口；当前 UI 不应为了“预留入口”展示空卡片、文件 Tab 或不可用的编辑按钮。

## 设计原则

移动端采用成熟工作台的克制风格：

- 默认层只保留当前对象、下一步动作和会改变行为的 attention；常规成功、实现类型、路径、计数和原始日志进入详情。
- 当前只使用会话表面语法：对话是可读的连续文本，设置是稳定的决策列表。资料行与内容冲突提示属于后续内容 surface，不提前以空状态或占位入口出现。
- 通过空间、阅读宽度和侧栏出现来表达状态变化，避免用大标题、渐变、厚重阴影或连续弹窗制造“高级感”。
- 使用 Material 3 语义 token（`--md-sys-color-*`、`--md-sys-typescale-*`、`--md-sys-shape-*`）表达颜色、文字和形状；组件只使用语义角色配对，不在页面规则中重新发明色板。
- 表面优先使用 tonal surface 层级表达深度，默认不依赖阴影；按钮、芯片和可点击行使用 `full` / `small` / `medium` 等 shape token，避免散落的圆角数值。
- 间距以 4/8dp 节奏为基础，所有交互控件的可触区域至少为 48dp（CSS 中为 `--aa-mobile-hit-size`）；窄屏优先保证标题、正文和主操作可读，次级元数据允许换行或折叠，不得挤压输入框。
- 按 Material 3 窗口尺寸类做渐进适配：compact（手机）保持单列，medium/expanded（平板或横屏）增加阅读宽度但限制正文最大宽度，避免把手机界面简单拉伸。
- 所有可操作元素必须有可见的键盘/辅助技术焦点，实时会话流在流式期间不逐 token 播报，弹层打开时主路由应从辅助技术和焦点顺序中暂时隔离。
- 语义色只用于归属识别、等待和失败等有行为后果的状态；Space 色点是身份线索，不是装饰分类。

## 各页面的默认层

### 首页

首屏阅读顺序是“Space 列表 → 进入某个 Space → 在该 Space 开始新的对话”。模型选择、连接状态和离线提示只在新对话输入区作为次级上下文出现。没有 Space 时应解释为什么必须先创建 Space；不得允许无归属对话偷偷落入全局列表，也不在首页以输入框抢占 Space 选择层级。

### Space

顶部只显示返回、当前 Space 名称和侧栏入口。正文使用紧凑的“在此空间开始对话”动作，随后展示该 Space 的对话。当前阶段只展示对话；笔记、资料和文件入口延期到后续内容 surface，不在移动端 Space 首层渲染。

### Conversation

标题与 Space breadcrumb 放在同一组双行 header 中，breadcrumb 可点击回到 Space。正文保持受控阅读宽度：用户消息靠右、助手正文按文档节奏展示，工具活动、确认和原始输出按需展开。运行中、待确认、失败等状态只在改变用户行为时占据状态行。

## 归属与同步边界

Conversation 的归属是数据事实，不由移动端根据路径或标题推断。当前协议只稳定支持 `spaceId`；Workspace 归属必须等待正式 WorkspaceFeature 和 `OwnerRef = { kind, id }` 契约，同时贯穿桌面、Relay、Vault、pending/outbox 和移动投影后再开放入口。不得把桌面路径写入移动端、Relay、Vault 或 localStorage。

内容 surface 恢复后，同步冲突必须投影到所属 Space，并在对应内容行提供单一 attention cue；设置页只提供总览。当前阶段的离线待发送项必须保留在原 Space 内，重连后只能转正一次。

## 验收清单

- 首屏一秒内能看出当前归属和下一步动作。
- 不存在全局最近对话、文件 Tab、知识库首层入口或无主 Conversation 入口。
- Space → Conversation → 返回的栈关系稳定，Android 返回先关闭最上层 sheet/drawer，再退出当前页面。
- 常规完成状态保持安静；运行、待确认和失败有清晰且可行动的提示。内容冲突属于后续内容 surface 的验收项。
- 390px、320px 宽度下输入框、标题、48dp 触控目标和底部安全区均不被挤压；600px 以上窗口仍限制会话正文阅读宽度。
- 会话正文、确认和运行证据完整可达；资料与文件的移动端浏览不属于当前阶段。

## Material 3 实现口径

当前移动端是 React/Vite WebView，而不是独立的 Jetpack Compose 页面。因此采用 Material 3 的 Web 兼容路径：CSS 语义 token 加原生 HTML/React 组件，不新增一套平行组件库。Android 原生壳只负责系统栏、窗口安全区和返回事件；视觉组件的颜色、类型、形状和布局事实集中在移动端样式与组件中。

主题先提供稳定的 light/dark baseline scheme，并为后续 Android 12+ 动态颜色接入保留语义角色边界。动态颜色接入时只替换 `--md-sys-color-*` 的 scheme，不修改页面组件选择器或业务状态映射。

当前发布面只实现会话相关的 app bar、navigation drawer、list、dialog、bottom sheet、text-field-like composer、approval card 和 feedback state。文件、知识库、编辑器和冲突样式即使保留在代码中，也不属于当前导航或验收范围，出生时应作为独立内容 surface 评审。
