# 系统总览

## 架构图

```text
用户提示词
  -> Imagination
  -> Seed Cluster
  -> Seed Packet
  -> User Approval Gate
  -> Soil
  -> Initial Rooting
  -> Root Brief
  -> Core Control Cluster
  -> Growth Plan
  -> Workflow IR
  -> Branch / Leaf Runtime
  -> Flower Verification / Acceptance
  -> Root Callback / Re-rooting
  -> Run Memory
  -> Experience Candidate / Path Bias
  -> Governance Gate
  -> Capability Asset / Fruit / Retire
```

## 分层原则

- Imagination 是用户提示词中的原始想象，不能直接进入正式运行。
- Seed Cluster 负责前置成像、最小化搜索、反驳、风险识别和用户确认。
- Seed Packet 是启动种子包，用户确认后才可以种入 Soil。
- Soil 保存固定资产、长期证据和治理规则，不接收未经治理的临时输出。
- Root System 负责 Initial Rooting、Lateral Rooting 和 Deep Rooting，不是一次性前置调研。
- Root Brief 是根系探索输出，必须版本化并保留证据来源。
- Core Control Cluster 负责综合判断、制定 Growth Plan、触发 Root Callback 和修订计划。
- Growth Plan 是执行前入口，必须引用具体 Root Brief 版本。
- Branch / Leaf Runtime 负责执行任务，不能绕过 MessageBus、Router 和状态机。
- Flower Verification 与 Acceptance 判断结果是否成立，不能由执行者自我放行。
- Run Memory 记录本次运行经验，Experience Candidate 记录可复用候选，Capability Asset 才能进入土壤。
- Adapter 只做外部格式转换，不能定义核心产品模型。

## 目录对应关系

- `docs/`：人类可读指南和资料库。
- `.trellis/`：当前开发 AgentArbor 仓库时的 AI 工作流。
- `.agents/`：官方 Agent Skills 兼容层。
- `.codex/`：Codex 开发适配层。
- `.opencode/`：OpenCode 开发适配层。
- `.agentarbor/`：未来 AgentArbor 原生机器可读资产层。
- `src/`：未来 TypeScript 实现。

开发时不能把这些目录的职责混用。
