# 花层（Flower Cluster）- 验证与成熟判断

## 职责

花层负责验证、评审、成熟度判断和交付前确认。它判断结果是否成熟到可以交付、沉淀、晋升或脱离。

Flower Cluster 不是执行层，也不是最终用户确认的替代品。

## 核心职责

| 职责 | 输出 |
| --- | --- |
| Verification | 验证报告、失败证据、通过证据 |
| Acceptance Review | 验收建议、用户确认请求 |
| Debt Review | 技术债、结构债、测试债和文档债判断 |
| Maturity Review | 是否可以形成 Fruit、Capability Asset 或 Experience Candidate |
| Root Callback Suggestion | 是否需要补探、重探或修订 Growth Plan |

## 验收矩阵

```text
验收维度：
├── 功能验收：需求用例是否通过
├── 自动测试：单元、集成、端到端或等价检查
├── 代码质量：lint、typecheck、build 或项目等价门
├── 架构健康：边界、重复、局部最优和技术债
├── 文档完整性：入口、索引、契约和交接
├── 权限安全：最小权限、敏感边界和审计证据
└── 成本与时延：运行成本、工具成本和可持续性
```

## Root Callback 关系

Flower Cluster 发现以下问题时，应发起或建议 Root Callback：

- 验证失败来自上游事实或目标理解错误。
- 当前 Growth Plan 的核心前提不成立。
- Path Bias 与本次证据冲突。
- 验证要求暴露出新的未知项。

Flower Cluster 不能自行修订 Growth Plan。修订必须交回 Core Control Cluster。

## 禁止事项

- 不执行叶层任务。
- 不替代用户确认。
- 不把验证通过直接等同于长期资产入土。
- 不把失败隐藏为“需要后续优化”。
