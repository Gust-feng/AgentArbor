# 前后端与用户视图

## 后端是运行事实源

普通 Agent 的真实工作能力、运行状态和恢复语义必须由后端负责。

要求：

- 后端负责上下文装配、模型调用、工具可见性、工具执行、命令确认门控、状态流转、事件投影和持久化。
- 前端负责发起请求、订阅事件、展示 read-model、提交命令确认决定。
- 默认用户视图必须由后端直接给出，而不是由前端从一堆内部结构中推导。
- 恢复运行和历史运行的 read-model 必须只使用 run 创建时冻结的 capability snapshot 和 information access；缺失这些出生事实的开发期旧记录直接失效，不能用当前配置、旧 model call 或 UI 状态回填。
- live run view 必须优先读取已进入终态 payload 的 capability resolution、结果详情和运行投影；只有运行尚未产生终态 payload 时，才允许回退到 job 创建时的兼容字段，避免结算后 read-model 显示过期事实。

禁止事项：

- 前端从 `canvas`、`detail`、调试字段或历史兼容结构反推当前 Agent 状态。
- 前端承担命令确认恢复、工具结果语义解释或运行完成判定。
- 为了省事把后端边界让给前端组件。
- 结算后继续用旧 job 字段覆盖 completed / blocked / failed / cancelled payload 中已经冻结的运行事实。

## 默认用户视图必须做减法

普通 Agent 的默认用户视图只服务于当前任务完成，不服务于内部架构炫示。

默认应该优先展示：

- 当前状态
- 正在做什么
- 命令确认
- 最终结果
- 关键工具动作
- 失败原因
- 下一步

默认不应首屏化展示：

- token / budget 细节
- 模型协议 continuation、内部 token 计量细节
- raw refs / debug refs
- canvas 内部结构
- deep / rootlet / convergence 等长期架构术语

禁止事项：

- 为了“透明”把内部结构直接堆到默认面板。
- 在普通路径首屏展示 deep、Plan、Agent cluster 或调试导向文案。
- 用花哨状态文案掩盖真实的工具行为和失败原因。
