# 术语表

## Desktop Shell（桌面工作台）

Desktop Shell 是 AgentArbor 的唯一用户入口。它包含 Task Inbox、Workspace Context、Main Canvas、Artifact Area 和 Observation Panel。用户不需要直接面对 Underground 或 Aboveground 两个内部 runtime。

## Default Agent / 普通 Agent

普通 Agent 是当前默认桌面会话入口，负责连续对话、模型工具循环、授权工具执行、命令确认、运行投影、持久化和用户可见结果。它不自动升级到 Underground，不派生 child/rootlet，也不把普通文件编辑或一次工具循环包装成 Plan / Handoff / deep flow。

## Deep / 深入 Agent 集群

Deep 是未来显式深入模式，用于需要目标成形、多路探索、child/rootlet 派生、父层综合、Plan 交接、执行组织和治理回流的任务。它不是废弃方向，但当前不作为默认入口，也不能反向污染普通 Agent 的工具可见性、事件投影、确认语义和用户文案。

## Task Soil（任务土壤）

Task Soil 是当前任务级临时土壤，保存当前任务目标、文件引用、项目上下文、网页材料、用户临时约束、权限边界和本轮运行材料。Task Soil 可以引用 Global Soil，但不能直接污染 Global Soil。

## Global Soil（长期土壤）

Global Soil 保存经过治理的长期偏好、Capability Asset、Path Bias、历史约束、失败模式和长期事实。临时运行记录、单次总结和未验证候选不能直接进入 Global Soil。

## Underground Cognitive Runtime（地下认知运行时）

地下认知运行时负责方向智能：目标成形、多路探索、动态派生 child agent、父层综合、裁决、追问或停止。它输出 Plan、Nutrient Patch、Plan vNext、用户澄清请求或停止依据，不执行正式任务，不写长期资产。

## Shared Agent Kernel（共享 Agent 内核）

Shared Agent Kernel 是地下和地上共同使用的能力内核，包括 `AgentLoop`、`AgentTurnRuntime`、`ToolCenter`、`WorkspaceView`、`Mailbox`、`Guard`、`Trace`、预算和权限边界。

## Agent Fabric

Agent Fabric 是动态派生 child agent 的执行机制，不是产品入口。MVP 阶段只允许一层 child agent；child/rootlet 输出必须经过父层 synthesis / convergence 才能进入 Plan。

纯函数、helper、adapter、formatter、文件编辑动作或状态更新不应命名为 agent。只有具备目标理解、上下文判断、行动选择、输入输出契约和可观察运行边界的执行主体，才应使用 agent 命名。

## Plan

Plan 是 Underground 到 Aboveground 的产品级交接对象。它保存任务方向、证据、约束、风险、不确定性、执行入口和验证要求。Plan 不是长期资产，也不是最终交付物。

## Plan Package / `.agentarbor`

Plan Package 是 Plan 的可持久化形态，支持暂停恢复、版本管理、人类可读、审计复盘和跨进程消费。`.agentarbor` 是 Plan Package 的实现/存储形态或目录名，不再作为独立产品概念树节点。

## Aboveground Execution Runtime（地上执行运行时）

地上执行运行时读取 approved Plan，执行文件修改、文档生成、原型制作、工具调用和验证。它不能自建方向探索集群；信息不足时必须发起 Nutrient Request。

## Workflow IR（工作流中间表示）

Workflow IR 用于表达执行任务图、依赖、状态、输入输出、恢复点、失败处理和验证门。它由 Aboveground 从 Plan 派生，不能绕过 Plan 和权限边界。

## Constraint Engineering（约束工程）

约束工程把目标、非目标、权限、成本、时间、技术边界、安全要求、人工确认、验收门和资产治理转化为可执行契约。它让约束贯穿 Task Soil、Plan、Aboveground 执行、Fruits、Governance Pipeline 和回流后的 Global Soil。

## Constraint / ConstraintRef（约束与约束引用）

Constraint 是约束事实源。ConstraintRef 是 Plan、Execution Plan、TaskSpec、Verification Result、Capability Asset 和 Fruit Detachment 对约束的引用。自然语言约束说明可以保留，但不能替代可执行约束引用。

## Nutrient Request（养料请求）

Nutrient Request 是 Aboveground 向 Underground 请求养料的机制。它用于证据不足、Global Soil 资产适配不足、外部事实缺口、约束细节不足、上下文缺口、Path Bias 失效、关键假设被证伪或治理证据不足等场景。Aboveground 不能用自建方向探索集群替代 Nutrient Request。

## Nutrient Patch（养料补充包）

Nutrient Patch 是 Underground 对 Nutrient Request 的结构化回应。它补充证据引用、Global Soil 资产引用、ConstraintRef、风险更新、假设判断和对执行的影响；必要时生成 Plan vNext。

## PathMemory（路径记忆）

PathMemory 是历史实验中的单次稳定终态运行路径档案。当前生产不创建、不采集、不读取、不注入，也不作为新路径依赖的迁移来源。

## PathDependency（路径依赖）

PathDependency 是当前生产的程序性记忆：模型在任务完成后主动提炼并保存的可复用方法论。它保存适用条件、验证方式和失败边界，不保存 transcript、原始工具序列或盲目回放脚本；未来相似任务由模型通过有界目录、`MemorySearch` 和 `MemoryRead` 自主决定是否复用。

## Experience Candidate（经验候选）

Experience Candidate 是历史治理构想中从 PathMemory 提取的可复用经验候选。它当前未出生，不能被当作 PathDependency 的兼容名称或生产输入。

## Capability Asset（能力资产）

Capability Asset 是经过治理后进入 Global Soil 的正式能力资产。它必须有来源、输入输出契约、权限边界、版本、验证记录、适用范围和退役路径。

## Path Bias（路径倾向）

Path Bias 是历史运行对新任务的路径牵引。第二次遇到相似任务时，系统不会强行复刻上一次流程，但会倾向于参考已验证路径。Path Bias 只能影响 preference 和方案排序，不能覆盖 hard constraint。

## Intelligence Runtime / Intelligence Channel（智能运行时 / 智能通道）

智能运行时是 AgentArbor 调用模型的统一横切能力。它负责模型请求、provider adapter、模型响应、用量、失败和观测事件。单次模型、rootlet、工具或搜索输出只能作为候选材料，必须经过父层 agent 综合和确定性边界守卫后才能进入正式材料。

## Observation Panel（监督面板）

Observation Panel 是 Desktop Shell 的监督视角，展示 agent run tree、child 输出摘要、父层 synthesis、convergence 事件、模型和工具 refs、budget 和 trace。默认普通 Agent 阶段优先展示运行投影和真实工具/模型可见内容，不以脱敏或安全投影吞掉普通输出。

## Ring Memory（年轮记忆）

Ring Memory 是 EventLog、PathMemory 和 Experience Candidate 的聚合视图，用于观察系统如何在多次运行中生长。它不是新的平行事实源。

## Fruit（果实）

Fruit 是一次任务形成的交付物或候选沉淀，可以是报告、文档、代码改动、原型、PathMemory、Experience Candidate、能力候选或少数可脱离 agent。Fruit 必须经过 Governance Pipeline 才能进入 Global Soil。

## Governance Pipeline（治理管线）

Governance Pipeline 决定 Experience Candidate 是否可以成为 Capability Asset，Fruit 是否可以脱离母体运行，以及过时资产是否需要修剪或退役。

## Adapter（适配器）

适配器连接外部平台、模型、工具或协议。适配器负责格式转换，不负责定义 AgentArbor 核心产品语义。

## Atomic / 原子语义

Atomic 只用于真正有事务边界的工程场景，例如全成功/全失败、失败不落盘、明确回滚或一致性保证。普通用户可见动作优先使用“编辑”“补丁”“变更集”等朴素名称，不能为了显得高级把普通修改命名为原子修改。
