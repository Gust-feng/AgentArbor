# ADR 0003：能力资产注册表

## 状态

Accepted

## 背景

AgentArbor 需要生成、运行、测试、验证 AgentApp。

这个过程会涉及：

* 不同模型供应商。
* Tool calling / structured output / streaming 等协议差异。
* MCP server、resources、tools、prompts。
* Skill、Plugin、Tool、Runtime、Sandbox。
* 构建、测试、评测和权限策略。

如果每次构建 AgentApp 时再临时查找资料或临时写接入逻辑，AgentArbor 将无法复现、无法测试、无法审计，也无法解释为什么选择某个能力。

## 决策

AgentArbor 建立能力资产注册表。

能力资产以机器可读文件沉淀在：

```text
assets/
```

人类可读资料卡沉淀在：

```text
docs/04-参考沉淀/能力资产/
```

AgentArbor 构建 AgentApp 时，必须优先从能力资产注册表中选择能力。

## 资产类型

第一版支持以下资产类型：

```text
ProviderProfile
ProtocolAdapter
Tool / Toolpack
Skill
RuntimeProfile
SandboxTemplate
Evaluator
PermissionPolicy
AgentBlueprint
```

## 状态模型

资产必须标记状态：

```text
seed
draft
verified
trusted
deprecated
```

默认规则：

* `seed` 只能作为资料来源。
* `draft` 可用于原型开发。
* `verified` 可进入受控执行链路。
* `trusted` 可作为默认自动选择候选。
* `deprecated` 不再进入新生成链路。

## 安全边界

外部资产默认不可信。

以下资产必须经过权限和安全审查：

* 远程 MCP server。
* 外部 Skill。
* CLI / shell 工具。
* 需要网络的工具。
* 需要密钥的 Provider。
* 可以写文件或执行代码的 Runtime。

## 资产快照

每个生成的 AgentApp 必须记录使用过的资产快照。

建议路径：

```text
.agentarbor/assets-snapshot/
```

资产快照用于复现、审计和后续演化。

## 影响

后续开发不应把模型供应商、工具协议、沙箱环境、Skill 或权限策略硬编码在业务流程里。

正确方式：

```text
Capability Registry
  -> Asset Resolver
  -> Policy Validator
  -> AgentApp Generator
  -> AssetSnapshot
```

如果目标需要的资产不存在，AgentArbor 应生成 MissingAsset / EnvironmentProposal，而不是绕过注册表临时安装或接入。
