# ADR-0033：模型自主笔记记忆架构

## 状态

已接受。修正 ADR-0032 的记忆主线方向；PathMemory 保留但降级为运行档案。

## 背景

ADR-0032 建立了"先可靠采集客观 PathMemory，再生成候选，再治理召回"的记忆路线。第一阶段落地后，对 62 条真实 PathMemory 记录的审计得出三个事实：

1. 69% 的记录是无工具调用的闲聊轮次（"你好"、"继续"、"？"），没有复用价值。
2. 有实质工具序列的记录只保存了工具名与耗时索引，看不出任务在做什么、怎么做成的。
3. 模型完全看不到任何记忆——采集、治理、检索三层都建了，注入层永远排在最后，Agent 实际获得的记忆能力为零。

同期成熟产品的记忆实现给出了相反的样本。Claude Code 的 auto-memory 让模型在工作中把学到的东西写进 `MEMORY.md`（"构建命令是 pnpm build"、"测试在 __tests__/"、"用户偏好函数式组件"），每次会话启动时读回；Codex CLI 的 Memories 在会话后由模型总结学到的内容写入 `~/.codex/memories/`，下次会话读回。两者的共同点：

- **记的是模型提炼的经验与知识，不是客观执行流水。**
- **模型自己写、自己读；工程只提供存储、注入和让用户可见可删的机械能力。**
- **治理手段是透明性**：记忆就是用户随时可读、可改、可删的纯文本，而不是审批流水线。

用户的方向判断与此一致："这些东西应该让模型主动去做，而不是工程代替模型智能。"这也正是 `AGENTS.md` 根规则"禁止工程边界替 Agent 思考"的直接推论——ADR-0032 用采集 schema、治理状态机和确定性检索代替了模型对"什么值得记住"的判断，属于工程越界。

## 决策

### 1. 记忆的正式定义修正

Agent 记忆是**模型自己认为值得沉淀的经验、知识与偏好**，以模型撰写的自然语言笔记形式存在。执行流水、工具调用序列、终态事实不是记忆，是审计档案。

### 2. 笔记是记忆的唯一事实源

- 每个工作区一本笔记（跟随 `workspaceRoot`），记项目级知识：结构、命令、约定、踩过的坑、已验证的解法。
- 一本全局笔记，记跨项目的用户偏好：语言、回复风格、常用工具链。
- 笔记是纯 Markdown 文件，存放在 runtime 目录下（`runtime/agent-notes/`），不进 git 仓库，不含 schema。

### 3. 模型主动写，工程不代笔

- 通过 `NoteWrite` 工具让模型在任何时刻主动记笔记；何时记、记什么、怎么组织，完全由模型判断。
- 系统提示词提供记笔记的指引（何类信息值得沉淀），但不设关键词规则、不设自动触发、不做后台自动总结。
- 工程侧只做机械保障：原子替换、大小上限、版本冲突和可观察投影，不截断或改写笔记正文。
- 一次 run 启动时同时冻结注入正文与两本笔记的 SHA-256 内容版本。`NoteWrite` 只能基于该 run 当前持有的版本全量替换；同一 scope 的 Agent 写入由 `AgentNotesFeature` 串行化，仓储在每次 rename 尝试前重新比较磁盘正文。其他 run 或用户直接编辑文件后，旧写入必须返回当前完整正文与版本，不能静默覆盖。
- 冲突结果不会自动授权下一次写入。模型合并当前正文后，必须把冲突返回的 `currentVersion` 显式作为 `baseVersion` 重试；缺少确认或版本再次变化时继续拒绝写入。缺少 run-born 版本的旧 run 只读，不允许盲写。
- Panel 的 runtime-directory lease 排除第二个 AgentArbor 写者。外部编辑器不遵守该 lease，因此“比较版本到单次 rename 系统调用”之间仍存在无法用普通 Markdown 文件消除的极小竞态窗口；每次 Windows rename 重试前重新比较可避免把退避窗口扩大为静默覆盖。若未来要求跨任意编辑器严格线性化，必须改变“用户直接编辑同一个 Markdown 文件”的产品边界，不能伪称现有文件系统操作是绝对 CAS。

### 4. 启动时全文注入，不做检索

笔记随系统提示词全文注入每次 run；工作区作用域使用 capability snapshot 已冻结的 workspace，不使用 Host 进程的临时 cwd。当前笔记量级（单文件、数 KB）远低于需要检索的门槛；检索、压缩、分层召回等机制只有在笔记体量出现真实压力后按需出生（对应 Claude Code 只注入 MEMORY.md 前 200 行的同类约束，先用大小上限实现）。

### 5. 治理即透明

- 笔记就是 runtime 下可直接打开、编辑、删除的 Markdown 文件，用户的编辑权就是治理权。设置页的笔记编辑器是后续 Panel 增量，不是本批前置条件。
- 不为笔记建立 propose/accept 审批链。ExperienceCandidate 的治理机制保留给未来"候选能力入土 Global Soil"场景，不再作为记忆注入的前置门槛。

### 6. PathMemory 降级为运行档案

PathMemory 继续按 ADR-0032 采集，定位改为：给用户看的运行审计记录、以及未来诊断/统计的数据源。它不再是"记忆回流链路"的第一层，不承诺进入模型上下文。`/api/path-memory/*` 与设置页管理视图维持现状。

### 7. 所有权

新增 `src/app/agent-notes/` feature，拥有笔记的契约、存储、读取、注入投影、版本比较与测试。`NoteWrite` 工具通过既有 `AgentToolRegistryContribution` 机制由 Host 装配；注入通过 `prepareOrdinaryRunBirth` 组装 instructions 时拼接，对应的两个内容哈希作为可选 run-born 事实进入 `OrdinaryRunBirth`。正文不在 run state 中重复保存。不新建平行 runner、事件或 read-model。

## 与 ADR-0032 的关系

- §1（记忆定义）、§4（回流链路）、§8（检索晚于治理）中以 PathMemory 为记忆主线的表述被本 ADR 取代。
- §2/§3/§5/§6/§7（采集机制、写入分离、所有权、稳定终态时机、不复制大正文）对 PathMemory 作为运行档案继续有效。
- ADR-0032 对"模型自由总结直接注入，形成不可追溯自我强化"的担忧，由透明性化解：笔记全程用户可读可改可删，注入内容与笔记文件逐字一致，没有隐藏加工层。

## 不采用

- 后台自动总结会话生成记忆（模型在工作中主动记，而不是工程定时代记）。
- 向量检索、embedding、记忆分层召回（笔记量级不需要；未来按真实压力评估）。
- 笔记审批流（透明可编辑即治理）。
- 把 transcript、工具输出或用户原话自动抄录为记忆。

## 后果

- Agent 第一次真正拥有跨会话记忆，行为与 Claude Code / Codex 的记忆体验对齐。
- 记忆质量取决于模型的判断，符合"工程守边界、模型做判断"的根规则；坏笔记的纠正手段是用户直接改文件。
- PathMemory 的既有投入不废弃，转为审计与诊断价值。
