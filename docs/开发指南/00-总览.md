# 总览

## 本指南解决什么问题

本指南给 AgentArbor 后续实现提供统一口径。它回答四个问题：

1. AgentArbor 到底是什么。
2. AgentArbor 要用什么核心闭环证明价值。
3. 系统边界、数据契约、Agent 生命周期和平台适配如何分层。
4. 第一阶段实现边界是什么，什么算通过验收。

## 产品主线

AgentArbor 的当前产品主线是：

```text
Desktop Shell
  -> Task Soil
  -> Underground Cognitive Runtime
  -> Plan
  -> Aboveground Execution Runtime
  -> Fruits
  -> Governance Pipeline
  -> Global Soil
```

这条主线表达桌面通用 Agent 的长期完整任务闭环：Desktop Shell 接收任务和工作区上下文；Task Soil 保存本轮任务材料；默认普通 Agent 先在这套边界内完成连续会话、模型工具循环、命令确认、运行投影和结果展示；Agent 集群 beta 模块已通过当前 `deep` / `DeepRuntime` 实现暴露一层 child 最小协作闭环，长期完整 deep / Agent 集群再由 Underground Cognitive Runtime 通过 AI-first agent 协作完成目标成形、多路探索、父层综合和裁决；Plan 承接地下收束结果；Aboveground Execution Runtime 按 Plan 进行执行和验证；Fruits 保存交付物和候选沉淀；Run Memory 和 Experience Candidate 经过 Governance Pipeline 后，才允许以 Capability Asset、Path Bias、长期约束或失败模式回流 Global Soil。

长期产品架构事实源是 [ADR-0022-AgentArbor桌面通用Agent与双运行时架构](../架构设计/产品架构/ADR-0022-AgentArbor桌面通用Agent与双运行时架构.md)。当前默认普通 Agent 路线是 [ADR-0024-桌面基础Agent与基础设施优先路线](../架构设计/产品架构/ADR-0024-桌面基础Agent与基础设施优先路线.md)：继续优先打磨默认普通桌面 Agent。Agent 集群 beta 最小协作闭环是 [ADR-0025-deep一期Manager自由决策循环与一层child最小闭环](../架构设计/产品架构/ADR-0025-deep一期Manager自由决策循环与一层child最小闭环.md)：用户侧文案使用“Agent 集群”，内部 API / 实现仍可称 `deep` / `DeepRuntime`。普通路径不自动升级、不混入 deep 编排。

## 当前稳定结论

- AgentArbor 是桌面通用 Agent，不是泛聊天助手、完整 IDE、终端代理或一次性脚手架。
- 当前默认产品体验优先打磨普通桌面 Agent：连续对话、模型工具循环、命令确认、运行投影、会话持久化和工作台结果展示。
- 避免过度设计指的是普通路径命名和实现语义必须朴素准确，不是删除 deep / Agent 集群长期架构。
- 用户只面对统一 Desktop Shell；默认启动进入普通桌面 Agent。Panel 不提供“桌面 Agent / 多 Agent”顶部切换；Agent 集群只作为 `设置 -> 关于` 启用后的 beta 侧栏入口出现，deep、Underground 和 Aboveground 仍是内部实现或长期架构术语，不作为用户可见产品入口文案。
- Desktop Shell 包含 Task Inbox、Workspace Context、Main Canvas、Artifact Area 和 Observation Panel。
- Task Soil 是当前任务级临时土壤，保存用户目标、文件引用、项目上下文、网页材料、临时约束、权限边界和本轮运行材料。
- Global Soil 是长期土壤，保存长期偏好、Capability Asset、Path Bias、历史约束、失败模式和治理后的长期事实。
- 普通 Agent 不自动升级到 Underground，不派生 child/rootlet，不把普通文件编辑、helper、adapter、状态更新或一次工具循环包装成 Plan / Handoff / deep flow。
- 子 Agent 是普通 Agent 的工具能力（`call_sub_agent` / `call_sub_agents` / `spawn_sub_agent`），模型在普通会话中可自主调用专家子 Agent 完成代码、文档、研究、评审和测试等子任务；子 Agent 不能递归派生，输出是局部材料由父层模型决定如何使用（见 ADR-0026）。
- Underground Cognitive Runtime 负责方向智能：目标成形、多路探索、动态派生 child agent、父层综合、裁决、追问或停止；当前 Agent 集群 beta 已落地一层 child 最小闭环，但不进入默认普通路径。
- Aboveground Execution Runtime 负责执行智能：消费已成形 Plan，完成文件修改、文档生成、原型制作、工具调用、验证和交付；当前作为长期架构边界保留。
- Shared Agent Kernel 提供 `AgentLoop`、`AgentTurnRuntime`、`ToolCenter`、`WorkspaceView`、`Mailbox`、`Guard`、`Trace`、预算和权限边界；两个 Product Runtime 共享底层能力内核，但业务语义不同。
- Plan 是地下到地上的产品级交接对象，必须能暂停恢复、版本管理、人类可读、审计复盘、跨进程消费，并防止 child output 直通执行。
- `.agentarbor/` 是 Plan Package 的默认存储目录名或实现形态，不再作为独立产品概念树节点。
- Agent Fabric 是动态派生 child agent 的执行机制；MVP 只允许一层 child agent，长期递归必须受 maxDepth、预算和父层综合约束。
- Center Manager 决定是否派生、等待、打断、继续探索、追问用户或停止；Growth Governor 建议探索预算、并行度、rootlet 类型和停止条件。
- Parent Synthesis / Convergence 消费 child outputs，综合冲突材料，决定方向是否足够成立；Handoff / Plan Steward 只能组织 Plan，不能绕过父层 convergence。
- 父层中枢默认不直接使用外部探索工具；证据不足时应派 child 继续探索，而不是父层自己搜索。
- 四层权限模型是：`AgentSpec` 静态能力上限 ∩ `Parent DelegationDecision` 动态授权 ∩ `AgentRunContext` 当前阶段/任务/预算/用户授权裁剪 ∩ `ToolCenter / Guard` 强制执行 = 本轮实际能力。
- Main Canvas 展示结论、一句话理由、关键证据引用和可展开解释；Observation Panel 展示 agent run tree、child 摘要、父层 synthesis、convergence 事件、模型/工具 refs、budget 和 trace。
- reasoningTrace 保存模型可见的推理摘要、运行引用和必要结构信息；工程层不得以脱敏或安全投影为名改写普通模型输出。
- `agent`、`atomic`、`Plan`、`Handoff` 等命名必须匹配真实职责；`atomic` 只用于真正有全成功/全失败、回滚或一致性边界的场景。
- Aboveground 执行发现信息不足时发起 Nutrient Request；Underground 补充探索后产出 Nutrient Patch 或 Plan vNext；Aboveground 基于新版本继续、回退、分叉或停止。
- Governance Pipeline 是 `Fruits / Run Trace -> Run Memory -> Experience Candidate -> Governance Pipeline -> Capability Asset / Path Bias / Soil Update`，不能把 Memory、Candidate 和 Governance 混成一个节点。
- Path Bias 只能影响 preference 和方案排序，不能覆盖 hard constraint。
- `.agents/`、`.codex/`、`.opencode/` 是当前开发和平台适配层，不能反向决定产品语义。
