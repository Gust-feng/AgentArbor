# ADR-0013: 内核自研与协议适配边界

## Status

Accepted.

## Context

AgentArbor 需要兼容 Codex、OpenCode、Agent Skills、MCP、A2A、AG-UI、模型供应商和工具生态。但如果内部运行时直接以某个外部协议为核心模型，产品语义会被外部格式反向定义。

AgentArbor 的壁垒不是“接入多少协议”，而是智能体如何出生、如何分工、如何失败回流、如何验证、如何沉淀、如何演化、如何脱离母体。

## Decision

AgentArbor 采用：

```text
内核自研，协议兼容。
```

内部核心必须由 AgentArbor 自己定义：

- ArborMessage。
- TaskStateMachine。
- MessageBus。
- Router / Coordinator。
- AgentRegistry。
- CapabilityRegistry。
- ArtifactStore。
- EventLog。
- Verification / Acceptance。
- FailureRecovery。
- PermissionGate。
- LineageSystem。
- EvolutionEngine。

外部协议只能通过 adapter 接入：

```text
外部协议 -> Adapter -> ArborMessage
ArborMessage -> Adapter -> 外部协议
```

A2A 是对外智能体协作语言，MCP 是工具与数据插座，AG-UI 是界面事件通道。它们都不是 AgentArbor 内部运行时的事实源。

## Consequences

- 第一阶段必须优先冻结内部消息、状态、注册、产物和事件契约。
- 不先实现完整 A2A、MCP、AG-UI，也不让这些协议决定核心类型。
- 智能体之间不能直接乱连，必须通过 MessageBus、Router 和 TaskStateMachine 协作。
- Adapter 可以扩展，内核语义必须稳定。
- 平台适配输出可以生成官方格式，但 AgentArbor 原生事实仍在自身模型中。

## Non-Goals

不自研 HTTP、WebSocket、JSON-RPC、OAuth、基础数据库、向量数据库底层、模型推理服务、容器运行时、Git 基础能力和前端基础框架。
