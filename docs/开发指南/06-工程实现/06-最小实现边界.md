# 最小实现边界

## 第一阶段目标

第一阶段应证明 AgentArbor 可以作为桌面通用 Agent 完成一个最小任务闭环：用户从 Desktop Shell 输入任务，系统形成 Task Soil，经地下认知运行时生成 Plan，再由轻量地上执行运行时产出可验证 Fruit，并形成 Run Memory。

同时，第一阶段必须证明系统不是一次性生成器：运行结束后要形成 Run Memory，并让下一次相似任务能读取 Path Bias 候选。

## 最小路径

```text
Desktop Shell
  -> Task Soil
  -> Underground Cognitive Runtime 形成 Plan
  -> Aboveground Execution Runtime 消费 Plan
  -> 生成 Workflow IR / tool actions
  -> Verification
  -> Fruits
  -> Run Memory / Experience Candidate
  -> Governance Pipeline
  -> Path Bias / Capability Asset candidate
  -> Global Soil
```

## 第一阶段骨架

第一阶段不要从“写很多智能体”开始。必须先让任务、Plan、执行、产物和事件跑通。

最小实现顺序：

```text
1. Desktop Shell / Task Inbox
2. TaskSoil
3. Constraint / ConstraintRef
4. AgentSpec / AgentRunContext
5. Plan
6. PlanPackage
7. AbovegroundExecutionPlan
8. WorkflowIR
9. NutrientRequest / NutrientPatch
10. PlanRevision
11. InMemoryEventLog
12. InMemoryArtifactStore
13. 最小 Aboveground consumer
14. 最小 demo
```

最小 demo 必须证明：

```text
用户任务
  -> Task Soil
  -> Underground Cognitive Runtime
  -> child/rootlet 一层派生
  -> 父层 synthesis / convergence
  -> approved Plan
  -> Aboveground consumer
  -> 生成 Artifact
  -> Verification
  -> 可选 nutrient_request / nutrient_patch / plan revision
  -> 生成 Fruit 候选
  -> RuntimeDatabase 写入 Run / Event / ToolCall / ModelCall / Artifact 安全记录
  -> 生成 RunMemory
  -> 生成 ExperienceCandidate
  -> 生成 PathBias 候选
  -> EventLog 可回放全过程
```

## 暂不做

第一阶段不做：

- A2A Adapter。
- 完整 MCP Adapter。
- AG-UI Adapter。
- 完整插件市场。
- 企业多租户。
- 多层递归 Agent Fabric。
- 完整能力资产治理系统。
- 完全自动自我修改。
- 无人值守高风险命令执行。
- 通用后端数据库、ORM、迁移体系和生产级多后端管理。
- 复杂可视化编排器。

真实模型接入必须经过智能通道，不得直接散落在领域模块。

## 最小验收

第一阶段通过条件：

- 用户任务能进入 Desktop Shell。
- Task Soil 能表达任务、上下文和权限边界。
- 地下 runtime 能通过 fake/stub AI runtime 完成 AI 路径。
- 无 `AgentTurnRuntime` 不会产出 approved Plan。
- 至少一层 child/rootlet 参与，且输出不直通 Plan。
- Plan 能被 Aboveground consumer 读取。
- 至少产生一个 Artifact。
- 至少执行一次 Verification。
- 至少形成一个 Fruit 候选。
- 至少写入完整 EventLog。
- 至少把运行记录写入 appHome / runHome 下的 RuntimeDatabase 安全投影，并证明不泄漏 raw prompt、raw provider response、hidden reasoning、raw tool output、API key 或 token。
- 至少证明 hard constraint 可以阻断或要求确认，soft constraint 可以记录偏离，preference 只能影响方案排序。
- Nutrient Request / Patch 的触发条件、消息和结果结构已经保留，哪怕最小 demo 只走不触发路径。
- 至少写入一次 RunMemory。
- 至少生成一个 ExperienceCandidate。
- 至少形成一个可供下一次相似任务读取的 PathBias 候选。
- Main Canvas 能展示结果级解释，Observation Panel 能展示安全监督投影。
