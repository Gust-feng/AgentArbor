# 核心数据模型

## arbor.json

`arbor.json` 是 AgentApp 或导出资产的入口描述文件。第一阶段可以先作为草案设计，不提前塞进 `.agentarbor/`。

建议字段：

```json
{
  "schemaVersion": "0.1",
  "kind": "agentapp",
  "name": "",
  "goal": {},
  "directionHandoff": {},
  "constraints": [],
  "growthPlanVersions": [],
  "workflow": "",
  "runtime": {},
  "capabilities": [],
  "nutrientRequests": [],
  "nutrientPatches": [],
  "runMemory": [],
  "pathBias": [],
  "lineage": {},
  "exports": []
}
```

## Direction Handoff

Direction Handoff 是 `.agentarbor` 中的方向交接包。它必须描述：

- 来源用户目标和确认记录。
- 目标、非目标、验收门和边界。
- 假设、缺失信息、风险和升级条件。
- Soil 引用、可复用能力、历史证据和失败模式。
- ConstraintRef 与候选约束状态。
- 可选方向、适用条件、不适用条件、推荐方向和证据来源。
- 方向裁决、合并、淘汰、反驳和风险登记。
- 候选观察、候选证据和候选主张的来源引用与收束审查记录。
- Growth Entry。
- 版本和有效状态。

Direction Handoff 不是长期资产，也不是 Growth Plan。
单个探索 agent 或根须集群的原始输出不能直接成为 Direction Handoff 中的事实、约束或方向依据。

## Goal

目标对象必须包含：

- 原始目标。
- 澄清目标。
- 非目标。
- ConstraintRef。
- 验收标准。
- 风险。
- 当前状态。
- 变更记录。

## Growth Plan

Growth Plan 必须描述：

- 来源 Direction Handoff 版本。
- 计划版本号。
- 选定方向。
- 是否采用 Path Bias。
- Workflow IR 摘要。
- 运行组织形态。
- 任务列表。
- 约束采用与分发。
- 复用策略。
- 沉淀策略。
- 验证和验收门。
- Nutrient Request 触发点。

## Growth Plan Revision

Growth Plan Revision 必须描述：

- 来源 Growth Plan 版本。
- 来源 Direction Handoff 版本。
- 修订原因。
- 影响范围。
- 决策：继续、回退、分叉或停止。
- 新 Workflow IR 或变更摘要。

## Agent Manifest

Agent 清单必须包含：

- 名称。
- 职责。
- 输入。
- 输出。
- 可用能力。
- 权限边界。
- 协作关系。
- 验证要求。
- 生命周期状态。

## Constraint

Constraint 必须描述：

- 来源。
- 类型。
- 等级：hard、soft 或 preference。
- 约束内容。
- 责任方。
- 适用范围。
- 证据引用。
- 执行门。
- 冲突处理策略。
- 当前状态。

ConstraintRef 必须描述：

- 约束 ID。
- 在当前对象中的要求等级。
- 当前执行门。

## Capability Asset

能力资产必须包含：

- 能力名称。
- 能力类型。
- 输入输出。
- 依赖。
- 权限。
- 适用范围。
- 来源。
- 验证记录。
- 版本。
- 退役策略。

## Nutrient Request / Nutrient Patch

Nutrient Request 必须描述：

- 触发者。
- 触发原因。
- 关联 Growth Plan 版本。
- 关联任务、验证报告或治理报告。
- 养料类型：证据、Soil 资产、外部事实、约束细节、上下文或能力线索。
- 阻塞等级。
- 当前假设。
- 缺口说明。

Nutrient Patch 必须描述：

- 来源 Nutrient Request。
- 补充的 EvidenceRef、SoilRef、ConstraintRef、FactRef、Context Supplement 或 Capability Hint。
- 候选观察、候选证据和候选主张的来源引用与收束审查记录。
- 对当前假设的判断。
- 对 Growth Plan 的影响。
- 输出 Direction Handoff 版本，或无需补充的证据。

## Run Memory

Run Memory 必须描述：

- 来源目标和任务。
- 来源 Growth Plan。
- 运行中新增、修改、违反、豁免或退役的 ConstraintRef。
- 参与 agent、地上生长组织和验证组织。
- 实际路径。
- Nutrient Request / Patch 与 Growth Plan Revision。
- 产物引用。
- 验证证据。
- 偏离原因。
- 成功模式。
- 失败模式。
- 下一次可参考线索。

## Experience Candidate

Experience Candidate 必须描述：

- 来源 Run Memory。
- 可复用经验。
- 适用目标类型。
- 前置条件。
- 必须保留的验证门。
- 不适用条件。
- 置信度。
- 治理状态。

## Path Bias

Path Bias 必须描述：

- 来源 Experience Candidate 或 Capability Asset。
- 适用目标类型。
- 推荐节点和能力组合。
- 必须保留的验证门。
- 已知失败模式。
- 不适用条件。
- 置信度。

Path Bias 只能影响 preference 和方案排序，不能覆盖 hard constraint。

## Ring Memory

Ring Memory 必须描述：

- 聚合的 EventLog 范围。
- 聚合的 Run Memory 范围。
- 聚合的 Experience Candidate 范围。
- Nutrient Request / Patch 和 Growth Plan Revision 趋势。
- 生长趋势。
- 重复失败模式。
- 可修剪资产。

Ring Memory 只能作为聚合视图，不能替代 EventLog、Run Memory 或治理记录。

## Lineage Record

谱系记录必须描述：

- Direction Handoff 版本。
- Growth Plan 版本。
- Workflow IR。
- 参与 agent。
- 使用能力。
- Nutrient Request / Patch。
- 关键决策。
- 验证证据。
- 派生资产。
- 分支和合并关系。
