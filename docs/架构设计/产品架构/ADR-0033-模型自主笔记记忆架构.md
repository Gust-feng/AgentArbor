# ADR-0033：模型自主笔记记忆架构

## 状态

已接受（2026-08-10 修订）。

本 ADR 定义声明性记忆。路径依赖作为程序性记忆的扩展，见 [ADR-0036：路径依赖（程序性记忆）系统](ADR-0036-路径依赖方法论记忆系统.md)。

## 背景

早期 PathMemory 方案把运行流水、工具调用和治理候选当作记忆主线，但真实记录缺乏任务语义，且模型没有获得可复用的上下文。模型需要能够主动判断什么值得沉淀，并让用户可以直接看到、修改和删除这些内容。

当前产品把长期记忆分成两个互补类型：

- 声明性记忆：知道什么，包括事实、偏好、约定和稳定知识；
- 程序性记忆：怎么做成，包括路径依赖和可复用任务方法。

执行日志、工具结果和 Run 状态仍是运行事实或审计材料，不因持久化而自动变成记忆。

## 决策

### 1. Agent Notes 是声明性记忆的事实源

Agent NotesFeature 拥有声明性记忆的：

- 全局和 owner 作用域内容；
- Markdown 正文；
- 读取、注入、版本和冲突处理；
- 用户编辑、删除和可观察投影。

当前生产实现使用全局笔记和当前 Conversation owner（Space 或 Workspace）的局部笔记。owner 是 run birth 冻结的稳定身份，不能由 capability snapshot execution root、路径哈希或临时 cwd 推导；旧路径键笔记不猜测迁移，保留目录但不再作为当前 owner 记忆读取。

Agent Notes 不是整个记忆系统的唯一事实源。它是声明性记忆的唯一事实源；程序性路径依赖由 ADR-0036 定义的独立 feature 持有。

### 2. 模型主动写入，工程不代笔

模型通过 NoteWrite 在明确判断值得沉淀时写入笔记。工程提供：

- 原子持久化；
- 大小限制；
- scope capability；
- expectedVersion/baseVersion 冲突保护；
- 可观察的成功、冲突和失败结果。

工程不从 transcript、工具结果、用户原话或关键词规则自动抄录记忆，也不替模型判断内容价值。NoteWrite 的正文是全量替换，模型必须在冲突后读取当前正文、合并并显式携带新基线重试。

### 3. 当前 Notes 的交付与未来渐进披露

在现有实现中，Agent Notes 在 Run birth 按冻结作用域全文注入，并保存对应的内容版本。这是兼容能力，不代表所有未来记忆都必须全文常驻。

路径依赖和后续条目化记忆采用 ADR-0036 的渐进式披露：

1. Run birth 提供有限目录；
2. Agent 通过搜索发现候选；
3. Agent 按需读取完整正文。

迁移期间保留 Notes 全文注入，避免在新机制尚未验证前造成能力倒退。

### 4. 治理以透明和直接编辑为主

记忆必须让用户能够直接查看、编辑和删除。当前不设置每次写入的审批链，也不把 ExperienceCandidate 的治理状态机作为 Agent Notes 的前置门槛。

“不自动审批”不等于“不留来源”：路径依赖和后续条目化记忆应保留来源 Run、owner 和 revision，使用户可以判断其来历。现有 Notes 继续遵守当前的正文版本和冲突契约；来源字段在后续条目化时再补齐，不把当前实现误说成已经具备该事实。自动 Dream 总结不属于本 ADR；未来需要另立提案和激活契约。

Agent Notes 继续遵守当前 runtime 文件的删除和持久化边界；路径依赖明确不参与 Workbench 备份、删除即直接删除，owner 删除和历史引用处理见 ADR-0036。未来新增的记忆类型分别声明自己的数据生命周期。

### 5. 历史 PathMemory 与 ExperienceCandidate 停用

PathMemory / ExperienceCandidate 是保留源码的历史运行档案和治理实验：

- 当前生产组合根不创建、不采集、不读取、不注入；
- 现有 runtime 目录不迁移、不导入新记忆；
- 它们不能通过改名或兼容 API 充当新的路径依赖。

ADR-0032 中关于自动采集和记忆回流的生产决策由本 ADR 及 ADR-0036 取代；ADR-0032 仅保留历史实验参考价值。

### 6. 所有权与事实方向

AgentNotesFeature 只拥有自己的记忆事实。OrdinaryAgentFeature 拥有 Run 中的模型输入、工具事实、记忆读取引用和使用记录。Panel 是单向查询和命令适配器，不从 UI 文本重建记忆或 Run 事实。

不同记忆 feature 可以共享稳定的 owner、memory id、revision 和来源引用类型，但不共享业务仓储、全局状态或第二套运行时。

## 与 ADR-0036 的关系

| 维度 | Agent Notes | 路径依赖 |
| --- | --- | --- |
| 记忆类型 | 声明性 | 程序性 |
| 典型内容 | 项目用 pnpm、用户偏好、工作约定 | 复杂任务的解决思路、适用条件和验证边界 |
| 写入方式 | NoteWrite 全量更新作用域正文 | PathDependencySave 条目写入 |
| 读取方式 | 当前实现全文注入；未来逐步条目化 | 有限目录、MemorySearch、MemoryRead |
| 事实 owner | AgentNotesFeature | PathDependencyFeature |
| Run 引用 owner | OrdinaryAgentFeature | OrdinaryAgentFeature |

两者组成同一记忆产品，但不把一个 feature 的 store 当成另一个 feature 的内部实现。

## 后果

- Agent 获得透明、可编辑的跨 Run 记忆；
- 复杂任务方法可以在独立路径依赖中积累，不必污染普通项目笔记；
- 记忆质量依赖模型判断，工程只守权限、版本、来源和持久化边界；
- 现有 Notes 全文注入仍有增长压力，必须通过 ADR-0036 的渐进披露逐步收口；
- 历史 PathMemory 的采集投入保留为诊断参考，但不再承担记忆职责。
