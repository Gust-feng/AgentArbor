# 根层（Root System）- 持续地下生命系统

## 职责

根层不是一次性调研阶段。Root System 是持续地下探索与吸收系统，它在 Seed Packet 种入 Soil 后初始生根，并在运行期根据地上组织反馈继续侧根扩展或深根重探。

Root System 的输出是版本化 Root Brief，不是最终计划。

## 内部结构

| 结构 | 职责 | 自由度 |
| --- | --- | --- |
| Rootlet Cluster | 根须集群，面向具体方向做事实、资产、风险、相似运行和未知项探索 | 高 |
| Root Agents | 具体探索个体，按任务临时出生、解散或等待治理 | 中 |
| Root Crown Cluster | 根颈固定核心，汇总根须信息、去重、校验证据并输出 Root Brief | 低 |

Root Crown Cluster 应由多个低自由度核心 agent 构成，而不是单个最强模型独断。它可以使用强模型做综合，但必须保留反驳、证据校验和不确定性标注职责。

## 输入

- 已通过 User Approval Gate 的 Seed Packet。
- Soil 中的 Capability Asset、治理规则、历史证据和失败模式。
- Run Memory。
- Experience Candidate。
- Path Bias。
- Root Callback Request。
- 外部事实和资料来源。
- 当前权限边界。

## 输出

Root Brief 至少包含：

- Root Brief 版本号。
- Rooting Mode：Initial、Lateral 或 Deep。
- 目标理解。
- 可复用资产。
- 相似运行。
- 可参考 Path Bias。
- 未知项。
- 约束。
- 风险。
- 可选方向。
- 推荐方向。
- 证据引用。

## 生根模式

| 模式 | 触发 | 输出 |
| --- | --- | --- |
| Initial Rooting | Seed Packet 首次种入 Soil | Root Brief v1 |
| Lateral Rooting | 局部分支信息不足、局部验证失败或局部 Path Bias 失效 | Root Brief v2+ 的局部补充 |
| Deep Rooting | 核心假设、目标、权限、成本或外部事实发生重大变化 | Root Brief v2+ 的整体重估 |

## Root Callback

Root Callback 可以由 Core Control Cluster、Branch Agent 或 Flower Cluster 发起。根层收到回调后必须判断应执行 Lateral Rooting、Deep Rooting，还是明确“不需要重探”。

Root Callback 的结果只能是：

- 新的 Root Brief 版本。
- 明确无需重探的证据。

## 禁止事项

- 不制定最终 Growth Plan。
- 不直接执行地上任务。
- 不绕过 Soil 权限读取或写入资产。
- 不把单次历史路径强制套用到当前任务。
- 不把 Root Brief 写成聊天总结。
- 不把 Root System 写成启动前一次性调研。
