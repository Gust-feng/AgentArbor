# ADR-0027：工具执行事实与单向消费架构

## 状态

已采纳，适用于 `0.1.x` 开发主线。

## 背景

历史工具链同时携带执行结果、模型投影、UI display、envelope 和 broker 调用计数，导致执行层、模型层、事件层、持久化层和 Panel 互相读取对方的派生字段。同一调用可能由多个消费者重复推导状态，取消也曾被折叠成失败。这些兼容结构削弱了模块边界，并使 live、replay 与持久化难以证明一致。

项目仍处于开发期，因此本轮选择清洁断代，不迁移旧本地 runtime JSON，也不保留 deprecated alias、兼容 facade 或旧字段读取分支。

## 决策

工具执行的唯一权威结果是 `ToolCallResult`：

```text
ToolCenter -> ToolCallResult
                 |
                 +-> model ToolResult
                 +-> append-only tool events
                 +-> tool-call read-model -> Panel
                 +-> runtime factual records
```

`ToolCallResult` 只包含 `callId / toolName / input / output / status / error / errorDomain / errorFacts / durationMs / confirmationRequest`。ToolCenter 负责权限、输入、确认、取消、执行和事实归一化，不拥有调用预算，不生成模型内容、展示对象或持久化对象。

`input / output` 使用 `ToolFactValue`：只允许 JSON 可表达的 `null / string / finite number / boolean / array / plain object`。`undefined` 对象字段被显式省略；循环引用、`BigInt`、函数、symbol、非有限数字和 class instance 必须在工具边界明确失败，不能依赖 `JSON.stringify` 静默丢字段或改变事实。ToolCenter 同时归一化调用输入与 executor 输出。executor 一旦返回，返回值就是本次执行事实；随后到达的 abort 只能取消 owning loop，不能把已返回的副作用结果改写成“未执行”。executor 启动后抛错或响应 abort 时，若副作用状态无法确定，必须返回 `sourceExecutionStatus: unknown` 与 `doNotBlindlyRetry`；取消请求不等于事务回滚。

模型边界通过 kernel 纯函数把 `ToolCallResult` 转换为 `ToolResult`。`ToolResult` 的正文是排他联合，只能是 `none / text / json` 之一；同一完整结果不得同时写入文本正文和结构化正文，也不得再套一层 `agentContent / modelResult / envelope`。模型消息只携带下一步判断所需的状态、单份正文与错误事实；`callId / toolName` 使用消息协议已有字段，不在正文内重复序列化，耗时等观察事实留在事件和 read-model。

工具附件使用带外 `ModelMessage.attachments` 进入下一轮模型请求，内部以 `image / audio / file` 判别类型保留真实媒体语义，JSON 正文只保留附件元数据，不能复制 base64。provider adapter 负责把类型映射到自身协议；不支持的媒体或格式必须形成可观察的模型请求失败，不能把 audio 降级伪装成 file，也不能静默删除附件。工具调用预算只属于 Agent loop。

continuation 是工具输出顶层的显式契约，通用 ToolCenter/kernel 只读取 `continuation` 或 `continuations`，不按 `nextStartChar / nextOffset / rawContentRef` 等历史字段递归猜测。MCP 规范定义的是 `content[]` 与可选 `structuredContent`，没有定义工具结果 continuation；AgentArbor 的 MCP adapter 因此原样保留 `structuredContent` 中 continuation-shaped 字段，不把任意 `nextInput` 提升成通用可执行 continuation。只有拥有明确分页契约的专用 producer/adapter 才能返回 canonical continuation。小结果完整返回且不附带从头重读的冗余 continuation；大结果由 producer 返回首段、截断事实和从未读位置开始的可执行 `nextInput/ref`。任何当前结果序列化后仍超过共享内联预算时，Host-owned 的进程内 `ToolOutputStore` 必须先保存当前完整文本、JSON 或失败证据，并返回预览、`tool-output://` 引用和 `read_tool_output` 的可执行下一段输入；读取当前页不会重跑原工具。聚合审批历史或批量结果被缩短时，每个被缩短或省略的 stage 都必须由该 stage 自己的 continuation 覆盖；某一阶段的 ref 不能证明其他阶段可恢复。真实分页/offset ceiling 或无法安全重放副作用请求时，producer 必须返回明确失败事实，不能返回 `completed + truncated` 的不可续读结果或会重放副作用的 synthetic continuation。无法写入 store 时必须明确失败：原 completed 转为 delivery failure，并保留 `sourceExecutionStatus: completed` 与 `doNotBlindlyRetry`；原 failed/cancelled/approval 保留自身语义、错误和确认事实，不能用更大的特例预算掩盖不可恢复输出。

MCP adapter 只保留服务端 `content[]` 与可选 JSON 对象 `structuredContent` 的单份语义事实，不再生成 `summary / mcpResult / result` 三份包装。外部 `structuredContent` 先在 adapter 边界做对象形状、JSON-safe 验证与脱离，用于精确镜像比较；adapter 不再归一整份 assembled executor output，最终 canonical output 仍由 ToolCenter 统一归一化。只允许一种无损去重：某个 text part 必须能解析为 JSON，且解析值与已验证的 `structuredContent` 深度完全相等，才能删除这份精确镜像；解析失败、近似相同、只包含部分字段或正文不同都必须完整保留。若远端调用已返回后附件预算或 `structuredContent` 验证失败，必须映射为 post-execution delivery failure，保留可交付的 sibling content、`sourceExecutionStatus` 与 `doNotBlindlyRetry`。`isError=true` 映射为正式 failed `ToolCallResult`；图片、音频和非图片 embedded resource blob 分别通过带外 `image / audio / file` attachment 传递，JSON 只保留 MIME、文件名/URI、长度和附件索引。provider 必须保持附件来源角色：Chat 不得把 tool-origin 媒体提升成 user 消息，Responses 可消费 tool-origin image/file，当前 OpenAI adapters 不支持 tool-origin audio；Responses 还必须按整份请求校验官方文件输入预算，不能把 MCP 的单结果 32 MiB Host 上限误当作 provider 请求上限。当前 provider 不支持的媒体必须返回可观察失败，不能静默标成成功、把 audio 伪装成 file 或标记为 `not_retained`。

工具生命周期事件固定为 `tool.requested / tool.completed / tool.failed / tool.cancelled`，确认等待使用 `user_approval.requested`。`completed / failed / cancelled` 是互斥终态。事件只保存一次有界事实快照：requested 保存 input，终态保存 output/error/duration，不在每个阶段重复完整 input；错误、错误事实和顶层 continuation(s) 必须保留。统一 reducer 从 append-only event entries 生成 tool-call facts：重复事件幂等，首个终态不可被后续 requested、approval 或其他终态覆盖，缺少 requested 时仍可恢复终态事实，但 input 可以为空。

`ToolDisplayProjection` 属于 Observation/Panel read-model。Panel summary、preview 和 display 只能从调用事实派生，不写回事件、ToolCallResult 或 runtime database。持久化的生命周期 event payload 是唯一可重放工具事实；`RuntimeToolCallRecord` 只作为 callId/终态/错误/引用/时间索引，不复制 input/output。Sub-Agent trace 只保存 request/response refs、usage、状态、tool-call refs 和单份 `fullOutput` continuation owner，不保存累计模型 messages、逐轮 response 正文、工具 input 或 display。

## 兼容与数据

删除 `ToolSafeProjection`、`ToolResultEnvelope`、`projection`、`envelope`、`resetCallCount`、`getCallCount`、内部 `run_command` alias 和字段猜测式 continuation。旧 JSON 的多余字段不会被读取；旧 snapshot 若缺少当前 Ordinary/Multi-Agent 出生事实或无法满足新契约，视为开发期失效数据，可以清理本地 runtime 目录后重新运行。

## 约束

- adapter 和 ToolCenter 不得依赖或生产 Observation/Panel display 类型。
- kernel 不得依赖 app。
- runtime database 不得依赖 Panel UI 类型或保存 display/envelope 历史副本。
- live、replay、conversation history 和持久化视图必须复用同一事件归约语义。
- 工具 producer 不得返回 `canonicalResult / display`，不得把同一正文同时放入多个等价字段。
- continuation 必须能由当前工具集合实际执行；纯诊断引用不能冒充可恢复 continuation。
- `ToolOutputStore` 只由 Composition Root 创建，第一版完整内容不持久化、不进入 RuntimeDatabase，不替代 producer 自己的文件、日志、HTTP 或 Sub-Agent continuation；它只保证当前进程内的超大交付事实可重建。`tool-output://` 引用元数据可以作为 `live_only` 工具事实进入事件和 RuntimeDatabase，但进程重启后必须明确失效。读取器必须由父 run 冻结授权，Deep child / Sub-Agent 只可把它作为 transport companion 自动继承。窗口不得拆分 UTF-16 surrogate pair，完整读完释放单个 ref；Ordinary 未消费引用保留到 TTL 或 Panel 关闭，容量不足时拒绝新 retain 而不驱逐 live fact；Multi-Agent conversation 删除释放稳定 run owner，Panel 关闭再全量清理。模型附件原始字节只服务当前 provider 请求，不得进入持久化 child context、事件或 read-model；provider continuation 只有经过模型协议能力层的显式白名单、JSON-safe 验证和大小限制后才可持久化，当前仅允许 `openai_responses_output_items`。已知 Responses continuation key 若无法满足边界，Deep context persistence 必须以 `model_protocol_continuation_not_persistable` 明确失败；未知 provider extension 仍可忽略，禁止静默删除已知 continuation 后伪造可恢复状态。
- 新功能不得建立第二套 projection 中心或以兼容名恢复已删除契约。

## 影响

收益是事实所有权唯一、状态归约可测试、模型能力不被 UI 摘要削弱，并降低 Panel、持久化和子 Agent 对执行内部的耦合。代价是旧开发期运行历史不保证可读；这是本次断代的明确选择。

## 参考依据

- [MCP Tools Specification 2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)：定义 `content[]`、音频内容、embedded resource、`structuredContent` 与 `isError`；未定义工具结果 continuation。
- [OpenAI Function calling guide](https://developers.openai.com/api/docs/guides/function-calling)：工具输出通过原 `call_id` 回传；Responses 的 function output 可承载字符串、图片或文件。
- [OpenAI Responses create reference](https://developers.openai.com/api/reference/resources/responses/methods/create)：定义 input message 的角色层级，以及 `input_image / input_file` 协议字段。
- [OpenAI Reasoning guide](https://developers.openai.com/api/docs/guides/reasoning#keeping-reasoning-items-in-context)：Responses 工具循环应把上一轮 reasoning、function call 与 function output items 原样带入下一轮。
- [OpenAI Audio and speech guide](https://developers.openai.com/api/docs/guides/audio)：当前音频聊天输入走 Chat Completions；Responses 音频能力需按实际协议显式校验。
