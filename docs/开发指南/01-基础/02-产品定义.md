# 产品定义

## 一句话定义

AgentArbor 是一个桌面通用 Agent Workbench。Ordinary Agent 是默认工作方式，Multi-Agent 是显式深入协作功能，Sub-Agent 是 Ordinary 的 SDK AgentTool；Ordinary 与 Multi-Agent 拥有各自业务状态，通过中性模型、工具、确认、上下文算法和系统适配协作，Sub-Agent 调用事实进入父 Ordinary run。

## 用户获得什么

用户提出任务、选择文件夹、附加网页或提供项目上下文后，默认进入 Ordinary Agent。需要多路探索时由用户显式启动 Multi-Agent；需要局部专家任务时由 Ordinary 按工具契约调用 Sub-Agent。下面第 3-7 项是按需出生的长期能力，不是默认任务的固定流水线：

1. Task Soil：当前任务目标、文件引用、项目上下文、网页材料、临时约束、权限边界和本轮运行材料。
2. 普通 Agent 过程：模型理解上下文、按需调用授权工具、处理确认、安全记录事件并输出可审阅结果。
3. 地下认知过程：deep 模式下进行目标成形、多路探索、动态派生 child agent、父层 synthesis、convergence 裁决和必要澄清。
4. Plan：deep 模式下描述要做什么、为什么这样做、关键证据、约束、风险、不确定性、执行入口和验证要求。
5. 地上执行：按 Plan 进行文件修改、文档生成、原型制作、工具调用、验证和交付。
6. Fruits：交付物、运行报告、Run Memory、Experience Candidate 和可复用能力候选。
7. 治理回流：只有经过 Governance Pipeline 的内容才可以进入 Global Soil，形成 Capability Asset、Path Bias、长期约束或失败模式。
8. 监督解释：主画布显示结果级解释和 inline evidence，Observation Panel 显示普通 Agent run、工具 refs、运行事件、deep agent run tree、child 摘要、父层综合、budget 和 trace。

## 核心产品对象

### Desktop Shell

Desktop Shell 是用户唯一入口。它包含：

- Task Inbox / 输入区。
- Workspace Context / 文件、项目、网页上下文。
- Main Canvas / 当前任务主画布。
- Artifact Area / 结果与 Plan。
- Observation Panel / 监督面板。

用户不应该面对 Underground / Aboveground 两个产品入口。当前产品只有 Workbench；这些术语只表示按需出生的长期能力边界。

### Task Soil

Task Soil 是当前任务级临时土壤。它保存当前任务目标、文件引用、项目上下文、网页材料、用户临时约束、权限边界和本轮运行材料。Task Soil 避免每个杂任务直接污染长期土壤。

### Global Soil

Global Soil 保存长期偏好、Capability Asset、Path Bias、历史约束、失败模式和治理后的长期事实。只有 Governance Pipeline 通过后的内容才能回流 Global Soil。

### Underground Cognitive Runtime

地下认知运行时负责方向智能。它允许不确定、分叉、追问和停止。它通过 AI-first agent 协作完成目标理解、多路探索、动态派生 child agent、父层综合、裁决和 Plan 成形。

地下认知运行时是未来 deep / Agent 集群能力边界，不是普通会话的默认编排。普通 Agent 可以说明需要更深入流程，但不能由工程规则自动升级到 Underground。

### Shared Agent Kernel

Shared Agent Kernel 是地下和地上共同使用的能力内核，包括 `AgentLoop`、`AgentTurnRuntime`、`ToolCenter`、`WorkspaceView`、`Mailbox`、`Guard`、`Trace`、预算和权限边界。

语义推理属于 agent 的 `reason()`；`guard()` 只守 schema、预算、权限、hard constraint 和包结构，不能替 agent 判断用户真正要什么、候选如何取舍、是否继续探索或该调用什么工具。

### Agent Fabric

Agent Fabric 是动态派生 child agent 的执行机制。`AgentSpec` 定义静态能力上限，父层 `DelegationDecision` 在上限内动态授权，`AgentRunContext` 按阶段和预算继续裁剪，`ToolCenter / Guard` 最终执行边界。

MVP 阶段只允许一层 child agent。child/rootlet 输出只是局部材料，不能直接进入 Plan，必须经过父层 synthesis / convergence。

Agent Fabric 不用于包装普通文件修改、helper、adapter、formatter 或一次模型工具循环。只有真正需要动态派生执行主体并具备输入切片、输出契约、权限和可观察投影时，才应使用 agent / child agent 命名。

### Plan

Plan 是地下到地上的产品级交接对象。它描述当前任务的方向、证据、约束、风险、不确定性、执行入口和验证要求。

`.agentarbor` 是 Plan Package 的实现/存储形态或目录名，用于暂停恢复、版本管理、人类可读、审计复盘、跨进程消费和防止 child output 直通执行。产品文档应优先讲 Plan，而不是把 `.agentarbor` 当作独立概念树节点。

### Aboveground Execution Runtime

地上执行运行时消费已成形 Plan，负责执行智能。它可以进行文件修改、文档生成、原型制作、工具调用、验证和交付。它不应该自建方向探索集群；如果执行中发现信息不足，应发起 Nutrient Request。

普通 Agent 直接进行的授权文件编辑不应被命名为 Aboveground 执行，除非它确实消费了 approved Plan 或等价的 deep 交接对象。

### Nutrient Request

Aboveground 执行或验证发现 Plan 信息不足时，向 Underground 发起 Nutrient Request。Underground 补充探索后产出 Nutrient Patch 或 Plan vNext，Aboveground 基于新版本继续、回退、分叉或停止。

### Path Bias

Path Bias 是相似任务对已验证解决路径的自然倾向。它帮助系统不每次从零开始，但不强制复刻。当新任务的约束、权限或上下文与历史冲突时，系统必须选择新路径并记录偏离原因。

Path Bias 只能影响 preference 和方案排序，不能覆盖 hard constraint。

### Governance Pipeline

Governance Pipeline 是运行沉淀进入长期土壤前的治理过程：

```text
Fruits / Run Trace
  -> Run Memory
  -> Experience Candidate
  -> Governance Pipeline
  -> Capability Asset / Path Bias / Soil Update
```

Run Memory 是单次运行后的经验摘要。Experience Candidate 是可复用经验候选。Capability Asset 才是进入 Global Soil 的正式资产。

### Fruits

Fruits 是每次任务后的产物集合：交付物、运行报告、Run Memory、Experience Candidate 和能力候选。它们不能自动入土，也不默认变成独立 agent。

## 价值判断

AgentArbor 的价值由以下指标衡量：

- 用户是否能从一个统一桌面入口完成模糊任务成形和交付。
- 默认普通 Agent 是否能用朴素、准确的工具和事件语义完成日常任务，而不是把简单动作包装成 deep 流程。
- 地下 runtime 的探索和裁决是否真正由 AI agent 完成，而不是关键词规则伪装。
- child/rootlet 输出是否经过父层综合，避免局部材料直通 Plan。
- Plan 是否能被地上 runtime 消费并产出可见成果。
- 主画布解释是否足够帮助用户理解结果，Panel 是否足够监督 agent 协作过程。
- 每次运行是否形成 Run Memory 和 Experience Candidate。
- 类似任务再次出现时是否显著更快、更稳、更可解释。
- 能力是否能被治理后复用，失败、重复、过时能力是否能被修剪。
