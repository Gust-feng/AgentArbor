# ADR-0012: 植物学融合架构候选基线

## Status

Accepted as historical candidate baseline. Root semantics revised by [ADR-0015](ADR-0015-树形语义基线与Root重定义.md), then extended into the current continuous-root architecture by [ADR-0016](ADR-0016-种子层与持续根系架构.md).

## Context

ADR-0011 确定了 AgentArbor 采用“固定骨架 + 动态发育 + 分层通信”的融合方向。随后形成的 `植物学融合架构/` 把这个方向进一步展开为根、干、枝、叶、花、果、土壤七层。

本 ADR 的原始版本曾把 Root 定义为方向和目标治理职责。随着树形隐喻继续收敛，这一语义被证明不够贴合植物结构：土壤应保存固定资产，根应向不同方向探索并吸收信息，主干应汇总根系信息并制定生长计划。

因此，ADR-0012 保留为植物学融合架构的历史候选基线，但当前正式运行主线以 ADR-0016 为准。

## Decision

AgentArbor 保留植物学融合架构作为当前产品架构资料，但采用 ADR-0015 和 ADR-0016 的树形语义修正：

| 层级 | 当前语义 |
| --- | --- |
| Soil | 固定资产、能力资产、治理规则、历史证据和失败模式 |
| Seed | 前置成像和用户确认，输出 Seed Packet |
| Root System | 持续地下生命系统，输出版本化 Root Brief |
| Core Control Cluster | 汇总根系信息，制定和修订 Growth Plan 与 Workflow IR |
| Branch | 运行协调结构 |
| Leaf | 最小执行单元 |
| Flower | 验证、评审和成熟度判断 |
| Fruit | 成熟交付物、AgentApp、能力包或可脱离子 agent |
| Ring | EventLog、Run Memory 和 Experience Candidate 的聚合视图 |

旧研究结构仍可作为资料输入，但不能直接决定当前命名：

| 旧研究结构 | 当前处理规则 |
| --- | --- |
| Canopy 目标治理层 | 其治理和目标约束思想被拆入 Goal Kernel、Trunk Synthesis、Verification 和 Governance，不再作为 Root 语义。 |
| Trunk 阶段管理层 | 保留为主干综合与计划职责。 |
| Root 能力执行层 | 不沿用为 Root；执行和资产吸收职责分别进入 Leaf、Flower、Fruit 和 Soil。 |

`.agentarbor/` 采用增量填充策略：

- 可以为空，直到具体产品 agent、workflow、memory 或 schema 有清晰职责和出生依据。
- 不提前创建固定完整 agent 列表。
- 每个新增启动资产必须有对应计划、ADR 或产品架构依据，并同步 registry。
- registry 可以记录候选架构基线和填充策略，但不得登记不存在的资产路径。

## Consequences

- 当前正式运行主线以 ADR-0016 为准。
- 后续实现骨架层前，先完成 Seed Packet、Root Brief、Growth Plan、Root Callback、Growth Plan Revision、Run Memory、Experience Candidate、Capability Asset 和 Path Bias 的接口对齐。
- 历史资料保留，但旧 Root 语义不得继续污染当前架构入口。
- `.agentarbor/agents/` 当前为空是合理状态，不代表产品层缺失；它等待按真实出生依据逐步出生启动资产。
