# 路径记忆第一阶段开发方案

## 1. 目标

本方案是 [ADR-0032](../../架构设计/产品架构/ADR-0032-路径记忆与长期记忆回流架构.md) 的第一阶段实现契约。完成后，每个进入稳定终态的 Ordinary run 都会自动形成一条本地持久化 `PathMemory`，并能在进程重启后补齐遗漏记录。

本阶段解决的是“可靠地留下真实路径事实”，不是“让模型立刻拥有更聪明的长期记忆”。PathMemory 默认不进入模型上下文；只有后续 ExperienceCandidate、Governance 和检索契约稳定后，记忆才可能影响未来任务。

### 当前行为

- Pi Session 保存模型实际消费的会话树。
- Ordinary 保存 `ordinary-run/v5` run 状态、工具事实、终态和结果。
- `src/domain/fruits/contracts.ts` 中的旧 `RunMemory` 依赖未出生的 Plan/Aboveground 字段，没有生产 writer 或 repository。
- `src/domain/soil/store.ts` 只有内存只读引用；`run_memory` Research source 默认不可见且只读取空引用。
- `createPanelRuntime()` 没有装配记忆 feature，重启后也不会补写运行沉淀。

### 要求行为

- Ordinary 的 `completed / failed / blocked / cancelled` 稳定终态自动触发 PathMemory 采集。
- 一条 Ordinary run 最多对应一条 PathMemory；实时采集和重启对账共享同一幂等边界。
- PathMemory 只记录可证明的运行事实，不生成成功模式、偏离原因或复用建议。
- 记忆写入失败不改变已经提交的 Ordinary 终态，并留下可诊断错误；下次启动可重试补齐。
- PathMemory 拥有独立 schema、repository、facade、生命周期和测试，不进入 Ordinary store、Pi Session 或 Soil stub。

## 2. 第一阶段范围

### 必须交付

1. `path-memory/v1` 不可变数据契约和 Zod 边界校验。
2. 本地文件系统 repository，支持原子创建、读取、目录扫描列表、按来源查找和删除。
3. `PathMemoryFeature` command/query/event facade。
4. Ordinary 稳定终态事实 query 和全局终态通知。
5. `OrdinaryPathMemoryConnector` 的实时采集、启动对账和释放 drain。
6. 唯一 `createPanelRuntime()` 装配及关闭顺序。
7. 成功、失败、阻塞、取消、并发幂等、写入失败和重启补偿测试。
8. 实现完成后同步更新 `CURRENT_RUNTIME_MODE.md` 与相关开发指南。

### 明确不做

- 不引入新依赖、SQLite、PostgreSQL、向量库或图数据库。
- 不调用 LLM 做摘要、事实抽取、聚类或冲突合并。
- 不实现 `memory_write` Agent tool。
- 不实现语义搜索、embedding、rerank 或 prompt 注入。
- 不实现 ExperienceCandidate、PathBias、Governance、Global Soil 或 Ring Memory runtime。
- 不接入旧 `run_memory` Research adapter。
- 不做完整记忆管理 UI、云同步、导出、TTL 或自动清理。
- 不接入 Multi-Agent；Sub-Agent 调用仍只作为父 Ordinary 的工具路径事实出现。

## 3. 核心设计判断

### 3.1 第一阶段按 run 采集，不猜测“任务”

当前 Ordinary 是线性会话轮次模型，一个 run 对应一个用户 turn。工程层不知道多轮对话是否共同构成一个任务，也没有独立 Task 状态机。因此第一阶段使用 `sourceRunId` 作为路径记忆的来源身份。

未来可以新增只读聚合，把同一 conversation、显式 Task 或 Plan 的多条 PathMemory 组合为任务视图；原始 PathMemory 不修改、不合并。

### 3.2 所有终态都采集

采集状态包括：

- `completed`：模型正常结束，不代表验证成功。
- `failed`：provider、上下文或执行边界明确失败。
- `blocked`：需要新一轮输入或存在结果未知等阻塞事实。
- `cancelled`：用户或宿主取消；仍保留已经发生的工具事实。

`queued`、`running` 和 `awaiting_approval` 不是采集终态。不得用是否调用工具、用户文本长度或回答关键词过滤所谓“真实任务”。

### 3.3 终态和验证分开

Ordinary 当前没有正式 Verification owner。即使 run 调用了测试命令，PathMemory 也不能根据工具名或退出文本宣称任务已验证。

第一阶段所有 Ordinary 来源统一写入：

```ts
{ status: "not_recorded", evidenceRefs: [] }
```

未来只有正式 Verification/Acceptance 契约提供结构化结论时，才允许写入 `verified` 或 `failed`。

### 3.4 自动采集不自动召回

PathMemory v1 是 archive，不是 prompt context。第一阶段没有模型可见 memory tool，也不修改 system prompt。确定性 query 只供测试、诊断和未来 adapter 使用。

## 4. 功能边界

```text
OrdinaryAgentFeature
  commands -> 创建和推进 run
  queries  -> 稳定终态来源事实
  events   -> terminal facts ready 通知
       |
       v
OrdinaryPathMemoryConnector
  映射公开事实 + 调用 capture + 启动对账 + drain
       |
       v
PathMemoryFeature
  commands -> capture / delete
  queries  -> get / findBySource / list
  events   -> captured / deleted
       |
       v
PathMemoryRepository
  runtime/path-memory/
```

所有权规则：

- Ordinary 不导入 PathMemory contract，不直接写记忆 repository。
- PathMemory 不读取 Ordinary store、live map、Panel DTO 或 Pi Session 私有 entry。
- Connector 只依赖双方公开 facade，不能解释任务语义或缓存第二份状态。
- Panel route 和 UI 本阶段不拥有 PathMemory command/query。
- 只有 `createPanelRuntime()` 创建 connector 和两侧 feature。

## 5. 数据契约

以下是目标语义形状；实现时可按项目命名风格拆分文件，但不能削弱判别联合、readonly 和来源身份。

```ts
export const PATH_MEMORY_SCHEMA_VERSION = "path-memory/v1" as const;

export type PathMemoryToolStep = {
  readonly ordinal: number;
  readonly toolFactId: string;
  readonly parentToolFactId?: string;
  readonly toolName: string;
  readonly status: "completed" | "failed" | "cancelled";
  readonly durationMs: number;
  readonly resultRef: string;
  readonly error?: {
    readonly domain?: string;
    readonly code?: string;
    readonly message: string;
  };
};

export type PathMemoryVerification =
  | {
      readonly status: "verified" | "failed";
      readonly evidenceRefs: readonly string[];
    }
  | {
      readonly status: "not_recorded";
      readonly evidenceRefs: readonly [];
    };

export type PathMemoryOutcome =
  | {
      readonly terminalStatus: "completed";
      readonly answerRef: string;
    }
  | {
      readonly terminalStatus: "failed";
      readonly error: { readonly code: string; readonly message: string };
    }
  | {
      readonly terminalStatus: "cancelled";
      readonly reason: string;
    }
  | {
      readonly terminalStatus: "blocked";
      readonly reason: { readonly code: string; readonly message: string };
      readonly continueBy: "new_turn";
    };

export type PathMemory = {
  readonly id: string;
  readonly source: {
    readonly feature: "ordinary";
    readonly runId: string;
    readonly sourceRevision: number;
    readonly conversationId: string;
    readonly userTurnId: string;
    readonly assistantTurnId: string;
    readonly predecessorRunId?: string;
    readonly runCreatedAt: string;
    readonly terminalAt: string;
  };
  readonly scope: {
    readonly workspaceRoot: string;
    readonly workspaceSelection: "default" | "explicit";
  };
  readonly goal: {
    readonly userRequest: string;
    readonly taskContextRefs: readonly string[];
  };
  readonly path: {
    readonly executionStarted: boolean;
    readonly toolSteps: readonly PathMemoryToolStep[];
  };
  readonly outcome: PathMemoryOutcome;
  readonly verification: PathMemoryVerification;
  readonly evidenceRefs: readonly string[];
  readonly capturedAt: string;
};

export type PathMemoryDocument = {
  readonly schemaVersion: typeof PATH_MEMORY_SCHEMA_VERSION;
  readonly memory: PathMemory;
};
```

### 字段来源规则

| PathMemory 字段 | 唯一来源 | 禁止行为 |
| --- | --- | --- |
| `source.*` | Ordinary stable terminal query | 从 SSE、Panel read-model 或目录名反推 |
| `workspaceRoot` | run 出生时冻结的 capability snapshot | 使用当前全局 workspace 覆盖 |
| `userRequest` | `OrdinaryRunInput.userMessage` | 让模型重写成“更好的目标” |
| `taskContextRefs` | 本轮 Task Soil context refs | 复制附件字节或文件正文 |
| `toolSteps` | durable `ToolCallResult[]` | 复制 input/output，或按工具名猜测语义 |
| `outcome` | `OrdinaryRunStatus` | 把 completed 映射为 verified |
| `verification` | 正式 Verification source | 从命令名、退出码或回答文案推断 |
| `evidenceRefs` | source run/tool fact 的稳定引用 | 生成无法解析的伪 ref |

`toolSteps.ordinal` 只表示 Ordinary 持久化的事实顺序，不声明并行调用之间的因果关系。父子关系只使用 `parentToolFactId` 表达。

### 稳定引用格式

第一阶段使用可解析、无正文的逻辑引用：

```text
ordinary-run:<runId>
ordinary-run:<runId>#answer
ordinary-run:<runId>#tool:<toolFactId>
```

引用解析仍由 Ordinary 公开 query 负责。PathMemory 不读取其文件路径。

## 6. 幂等与不可变性

唯一来源键为：

```text
(source.feature = "ordinary", source.runId)
```

推荐使用确定性 id：

```text
path-memory:ordinary:<runId>
```

`capture` 的行为：

1. 目标不存在：校验后原子创建，返回 `created`。
2. 已存在且全部内容相同：返回 `existing`，不发布重复事件。
3. 已存在但 `sourceRevision` 或内容不同：返回 `path_memory_source_conflict`，不得覆盖。

PathMemory v1 创建后不可更新。后续若需要语义修订，应新增候选或版本化记录，而不是修改历史路径。终态稳定查询必须保证不会把仍可能追加工具事实的 run 交给 capture。

## 7. Ordinary 稳定终态契约

Ordinary 新增一个窄的公开来源投影，建议命名为 `OrdinaryStableTerminalRunFacts`。它只包含构造 PathMemory 所需的真实字段和 `sourceRevision`，不暴露完整 `OrdinaryRunState`、repository document、live controller 或 Pi 私有对象。

建议扩展 facade：

```ts
type OrdinaryStableTerminalRunFacts = {
  readonly runId: string;
  readonly sourceRevision: number;
  readonly turn: OrdinaryRunTurn;
  readonly userMessage: string;
  readonly taskContextRefs: readonly string[];
  readonly workspaceRoot: string;
  readonly workspaceSelection: "default" | "explicit";
  readonly executionStarted: boolean;
  readonly toolFacts: readonly {
    readonly toolFactId: string;
    readonly parentToolFactId?: string;
    readonly toolName: string;
    readonly status: "completed" | "failed" | "cancelled";
    readonly durationMs: number;
    readonly error?: {
      readonly domain?: string;
      readonly code?: string;
      readonly message: string;
    };
  }[];
  readonly status: Extract<
    OrdinaryRunStatus,
    { readonly kind: "completed" | "failed" | "cancelled" | "blocked" }
  >;
  readonly createdAt: string;
  readonly terminalAt: string;
};

interface OrdinaryAgentFeature {
  readonly queries: {
    // existing queries...
    getStableTerminalRunFacts(
      runId: string,
    ): Promise<OrdinaryStableTerminalRunFacts | undefined>;
  };
  readonly events: {
    // existing events...
    subscribeStableTerminalRuns(
      listener: (runId: string) => void,
    ): () => void;
  };
}
```

实现必须满足：

- 非终态返回 `undefined`。
- 仍有 execution、controller、pending tool round 或待收口 approval fact 时返回 `undefined`。
- live run 在所有已接受工具结果持久化并完成 `settleExecution` 后才通知。
- 启动恢复先完成 lost continuation、pending tool round 和 approval result 对账，再允许 query 返回。
- `toolFacts` 只投影已收口的最终工具结果，不包含 `approval_required`、input 或 output 正文。
- 同一 run 可以重复通知；consumer 必须幂等。
- 通知 listener 的异常不能回写或推翻 Ordinary 终态。

不要把该契约命名为 memory event。它表达的是 Ordinary 自己拥有的稳定终态事实，未来审计或其他只读 consumer 也可以使用。

## 8. PathMemory facade

建议公开契约：

```ts
export interface PathMemoryFeature {
  readonly commands: {
    capture(input: PathMemoryCaptureInput): Promise<
      | { readonly status: "created"; readonly memory: PathMemory }
      | { readonly status: "existing"; readonly memory: PathMemory }
    >;
    delete(memoryId: string): Promise<void>;
  };
  readonly queries: {
    get(memoryId: string): Promise<PathMemory | undefined>;
    findBySource(input: {
      readonly feature: "ordinary";
      readonly runId: string;
    }): Promise<PathMemory | undefined>;
    list(input?: {
      readonly conversationId?: string;
      readonly workspaceRoot?: string;
      readonly terminalStatus?: PathMemoryOutcome["terminalStatus"];
      readonly limit?: number;
    }): Promise<readonly PathMemory[]>;
  };
  readonly events: {
    subscribe(listener: (event: PathMemoryEvent) => void): () => void;
  };
  release(): Promise<void>;
}
```

第一阶段错误码至少包含：

- `path_memory_feature_released`
- `path_memory_not_found`
- `path_memory_source_conflict`
- `path_memory_snapshot_incompatible`
- `path_memory_repository_failure`

边界 JSON 以 `unknown` 读取，经 Zod 严格校验后进入内部类型。不得使用 `any`、双重断言或损坏数据的静默默认值。

## 9. 文件持久化

默认目录：

```text
<runtimeHome>/path-memory/
  records/
    <encoded-memory-id>.json
    .tmp/
```

选择 JSON 文件而不是数据库的理由：

- 当前只有单机、单进程 writer，数据量和查询能力尚未证明需要数据库。
- 项目已经有按记录原子落盘的 repository 模式。
- v1 schema 可直接检查和测试，不引入迁移框架或新运维依赖。
- 未来向量索引可以从 PathMemory 重建，不需要成为写入事实源。

repository 规则：

- record 原子 rename 成功即为 commit。
- 同一 source key 的创建使用 feature-owned FIFO，避免实时采集与启动对账并发双写。
- `findBySource` 使用确定性 memory id 直接读取；`list` 在第一阶段按需扫描并校验 `records/`。
- 损坏或未知 schema 的 record 明确报告 incompatible，不能覆盖或从当前配置猜测字段。
- v1 不迁移旧 `RunMemory`，不扫描 `.trellis`、Soil stub 或 Ordinary 私有目录拼装旧数据。
- v1 不设 TTL、不静默淘汰。删除只通过 PathMemory command。

第一阶段不维护 manifest、数据库索引或消费位点。当前 `runtimeHome` 已有单写者租约，配合 feature 内 source FIFO 足以保证本地一致性。只有真实 PathMemory 数量和查询耗时证明目录扫描不可接受后，才增加可从 records 重建的索引。

## 10. 实时采集与启动对账

### 实时路径

```text
Ordinary 提交稳定终态
  -> subscribeStableTerminalRuns(runId)
  -> connector.getStableTerminalRunFacts(runId)
  -> 映射 PathMemoryCaptureInput
  -> pathMemory.commands.capture(input)
  -> created / existing
```

Connector 必须跟踪在途 capture Promise，并把失败交给明确的 Host diagnostic sink。不得 fire-and-forget 后丢失 rejection。

### 启动对账

创建顺序：

1. 创建 Ordinary feature。
2. 创建 PathMemory repository 和 feature。
3. 创建 connector，并先注册稳定终态订阅。
4. Connector 启动自有 reconciliation Promise，调用 Ordinary `listRuns(Number.MAX_SAFE_INTEGER)`。
5. 对每个终态 summary 调用 `getStableTerminalRunFacts`。
6. 对返回的事实调用同一 `capture` command。
7. `createPanelRuntime()` 保持同步并正常暴露 runtime；connector 继续拥有、观察并在关闭时 drain 对账任务。

先订阅、后扫描可以覆盖初始化窗口；重复命中由 source key 幂等吸收。需要等待完整对账的目标测试或诊断调用可以显式等待 connector 的 `ready()`；Ordinary route 不依赖它，记忆失败不能阻止用户继续运行任务。第一阶段允许启动时全量扫描，因为当前本地数据规模有限。只有真实数据证明启动成本不可接受后，才增加 cursor/checkpoint，不提前建设消费位点系统。

### 关闭顺序

1. Host 停止新 HTTP 工作准入。
2. Ordinary release 取消或收口现有运行，并产生最后的稳定终态事实。
3. Connector 保持订阅直到 Ordinary release 完成。
4. Connector 取消订阅并 drain 已接受的 capture。
5. PathMemory feature release。
6. 释放 Pi Session storage 和 Host 其他资源。

任一记忆 drain 失败必须作为关闭诊断返回，但不能把已经持久化的 Ordinary 终态改成 failed。

## 11. 删除与来源生命周期

第一阶段 PathMemory 与来源 conversation 分别拥有生命周期：

- 删除 Ordinary conversation 不自动跨 feature 事务删除 PathMemory。
- 来源删除后，PathMemory 的 goal、路径元数据和终态仍可读；answer/tool evidence ref 可以变为 unavailable。
- 显式 `pathMemory.commands.delete` 删除记忆 record 和 manifest entry。
- 后续记忆管理 UI 应提供按来源查看和删除；本阶段只建立后端 command/query。

不做自动级联是为了避免在没有产品删除语义前引入跨 feature 事务。未来若用户确认“删除会话必须同时忘记”，应通过新的 Workbench command 编排并提供失败补偿，而不是让两个 repository 互相调用。

## 12. 失败语义

| 场景 | Ordinary 结果 | PathMemory 行为 |
| --- | --- | --- |
| 正常完成并写入成功 | 保持 completed | 创建一条 completed PathMemory |
| failed/blocked/cancelled | 保持原终态 | 创建对应终态 PathMemory |
| 重复实时通知 | 不受影响 | 返回 existing，不重复事件 |
| 实时记忆写入失败 | 不改 Ordinary | 报告 diagnostic；下次启动对账重试 |
| 进程在终态后、写记忆前退出 | 已有 Ordinary snapshot | 启动对账补写 |
| record 已存在但内容冲突 | 不改 Ordinary | 明确 source conflict，禁止覆盖 |
| 单条 record 损坏 | 不改 Ordinary | 报 incompatible，禁止覆盖 |
| 来源证据已删除 | 不改双方元数据 | ref 读取诚实返回 unavailable |

不要加入“记忆失败则重跑 Ordinary”或“自动重放工具”的恢复策略。记忆写入是下游副作用，不能重复真实任务。

这一步必须在编译和依赖搜索支持下进行，不能为了术语整齐误删延期 Multi-Agent 仍编译依赖的类型。

## 16. 验收门

第一阶段只有同时满足以下条件才算完成：

- 新建、失败、阻塞和取消的 Ordinary 稳定终态都能形成真实 PathMemory。
- completed 不会被写成 verified；没有任何关键词或工具名成功推断。
- 取消时不会漏掉已接受工具的最终事实，也不会重放副作用。
- 同一 source run 在并发、重复事件和重启对账下只有一条记录。
- 终态后写入失败不会改写 Ordinary，重启后可以补齐。
- 重启实例可查询既有 PathMemory，损坏数据不会静默回退。
- PathMemory 不复制 transcript、assistant 正文、工具 input/output 或附件字节。
- Ordinary、PathMemory、Connector、Composition Root 的依赖方向符合 ADR-0028。
- 没有新增数据库、向量依赖、后台 LLM、Global Soil 或 UI 占位。
- `CURRENT_RUNTIME_MODE.md` 在代码生效时已准确说明自动路径记忆采集；索引和术语无双重事实源。

## 17. 实现审查收口记录

> 记录时间：2026-07-26。以下问题来自路径记忆实现后的代码审查和聚焦验证。收口时间：2026-07-26，三项均已修复并补齐测试。

### 已收口 P1：显式删除的 PathMemory 会在重启后被对账重新生成

原现象：删除只移除 `runtime/path-memory/records/<memoryId>.json`，下次启动对账会用同一 `sourceRunId` 重新采集，删除的记录复活。

已实现修复：

- 删除先原子写入 `<runtimeHome>/path-memory/deletions/<encoded-memory-id>.json` tombstone（`path-memory-deletion/v1`），再移除 record；两步之间崩溃也不会复活。
- `capture` 遇到 tombstone 返回 `{ status: "suppressed", memoryId, deletedAt }`，不落盘、不发事件；更高 `sourceRevision` 也不能绕过 tombstone。
- get/findBySource/list 对带 tombstone 的 id 一律视为不存在，即使 record 文件因崩溃残留。
- connector 诊断增加 `skippedDeleted` 计数（realtime 与 reconciliation 各一）。
- tombstone 损坏或未知版本以 `path_memory_snapshot_incompatible` 明确报错，不静默当作不存在。
- 恢复被删除的记忆必须由未来的显式 command 清除 tombstone，没有默认复活路径。

已补测试：repository 删除后重建实例对账不复活、更高 revision 不绕过、损坏/未知版本 tombstone 报错、残留 record 读作不存在；feature 删除后 re-capture suppressed 且无事件；connector 实时重复通知与完整重启对账均不重建记录并计入 `skippedDeleted`。

### 已收口 P1：当前运行事实文档与实际接入范围不一致

采用原推荐的第二种修法：`CURRENT_RUNTIME_MODE.md` 已按“第一阶段 + 部分第二阶段”口径更新，明确包含只读 PathMemory 管理 UI、显式删除（tombstone 语义）、关键词 search（Latin 整词 + CJK bigram）、用户显式 ExperienceCandidate API，同时声明仍没有模型自动召回、memory tool、prompt 注入、PathBias、向量检索、后台 LLM 与 Governance/Global Soil。本方案第 2 节的“明确不做”仍描述第一阶段原始边界，实际范围以 `CURRENT_RUNTIME_MODE.md` 为准。

### 已收口 P2：ExperienceCandidate 持久化边界允许不可信 revision 和治理状态

已实现修复：

- schema 治理互斥：`proposed` 禁止 `decidedAt`；`accepted / rejected / retired` 必须有 `decidedAt`（原有）。
- `append(record)` 强制 gapless 链：revision 必须等于已存储最高 revision + 1；`origin.fromRevision` 必须等于 revision - 1。绕过 feature 的导入/fixture/bug 写入跳号或错误 origin 都以 `experience_candidate_revision_conflict` 拒绝。

已补测试：repository 拒绝无 revision 1 的 revision 2、拒绝跳号、拒绝 stale origin、拒绝 `proposed + decidedAt`；feature 并发 revise/decision 只产生一个合法 head（[1, 2] 无跳号，落败方收到 revision conflict）。

## 18. 后续演进

第一阶段完成并积累真实样本后，再按证据推进：

### 第二阶段：可检查的经验候选

- 增加只读 PathMemory 管理视图和显式删除。
- 由 Agent 或后台分析生成 `ExperienceCandidate`，保留来源 PathMemory、适用条件、不适用条件和置信度。
- 建立用户接受、拒绝、修订和冲突处理，不直接写 Global Soil。

### 第三阶段：受治理召回

- 先做 workspace + 结构字段 + 关键词检索，验证召回质量。
- 数据量和质量指标证明需要后，再增加 embedding/rerank；向量索引保持可重建。
- 只把治理后的候选或 PathBias 作为有界材料提供给 Agent，并记录采用/拒绝引用。

### 第四阶段：长期知识与多来源

- 在真实需求下出生稳定偏好、长期事实、Governance 和 Global Soil feature。
- 为 Multi-Agent 定义自己的终态来源契约，再接入 PathMemory；不能复用 Ordinary 状态或 repository。
- 只有出现真实实体时序查询需求后再评估 Graphiti/知识图谱路线。

阶段升级必须由真实 PathMemory 数量、重复任务样本、召回评估和用户治理需求驱动，不能因为框架支持就提前实现。
