# 问题解决与经验积累闭环

## 基本路径

AgentArbor 的第一验证环路不是"生成 AgentApp"，而是"理解问题、解决问题、沉淀经验"：

```text
用户问题 / 场景
  -> Soil（检索长期事实、能力资产、Path Bias、失败模式）
  -> Underground Center（目标成形、多方向探索、交叉裁决）
  -> .agentarbor Direction Handoff（问题解决方案 + 证据索引）
  -> Aboveground Center（Growth Plan、Workflow IR、执行组织）
  -> Aboveground Growth（执行解决、验证反馈、Nutrient Request）
  -> Verification / Acceptance（验收证据）
  -> Fruits（交付物、运行报告、Experience Candidate）
  -> Governance（治理门：评估、权限、版本、退役）
  -> Capability Asset / Path Bias（入土：下次类似问题自动牵引）
  -> Soil
```

用户获得的是**问题被解决**，以及解决方案和经验的长期沉淀。AgentApp 只是 Fruits 多种形态中的一种——当且仅当问题本身需要长期独立运行的任务时才产出。绝大多数场景下，用户关心的是问题有没有解决，而不是有没有多出一个 agent。

## 产品判断

- 用户入口是问题或场景描述，不是技术配置。
- Underground 的职责是理解问题、探索方案、交叉裁决——不是"设计一个 Agent"。
- Aboveground 的职责是执行解决方案——不是"生成一个 Agent"。
- Fruits 可以是可运行的交付物、能力包、运行报告或 Experience Candidate。AgentApp 只是其中一种可选形态。
- 方向交接、执行、验证、沉淀、治理必须形成闭环。这不是一次性任务，而是能力持续生长的循环。

## 必须具备的结构

- 目标内核：问题持续存在并驱动后续状态。
- Direction Handoff：用户问题必须先经过地下中枢成形、反驳、证据探索和交叉裁决。交接包描述的是"问题如何解决"，不是"Agent 如何设计"。
- Growth Plan：地上中枢形成执行入口，并基于 Nutrient Patch 可修订。
- Workflow IR：任务可暂停、恢复、分叉和验证。
- Aboveground Growth：任务由有边界、有交付物、有生命周期的协作单元推进。
- Verification：解决方案必须经过检查。
- Fruits：交付物和候选沉淀必须明确归属。
- Governance：经验进入长期资产前必须经过评估。
- 运行沉淀：每次任务必须产生 Run Memory、Experience Candidate 和 Path Bias。
- 谱系系统：解决方案的来源、分支和演化必须可追踪。

## AgentApp 的出生条件

AgentApp 不是产品主线。只有当问题同时满足以下条件时，才考虑产出独立运行的 AgentApp：

- 需要长期、定时、独立运行的执行单元（如每日监测、持续同步）。
- 有明确的输入输出契约和权限边界。
- Direction Handoff 中已经验证该问题适合独立执行形态。
- 有对应的 Workflow IR 和运行工程结构。
- 有测试或验收样例。
- 有 Run Memory、Experience Candidate 和 Path Bias。
- 有谱系记录和退役路径。

不满足上述条件的场景——绝大多数用户场景——由母体平台直接执行解决并沉淀经验，不分化子 agent。
