# ADR 0001：外部基础框架仅作参考

## 状态

Accepted

## 背景

项目之外存在一套 Agent 工程资料。它包含 Agent 项目模板、架构模板、脚本和参考项目复盘。

这些内容对低层 Agent 工程拆分有参考价值，但它们不是 AgentArbor 的产品源头。

AgentArbor 的主线来自自身愿景：

> 让自然语言目标长成可运行、可验证、可追溯、可继续演化的 AgentApp。

## 决策

外部基础框架仅作为基础工程参考使用。

它不能作为：

* AgentArbor 的主架构。
* AgentArbor 的最终生成物标准。
* AgentArbor 的产品定位。
* AgentArbor 的长期路线。
* AgentArbor 的灵魂来源。

若需要借鉴，必须先复制必要材料到本项目，或沉淀成本项目自己的参考文档。

当前沉淀文档为：

```text
docs/04-参考沉淀/Agent工程基础原则.md
```

当前 `templates/agent-project/` 只能视为初始参考模板，后续应被 AgentArbor 自己的 AgentApp 契约、`arbor.json`、Workflow IR、验证系统和谱系模型逐步重塑。

## 理由

外部基础框架解决的是较低层问题：

```text
一个 Agent 项目如何拆成 Prompt、Schema、工具、权限和测试。
```

AgentArbor 解决的是更高层问题：

```text
一个目标如何被孕育成可运行、可验证、可追溯、可继续演化的 AgentApp。
```

两者不是同一层级。低层参考不能反过来决定高层系统的灵魂。

## 可以参考

* Agent 项目保持薄。
* Prompt、Schema、工具、权限、测试一起版本化。
* 平台能力不复制到每个 Agent 项目。
* 外部复盘里的反例：事实源漂移、权限不集中、叙事命名污染核心模型。

## 不可直接采用

* 外部基础框架的完整目录结构。
* 外部基础框架的 AgentSpec 字段全集。
* 外部参考项目的叙事命名体系。
* 外部基础框架的长期平台路线。
* 把外部模板等同于 AgentArbor 最终标准。

## 影响

后续所有文档和代码应优先服从 AgentArbor 自身对象模型：

```text
ArborSpec
GoalSpec
AgentApp
WorkflowIR
AgentManifest
CapabilitySpec
ValidationResult
LineageRecord
```

若外部参考与上述模型冲突，以 AgentArbor 自身模型为准。
