# 最小运行契约

本文件定义进入第一阶段实现前必须冻结的最小运行契约。代码可以晚出生，但这些对象不能含混。

## 内部消息

`ArborMessage` 是 AgentArbor 的内部消息母语。外部协议必须通过 adapter 转换为内部消息，不能直接污染核心模型。

```ts
type ArborMessage<TPayload = unknown> = {
  id: string;
  traceId: string;
  taskId?: string;
  parentTaskId?: string;
  from: { id: string; role?: string; cluster?: string };
  to?: { id: string } | { role: string } | { group: string };
  type: ArborMessageType;
  intent: string;
  payload: TPayload;
  artifacts?: ArtifactRef[];
  requiredCapabilities?: string[];
  priority?: 'low' | 'normal' | 'high' | 'critical';
  permissions?: {
    canRead?: string[];
    canWrite?: string[];
    canExecute?: string[];
  };
  createdAt: string;
};
```

Direction Handoff 是方向交接包，不是长期资产，不是 Growth Plan。它应保存 Soil 引用和证据索引，不复制 Soil 内容。

单个探索 agent 或根须集群的输出不能直接进入 Direction Handoff。它们必须先以 `ExplorationCandidateRef` 记录为候选观察、候选证据或候选主张，再通过 `ConvergenceReview` 记录交叉校验、去重、来源归因和冲突裁决结果。Direction Handoff 与 NutrientPatch 只保存 `convergenceReviewRef`，不内嵌未治理的原始审查材料。

## 任务状态

```text
Draft
DirectionReady
Planning
Assigned
Running
Blocked
NutrientRequested
Revising
Verifying
AcceptedForDelivery
Fruiting
GovernanceReview
Delivered
Archived
Cancelled
Failed
```

守卫规则：

- `Planning` 前必须有已批准的 DirectionHandoff。
- `Assigned` 前必须有 GrowthPlan。
- `NutrientRequested` 必须由 NutrientRequest 进入。
- `Revising` 必须引用新的 DirectionHandoff 版本、NutrientPatch 或无需补充证据。
- `AcceptedForDelivery` 必须经过 Verification。
- `Fruiting` 必须有至少一个产物或候选沉淀。
- `GovernanceReview` 必须检查权限、谱系、版本、适用条件和退役路径。
- `Delivered` 必须经过 Acceptance。
- `Archived` 前必须写入 EventLog。
- `Archived` 前必须写入 RunMemory，或明确记录没有可沉淀内容的原因。
- 高风险操作必须经过 `user_approval.requested`。

## 第一阶段限制

第一阶段只实现内存版接口和最小事件链。不实现 A2A Adapter、MCP Adapter、AG-UI Adapter、完整模型调用、长期记忆治理、自主演化、复杂权限系统和数据库持久化。

第一阶段仍必须保留 `DirectionHandoff`、`GrowthPlan`、`NutrientRequest`、`NutrientPatch`、`GrowthPlanRevision`、`RunMemory`、`ExperienceCandidate` 和 `PathBias` 的最小结构。否则系统只能证明自己会执行一次任务，不能证明自己会把一次任务变成下一次任务的有效倾向。
