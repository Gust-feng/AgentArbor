# 技术主线

## 默认方向

当前默认实现路线是桌面基础 Agent 与基础设施优先。普通桌面会话先稳定消息输入、连续对话、模型工具循环、工具元数据、命令确认、事件重放、RuntimeDatabase read-model、Skills 元数据发现和用户友好工作台；地下/地上组织、Plan Package、Governance、Routines、可见 deep 入口和多 agent 团队模式保留为未来能力边界，不进入默认首屏、普通会话文案或本轮后端改动。

实现以 TypeScript 自研架构为主：

- 语言：TypeScript。
- 本地服务：Node.js。
- 持久化：本地嵌入式数据库优先。
- 前端：TypeScript Web 技术栈。
- 测试：单元测试、集成测试、任务样例测试、运行边界测试。
- 外部系统：通过 adapter 接入。

## 实现原则

- 先稳定基础 Agent 运行闭环，再考虑是否重启地下/地上高级组织。
- 普通模式和未来深入模式共享基础设施，但普通模式不得自动升级、调用或展示 Underground / child-agent / Plan 组织语义。
- 当前不做默认可见 deep 入口，不主动改动 deep 后端；未来 deep / Agent 集群项目必须由用户重新明确启动。
- 避免过度设计指的是普通路径命名和实现语义不能过重，不是删除 deep 长期方向。
- 新增名称应先匹配真实职责：普通文件编辑叫编辑或补丁，helper 叫 helper，adapter 叫 adapter；只有有目标理解、行动选择、输入输出契约和可观察运行边界时才叫 agent。
- 先保证权限、命令确认、验证和可恢复运行，再扩展自动化。
- 先让 ToolCenter、RunEvent、RuntimeDatabase 和 Skills 契约成为共享基础设施，再做 MCP 管理器、Routines 或团队 agent。
- 普通 HTTP/SSE/面板/会话投影不得因脱敏或安全投影吞掉普通回答、工具结果、错误信息、文件正文、stdout/stderr 或开发上下文；运行记录可以为体积和结构保存摘要，但不能替代模型可继续使用的真实工具结果。
- 先证明可恢复、可审计、可取消、可命令确认的桌面 Agent 运行，再谈 Governance 回流和能力资产出生。

## 不提前引入

除非进入明确实现阶段，否则不引入包管理器、构建系统、运行时代码或测试框架。
