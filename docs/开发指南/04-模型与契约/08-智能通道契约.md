# 智能通道契约

模型能力是中性基础设施。当前存在两种正式调用端口，它们服务不同执行形态，不能互相冒充：

```text
Ordinary -> AgentLoop -> Pi AgentHarness/Session adapter
Deep / 单轮模型消费者 -> IntelligenceChannel / AgentTurnRuntime -> OpenAI protocol adapter
```

`model-runtime` 统一解析冻结的模型配置并创建这两种端口。feature、route、Panel 和领域模块不能直接构造外部 SDK client、读取 provider 私有字段或解析原始流式协议。

## 当前支持范围

生产只支持：

- `openai_responses`
- `openai_compatible_chat_completions`

两种协议都以 `providerKind: "openai_compatible"` 进入模型配置。当前不支持 Anthropic、Gemini、Ollama 或其他原生协议；不得通过松散字段、旧枚举或兼容 facade 声称支持。fake 只能由测试显式注入，生产配置和 UI 不提供 fake 模型。

本地 settings 只接受 version 3。旧 settings、旧 provider 协议和损坏配置直接失效，不迁移、不双读；用户重新配置即可。API key 只保存在本地 secret/config 边界，HTTP 配置响应、事件、run snapshot 和日志不得返回原文。

## AgentLoop

Ordinary 生产主线使用 `src/app/model-runtime/agent-loop.ts` 的中性 `AgentLoop` 契约。其职责只有机械执行：

- 接收本轮 instructions、冻结工具边界、可选 AgentTool 和 `AbortSignal`；跨轮消息由 Pi Session 提供。
- 调用 Pi AgentHarness/Session 完成模型-工具-模型循环。
- 将工具调用委托给 ToolCenter gateway，并等待 Ordinary 持久接受工具事实。
- 在 Pi Session 的请求边界执行上下文窗口保护和 compaction；Ordinary 只接收 checkpoint 与 entry refs。
- 返回 Session refs、工具结果、usage、确认请求和最终状态。
- 通过 `onTextDelta` 发送实时正文；通过 `release()` 释放本次 loop 资源。

结果状态互斥：

- `completed`：Pi loop 给出最终正文和可用的 Session refs；是否成为业务完成由 Ordinary feature 决定。
- `approval_required`：返回 `live_only` continuation，等待确认后在同一进程继续。
- `cancelled`：取消已传播到 Pi、工具和资源 owner。
- `failed`：配置、provider、工具交付、上下文或 Pi 执行失败。

`AgentLoop` 不拥有 conversation、run、事件、仓储、read-model、重试策略或业务完成语义。Pi Agent、Harness、Session 和 provider 私有对象只存在于 adapter 内，不能写入 Ordinary snapshot。

## IntelligenceChannel 与 AgentTurnRuntime

Deep manager、child、synthesis 以及其他单轮模型消费者继续使用 `IntelligenceChannel`；需要模型-工具循环时由 `AgentTurnRuntime` 组合它与中性工具 broker。

这条端口负责归一化 `ModelRequest / ModelResponse`、输出契约、流式 delta、usage、失败和取消。它不读取 Ordinary feature，也不能成为统一 Run runtime。Deep 自己将结果映射到 Deep 状态、事件和存储。

## Provider adapter

adapter 负责：

- 鉴权、base URL、模型和请求选项。
- 消息、工具 schema、工具调用和附件协议映射。
- 真实流式输出、finish reason、usage 与 provider 错误归一化。
- OpenAI Responses 的白名单 continuation items 和官方请求能力。
- 冻结 provider profile 的请求方言与有限续接字段；DeepSeek、Kimi、GLM、MiniMax 的私有字段不得进入 feature。

两种正式调用端口必须复用同一份 provider 协议归一化规则。尤其是 Responses streaming，`AgentLoop` transport 与 `IntelligenceChannel` response normalizer 必须共同使用中性 adapter 的 output lifecycle 归并：流式 `output_index` 只标识事件序列中的 item，terminal output 可以压缩或省略已完成 reasoning，不能按 terminal 数组下标重新关联。item id、call id、类型、事件顺序和响应终态构成同一恢复契约；不得在某条调用链单独添加供应商特判、关闭 streaming 或丢弃 continuation。

adapter 不负责：

- Agent 的目标理解、工具选择或停止判断。
- 工具权限、命令确认和业务重试。
- feature 状态、事件、仓储、read-model 或完成语义。
- 用展示摘要替换普通回答、工具结果或错误正文。

OpenAI-compatible Chat 只能使用该 endpoint 明确支持的字段。当前统一 profile 策略处理 DeepSeek thinking/reasoning effort、Kimi thinking、GLM thinking 能力和 MiniMax `reasoning_split`；MiniMax profile 通过 Pi `compat` 显式启用累计正文/reasoning suffix 归一，文本 `reasoning_details` 作为 provider continuation 留在 Pi Session。Chat 与 Responses 都必须尊重冻结的 `stream` 设置，非流式 JSON 响应仍映射为同一 Pi message event 契约。OpenAI Responses 的 provider-native Web Search 由 binding 注入 hosted tool；未知 hosted output item 只允许在 provider、API 和 model 完全一致时原样回放，不能进入 Ordinary snapshot 或跨协议伪转换。refusal、`incomplete_details.reason` 和 provider error 必须形成正式失败，不能拼入普通回答或伪装成完成。

## Pi Session 上下文

- Pi Session 是模型消息、活动 branch/leaf、工具协议组和 compaction entry 的唯一事实源；Ordinary snapshot 只保存 session/entry refs。
- 下一轮由 Pi Session active leaf 提供历史并追加当前输入，不从 Panel 对话、活动事件、摘要或旧账本重建模型消息。
- 上下文压缩由 Pi AgentHarness/Session 在请求边界执行，必须保留完整未消费的工具协议组；压缩失败明确结束当前请求。
- 附件字节只服务当前 provider 请求，不进入 Ordinary snapshot；provider continuation 由 Pi adapter 管理。

## Usage 与缓存

`ModelUsage` 可以包含 input、output、cached input、uncached input、reasoning output、耗时和速度。规则如下：

- provider 未返回的字段保持未知，不能估算后冒充真实计量。
- `inputTokens` 是整次请求输入，不等于当前用户消息长度。
- `cachedInputTokens`、`uncachedInputTokens` 和 reasoning token 只能来自 provider usage。
- Chat 流式请求在 profile 支持时请求原生 usage；Responses 使用官方 usage 字段。
- UI 可以展示 usage，但展示字段不能反向参与上下文恢复、完成判断或计费事实重建。

## 流式输出

- 流式必须来自真实 provider/Pi 请求，不能在完整响应后切片伪造。
- 只有用户可见正文进入助手气泡；hidden reasoning、工具参数和 provider 原始事件不得作为正文输出。
- delta 是 live projection，不是第二事实源。运行完成后以 feature 保存的最终回答为准。
- surface 切换、取消或 run 结束后，旧回调不得继续污染当前视图；资源 owner 必须释放 listener 和 stream。

## 失败规则

以下情况不能声称完成：

- 模型未配置或协议不支持。
- provider/network 失败。
- 请求或输出契约失败。
- context overflow 或轮次/预算耗尽。
- 用户取消或工具取消。
- 工具结果无法完整交付给模型。
- live confirmation continuation 已丢失。
- Chat 返回 `length`、`content_filter` 或未知 finish reason，或 Responses 返回 `incomplete` / 非 `completed` 状态。

feature 只消费中性失败事实，不解析 Pi/provider 私有错误结构。自动重试只能有一个 owner；已经向用户输出可见流后，不得无 attempt identity 地透明重放。
