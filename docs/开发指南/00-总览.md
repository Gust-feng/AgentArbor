# 总览

## 本指南解决什么问题

本指南给 AgentArbor 后续实现提供统一口径。它回答四个问题：

1. AgentArbor 到底是什么。
2. AgentArbor 要用什么核心闭环证明价值。
3. 系统边界、数据契约、Agent 生命周期和平台适配如何分层。
4. 第一阶段实现边界是什么，什么算通过验收。

## 产品主线

AgentArbor 的产品主线是：

```text
自然语言目标
  -> Imagination
  -> Seed Cluster
  -> Seed Packet
  -> User Approval Gate
  -> Soil
  -> Initial Rooting
  -> Root Brief
  -> Core Control Cluster
  -> Growth Plan
  -> Workflow IR
  -> Branch / Leaf Runtime
  -> Verification
  -> Root Callback / Re-rooting
  -> Run Memory
  -> Path Bias
  -> Experience Candidate
  -> Capability Asset / Fruit / Retire
```

这条主线吸收了早期计划书中“从场景生成可运行 Agent 应用”的优点，也吸收了深度研究中“目标驱动、可追溯、可暂停、可分叉、可重生”的长期方向。新的正式基线采用真正持续生长的树形语义：用户提示词是想象，前置集群把想象变成种子，土壤承载种子，根系初始生根并持续生长，主干固定核心调控地上组织，地上执行遇到问题时可以回调地下组织继续补探。

## 当前稳定结论

- AgentArbor 面向的是 Agent / AgentApp 的孕育、运行、验证、演化和资产沉淀。
- 本地优先是底座，不是全部产品定义。
- AgentApp 是从目标、能力、工作流、验证和工程目录共同形成的可运行单元。
- Imagination 是用户提示词中的原始想象，不直接进入正式运行。
- Seed Cluster 是前置成像集群，负责把想象压缩为可审阅、可迭代、可批准的 Seed Packet。
- Seed Packet 是种子包；用户确认后才允许种入 Soil。
- Soil 是固定资产与治理层，不能被临时运行记录污染。
- Root System 是持续地下生命系统，负责 Initial Rooting、Lateral Rooting 和 Deep Rooting。
- Root Brief 是根系探索输出，必须版本化；Growth Plan 必须引用具体 Root Brief 版本。
- Core Control Cluster 是主干固定核心，负责制定和修订 Growth Plan 与 Workflow IR。
- Branch / Leaf / Flower 是地上动态运行组织，负责执行、验证和成熟判断。
- Root Callback 是地上组织遇到问题时回调地下组织的补探机制。
- Run Memory 是单次运行后的经验摘要，Experience Candidate 是可复用候选，Capability Asset 才是进入土壤的正式资产。
- Path Bias 是后续相似任务对已验证路径的自然倾向，不是流程复刻。
- 子 agent 是长期能力成熟后的果实，不是随手创建的角色文件。
- `.agentarbor/` 是未来运行时机器可读资产层，只在契约稳定并有真实出生依据时增量创建。
- `.agents/`、`.codex/`、`.opencode/` 是当前开发和平台适配层，不能反向决定产品语义。

## 资料关系

`docs/研究资料/深度研究v0.1/` 的价值在于系统性、章节化、面向长期架构的写法；早期计划书的价值在于把自然语言场景、AgentApp 生成和工程交付讲得清楚。

本指南继承它们的表达质量，但不继承所有旧方向。旧资料中的结论只有在与当前产品主线一致时，才会进入开发指南。
