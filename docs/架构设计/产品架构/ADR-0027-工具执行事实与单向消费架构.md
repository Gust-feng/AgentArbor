# ADR-0027：工具执行事实与单向消费架构

## 状态

已采纳，适用于 `0.1.x` 开发主线。

## 背景

历史工具链同时携带执行结果、模型投影、UI display、envelope 和 broker 调用计数，导致执行层、模型层、事件层、持久化层和 Panel 互相读取对方的派生字段。同一调用可能由多个消费者重复推导状态，取消也曾被折叠成失败。这些兼容结构削弱了模块边界，并使 live、replay 与持久化难以证明一致。

项目仍处于开发期，因此本轮选择清洁断代，不迁移旧本地 runtime JSON，也不保留 deprecated alias、兼容 facade 或旧字段读取分支。

## 决策

工具执行的唯一权威结果是 `ToolCallResult`：

```text
ToolCenter -> ToolCallResult
                 |
                 +-> model ToolResult
                 +-> append-only tool events
                 +-> tool-call read-model -> Panel
                 +-> runtime factual records
```

`ToolCallResult` 只包含 `callId / toolName / input / output / status / error / errorDomain / errorFacts / durationMs / confirmationRequest`。ToolCenter 负责权限、输入、确认、取消、执行和事实归一化，不拥有调用预算，不生成模型内容、展示对象或持久化对象。

模型边界通过 kernel 纯函数把 `ToolCallResult` 转换为 `ToolResult`，保留结构化 output、错误、附件和 continuation，不读取 Panel display。工具调用预算只属于 Agent loop。

工具生命周期事件固定为 `tool.requested / tool.completed / tool.failed / tool.cancelled`，确认等待使用 `user_approval.requested`。`completed / failed / cancelled` 是互斥终态。统一 reducer 从 append-only event entries 生成 tool-call facts：重复事件幂等，首个终态不可被后续 requested、approval 或其他终态覆盖，缺少 requested 时仍可恢复终态事实。

`ToolDisplayProjection` 属于 Observation/Panel read-model。Panel summary、preview 和 display 只能从调用事实派生，不写回事件、ToolCallResult 或 runtime database。持久化记录和子 Agent trace 只保存状态、错误事实、引用、时间和必要执行字段。

## 兼容与数据

删除 `ToolSafeProjection`、`ToolResultEnvelope`、`projection`、`envelope`、`resetCallCount` 和 `getCallCount`。旧 JSON 的多余字段不会被读取；旧 snapshot 若不满足新契约，视为开发期失效数据，可以清理本地 runtime 目录后重新运行。

## 约束

- adapter 和 ToolCenter 不得依赖或生产 Observation/Panel display 类型。
- kernel 不得依赖 app。
- runtime database 不得依赖 Panel UI 类型或保存 display/envelope 历史副本。
- live、replay、conversation history 和持久化视图必须复用同一事件归约语义。
- 新功能不得建立第二套 projection 中心或以兼容名恢复已删除契约。

## 影响

收益是事实所有权唯一、状态归约可测试、模型能力不被 UI 摘要削弱，并降低 Panel、持久化和子 Agent 对执行内部的耦合。代价是旧开发期运行历史不保证可读；这是本次断代的明确选择。
