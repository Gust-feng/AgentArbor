# 路径倾向机制

> 适用范围：治理后的长期偏好能力。它不能成为 Ordinary / Multi-Agent 的隐藏路由或全局模式选择器。

## 定义

Path Bias 是历史运行对新任务的路径牵引。第二次遇到相似任务时，系统不会强行复刻上一次流程，但会倾向于参考已经验证过的有效路径、失败模式和约束经验。

Path Bias 属于 Global Soil 中的长期牵引，不属于 Task Soil 的临时材料。Task Soil 可以引用 Path Bias，但不能把本轮运行经验直接写成 Path Bias。

## 形成过程

```text
Fruits / Run Trace
  -> PathMemory
  -> Experience Candidate
  -> Governance Pipeline
  -> Path Bias
  -> Global Soil
```

PathMemory 是单次运行的客观路径档案。Experience Candidate 是可能可复用的候选经验。Governance Pipeline 负责筛选、验证、归因、去重、版本化和退役管理。只有通过治理的经验才允许成为 Path Bias。

## Underground Cognitive Runtime 的职责

未来的检索 owner 可以在目标成形或响应显式研究需求时，读取与当前 Task Soil 相似的 PathMemory、Experience Candidate、Capability Asset 和 Path Bias，并把可用的路径倾向作为材料提供给 Agent。

Plan 中的 Path Bias 引用应说明：

- 来源运行或资产。
- 与当前任务的相似点。
- 推荐路径。
- 关键验证门。
- 已知失败模式。
- 不适用条件。
- 证据强度。

Path Bias 只能成为判断材料，不能替代本轮目标理解、证据探索或父层 convergence。

## Aboveground Execution Runtime 的职责

地上执行运行时不能被 Path Bias 绑架。它必须重新比较当前 Plan、hard constraint、soft constraint、preference、权限、上下文、风险和验证要求，再决定：

- 采用历史路径。
- 采用历史路径的一部分。
- 调整历史路径。
- 明确拒绝历史路径。

决定结果必须进入 owning feature 的执行记录；运行结束后由生命周期自动形成新的 PathMemory，语义取舍另行进入 Experience Candidate。

如果 Path Bias 在执行或验证中失效，Aboveground 应发起 Nutrient Request。新的 Nutrient Patch 或 Plan vNext 必须说明历史路径为什么失效，以及后续需要继续、回退、分叉还是停止。

## 禁止事项

- 禁止把 Path Bias 当模板复刻。
- 禁止用上次成功替代本次验证。
- 禁止跳过当前目标、权限和上下文判断。
- 禁止覆盖 hard constraint。
- 禁止把单次成功直接晋升为 Capability Asset 或 Path Bias。
- 禁止让 Path Bias 绕过 Agent Fabric、Plan、Verification 或 Governance Pipeline。
