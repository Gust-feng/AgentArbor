# 远程协同第一阶段开发方案

## 目标

在不依赖真实公网服务器和安卓真机的前提下，交付可在本地完成端到端验证的三部分：

1. 独立 Node.js Relay，可按 Linux 进程运行；
2. 由唯一 Host Composition Root 装配的桌面 Remote Collaboration connector；
3. Android 9+ 浏览器可用的 React PWA。

产品与数据边界以 [ADR-0034](../../架构设计/产品架构/ADR-0034-远程协同与选择性同步架构.md) 为准。

## 模块所有权

`src/app/remote-collaboration/` 拥有：

- `protocol/`：`remote-collaboration/v1` wire schema、消息包络与 Zod 校验；
- pairing/device 契约；
- desktop connector 的连接、重连、outbox/inbox、cursor、ACK 与 command result；
- 远程 ID 映射、同步状态和冲突；
- feature 仓储接口、SQLite 实现与定向测试；
- Relay 的领域服务与 HTTP/WebSocket adapter。

`src/app/remote-relay.ts` 只做 Linux/Node 进程入口与环境配置，不装配 Agent 运行时。`src/app/mobile-ui/` 只做移动投影、表单和协议客户端。

其他 feature 不反向 import Remote Collaboration。Host 通过公开 facade 组装以下窄端口：

- Ordinary：提交消息、取消、确认决定、读取/订阅用户可见对话投影；
- Space：创建 Space、读树、用稳定 ID 写允许同步的引用；
- Workbench Assets：列出/读取允许同步的资产、按 fingerprint 更新文本；
- Agent Notes：用不暴露 `workspaceRoot` 的 notebook 映射读取/按版本写入；
- Managed Files：仅在已登记 `managed_folder` 根内按相对路径读写，并使用 fingerprint CAS。

connector 不调用 `/api/*`，不读取这些 feature 的 repository 或 SQLite 表。

## 协议边界

所有帧都带 `protocolVersion: "remote-collaboration/v1"`。持久投递消息至少包含：

- `messageId`：Relay 稳定身份；
- `sequence`：目标设备方向单调序号；
- `commandId` 或 `eventId`：业务幂等身份；
- `sourceDeviceId / targetDeviceId`；
- `kind` 与经 Zod 校验的 payload；
- `createdAt`。

客户端 reconnect 时发送最后持久 ACK cursor；Relay 重放其后的消息。单连接使用有界发送队列，慢消费者断开后依靠持久 cursor 重连，不能无限缓存。协议不传 reasoning、完整工具结果或外部工作区内容。

## 本地存储

- Relay 使用独立 SQLite 文件，拥有 pairing、device、link、message 与 ack 表。
- Desktop connector 使用 AgentArbor runtime SQLite 中自己的 migration owner，仅保存 device binding、outbox/inbox、cursor、远程映射和 command result。
- Mobile 使用 IndexedDB 保存连接信息、outbox、cursor 与只读缓存；localStorage 只保存非敏感 UI 偏好。
- token 只通过专用凭据存储接口读写；浏览器首版在 TLS 同源上下文保存 token，后续 Capacitor 使用系统 secure storage。

## 首版命令

- `conversation.submit`：新建或继续已共享对话；`commandId` 同时作为 Ordinary `submissionId`。
- `run.cancel`。
- `confirmation.decide`：`approve_once | deny | guidance`。
- `space.create`。
- `note.replace`：完整正文 + `expectedVersion`。
- `asset.replace_text`：正文 + `expectedFingerprint`。
- `managed_file.replace_text`：相对路径 + `expectedFingerprint`。
- `managed_file.create_text`：在 AgentArbor 受管文件夹内创建相对路径文本文件。

所有命令都返回 `command.result`，明确 `applied / conflict / failed`。读取侧使用 `asset.snapshot`、`managed_folder.snapshot` 等 snapshot/event 投影，不通过远程客户端猜测 owning feature 状态。

## 验证

定向测试必须覆盖：

- 双方确认前不能签发长期 token；错误码、过期和撤销；
- token 哈希存储与撤销后拒绝连接；
- 离线消息重放、sequence 顺序、ACK、重复 commandId；
- WebSocket 慢消费者的有界队列；
- Ordinary submissionId 幂等、取消和三种确认决定；
- Space 稳定 ID、笔记/资产/managed file CAS 冲突；
- `local_file`、`workspace_folder`、绝对路径和 `..` 路径被协议边界拒绝；
- Relay 与桌面重启后的持久 cursor/inbox；
- PWA 的配对、离线 pending、确认和冲突交互。

真实公网验收后置到用户提供服务器信息后进行，至少补充 TLS、反向代理 WebSocket、systemd、备份恢复和 Android 真机网络切换验证。
