# 工作流程示例

## 示例：创建股票数据智能体应用

### 用户想象

```text
帮我创建一个股票数据 AgentApp，每天自动获取东方财富的股票数据，并生成日报。
```

## Phase 1：Seed Cluster 前置成像

```text
Step 1: 接收 Imagination
├── 保存用户原始想象
├── 初步识别目标、非目标和风险
└── 判断是否需要最小化搜索

Step 2: 最小化搜索与反驳
├── 检查数据来源可行性
├── 检查合规、频率限制和稳定接口
├── 标记验证码、封禁、服务条款和成本风险
└── 形成可选方向

Step 3: Seed Packet
├── 00-用户原始想象.md
├── 01-目标成像.md
├── 02-非目标与边界.md
├── 03-假设与缺失信息.md
├── 04-最小化搜索.md
├── 05-反驳与风险.md
├── 06-可选方向.md
├── 07-用户决策记录.md
├── 08-启动建议.md
├── handoff-to-root.md
└── seed.meta.json

Step 4: User Approval Gate
├── 向用户展示 Seed Packet
├── 用户确认、修改或拒绝
└── 只有确认后才种入 Soil
```

## Phase 2：Root System 初始生根

```text
Initial Rooting
├── Rootlet Cluster 检索 Soil 中的能力资产
├── 检索相似 Run Memory 和 Path Bias
├── 检查外部事实、数据接口和失败模式
├── Root Crown Cluster 汇总证据
└── 输出 Root Brief v1
```

Root Brief v1 可能推荐：

- 优先使用官方或稳定数据接口。
- 如果没有稳定接口，再限定范围验证网页采集。
- 必须设置合规、频率、失败恢复和验证门。

## Phase 3：Core Control Cluster 制定计划

```text
Core Control Cluster
├── 读取 Root Brief v1
├── 判断是否采用 Path Bias
├── 选择运行组织形态
├── 制定 Growth Plan v1
├── 生成 Workflow IR
└── 定义 Root Callback 触发条件
```

Growth Plan v1 包含：

- 数据源验证任务。
- 数据采集实现任务。
- 数据清洗与存储任务。
- 日报生成任务。
- 测试和验收门。
- 运行沉淀策略。

## Phase 4：Branch / Leaf 执行

```text
Branch System
├── 分配数据源验证分支
├── 分配采集实现分支
├── 分配日报生成分支
└── 汇总执行证据

Leaf Agents
├── 执行最小工作单元
├── 产出 Artifact
├── 记录 EventLog
└── 报告阻塞或失败证据
```

## Phase 5：Flower 验证与 Root Callback

如果验证发现东方财富网页采集被验证码拦截：

```text
Flower Cluster
├── 标记 verification.failed
├── 说明失败来自上游事实变化
├── 发起 root_callback.requested
└── 请求 Deep Rooting 或 Lateral Rooting

Root System
├── 重新检查数据源策略
├── 查找替代数据源或官方接口
└── 输出 Root Brief v2

Core Control Cluster
├── 基于 Root Brief v2 形成 Growth Plan Revision
├── 决定回退网页采集路径
└── 切换到更稳定数据接口
```

## Phase 6：交付与沉淀

```text
Verification passed
  -> Fruit / Delivery
  -> Run Memory
  -> Experience Candidate
  -> Path Bias
  -> Governance Gate
  -> Soil / Ring Memory
```

第一次任务沉淀出的 Path Bias 可能是：

- 相似股票数据任务优先检查官方接口、合规边界和频率限制。
- 遇到验证码或封禁风险时，先 Root Callback，而不是让叶层继续硬爬。
- 数据源策略必须有验证门和替代路径。

## 核心价值

| 价值 | 说明 |
| --- | --- |
| 前置成像 | 用户想象先变成 Seed Packet，而不是直接执行 |
| 持续根系 | 根系运行期仍可补探或重探 |
| 主干修订 | Growth Plan 可基于新 Root Brief 修订 |
| 验证保障 | Flower Cluster 不只验收结果，也能发现上游事实错误 |
| 运行沉淀 | 每次任务都形成 Run Memory、Experience Candidate 和 Path Bias |
| 资产治理 | 只有经过治理的经验和能力才能进入 Soil |
