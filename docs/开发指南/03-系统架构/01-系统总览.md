# 系统总览

## 架构图

```text
用户目标和环境输入
  -> Soil
  -> Underground Center
  -> .agentarbor
  -> Aboveground Center
  -> Aboveground Growth
  -> Fruits
  -> Governance
  -> Soil
```

`Soil` 是长期事实和治理土壤。`Underground Center` 在土壤中完成需求成形、约束提取、证据探索和方向综合。`.agentarbor` 是方向交接包，承接地下中枢输出并交给地上中枢。`Aboveground Center` 制定 Growth Plan、Workflow IR、上下文拓扑、执行组织和验证门。`Fruits` 只保存交付物和候选沉淀，必须经过 `Governance` 才能回流 Soil。

## 分层原则

- Soil 保存固定资产、长期证据、治理规则、Capability Asset、Path Bias、失败模式和稳定约束。
- Underground Center 负责把用户想象变成可执行方向：目标、非目标、假设、权限、成本、风险、证据和升级条件必须明确。
- Underground Center 只在授权边界不清、目标冲突、关键事实不足、高风险动作或治理冲突时询问用户。
- `.agentarbor` 只保存方向交接包，不保存最终资产，不复制 Soil，不替代 Growth Plan。
- Aboveground Center 负责把方向交接包转为 Growth Plan、Workflow IR、Context Topology、任务切片、验证门和修订规则。
- Aboveground Growth 负责具体执行、协作、产物提交和验证反馈，不能绕过 Aboveground Center 自行改方向。
- Fruits 可以是交付物、AgentApp、能力包、可脱离子 agent、Run Memory 或 Experience Candidate，但不是 Soil。
- Governance 决定果实是否晋升、拒绝、导出、退役或回流 Soil。
- Constraint / ConstraintRef 必须贯穿每一层，Path Bias 只能影响 preference 和方案排序，不能覆盖 hard constraint。
- Adapter 只做外部格式转换，不能定义核心产品模型。

## 目录对应关系

- `docs/`：人类可读指南和资料库。
- `.trellis/`：当前开发 AgentArbor 仓库时的 AI 工作流。
- `.agents/`：官方 Agent Skills 兼容层。
- `.codex/`：Codex 开发适配层。
- `.opencode/`：OpenCode 开发适配层。
- `.agentarbor/`：未来 AgentArbor 原生方向交接包目录，只在契约稳定后增量创建。
- `src/`：未来 TypeScript 实现。

开发时不能把这些目录的职责混用。
