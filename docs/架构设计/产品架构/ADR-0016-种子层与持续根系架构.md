# ADR-0016: 种子层与持续根系架构

## 状态

已采纳。

## 背景

ADR-0015 把 AgentArbor 的 Root 语义修正为探索型根系，并建立了 Soil、Root Brief、Growth Plan、Run Memory、Path Bias、Fruit 和 Ring Memory 的树形基线。

进一步讨论后，当前架构需要补齐两个关键缺口：

1. 用户提示词不应直接进入 Root System。提示词更像一个“想象”，需要先经过前置成像、反驳、最小化搜索、风险识别和用户确认，才能成为可以种入土壤的种子。
2. Root System 不应是一次性前置调研。自然生长中根系会随着地上组织需要继续扩展；因此地上执行、验证或主干控制发现问题时，必须能回调地下组织继续侧根扩展或深根重探。

## 决策

AgentArbor 正式采用以下持续生长主线：

```text
Imagination
  -> Seed Cluster
  -> Seed Packet
  -> User Approval Gate
  -> Soil
  -> Initial Rooting
  -> Root Brief
  -> Core Control Cluster
  -> Growth Plan
  -> Workflow IR
  -> Branch / Leaf / Flower / Fruit
  -> Root Callback / Re-rooting
  -> Run Memory / Ring Memory / Soil
```

核心定义：

| 概念 | 定义 |
| --- | --- |
| Imagination | 用户提示词中的原始想象。它可能含混、跳跃、缺少边界，不能直接进入正式运行。 |
| Seed Cluster | 前置成像集群，负责理解、拆解、反驳、最小化搜索、风险识别、可选方向和用户确认。 |
| Seed Packet | Seed Cluster 的输出，建议是一个文件夹形态的启动种子包。 |
| User Approval Gate | 用户确认门。Seed Packet 被确认或迭代修改后，才可以种入 Soil。 |
| Root System | 持续地下生命系统，包含初始生根、侧根扩展和深根重探。 |
| Root Continuity | 根系连续性。Root System 生成第一版 Root Brief 后仍可在运行期继续生长。 |
| Root Callback | 地上组织回调地下组织的补探机制。 |
| Lateral Rooting | 侧根扩展，用于局部问题补探。 |
| Deep Rooting | 深根重探，用于 Growth Plan 前提可能错误时的整体重估。 |
| Core Control Cluster | 主干固定核心集群，制定和修订 Growth Plan 与 Workflow IR，避免单点最强 agent 失效。 |
| Growth Plan Revision | 基于新的 Root Brief 版本修订 Growth Plan 的机制。 |

## Seed Packet 形态

Seed Packet 建议采用文件夹结构：

```text
seed-packet/
  00-用户原始想象.md
  01-目标成像.md
  02-非目标与边界.md
  03-假设与缺失信息.md
  04-最小化搜索.md
  05-反驳与风险.md
  06-可选方向.md
  07-用户决策记录.md
  08-启动建议.md
  handoff-to-root.md
  seed.meta.json
```

`handoff-to-root.md` 是 Root System 的正式输入。`seed.meta.json` 保存 seed id、状态、用户确认记录、适用范围、风险等级和版本。

## Root Callback

Root Callback 可以由 Core Control Cluster、Branch Agent 或 Flower Cluster 触发。触发原因包括：

- 运行中发现信息不足。
- Leaf Agent 反复失败。
- Flower Cluster 验证不通过。
- Path Bias 失效。
- Soil 中原有资产不适用。
- 用户修改目标。
- 权限、成本或不可逆动作前提不成立。
- Growth Plan 的关键假设被证伪。

Root Callback 的输出必须是新的 Root Brief 版本，或明确“不需要重探”的证据。

## Root Brief 与 Growth Plan 版本

- `Root Brief v1` 来自 Initial Rooting。
- `Root Brief v2+` 来自 Lateral Rooting 或 Deep Rooting。
- 每个 Growth Plan 必须引用具体 Root Brief 版本。
- Growth Plan Revision 必须记录修订原因、影响范围、Workflow IR 变化和继续、回退、分叉或停止决策。

## 边界

- Seed Cluster 是启动门，不属于地下 Root System，也不属于地上执行组织。
- Seed Packet 不是 Growth Plan，也不是长期资产。
- Root System 不是一次性调研；它贯穿运行期。
- Core Control Cluster 不是单个万能最强 agent，而是低自由度固定核心集群。
- 动态任务集群负责探索和执行扩展，固定核心集群负责汇总、决策和抗单点认知失败。

## 影响

- ADR-0015 的线性主线被本 ADR 扩展为持续生长架构。
- 开发指南必须加入 Seed Cluster、Seed Packet、Root Callback、Root Brief Versioning 和 Growth Plan Revision。
- 植物学融合架构中的根层和干层必须表达持续生长与回调机制。
