# Pi 原生底层迁移契约

## 目的

本文件约束当前从 OpenAI Agents SDK 与 AgentArbor 重复底层迁移到 `@earendil-works/pi-agent-core` / `@earendil-works/pi-ai` 的实现工作。长期架构以 [ADR-0030](../../架构设计/产品架构/ADR-0030-AgentArbor-Pi原生底层架构.md) 为准。

当前行为（本迁移切片完成后）：OrdinaryAgentFeature 通过窄 Pi AgentHarness/Session adapter 运行；Pi 保存模型 transcript、branch/leaf、compaction 与 provider continuation，Ordinary 保存 `ordinary-run/v5` 业务事实和 `ordinary-conversation/v2` Session ref。

要求行为：OrdinaryAgentFeature 通过一个窄 Pi adapter 使用 Pi Agent/Harness、Session、compaction 与 pi-ai provider；AgentArbor 只保留产品与宿主能力，并删除被 Pi 接管的重复实现。

当前实施状态（2026-07-21）：A-E、Ordinary Sub-Agent 与 OpenAI Agents SDK 主循环退役已经完成；F 的 Ordinary provider binding 已进入生产，普通 Agent 的语义 Skills 路由也已通过窄无工具模型集合通道接入 Pi。自定义 OpenAI-compatible provider binding、动态 API key 每请求解析、profile identity 隔离、非流式 Chat/Responses、provider-native Web Search、refusal/incomplete 失败语义和 MiniMax 累计流兼容已经完成。必要的 pi-ai 0.80.10 上游修复由 pnpm patch 固化。Multi-Agent 与其他 parity-sensitive `IntelligenceChannel` consumer 尚未切换；file/audio/URL/file-id 输入和 Host 自定义 fetch 仍有公开契约缺口，因此不能宣称第二套 Chat/Responses transport 已经全局删除。

## 所有权

| 事实或能力 | 唯一 owner | 说明 |
| --- | --- | --- |
| 模型会话消息、branch、leaf、compaction entry | Pi Session | AgentArbor 只保存稳定 ref，不复制 transcript |
| 模型循环、流式 delta、工具批次 | Pi Agent/Harness | 通过 adapter 映射为 Ordinary 命令与事件 |
| provider、transport、动态 API key | pi-ai Models/provider + 中性 binding | Pi 负责 transport；binding 只把冻结 profile 映射为公开 compat/payload hook，并逐请求解析 key |
| run 状态、完成语义、队列、确认状态 | OrdinaryAgentFeature | Pi 事件不能直接写业务终态 |
| 工具权限、预检、执行与 ToolCallResult | ToolCenter | Pi AgentTool 只是调用适配 |
| 完整大结果与 continuation | ToolOutputStore | Pi Session 只保存模型可见有界结果 |
| MCP、Skills、附件、工作区、进程 | AgentArbor owning module / Host | 作为 AgentTool 或输入资源接入 |
| Panel DTO、SSE、read-model | OrdinaryAgentFeature / Panel adapter | 不暴露 Pi 私有对象 |

## 切片顺序与删除条件

### A. 依赖与能力门

- 固定 Pi 与 Node 版本。
- 用可执行测试验证 Session move/fork、JSONL 重启、Harness 保存、工具顺序、确认等待、取消释放、compaction 和动态凭据。
- 任何必要缺口先报告，不进入生产代码绕行。

完成条件：契约测试通过，能力矩阵没有未决的阻断项。

### B. Pi Session 切片

- 新建 Pi Session repository 的 Host 装配与 Ordinary session ref。
- 新 conversation 只写新 Session；旧 conversation/snapshot 明确失效。
- rollback/retry 直接移动或 fork Pi leaf，并让 Ordinary conversation projection 读取分支摘要。
- Ordinary run 开始/结束保存对应 session entry ref。

同切片删除：Ordinary 自有消息 lineage、`canonicalMessages` 写入与旧恢复读取。若消费者尚未迁完，不得把双写合入稳定分支。

### C. Pi Agent/Harness 切片

- 一个 run 创建一个受 Ordinary owner 管理的 Pi execution scope。
- Pi stream/event 映射为 Ordinary live activity；最终状态仍由 Ordinary reducer 提交。
- provider stop reason、toolUse、length、error、aborted 必须显式归类。
- `abort()`、listener 退订和 Host 关闭均有唯一 owner。

同切片删除：OpenAI Agents SDK Ordinary loop、其 continuation wrapper 和仅为 SDK 对象存在的兼容类型。

### D. AgentTool 与确认切片

- 从冻结 tool catalog 创建 Pi AgentTool；参数 schema 和 description 来自现有事实，Ordinary 的 executionMode 统一固定为 parallel。该设置表达模型同批调用语义，不免除 adapter 的机械一致性责任；本地文件 `Write` / `Edit` 只在同一规范路径的短临界区使用 Host-owned FIFO，不同路径保持并行。
- `execute` 调用 ToolCenter preflight/execute，不复制权限或确认规则。
- approval 在 `execute` 内等待同一 AgentArbor confirmation；approve 最多执行一次。
- deny/guidance 返回当前 call id 对应的 error tool result，让模型继续；不得调用 Pi `abort()` 或终止其他 tool call。
- 用户显式停止整个 run 使用独立 Ordinary cancel command，不与 confirmation denial 共用状态或结果。
- 完整结果先进入 AgentArbor fact/evidence，再生成 Pi 模型消息。

同切片删除：旧 SDK tool wrapper、SDK approval state 与重复结果 envelope。

### E. Compaction 切片

- prompt 前通过 Pi Session/compaction 处理持久历史。
- 同一 prompt 的每次 provider 请求前执行物理窗口检查。
- 最新未消费工具组不可拆分；保留后仍超窗明确失败。
- compaction entry 成为 Session 分支事实，Ordinary 只记录 ref/业务事件。

同切片删除：`loop-context-compaction` 中被 Pi 覆盖的估算、切点、摘要与消息重写；只保留无法下沉的产品映射。若必须复制 Pi 状态机，按 ADR-0030 停线报告。

### F. pi-ai Provider 切片

- 设置和 capability snapshot 使用 Pi provider/model identity。
- pi-ai 负责流式 transport；中性 binding 通过 Pi 公开 `compat` 与 payload hook 映射冻结的 provider 方言，动态 API key 由 AgentArbor 每次请求解析后注入。
- 自定义 OpenAI-compatible endpoint 通过 Pi 扩展点注册。
- 未知模型工具能力按 provider/protocol round-trip 与冻结 override 决定。

同切片删除：Ordinary 使用的 OpenAI Agents SDK model adapter 和对应依赖。Multi-Agent 与 parity-sensitive `IntelligenceChannel` consumer 使用的 Chat/Responses transport 必须保留到等价门通过。

当前停线项只剩 Pi 公共消息契约无法无损表达的部分 file/audio/URL/file-id 输入，以及 provider transport 没有 Host 自定义 fetch 注入口。Ordinary 已通过公开 `compat` / `before_provider_payload` 映射 Chat provider 方言、视觉能力和冻结请求设置；仓库 patch 补齐 `stream:false`、refusal diagnostic、Responses hosted output continuation/`incomplete_details.reason`、MiniMax 累计 delta 和文本 `reasoning_details`。provider-native Web Search 由 binding 注入，并以同 provider/API/model 的 opaque Session continuation 保证下一轮回放。未经用户明确选择“接受附件/Host fetch 降级”“暂留旧 transport”或“继续推动 Pi 补齐”，不得切换 Multi-Agent 与其他 parity-sensitive `IntelligenceChannel` consumer 的生产 provider，也不得删除其现有 transport。

Ordinary 当前只把 inline image 附件映射为 Pi tool-result image，并直接写入 Pi durable Session；不再维护运行期 overlay 或第二份上下文。file/audio 以及 URL/file-id image 无法由当前 Pi 公共消息契约无损表达时，adapter 必须形成 `tool_result_attachment_not_supported`，保留 `sourceExecutionStatus` 和 `doNotBlindlyRetry` 后停止该工具轮，不能把附件删除后继续报告成功。若 Pi compaction 的待摘要前缀包含 image，当前 request-boundary API 必须明确返回 `context_compaction_images_unsupported`，不得生成丢图摘要。

当前附件上下文口径（覆盖上一条迁移期的临时 overlay / “不落 JSONL”描述）：支持的 inline image 是 Ordinary durable Pi Session 的一部分，后续轮次必须能够从 Session 重建并继续交给模型；图片原始字节不复制进 Ordinary run snapshot、事件、ToolCallResult 或 Panel read-model。Deep child / Sub-Agent 不建立可恢复的独立 Session，仍不得把附件字节写入持久化 child context。

### G. 收口

- Sub-Agent 改为普通 Pi AgentTool + 嵌套 Pi Agent/Harness，仍归父 Ordinary run。
- Multi-Agent 只做回归，不改业务实现。
- 删除废弃 facade、source guard 例外、旧文档和迁移期对照测试。
- 更新 `CURRENT_RUNTIME_MODE.md` 后再把 Pi 主链视为当前稳定事实。

## 关键实现约束

- 不新增 universal `RunRuntime`、全局 Pi manager 或 service locator。
- Pi adapter 放在中性模型/Agent 接入边界；不得导入 Panel 类型或 Ordinary repository 实现。
- Ordinary feature 通过精确端口创建、运行、取消和释放 Pi scope。
- Pi provider/message/session 私有结构在 adapter 边界验证后映射，不进入业务 snapshot。
- 不使用模型名白名单恢复协议能力判断。
- 不吞掉模型正文、工具输出、错误、stdout/stderr 或 continuation。
- 不以兼容为由读取旧会话；不主动删除旧磁盘字节。

## 迁移期验证门

每个代码切片至少执行：

```text
pnpm build:node
node --test <本切片目标测试>
git diff --check
```

跨 Ordinary facade 的切片增加：

```text
pnpm typecheck:panel
pnpm build:panel
```

最终收口执行全量 `pnpm test`，并做真实 Ordinary 验收：连续多轮、至少一次工具调用、一次确认 approve、一次 cancel、一次 rollback 分支和一次进程重启恢复。

## 当前已验证基线

- Pi Session move/fork 保留废弃分支。
- Pi JSONL Session 重启后恢复活动 branch。
- Pi AgentHarness 保存 prompt/answer 到 Session。
- Pi 同一 assistant turn 的 Ordinary 工具调用统一并行，完成事件可乱序，tool result message 保持来源顺序。
- AgentArbor 确认门可以在 Pi AgentTool 执行边界暂停并只恢复一次。
- confirmation denial 可以只生成当前 call id 的 error tool result，副作用不执行，Pi 随后把拒绝事实交给模型继续循环。
- Pi 0.80.10 在真正的 run abort 发生于多调用顺序批次中时仍可能留下不完整 tool group；Pi 按用户决定保持不动。该限制属于全局 run cancellation 的 adapter conformance，不得再与单次 confirmation denial 混用。
- Ordinary 已通过真实本地 OpenAI-compatible 流式端点完成模型 -> `read` -> 工具结果 -> 模型的完整 Pi Session 工具轮。
- Ordinary provider parity 已通过真实非流式工具轮、Responses hosted output 跨轮回放、refusal/incomplete 失败和 MiniMax 累计流测试；剩余停线项见 [Pi-Agent全面接入能力盘点](../../研究资料/工程研究/Pi-Agent全面接入能力盘点.md)。

这些是依赖版本 `0.80.10` 的契约事实；升级 Pi 时必须重跑。
