# 状态机

## 状态表

| 状态 | 所在层 | 说明 | 退出条件 |
| --- | --- | --- | --- |
| Draft | Underground Center | 目标尚未澄清 | 目标、非目标和关键约束可判断 |
| DirectionReady | `.agentarbor` | Direction Handoff 已批准 | Aboveground Center 接管 |
| Planning | Aboveground Center | 制定 Growth Plan 和 Workflow IR | Growth Plan 完成 |
| Routing | Aboveground Center | 选择运行组织和任务切片 | 任务已分配 |
| Executing | Aboveground Growth | 执行任务 | 产物、阻塞或失败事件 |
| Verifying | Verification | 验证、评审和成熟判断 | 验证通过、失败或建议养料请求 |
| NutrientRequested | Underground Center | Nutrient Request 后补充养料或方向再成形 | Nutrient Patch、新 Direction Handoff 或无需补充证据 |
| Revising | Aboveground Center | Growth Plan Revision | 继续、回退、分叉或停止决策 |
| Fruiting | Fruits | 交付或候选沉淀形成 | Fruit 进入治理或归档 |
| GovernanceReview | Governance | 入土、导出、拒绝或退役裁决 | 决策完成 |
| Sedimenting | Soil / Ring | 形成 Run Memory、Experience Candidate、Path Bias | 沉淀完成 |
| Archived | Governance | 任务关闭 | 谱系与记录完整 |

## 主流程

```text
Draft
  -> DirectionReady
  -> Planning
  -> Routing
  -> Executing
  -> Verifying
  -> Fruiting
  -> GovernanceReview
  -> Sedimenting
  -> Archived
```

## 养料供给流程

```text
Executing / Verifying / GovernanceReview
  -> NutrientRequested
  -> DirectionReady / Revising
  -> Routing / Executing / Fruiting / Archived
```

## 守卫条件

- `Planning` 前必须有已批准 Direction Handoff。
- `Routing` 前必须有 Growth Plan。
- `Executing` 前必须有 Workflow IR 任务切片。
- `NutrientRequested` 必须由 Nutrient Request 触发。
- `Revising` 必须引用 Nutrient Patch、新的 Direction Handoff 版本或无需补充证据。
- `Fruiting` 必须经过 Verification 和 Acceptance。
- `GovernanceReview` 必须有 Fruit、谱系和验证证据。
- `Sedimenting` 只能写入通过治理的材料。

## 禁止跳转

- 不允许跳过 Direction Handoff 或 Growth Plan 直接进入执行。
- 不允许 Nutrient Request 绕过 Verification 或用户确认。
- 不允许未治理 Fruit 直接进入 Soil。
