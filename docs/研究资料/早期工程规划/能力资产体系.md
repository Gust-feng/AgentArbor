# 能力资产体系

## 1. 定位

能力资产体系是 AgentArbor 从“会写文档的规划工具”走向“能生成、运行、测试、验证 AgentApp 的工程系统”的关键基础。

AgentArbor 不应该在构建 Agent 时临时去查模型协议、MCP 工具、Skill、插件、沙箱、运行时和评测方式。它应该先拥有自己的能力资产注册表，再从注册表中选择、组合、授权、快照和验证。

一句话：

> AgentArbor 不是临时找能力，而是从受控资产中孕育 AgentApp。

## 2. 三层资产模型

```text
Source
  -> Source Note
  -> Asset Spec
```

### 2.1 Source

来源地址和出处。

例如：

```text
OpenAI Tools 文档
MCP Tools 规范
CubeSandbox 仓库
Vitest 文档
pytest 文档
```

Source 只证明“从哪里来”，不能直接被代码使用。

### 2.2 Source Note

人类可读沉淀。

位置：

```text
docs/04-参考沉淀/能力资产/
```

Source Note 负责回答：

* 这份资料说了什么。
* 哪些字段对 AgentArbor 有用。
* 哪些地方需要核验。
* 哪些能力有权限和安全风险。
* 应该如何抽象成 AgentArbor 的内部对象。

### 2.3 Asset Spec

机器可读资产。

位置：

```text
assets/
```

Asset Spec 负责让代码读取：

* Provider 能力。
* Protocol Adapter。
* Tool / Toolpack。
* Skill。
* Runtime Profile。
* Sandbox Profile。
* Evaluator。
* Permission Policy。

## 3. 当前资产目录

```text
assets/
  capability-registry/
    asset-registry.seed.json
    agent-blueprints.seed.json
    capability-schema.seed.json
    mvp-roadmap.seed.json
    sources.seed.json
    raw/
  providers/
  protocols/
  tools/
  runtime-profiles/
  skills/
  evaluators/
  policies/
  schemas/
```

`capability-registry/` 是从表格抽取出来的 seed。

其他目录是从 seed 中沉淀出的 v0.1 资产草案。

## 4. 资产状态

每个资产必须有状态。

```text
seed       从外部资料或表格抽取，尚未拆分成正式规格。
draft      已按 AgentArbor 资产模型整理，可用于原型开发。
verified   已完成官方来源核验、测试样例、权限审查。
trusted    可进入默认自动执行链路。
deprecated 不再建议使用。
```

第一版可以读取 `draft`，但默认自动执行链路只能使用 `verified` 或项目内部明确允许的资产。

## 5. 资产生命周期

```text
发现资料
  -> 记录 Source
  -> 写 Source Note
  -> 生成 Asset Spec draft
  -> Schema 校验
  -> Mock / Replay 测试
  -> Live / Sandbox 验证
  -> 权限审查
  -> 标记 verified
  -> 进入 AgentApp 生成链路
  -> 生成时写入 AssetSnapshot
```

## 6. AgentArbor 构建 AgentApp 时如何使用资产

```text
用户目标
  -> RequirementSpec
  -> 查询 Capability Registry
  -> 选择 Provider / Runtime / Skill / Tool / Evaluator / Policy
  -> 生成 AgentBlueprint
  -> 生成 AgentApp
  -> 写入 AssetSnapshot
  -> 沙箱运行
  -> 验证结果
```

如果需要的能力不存在，应进入：

```text
MissingAsset
Suspend
EnvironmentProposal
```

而不是让 Agent 临时联网搜索并直接接入。

## 7. 资产快照

每个生成的 AgentApp 应保存当时使用的资产快照：

```text
.agentarbor/assets-snapshot/
  providers/
  protocols/
  tools/
  runtime-profiles/
  skills/
  evaluators/
  policies/
```

快照用于回答：

* 当时为什么选择这些能力。
* 每个能力是什么版本。
* 每个能力需要什么权限。
* 验证时用的是什么运行环境。
* 失败时应该如何复现。

## 8. 选择语言和运行环境

AgentArbor 可以自主评估 AgentApp 使用什么语言开发，但只能在可用 Runtime Asset 中选择。

语言选择必须同时满足：

* 任务适配。
* Runtime Profile 可用。
* Sandbox Profile 可用。
* BuildRecipe 可执行。
* TestRecipe 可验证。
* 权限和网络策略可控。

如果没有合适运行环境，Agent 只能生成环境方案，不能直接执行安装。

```text
Environment Planner
  -> runtime.yaml
  -> build-recipe.yaml
  -> test-recipe.yaml
  -> Policy Validator
  -> Sandbox Builder
  -> Runner
```

## 9. 默认安全姿态

```text
default_network: deny
default_filesystem: workspace_only
default_shell: deny
default_secrets: deny
external_assets: untrusted
```

权限由策略引擎执行，不能只写在 Prompt 中。

## 10. 第一版落地顺序

第一版优先激活：

```text
Provider:
  model.openai.responses
  model.openai.chat_compatible

Protocol:
  protocol.openai.responses
  protocol.openai.function_call
  protocol.openai.structured_output
  protocol.mcp.client
  protocol.agent_skills

Runtime:
  runtime.cubesandbox
  runtime.workspace_manager
  runtime.command_runner
  runtime.template.node
  runtime.template.python

Tool:
  tool.git.*
  tool.file.*
  tool.shell.run
  tool.test.pytest
  tool.test.vitest
  tool.secret_scan

Skill:
  skill.code_repair
  skill.repo_map
  skill.test_failure_diagnosis
  skill.diff_review

Evaluator:
  eval.build
  eval.unit_tests
  eval.diff_scope
  eval.secrets
  eval.requirement_match

Policy:
  policy.default
```

目标不是资产数量多，而是第一条工程闭环能真实跑通。
