# 工作台界面

## 界面目标

AgentArbor Desktop 不是营销首页，也不是单纯调试面板。它是桌面通用 Agent 的工作台：用户提交任务、绑定工作区上下文、查看模型判断、动作、待确认事项和最终输出。

用户只面对一个工作会话入口，不应该被迫理解 Underground / Aboveground、Task Soil、Plan Package、Agent Run Tree、provider 等内部术语。这些内部细节只进入设置、诊断或开发者详情。

工作台必须先像本地桌面 Root Agent 一样可用。用户可以随意提问、闲聊、询问模型身份、让系统解释概念或处理小请求，也可以让它查证资料、读取授权材料、等待确认并产出结果；默认路径是普通工具型 Root Agent 会话，直接由 LLM 决定回答、查证、读取授权上下文、请求确认或给出用户指导。工程层不得用关键词、长度或固定规则自动升级模式；它只负责空输入、配置、schema、预算、权限和脱敏边界。

复杂方向成形保留为未来 deep / advanced 项目边界。当前阶段不做可见 deep 入口，不主动改动 deep 后端，也不把复杂输入自动包装成通用 Work Session。界面的基本节奏是“默认普通 Agent 就能工作”，内部复杂组织术语只允许进入诊断或开发者详情的安全投影。

同一会话必须支持连续对话。发送新消息只能追加新的用户回合和助手回合，不能清空已有 transcript；后续请求应把最近可见对话按原 `user` / `assistant` 角色作为独立模型消息传给后端，并保证当前用户输入仍是最后一条 user message。

## 工作台结构

```text
桌面工作台
  - 会话导航：新任务、最近会话、待确认提醒、设置
  - 主工作区：持续对话、线性工作轨迹、内联确认、线性正文
  - 输入区：底部常驻消息输入，折叠附件、模型选项和权限
  - 工作上下文：待办、当前上下文、近期活动，默认进入详情或按需展开
  - 详情与设置：模型服务、能力与服务、工作区、确认边界和安全诊断
```

### 会话导航

承接新任务、最近会话、待确认提醒和设置。左侧导航不能把内部架构层级、能力管理、工具管理或平台适配做成产品菜单；工作方法、工具清单和外部能力开关不作为导航或独立能力后台出现，运行时由助手按当前任务自主判断。顶栏只有在承接真实 Shell 职责时才出生；如果只剩折叠按钮、工作区 chip、运行状态或待确认数量，就应删除，而不是保留空栏。待确认入口归侧栏提醒和当前会话本身。最近会话只负责恢复和继续会话，不能加入仅前端生效的重命名、置顶、删除等假管理操作；这些操作只有在后端持久化、权限、恢复语义和测试边界稳定后才能出生。Routines / 例行任务必须等真实调度器出生后再进入可见导航，当前不能展示假入口。左侧导航不应在底部常驻“本地工作”这类说明块。空态下它应更像会话列表，而不是任务管理系统或能力后台。

### 主工作区

主工作区服务用户完成任务，形态是持续的线性 agent 工作流，而不是“表单 + 文档预览”、结果卡片墙或工程监控台。它展示：

- 当前任务理解和状态。
- 普通问题的直接回答。
- 运行中的可扫读线性活动轨迹。
- 已执行动作、已读材料和阶段性判断的精炼摘要，按发生顺序自然交替出现。
- 需要用户授权、拒绝或补充指导的待确认事项。
- 模型按自然语言连续输出的回答、草稿、成果或失败说明。

主工作区解释“agent 正在怎么判断和继续”，默认显示轻量完整的工作轨迹，而不是只压成一条当前状态；但它也不展示完整内部运行过程，不默认拆成“结果 / 证据 / 下一步”等独立模块。思考摘要、工具动作、等待确认和正文应在同一个助手回合里形成连续节奏。若模型需要说明依据、风险、不确定性或下一步，应自然写入同一条线性正文；安全 refs、产物 refs、工具 refs 和诊断材料进入详情或开发者层。
完成态优先保留模型输出本身；若后端只返回产物结构而没有正文，界面可以把产物标题、摘要和主要段落降级为线性正文兜底，但不能渲染成独立报告卡、证据卡或下一步卡。
若本轮只是普通问答，完成态只展示回答和必要的可继续追问方向，不展示空报告或假产物。

### 输入区

输入区默认常驻在主工作区底部，首屏只保留消息输入、发送、附件和一个轻量选项入口。模型选择、思考强度、上下文引用、权限引用、附件细节和服务配置默认折叠到输入选项、设置或详情入口中，不能占据首屏注意力。模型选项可以让用户表达偏好，但不能把普通会话变成模型管理器；运行中仍由助手根据任务自主判断是否使用上下文、模型能力和外部查证。

### 设置页

设置页承接会改变基础运行条件和能力可用边界的配置：模型服务、能力与服务、工作目录和确认边界。能力与服务可以展示已有真实后端支撑的网页查证、运行时工具和工作方法启用状态，但只能表达“哪些服务可用、哪些边界生效”，不能把普通会话变成能力后台、工具启动器、规则后台或固定流程编排器。工具是否调用、工作方法是否注入、网页是否查证，仍由助手根据当前任务自主判断。

确认边界可以作为设置说明存在，用于解释命令执行、删除文件、外部提交等高影响动作会在当前会话里确认；它不提供一组替代模型判断的全局规则。常规说明、界面密度、装饰性偏好、假工具接入和无后端支持的会话管理不进入设置页；若未来需要这些能力，必须先有真实持久化、权限边界、恢复语义和测试覆盖。

### 右侧上下文栏

工作上下文服务普通用户的浅层监督，但不再作为空态和普通问答的默认首屏结构。它只在真实工作会话需要时按需展开，或进入详情抽屉的概览区。它展示：

- 待办：需要用户判断、授权或补充的信息。
- 当前上下文：本轮任务引用的文件、网页、项目或短摘要。
- 近期活动：人类可读的工作进度，例如正在阅读上下文、调用授权工具或生成回答。

工作上下文不是固定流程图，也不是架构监控卡片墙。文件、网页、证据或产物引用可以进入详情概览，但不能抢占主工作区的线性 agent 流。

### 开发者详情抽屉

诊断、Agents 和设置解释“系统如何形成这个结果”。它们可以展示：

- 模型配置边界和失败摘要。
- 输出契约、模型 / 工具 refs 和安全 trace。
- agent 运行树、child 输出摘要和父层综合。
- budget、permission、调试 JSON 的安全投影。

开发者详情不展示 raw prompt、raw provider response、raw tool output、未被协议声明为可展示的内部推理、密钥或 token。

## 模型思考展示

思考强度是用户可见的输入区能力，只在当前模型明确支持可调节推理强度时展示。用户选择轻量、标准或深入后，系统必须把该意图编译进对应协议请求。

如果厂商协议明确返回可展示的思考内容或思考摘要，例如 OpenAI Responses 的 reasoning summary，或 OpenAI-compatible Chat Completions 里的 `reasoning_content`，普通会话必须把它作为当前答案前的正式思考阶段展示，和回答正文处于同一对话层级，但不能混入正文答案块。界面通过位置、留白和与工具调用一致的轻量折叠入口表达阶段关系，不额外显示“思考”标题、教学说明、状态卡或运行时解释。这里展示的是厂商返回的可见字段，不是 AgentArbor 自己臆造的推理链。

如果协议或模型没有返回思考内容，界面不能伪造推理过程，也不需要用额外文案提示用户“已按某个思考强度调用”。raw prompt、raw provider response、raw tool output、密钥、token，以及内部能力机制或长期沉淀机制的实现名，仍然不能进入普通会话。

## 三层解释结构

普通用户默认看到：模型的关键判断、动作、待确认事项和连续输出。

用户展开当前输出或追问时看到：为什么这样判断、为什么暂不选另一个方向、主要风险、还缺什么、相关活动摘要。

开发者打开详情时看到：agent run tree、child 摘要、父层 synthesis、模型和工具 refs、budget、trace 和安全 reasoningTrace 投影。

用户追问“为什么推荐方案 A 而不是方案 B”时，应先在主工作区获得线性解释摘要，再选择是否打开开发者详情查看完整监督 trace。

## 界面边界

UI 不能直接绕过权限层访问本地资产，不能直接写长期能力注册表，也不能把平台适配格式展示成 AgentArbor 原生事实。
