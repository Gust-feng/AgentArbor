# 地下养料供给与方向修订

## 定位

地下组织不是只在异常时被唤起的调研层，而是持续为地上生长供给养料的系统。`.agentarbor` 是第一批方向养料包；运行中地上组织缺少证据、资产适配、约束细节、外部事实、上下文或能力线索时，应向 Underground Center 发起 Nutrient Request。

地上组织负责沿既定方向生长，不负责重新探索方向。它可以报告执行反馈、验证失败和局部材料缺口，但不能自建方向探索 agent 集群替代地下组织。

## 养料类型

| 养料类型 | 地上缺口 | 地下输出 |
| --- | --- | --- |
| 证据养料 | 方向依据、验证依据或假设依据不足 | EvidenceRef、Assumption Verdict |
| Soil 资产养料 | 需要复用能力、历史路径、失败模式或治理规则 | SoilRef、Capability Asset Ref、Path Bias Ref |
| 约束养料 | 权限、成本、安全、验收或治理边界不清 | ConstraintRef、CandidateConstraintRef、冲突说明 |
| 外部事实养料 | 需要当前事实、外部标准、平台能力或环境边界 | FactRef、来源、时间戳、可信度 |
| 上下文养料 | 执行节点缺材料、上下文切片不够或引用不清 | Context Supplement、适用范围 |
| 能力线索养料 | 不确定是否已有能力可用或需要新能力 | Capability Hint、适用条件、不适用条件 |

## 供给模式

| 模式 | 触发场景 | 输出 |
| --- | --- | --- |
| 初始方向供给 | 用户目标进入地下中枢 | `.agentarbor` 方向交接包 v1 |
| 局部养料补充 | 局部任务材料不足、局部失败、局部验证不清 | Nutrient Patch |
| 方向补充 | Growth Plan 前提需要补证据或补约束 | 新 Direction Handoff 版本或 Handoff Supplement |
| 方向再成形 | 方向前提被证伪、目标变化、Path Bias 失效 | 新 Direction Handoff 版本和计划重估建议 |

## 请求者

- Aboveground Center。
- Aboveground Growth 执行组织。
- Verification / Maturity。
- Governance。

请求者只能描述缺口、用途、阻塞等级、当前假设和需要支撑的节点，不能直接指定地下组织必须采用的结论。

## 触发原因

- 证据不足。
- 地上执行反复失败，需要判断失败是执行问题还是方向养料不足。
- 验证不通过，且缺少可判定证据。
- Path Bias 失效。
- Soil 资产不适用或适用条件不清。
- 用户修改目标。
- 权限、成本或不可逆动作前提不成立。
- Growth Plan 的关键假设被证伪。
- 果实治理发现谱系、权限或证据不足。

## 养料请求流程

```text
地上组织发现养料缺口
  -> Nutrient Request
  -> Underground Center 判断需要局部补充、方向补充或方向再成形
  -> 补齐证据、约束、用户确认、Soil 引用、外部事实或能力线索
  -> 生成 Nutrient Patch 或新的 .agentarbor 方向交接包版本
  -> Aboveground Center 消化养料并判断是否修订 Growth Plan
  -> 地上生长继续、回退、分叉或停止
```

## 版本规则

- `.agentarbor` 方向交接包必须版本化。
- Nutrient Request 和 Nutrient Patch 必须关联具体 Growth Plan、Workflow IR 节点、验证门或治理记录。
- 每个 Growth Plan 必须引用具体方向交接包版本。
- Growth Plan Revision 必须记录引用的 Nutrient Patch、修订原因、影响范围、继续、回退、分叉或停止决策。
- 如果无需补充养料，也必须记录证据和判断理由。

## 禁止事项

- 不把地下中枢写成启动前一次性调研。
- 不用过期方向交接包掩盖新证据。
- 不让地上生长组织自行修订 Growth Plan。
- 不让地上组织自建方向探索集群替代地下养料供给。
- 不用 Nutrient Request 替代 Verification。
- 不把方向再成形当作普通局部养料补充。
