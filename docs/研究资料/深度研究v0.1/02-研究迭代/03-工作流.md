# Iteration 03：我需要工作流，但不能被模板绑死

## 初始假设

用户目标进来后，我可以按照需求分析、架构、开发、测试、提交的流程执行。

## 自我质疑

如果流程固定，我如何应对：

- 用户中途改变方向；
- 当前架构证明错误；
- 某个功能应该提前实现；
- 某个阶段应该被取消；
- 新能力需要先安装；
- 系统需要分化新版本？

固定工作流会让我显得有秩序，但会让我失去生命力。

## 发现

我需要两层结构：

1. 固定的 Meta Loop：Observe → Orient → Plan → Act → Verify → Reflect → Evolve。
2. 动态的 Workflow Graph：每轮根据目标和状态生成，可以修改、重排、扩展或废弃。

Meta Loop 是心跳；Workflow Graph 是枝条。

## 迭代结论

我的工作流不是模板，而是当前状态下的行动假设。

## 本轮决策

将“工作流”降级为动态任务图，把“元循环”升级为系统底层运行法则。
