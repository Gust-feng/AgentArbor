# 智能通道契约

智能通道是 AgentArbor 调用模型的统一契约。它不是新的事实源，也不是概念树节点；它让模型能力以可审计、可替换、可失败和可观测的方式服务各层。

所有真实模型调用必须通过智能通道。领域模块、应用编排、CLI、未来 UI 和测试入口都不能直接绑定 provider SDK；应用组合根只能负责装配 provider adapter 和智能通道，不能把 provider-specific 字段泄漏给业务流程。

## 核心对象

### ModelRequest

`ModelRequest` 描述一次模型调用的内部请求。它必须说明调用目的、调用方、输出契约、约束和预算。

```ts
interface ModelRequest {
  requestId: string;
  traceId: string;
  callerRef: ObservationRef | string;
  purpose:
    | "intent_profile"
    | "rootlet_candidate"
    | "counterfactual"
    | "plan_draft"
    | "verification_advice"
    | "governance_advice";
  inputRefs: ObservationRef[];
  sanitizedMessages: ModelMessage[];
  outputContract: ModelOutputContract;
  constraintRefs: ConstraintRef[];
  budget: ModelBudget;
  sensitivity: "public" | "internal" | "restricted";
  requestedAt: string;
}
```

`sanitizedMessages` 只保存已清洗、已授权进入模型上下文的内容。未授权 Soil 内容、密钥、完整运行私密材料和平台凭证不能进入请求。

### ModelResponse

`ModelResponse` 描述 provider 返回后经过智能通道归一化的结果。

```ts
interface ModelResponse {
  responseId: string;
  requestId: string;
  providerId: string;
  model: string;
  status: "completed" | "failed" | "cancelled";
  outputKind: "candidate" | "draft" | "explanation" | "evidence_suggestion";
  structuredOutput?: unknown;
  textOutputRef?: ArtifactRef;
  usage?: ModelUsage;
  finishReason?: "stop" | "length" | "tool_call" | "content_filter" | "error";
  validation: ModelOutputValidationResult;
  completedAt: string;
}
```

`structuredOutput` 仍然只是模型产出。它必须被调用方的确定性规则转成候选池、收束决策输入、计划草案或治理建议，不能直接写入 Direction Handoff、Growth Plan、Run Memory 或 Soil。

### ModelUsage

`ModelUsage` 归一化 provider 用量，供成本、审计和观测使用。

```ts
interface ModelUsage {
  inputTokens?: number;
  outputTokens?: number;
  totalTokens?: number;
  estimatedCostUsd?: number;
  latencyMs?: number;
}
```

用量字段可以缺失，但不能伪造。provider 不返回的字段应保持空值，并在观测层显示为 unknown。

### ModelCallRef

`ModelCallRef` 是正式材料引用模型调用的方式。

```ts
interface ModelCallRef {
  requestId: string;
  responseId?: string;
  providerId?: string;
  model?: string;
  outputKind: "candidate" | "draft" | "explanation" | "evidence_suggestion";
  eventRefs: string[];
  validationStatus: "pending" | "passed" | "failed";
}
```

Direction Handoff、Growth Plan、Verification Result 或 Governance Review 可以引用 `ModelCallRef`，但不能把未验证模型正文当成事实复制进去。

## 接口边界

### ModelProvider

`ModelProvider` 是 provider adapter 的最小接口。它只处理供应商协议差异。

```ts
interface ModelProvider {
  providerId: string;
  complete(request: ModelRequest): Promise<ModelResponse>;
}
```

Provider adapter 不能读取或写入 Soil、`.agentarbor`、Fruits、Governance Registry 或任务状态机。

### IntelligenceChannel

`IntelligenceChannel` 是业务层唯一能调用的模型入口。

```ts
interface IntelligenceChannel {
  request(request: ModelRequest): Promise<ModelResponse>;
  validateResponse(request: ModelRequest, response: ModelResponse): ModelOutputValidationResult;
}
```

智能通道负责：

- 校验请求是否带有目的、预算、输出契约和授权上下文。
- 发布模型调用事件。
- 调用合适的 provider adapter。
- 归一化 provider 响应。
- 执行输出契约校验。
- 返回可失败结果，而不是抛给业务层自行猜测。

## 事件契约

智能通道最低必须发布以下事件：

| 事件 | 触发时机 | 最低字段 |
| --- | --- | --- |
| `model.requested` | 请求通过通道校验并准备调用 provider | `requestId`、`traceId`、`purpose`、`callerRef`、`providerId`、`model`、`budget`、`inputRefs` |
| `model.completed` | provider 返回且响应归一化完成 | `requestId`、`responseId`、`usage`、`finishReason`、`outputKind`、`validationStatus` |
| `model.failed` | provider 失败、超时、输出不合约或预算越界 | `requestId`、`failureKind`、`retryable`、`fallback`、`sanitizedErrorRef` |

事件不得包含：

- API key、access token 或 provider 凭证。
- 未清洗完整 prompt。
- 未授权 Soil 内容。
- 用户隐私正文。
- provider 原始错误中的敏感字段。

## 配置边界

首个真实 provider 接入可以使用环境变量：

```text
OPENAI_API_KEY
AGENTARBOR_MODEL
AGENTARBOR_MODEL_BASE_URL
```

规则：

- `OPENAI_API_KEY` 只由 provider adapter 读取。
- `AGENTARBOR_MODEL` 是运行配置，不是代码常量。
- `AGENTARBOR_MODEL_BASE_URL` 仅用于兼容网关或自托管 OpenAI-compatible endpoint。
- 环境变量不得写入 EventLog、Snapshot、Direction Handoff Package、Run Memory、Experience Candidate 或 Soil。

## 验证规则

- 模型输出必须匹配 `outputContract`；不匹配时返回 failed 或 validation failed。
- AI 输出只能进入候选池、草案或建议层；进入正式材料前必须通过调用方的确定性收束和验证。
- hard constraint 不能被模型输出覆盖。
- Path Bias 只能影响模型请求的偏好和排序提示，不能覆盖约束。
- LLM-as-judge 只能作为 Verification / Governance 的建议输入，不能单独决定通过。

## 首个接入范围

首个真实模型接入应只接入 Underground Center 的目标理解和 rootlet 候选生成：

- Intent Core 可以请求目标结构化建议。
- Rootlet 可以请求候选方向、风险、证据建议或反例。
- Convergence Judge 仍按确定性规则裁决。
- Handoff Steward 仍只打包已收束、已验证的候选。

Aboveground、Verification、Governance 的真实模型调用应在智能通道最小实现稳定后逐步接入。
