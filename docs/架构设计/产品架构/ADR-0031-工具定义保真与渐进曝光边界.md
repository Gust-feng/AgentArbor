# ADR-0031：工具定义保真与渐进曝光边界

## 状态

Accepted（2026-07-22）。本 ADR 补充 ADR-0027、ADR-0029 与 ADR-0030，不取代它们。

## 背景

AgentArbor 的工具既是模型可选择的能力，也是已经冻结的运行授权。把“模型看见什么”“本轮允许执行什么”和“执行前是否需要用户确认”混成一个列表，会产生两类错误：隐藏定义却仍允许调用，或为了节省上下文而改变权限。MCP 还可能拥有大量真实 provider 定义，完整注入每个模型请求会消耗上下文；Pi 则已经拥有当前请求的 active tool set、Session 协议持久化和原生调度能力。

## 决策

### 1. 定义必须保真

工具定义以冻结 run 的 canonical `name`、模型可见 `description`、完整 `inputSchema`、provider 实际提供的 `outputSchema` / annotations 和必要来源元数据为事实。MCP catalog 同时保留 provider 原始方法名与 canonical 名称，并通过稳定 `definitionHash` 标识定义版本；调用方不得凭名称猜测 provider、协议或远端方法。模型请求只投影协议实际消费的定义字段；输出 schema、annotations、执行元数据和确认策略不应被伪装成模型输入定义，也不能用摘要替代 canonical 定义。

### 2. 三层边界独立

- **曝光（visibility）**：本轮模型请求中可见的完整定义集合。渐进曝光只改变模型当前可见集合。
- **执行授权（execution authorization）**：capability snapshot 先冻结 catalog 上限；模型 loop 开始前，再结合冻结策略、真实 executor 和本轮已成功加载的 Skill 资源做一次客观 boundary resolution，并冻结最终允许执行名称与 broker。Skill 资源只能激活冻结 catalog 中已有的 `skill_read` companion，不能从 catalog 外新增工具。`mcp_load`、模型输出和运行中状态都不能扩张最终授权。
- **确认（confirmation）**：由工具风险与用户授权策略决定是否在执行前暂停。曝光或加载定义不触发远端执行，也不绕过确认。

任何实现必须能单独测试三层；不得以“已曝光”推导“已授权”，也不得以“无需确认”推导“可执行”。

### 3. MCP 渐进曝光是成本优化

core 常驻工具和 Sub-Agent 工具按冻结边界直接可见。MCP 工具只有在真实 provider catalog 中存在、服务已启用且配置完整、缓存定义已进入本轮快照、惰性 executor 已装配并通过权限边界时才可成为候选。MCP 连接发生在真正执行远端工具时；渐进曝光不得要求预先建立连接，否则会破坏 lazy-connect 边界。若完整定义集合的实际序列化 token 成本达到模型上下文成本门控，运行时才可延迟长尾 MCP 定义，并向模型提供 `mcp_search` 与 `mcp_load` 控制工具。

控制工具只搜索/加载冻结 catalog：搜索不连接服务器、不执行工具；加载只让已授权完整定义从下一次模型请求开始可见。成本计数不确定、定义冲突或节省不足时，回退为完整定义直接可见。不得按 provider 名、模型名或字符串关键词猜测是否支持原生 tool search。

### 4. active set 与 Session 隔离

run-local active set 是当前模型请求的机械投影，由 Pi AgentHarness 管理；它不是新的权限仓储。`mcp_load` 的 activation marker 只服务发出它的 live Pi 工具轮与后续请求；durable Session 可以保留该轮实际消费的 marker 作为 transcript 事实，但新 root/delegated run 不从历史 marker 恢复 active set。每次新执行都重新应用冻结 boundary 与成本门控，从 initial active set 开始，并从本次模型上下文隔离历史 `addedToolNames`；对账恢复只能补写 canonical `ToolCallResult`，不得从公开工具输出推导或伪造 protocol marker。

### 5. 结果与失败保持可继续性

工具结果沿 ADR-0027/0029 的完整事实链传递，超限结果使用既有 evidence/read 工具，不做摘要覆盖。Pi 返回没有 canonical AgentArbor 结果包络的 immediate failure 时，适配层必须保留原始文本并归一化为标准 `ToolCallResult`：取消保持 `cancelled`；已接受执行但未形成规范结果归为 execution failure；未知或非 active 工具归为 runtime/schema rejection，并标记 `doNotBlindlyRetry`。这类失败不能被静默吞掉，也不能触发盲目重试。

## 后果

- 模型仍可自主选择工具；确定性规则只保护权限、预算、证据和确认边界。
- 大型 MCP catalog 可以按真实定义成本渐进暴露，同时保持执行授权和结果保真。
- provider/model 更换不会要求重写 AgentArbor 的工具语义；原生 tool search 只在 adapter 能证明能力时接入。
- 需要为 visibility plan、live activation、跨 run reset/对账隔离、Pi immediate failure 和恢复路径提供契约测试。

## 不采用

- 不按 provider 或模型名称猜测 native tool search。
- 不把 catalog-only capability 注册为假 executor。
- 不建设全局 active tool registry、第二套 Session 或统一工具工作流。
- 不用固定关键词、工具数量上限或安全摘要替代模型选择。
