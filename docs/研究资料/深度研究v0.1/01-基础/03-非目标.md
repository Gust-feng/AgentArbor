# AgentArbor 不做什么

明确不做什么，和明确做什么同样重要。

## 1. 不做另一个普通 AI 编程助手

AgentArbor 不以“帮你补全代码”“解释代码”“生成函数”为核心卖点。这些能力可以存在，但只是底层能力的一部分。

## 2. 不做固定模板工作流平台

AgentArbor 不能被设计成一套固定流程：需求分析 → 架构设计 → 编码 → 测试 → 提交。这个流程可以作为某些情况下的任务图，但不应该成为系统的本质。

## 3. 不做低代码 Bot 搭建器

AgentArbor 的目标不是让用户拖拽节点拼一个聊天机器人。它的目标是孕育一个完整 AgentApp 工程。

## 4. 不做完全无治理的自主系统

AgentArbor 追求自主，但不追求失控。危险命令、删除文件、推倒重来、分化主线、变更目标等操作必须被治理。

## 5. 不做一次性生成器

一次性从 Prompt 生成项目只是出生，不是生命。AgentArbor 必须能维护、转向、分化、重生。

## 6. 不把“多 Agent 数量”当成高级

更多 Agent 不等于更聪明。AgentArbor 应该动态决定需要多少 Agent，并防止 Agent 官僚化。

## 7. 不让 UI 掩盖内核

漂亮的 Workbench 很重要，但 AgentArbor 的价值在于自主内核、验证系统、演化系统和治理系统。

## 8. 不承诺无限正确

AgentArbor 可以追求无限扩展能力，但不能假装无所不能。它必须知道何时需要用户确认，何时需要暂停，何时需要重生。
