# 持续根系与根系回调

## 定位

Root System 是持续地下生命系统，不是一次性前置调研。它在 Seed Packet 种入 Soil 后初始生根，并在运行期根据地上组织反馈继续生长。

## 三种根系生长

| 模式 | 触发场景 | 输出 |
| --- | --- | --- |
| Initial Rooting | Seed Packet 被确认并种入 Soil | Root Brief v1 |
| Lateral Rooting | 局部分支信息不足、局部失败、局部验证不清 | Root Brief v2+ 的局部补充 |
| Deep Rooting | Growth Plan 前提被证伪、目标变化、Path Bias 失效 | 新 Root Brief 版本和计划重估建议 |

## Root Callback

Root Callback 是地上组织回调地下组织的机制。

可触发者：

- Core Control Cluster。
- Branch Agent。
- Flower Cluster。

触发原因：

- 信息不足。
- Leaf Agent 反复失败。
- Flower Cluster 验证不通过。
- Path Bias 失效。
- Soil 资产不适用。
- 用户修改目标。
- 权限、成本或不可逆动作前提不成立。
- Growth Plan 的关键假设被证伪。

## 回调流程

```text
地上组织发现问题
  -> Root Callback Request
  -> Root System 判断 Lateral 或 Deep Rooting
  -> 派生新根须探索
  -> 生成新的 Root Brief 版本
  -> Core Control Cluster 修订 Growth Plan
  -> Branch / Leaf 继续、回退、分叉或停止
```

## 版本规则

- `Root Brief v1` 来自 Initial Rooting。
- `Root Brief v2+` 来自 Lateral Rooting 或 Deep Rooting。
- 每个 Growth Plan 必须引用具体 Root Brief 版本。
- Growth Plan Revision 必须记录修订原因、影响范围、继续、回退、分叉或停止决策。

## 禁止事项

- 不把 Root System 写成启动前一次性调研。
- 不用旧 Root Brief 掩盖新证据。
- 不让 Branch / Leaf 自行修订 Growth Plan。
- 不用 Root Callback 替代 Verification。
- 不把 Deep Rooting 当作普通局部补探。
