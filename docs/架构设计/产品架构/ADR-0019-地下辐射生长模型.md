# ADR-0019: 地下辐射生长模型

日期：2026-05-01

状态：Accepted

## 决策

Underground Center 采用地下辐射生长模型。地下组织不是线性流水线，也不是平级 agent 聊天室；它是一个稳定中枢组织，围绕用户想象向外生成临时探索根须集群，再把多方案、多证据、多约束和多风险收束为 `.agentarbor` 方向交接包。

核心结构如下：

```text
User Imagination
  -> Underground Center
  -> Radial Exploration Clusters
  -> Cross-Critique
  -> Convergence
  -> Direction Handoff Package (.agentarbor)
```

地下辐射生长遵循“中枢固定、根须动态、探索发散、方向收束”的原则。

## 中枢组织

地下中枢本体保持稳定，不随每个任务随意重组。它至少包含以下职责：

| 职责 | 作用 | 输出 |
| --- | --- | --- |
| Intent Core | 维护用户想象、目标原像、非目标和验收边界 | 目标原像、非目标、验收门 |
| Growth Governor | 决定探索方向、探索深度、预算和停止条件 | 探索计划、预算、停止条件 |
| Constraint Sentinel | 守住权限、成本、安全、技术和人工确认边界 | Constraint / ConstraintRef 候选 |
| Evidence Ledger | 管理证据、来源、可信度、时间点和可追溯关系 | EvidenceRef、FactRef、证据索引 |
| Convergence Judge | 比较多方案，决定保留、合并、淘汰或升级给用户 | 方向裁决、取舍理由 |
| Handoff Steward | 组装 `.agentarbor` 方向交接包 | Direction Handoff Package |

这些职责可以由一个强 agent 承担，也可以由固定核心集群承担；无论实现形态如何，它们必须作为 Underground Center 的稳定能力边界存在。

## 辐射根须集群

地下中枢可以按任务需要生成临时探索根须集群。根须集群不是长期 agent，也不是地上执行组织；它们只为方向成形和养料供给服务。

| 根须集群 | 触发场景 | 交付物 |
| --- | --- | --- |
| Option Cluster | 存在多个可行方向 | 候选方向、取舍、适用条件 |
| Risk Cluster | 成本、失败、合规或维护风险不清 | 风险登记、失败模式、阻断项 |
| Asset Fit Cluster | 需要判断 Soil 资产是否适配 | Soil 引用、适配条件、不适用条件 |
| Evidence Cluster | 需要外部事实、环境事实或依赖事实 | EvidenceRef、FactRef、可信度 |
| Constraint Cluster | 方向需要映射为可执行约束 | Constraint / ConstraintRef 候选 |
| Counterfactual Cluster | 需要反驳方向或识别局部最优 | why-not、反例、替代方向 |

根须集群必须有明确输入、预算、输出和退场条件。它们不能直接制定 Growth Plan，不能调度地上生长，也不能把运行产物写入 Soil。

单个探索 agent 或单个根须集群的调研输出不能被直接信任，也不能直接写入 Direction Handoff、Nutrient Patch 或其他正式交接材料。此类输出只能先作为 `Observation`、`Evidence Candidate` 或 `Claim Candidate` 进入地下中枢的候选池。负责该根须集群的汇总/裁决 agent，或 Underground Center 的 Convergence Judge / Handoff Steward，必须完成交叉校验、去重、来源归因和冲突裁决后，才能把汇总结果提升为方向依据、证据引用、风险记录、约束候选或养料补充。

## 多方案与收束

地下组织必须天然支持多方案，而不是默认只产出一个方向。每个候选方向至少记录：

- `optionId`。
- `directionSummary`。
- `supportingEvidenceRefs`。
- `soilAssetFitRefs`。
- `constraintImpact`。
- `riskProfile`。
- `costProfile`。
- `unknowns`。
- `whyNot`。
- `recommendationScore`。
- `doNotChooseWhen`。

Convergence Judge 不能只按分数选择方向。它必须记录：

- 保留哪个主方向。
- 哪些方向被合并。
- 哪些方向被淘汰。
- 哪些冲突需要用户确认。
- 哪些备选方向可以作为未来地上中枢的参考。
- 哪些 `Observation`、`Evidence Candidate` 或 `Claim Candidate` 被采纳、合并、驳回或保留为未知项，以及对应来源。

## 生长预算

地下辐射生长必须受控。每次方向成形或养料供给都必须定义生长预算：

- 最大探索方向数。
- 每个方向最大探索深度。
- 最大外部事实查询数。
- 最大成本或时间预算。
- 是否允许询问用户。
- 是否允许触发更深一层探索。
- 停止条件。

预算耗尽后，地下中枢必须收束为 `.agentarbor`、Nutrient Patch、用户升级确认，或明确停止依据。系统不能因为持续探索而无限推迟方向交接。

## `.agentarbor` 影响

地下辐射生长要求 `.agentarbor` 不只保存最终方向，也保存方向如何被选择。方向交接包建议扩展为：

```text
.agentarbor/
  direction.md
  options.json
  decision-record.md
  constraints.json
  soil-refs.json
  evidence-index.md
  risk-register.md
  open-questions.md
  escalation-rules.md
  growth-entry.json
  handoff.meta.json
```

新增材料职责：

- `options.json`：保存候选方向、适用条件、不适用条件和比较维度。
- `decision-record.md`：保存最终方向裁决、合并、淘汰和用户确认依据。
- `risk-register.md`：保存风险、反驳、失败模式和阻断项。

`.agentarbor` 仍然只是方向交接包。它不能保存最终资产，不能复制 Soil，不能替代 Growth Plan，也不能预填未来运行资产。

## 用户升级

地下辐射生长只在以下情况打断用户：

- 目标或非目标互相冲突。
- hard constraint 无法裁决。
- 权限、成本、安全或不可逆动作越界。
- 多个方向都可行但价值取舍必须由用户决定。
- 关键事实无法通过 Soil 或外部证据确认。

除此之外，地下中枢应继续在授权边界内探索、反驳、收束，并把非阻塞未知项写入 `open-questions.md`。

## 边界

- 地下中枢负责方向生产和养料供给，不负责地上执行。
- 根须集群是地下组织临时生长出的探索结构，不是长期资产。
- 多方案比较是方向成形的必要过程，不是执行计划。
- `.agentarbor` 是交接包，不是研究报告堆积区。
- 地上组织缺少方向证据、资产适配、外部事实、约束细节、上下文或能力线索时，应通过 Nutrient Request 回到地下中枢。

## 后果

- 后续开发地下中枢时，应优先实现中枢固定职责、根须集群生命周期、候选方向记录和收束机制。
- 现有 `docs/开发指南/03-系统架构/07-地下中枢与方向成形.md` 应吸收本 ADR 的稳定结论，不再把地下组织描述为简单线性流水线。
- `.agentarbor` 契约应补充 `options.json`、`decision-record.md` 和 `risk-register.md`，但当前仓库仍不提前创建 `.agentarbor/` 运行资产。
