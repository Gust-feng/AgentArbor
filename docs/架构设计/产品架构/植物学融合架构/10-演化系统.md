# 演化系统

## 概述

演化系统负责根据验证结果、运行证据、Root Callback、债务情况和用户决策，决定系统是继续、回退、分叉、停止、沉淀还是孕育果实。

演化不是让执行层随意改方向。所有演化都必须回到 Core Control Cluster 的 Growth Plan Revision 或 Governance Gate。

## 演化类型

| 类型 | 触发 | 处理 |
| --- | --- | --- |
| Patch | 问题局部、影响面小 | 保持 Growth Plan，局部修复 |
| Refactor | 同一区域反复补丁或结构债上升 | Growth Plan Revision，重组相关任务 |
| Redirect | 当前路线长期收益差 | Deep Rooting 后修订方向 |
| Branch | 多个方向证据接近 | 限定预算分叉验证 |
| Stop | 核心前提不成立或风险不可接受 | 停止并沉淀失败证据 |
| Fruit | 结果成熟且可复用或可脱离 | 进入 Fruit / Governance Gate |
| Retire | 能力过期、失败或被替代 | 退役或降级资产 |

## 决策流程

```text
Verification / Runtime Evidence / User Change
  -> Evolution Assessment
  -> Root Callback 或 No Re-rooting Evidence
  -> Growth Plan Revision
  -> continue / rollback / branch / stop
  -> Run Memory / Experience Candidate / Governance Gate
```

## 判断维度

- 目标是否仍然有效。
- Root Brief 证据是否足够。
- Path Bias 是否失效。
- 当前计划是否制造局部最优。
- 权限、成本、时间和外部依赖是否仍成立。
- 验证门是否可信。
- 继续执行的收益是否高于结构债和风险。

## 记录要求

每次演化至少记录：

- 触发事件。
- 相关 Root Brief 版本。
- 相关 Growth Plan 版本。
- 是否触发 Root Callback。
- 决策类型。
- 影响范围。
- 继续、回退、分叉或停止依据。
- 沉淀策略。

## 禁止事项

- 不用“优化”掩盖核心假设失效。
- 不让 Leaf Agent 自行决定长期演化方向。
- 不把验证失败直接写成成功经验。
- 不把单次成功直接晋升为 Capability Asset 或 Fruit。
