# AgentArbor 文档

`docs/` 是 AgentArbor 的人类可读文档入口。

这里保存四类当前需要的人类可读材料：

- 当前开发入口：稳定、可执行、面向实现的开发指南。
- 研究资料：深度研究报告、早期计划书、工程研究和外部参考研究。
- 架构设计：长期架构决策、协议边界、工作区结构和植物学融合架构。
- 任务看板：从 Trellis 任务状态生成的人类态势看板资产，不是计划源数据。

历史经验、推进记录、阶段计划、会话沉淀、草案包和准备包不再保留在 `docs/` 活跃知识面中。对未来开发没有直接架构或研究价值的材料应删除，避免干扰。

当前文档目标是让新开发者在进入实现前能快速回答这些问题：

1. AgentArbor 是什么，解决什么问题。
2. 为什么它不是一次性 Agent 生成器，而是 Agent / AgentApp 孕育与演化平台。
3. Imagination、Seed Cluster、Seed Packet 和 User Approval Gate 如何把用户提示词变成可启动的种子。
4. Root System、Root Callback、Core Control Cluster、Branch / Leaf / Flower、Fruit 和 Ring Memory 如何共同构成持续生长系统。
5. Run Memory、Experience Candidate、Capability Asset 和 Path Bias 如何把一次运行反哺到下一次任务。
6. 系统由哪些核心边界组成，哪些东西不能混放。
7. 开发时必须遵守哪些工程规则。
8. 哪些架构设计和研究资料可以作为后续设计输入。

## 文档原则

- 开发指南只写稳定结论，不保留讨论过程。
- 研究资料只保留对未来产品定位、架构、能力体系、工程实现有参考价值的研究报告和基础资料。
- 架构设计只保留长期结构性决策和架构草案。
- 任务看板只做 `.trellis/tasks/` 的人类可读投影视图，展示前置任务、当前任务和未来方向，不能成为第二套计划源。
- 旧路线、旧命名、旧实验、经验流水、推进记录和准备资料包不进入活跃文档树。
- 所有目录名、文档名和正文默认使用简体中文。`README.md` 是目录索引文件的唯一保留例外。
- 平台适配文件、任务工作流、运行时草案和机器可读资产不放在 `docs/`。
- 文档内容必须能直接指导实现，不能只堆概念或口号。

## 与其他目录的边界

- `.trellis/` 保存当前 AI 开发工作流、任务上下文和项目规范。
- `.agents/` 保存官方 Agent Skills 兼容文件。
- `.codex/` 保存 Codex 开发适配文件。
- `.opencode/` 保存 OpenCode 开发适配文件。
- `.claude/` 保存 Claude Code 开发适配文件。
- `.agentarbor/` 保存未来 AgentArbor 运行时自己的机器可读启动资产，只在契约稳定后增量创建。
- `src/` 保存未来实现代码。

`docs/开发指南/` 负责当前开发规则。

`docs/研究资料/` 和 `docs/架构设计/` 负责保存思想来源、研究材料和架构判断。后续实现可以吸收这些材料，但不能把其中任何单篇历史文档直接当作当前执行计划。

阶段推进、任务计划、续接状态和工作流记录由 `.trellis/` 管理；根目录不新增 `Plan/` 或 `Plans/` 作为并行计划入口。稳定的实现边界和验收门写入 `docs/开发指南/06-工程实现/`。

当前 `.trellis/`、`.agents/`、`.codex/`、`.opencode/`、`.claude/` 和 `.agentarbor/` 默认是本地开发态点目录，不进入当前提交基线。未来需要共享其中任何一类模板或运行时资产时，应先在架构设计或开发指南中明确边界，再调整提交策略。
