# 模块划分

未来 `src/` 建议围绕功能闭环组织领域模块，同时把消息、状态机、事件、权限、模型和产物等横切内核放在明确边界内。源码布局采用 `domain / kernel / adapters / app` 四层，但模块所有权优先按功能闭环判断，横向分层只是实现手段：

```text
src/
  domain/
    soil/
    task-soil/
    underground/
    plan/
    aboveground/
    fruits/
    governance/
    lineage/
    intelligence/
    runtime-database/
  kernel/
    messages/
    state-machine/
    events/
    permissions/
    artifacts/
    intelligence/
    tools/
  adapters/
    intelligence/
    runtime-database/
    tools/
  app/
    desktop/
    underground/
    aboveground/
    panel/
```

## 职责边界

- `domain/soil`：Global Soil，保存长期偏好、Capability Asset、Path Bias、稳定约束、治理规则、历史证据和失败模式。
- `domain/task-soil`：Task Soil，保存当前任务目标、文件/网页/项目引用、临时约束、权限边界和本轮运行材料。
- `domain/underground`：目标成形、多路探索、动态派生、父层综合、用户澄清、Nutrient Request 处理和 Nutrient Patch / Plan vNext 生成。
- `domain/plan`：Plan / Plan Package 的读写契约、版本、引用校验、validation result 和执行入口；`.agentarbor` 只是其可能的存储目录形态。
- `domain/aboveground`：执行计划、Workflow IR、任务切片、工具动作、执行组织选择、验证门编排和 Plan Revision。
- `domain/fruits`：交付物、运行报告、Run Memory、Experience Candidate 和能力候选。
- `domain/governance`：候选成熟度评估、权限审查、谱系归因、版本、导出、退役和入土裁决。
- `domain/lineage`：Task Soil、Plan、Nutrient Patch、执行记录、产物、验证和入土结果之间的谱系。
- `domain/intelligence`：智能通道领域契约、模型调用目的、输出类型、`ModelCallRef` 和模型产出引用规则；它是横切契约，不是业务节点。
- `domain/runtime-database`：Lite / Full 共用的运行记录契约，表达 Workspace、Run、Event、ToolCall、ModelCall 和 Artifact 的安全持久化记录；业务层依赖该端口，不依赖具体本地文件、PGlite 或 PostgreSQL 实现。
- `kernel/messages`：ArborMessage、MessageBus、Router 和跨模块消息协议。
- `kernel/state-machine`：运行阶段、状态转移和 Plan Revision 状态机制。
- `kernel/events`：EventLog、事件发布、事件订阅和审计轨迹。
- `kernel/permissions`：权限声明、授权检查、用户升级确认和高风险动作门。
- `kernel/artifacts`：ArtifactStore、产物引用、校验摘要和临时运行材料索引。
- `kernel/intelligence`：模型运行时、请求校验、输出契约校验、模型调用事件、失败策略和 provider registry；它不能保存业务事实。
- `kernel/tools`：工具执行边界、工具权限、预算、结果归一化和安全投影。
- `adapters/intelligence`：OpenAI-compatible、Anthropic、Gemini、Qwen、Ollama/vLLM 或其他 provider adapter；只有这一层可以直接处理供应商协议和凭证。
- `adapters/runtime-database`：RuntimeDatabase 的可替换本地存储实现；当前可用文件系统安全投影验证 appHome / runHome、运行记录和无 secret 泄漏边界，后续可替换为 PGlite 或 PostgreSQL + pgvector。
- `adapters/tools`：MCP、浏览器、文件、搜索、终端或外部工具协议适配。
- `app/desktop`：Desktop Shell、任务入口、工作区上下文和成果区域。
- `app/underground`：Underground Cognitive Runtime 的应用编排和内置 agent specs。
- `app/aboveground`：Aboveground Execution Runtime 的应用编排和执行入口。
- `app/panel`：Observation Panel 的安全投影和 UI 资产。

## 横切规则

- `domain/` 保存 AgentArbor 产品语义；它不能依赖具体平台 adapter。
- `kernel/` 可以被 `domain/`、`app/` 和 `adapters/` 复用，但不能保存业务事实，也不能替代 Task Soil、Plan、Fruits 或 Governance。
- `adapters` 只能转换格式，不能定义核心领域模型。
- `app` 只能通过正式服务或应用层接口读写，不能直接写 Global Soil 或治理注册表。
- `domain/plan` 只能引用 Global Soil 中的稳定资产，不能复制 Global Soil 内容形成第二事实源。
- `domain/fruits` 不能直接写 `domain/soil`；必须经过 `domain/governance`。
- `domain/aboveground` 可以向 `domain/underground` 发起 Nutrient Request，但不能自建方向探索集群，也不能静默改写 Plan。
- `domain/underground` 可以读取 Task Soil 和 Global Soil 引用，可以写 Plan / Nutrient Patch，不能创建最终果实。
- 任何运行流程需要模型能力时，只能依赖智能通道契约或注入的 `AgentTurnRuntime` / `IntelligenceChannel`；应用组合根可以装配 provider adapter，但不能让领域层、kernel 或业务编排直接读取 provider 环境变量或调用 provider SDK。
- 工具权限必须按 `AgentRunContext` 的有效权限裁剪，不能只看 agent role 或 prompt。
- 运行记录必须通过 RuntimeDatabase 契约保存安全投影：Run、Event、ToolCall、ModelCall 和 Artifact 记录只能包含摘要、refs、状态、时间和脱敏错误，不能保存 raw prompt、raw provider response、hidden reasoning、raw tool output、secret 或 live runtime/store 引用。

## 禁止穿透

`app` 不能直接写注册表；adapter 不能定义核心模型；地上运行不能绕过 `kernel/permissions`；临时任务不能直接写长期能力资产；果实不能绕过治理进入土壤；领域层、kernel 和业务编排不能直接导入模型供应商 SDK。
