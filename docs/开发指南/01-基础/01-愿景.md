# 愿景

## 长期愿景

AgentArbor 要成为面向本地工作区的桌面通用 Agent。

用户不应该把同一个任务反复描述、反复从零组织文件、网页、项目上下文、工具和模型。用户只需要通过 Desktop Shell 给出任务和相关工作区材料，系统把这些材料组织为 Task Soil，由 Underground Cognitive Runtime 完成目标成形、多路探索、动态派生 child agent、父层综合、裁决、追问或停止；当地下方向足够成立时形成 Plan，再由 Aboveground Execution Runtime 按 Plan 执行文件修改、文档生成、原型制作、工具调用和验证。

随着真实任务重复发生，系统应识别哪些做法稳定有效，哪些失败模式值得避免，哪些能力可以治理后复用。第二次相似任务不应从零开始，也不应机械复刻第一次流程，而应通过 Path Bias 自然倾向于已经验证过的有效路径。长期积累下，系统在相似领域的成形更快、执行更稳、解释更清楚，用户获得一个越用越聪明的桌面工作台。

## MVP 愿景

比赛阶段不追求完整平台，也不追求完整 OS 自动化。MVP 应证明一个清晰闭环：

```text
任务输入
  -> Task Soil
  -> Underground Cognitive Runtime
  -> Plan
  -> Aboveground Execution Runtime
  -> Fruit
  -> Run Memory
```

MVP 必须展示：

- 用户从统一 Desktop Shell 提交任务。
- 地下 runtime 以 AI-first 方式进行目标理解、rootlet / child agent 动态派生、父层综合和裁决。
- 主画布展示结果级解释，Observation Panel 展示 agent 协作的运行投影。
- Plan 能被地上 runtime 消费，形成至少一种可见成果，例如研究报告、执行计划、文档草案、原型或小型代码改动。
- 无 `AgentTurnRuntime` 不允许产出 approved Plan；默认稳定测试使用 fake/stub AI runtime 验证 AI 路径。

## 不做什么

AgentArbor 不是泛聊天助手，也不是完整 IDE、终端代理、插件市场或外部 agent 平台复制品。它可以读取本地工作区、调工具、生成文档和执行有限任务，但这些能力都服务于“任务成形、agent 协作、Plan 交接、执行交付、治理回流”的闭环。

## 植物语义的保留范围

植物语义保留为职责边界，不再作为堆概念的设定集：

- Task Soil 表示本轮任务的临时土壤。
- Global Soil 表示治理后的长期资产、偏好、约束、失败模式和 Path Bias。
- Underground 表示方向智能。
- Aboveground 表示执行智能。
- Fruits 表示交付物和候选沉淀。
- Governance 表示候选经验入土前的筛选、验证、归因、去重、版本化和退役管理。

任何把 Task Soil 直接写入 Global Soil、把 child output 直接写入 Plan、把 `.agentarbor` 写成独立产品节点、把 Aboveground 写成新的方向探索集群、或让工程边界替 agent 做语义判断的设计都必须修正。
