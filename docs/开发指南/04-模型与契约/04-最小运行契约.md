# 最小运行契约

本文件定义当前桌面通用 Agent 主线必须冻结的最小运行契约。代码可以渐进实现，但对象边界不能含混。

## 内部消息

`ArborMessage` 是 AgentArbor 的内部消息母语。外部协议必须通过 adapter 转换为内部消息，不能直接污染核心模型。

```ts
type ArborMessage<TPayload = unknown> = {
  id: string;
  traceId: string;
  taskId?: string;
  parentTaskId?: string;
  from: { id: string; role?: string; runtime?: string };
  to?: { id: string } | { role: string } | { group: string };
  type: ArborMessageType;
  intent: string;
  payload: TPayload;
  artifacts?: ArtifactRef[];
  requiredCapabilities?: string[];
  priority?: "low" | "normal" | "high" | "critical";
  permissions?: {
    canRead?: string[];
    canWrite?: string[];
    canExecute?: string[];
  };
  createdAt: string;
};
```

## Constraint 与 ConstraintRef

`Constraint` 是约束工程的事实源，`ConstraintRef` 是其他运行对象对约束的引用。自然语言说明可以解释约束背景，但不能替代可执行约束引用。

```ts
type Constraint = {
  id: string;
  source:
    | "user"
    | "task_soil"
    | "underground"
    | "plan"
    | "aboveground"
    | "verification"
    | "governance"
    | "global_soil"
    | "external";
  type:
    | "goal"
    | "non_goal"
    | "scope"
    | "permission"
    | "cost"
    | "time"
    | "technical"
    | "data_security"
    | "human_approval"
    | "verification"
    | "asset_governance"
    | "evolution";
  level: "hard" | "soft" | "preference";
  statement: string;
  owner: "user" | "underground" | "aboveground" | "verification" | "governance";
  appliesTo: string[];
  evidenceRefs: string[];
  enforcementGate:
    | "plan"
    | "task_assignment"
    | "tool_execution"
    | "verification"
    | "fruit_governance"
    | "soil_promotion";
  conflictPolicy:
    | "block"
    | "ask_user"
    | "aboveground_decides"
    | "verification_reviews"
    | "governance_review";
  status: "proposed" | "approved" | "active" | "waived" | "violated" | "retired";
};

type ConstraintRef = {
  constraintId: string;
  requiredLevel: "hard" | "soft" | "preference";
  enforcementGate: Constraint["enforcementGate"];
};
```

## AgentSpec 与实际权限

```ts

    maxChildren?: number;
  };

```

本轮实际能力必须由四层相交决定：

```text
AgentSpec 静态能力上限
  ∩ Parent DelegationDecision 动态授权
  ∩ AgentRunContext 当前阶段 / 任务 / 预算 / 用户授权裁剪
  ∩ ToolCenter / Guard 强制执行
  = 本轮实际能力
```

MVP 中 `canDelegate` 默认为 `false`，只有 Center Manager 可派生一层 child/rootlet。

## 任务状态

```text
Draft
Shaping
PlanReady
Executing
Blocked
NutrientRequested
Revising
Verifying
AcceptedForDelivery
Fruiting
GovernanceReview
Delivered
Archived
Cancelled
Failed
```

守卫规则：

- `PlanReady` 前必须有 approved Plan。
- `Executing` 前必须有 ExecutionPlan 或等价执行入口。
- `NutrientRequested` 必须由 NutrientRequest 进入。
- `Revising` 必须引用 NutrientPatch、Plan vNext 或无需补充证据。
- `AcceptedForDelivery` 必须经过 Verification。
- `Fruiting` 必须有至少一个产物或候选沉淀。
- `GovernanceReview` 必须检查权限、谱系、版本、适用条件和退役路径。
- `Delivered` 必须经过 Acceptance。
- `Archived` 前必须写入 EventLog。
- `Archived` 前必须写入 RunMemory，或明确记录没有可沉淀内容的原因。
- 高风险操作必须经过用户确认。

## 第一阶段限制

第一阶段以内存运行时和最小事件链证明 Agent 工作闭环，并通过 RuntimeDatabase 保存 Run、Event、ToolCall、ModelCall 和 Artifact 的安全投影。A2A Adapter、完整 MCP Adapter、AG-UI Adapter、长期记忆治理、自主演化、复杂权限系统、完整 ORM/迁移体系和生产级数据库后端按后续 Full Profile 演进。

第一阶段仍必须保留 `TaskSoil`、`Plan`、`PlanPackage`、`ExecutionPlan`、`NutrientRequest`、`NutrientPatch`、`PlanRevision`、`RunMemory`、`ExperienceCandidate` 和 `PathBias` 的最小结构。否则系统只能证明自己会执行一次任务，不能证明自己会把一次任务变成下一次任务的有效倾向。
