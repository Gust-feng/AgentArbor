# 术语表

## Soil（土壤）

土壤是固定资产与治理层，保存经过治理的能力资产、历史运行证据、可检索资料、约束、权限策略、失败模式和长期偏好。临时运行记录不能直接进入土壤。

## Underground Center（地下中枢）

地下中枢负责需求成形、约束提取、证据探索、方向综合、用户升级确认和运行期养料供给。它输出 `.agentarbor` 方向交接包和 Nutrient Patch，不执行正式任务，不写长期资产。

## Direction Handoff（方向交接包）

Direction Handoff 是地下中枢交给地上中枢的版本化交接物。它保存目标、非目标、ConstraintRef、Soil 引用、证据索引、未决问题、升级规则和 Growth Entry。它不是长期资产，也不是 Growth Plan。

## `.agentarbor`

`.agentarbor` 是未来 AgentArbor 原生方向交接包目录。它只负责从地下中枢向地上中枢传递方向、约束、证据和 Growth Entry；不保存最终资产，不替代 Soil。

## Aboveground Center（地上中枢）

地上中枢读取 Direction Handoff，制定和修订 Growth Plan、Workflow IR、Context Topology、任务切片、验证门和沉淀策略。

## Aboveground Growth（地上生长）

地上生长是按 Growth Plan 和 Workflow IR 组建的执行组织。它可以采用 single agent、sub-agent tree、shared team cluster 或 competitive team cluster，但所有消息必须经过 MessageBus、Router 和状态机。

## Constraint Engineering（约束工程）

约束工程把目标、非目标、权限、成本、时间、技术边界、安全要求、人工确认、验收门和资产治理转化为可执行契约。它让约束贯穿 Soil、Underground Center、`.agentarbor`、Aboveground Center、Fruits、Governance 和回流后的 Soil。

## Constraint / ConstraintRef（约束与约束引用）

Constraint 是约束事实源。ConstraintRef 是 Direction Handoff、Growth Plan、TaskSpec、Verification Result、Capability Asset 和 Fruit Detachment 对约束的引用。自然语言约束说明可以保留，但不能替代可执行约束引用。

## Growth Plan（生长计划）

Growth Plan 是执行前计划入口。它至少包含目标、选定方向、Direction Handoff 版本、Workflow IR、运行组织形态、任务列表、复用策略和沉淀策略。

## Growth Plan Revision（生长计划修订）

Growth Plan Revision 是基于新 Direction Handoff 版本、Nutrient Patch 或无需补充证据修订计划的机制。它必须记录修订原因、影响范围、继续、回退、分叉或停止决策。

## Workflow IR（工作流中间表示）

Workflow IR 用于表达任务图、依赖、状态、输入输出、恢复点、失败处理和验证门。它由 Growth Plan 派生，不能绕过 Aboveground Center。

## Nutrient Request（养料请求）

Nutrient Request 是地上组织向地下中枢请求养料的机制。它用于证据不足、Soil 资产适配不足、外部事实缺口、约束细节不足、上下文缺口、Path Bias 失效、关键假设被证伪或治理证据不足等场景。地上组织不能用自建方向探索集群替代 Nutrient Request。

## Nutrient Patch（养料补充包）

Nutrient Patch 是地下中枢对 Nutrient Request 的结构化回应。它补充证据引用、Soil 资产引用、ConstraintRef、风险更新、假设判断和对 Growth Plan 的影响；必要时生成新的 Direction Handoff 版本。

## Run Memory（运行记忆）

Run Memory 是单次运行后的经验摘要，来自 EventLog、Artifact、Verification 和 Acceptance 结果。它用于帮助下一次相似任务理解上一轮实际发生了什么。

## Experience Candidate（经验候选）

Experience Candidate 是从 Run Memory 中提取的可复用经验候选。它不能直接写入土壤，必须经过验证、去重、适用范围确认和治理门。

## Capability Asset（能力资产）

Capability Asset 是经过治理后进入土壤的正式能力资产。它必须有来源、输入输出契约、权限边界、版本、验证记录、适用范围和退役路径。

## Path Bias（路径倾向）

Path Bias 是历史运行对新任务的路径牵引。第二次遇到相似任务时，系统不会强行复刻上一次流程，但会倾向于参考已验证路径。Underground Center 负责发现，Aboveground Center 负责决定是否采用。

## Ring Memory（年轮记忆）

Ring Memory 是 EventLog、Run Memory 和 Experience Candidate 的聚合视图，用于观察系统如何在多次运行中生长。它不是新的平行事实源。

## AgentApp（智能体应用）

围绕目标形成的可运行智能体应用。它包含目标、运行时集群、能力声明、工作流、配置、工程目录、测试、文档和运行记录。

## Fruit（果实）

果实是成熟能力的可交付形态，可以是可复用模板、AgentApp、工作流包、工具组合或可脱离子 agent。果实必须经过治理门才能进入 Soil。

## Governance Gate（治理门）

治理门决定 Experience Candidate 是否可以成为 Capability Asset，Fruit 是否可以脱离母体运行，以及过时资产是否需要修剪或退役。

## Adapter（适配器）

适配器连接外部平台、模型、工具或协议。适配器负责格式转换，不负责定义 AgentArbor 核心产品语义。
