# 远程协同第一阶段开发方案

## 目标

第一阶段在同一仓库交付三部分：

1. 可作为 Linux 进程运行的独立 Node.js Relay；
2. 由唯一 Host Composition Root 装配的桌面 Remote Collaboration connector；
3. Android 9+ Capacitor 客户端与可安装 debug APK。

源码、协议和 APK 构建先在本地完成；公网 Relay 更新和 Android 真机联调在用户授权部署验证后进行。产品边界以 [ADR-0034](../../架构设计/产品架构/ADR-0034-远程协同与选择性同步架构.md) 为准。

## 模块所有权

`src/app/remote-collaboration/` 拥有：

- `remote-collaboration/v1` wire schema、账户/设备/配对契约和 Zod 校验；
- desktop connector 的显式启动、自动重连、本地 outbox/inbox、接收确认和 command result；
- 内容同步投影、分页、远程 ID、命令幂等与 CAS 冲突；
- Relay store、HTTP/WebSocket adapter 和定向行为测试。

`src/app/remote-relay.ts` 只装配 Relay 进程与环境配置，不装配 Agent runtime。`src/app/mobile-ui/` 拥有移动投影、IndexedDB 缓存、Secure Storage 凭据 adapter、协议客户端和移动 UI。`android/` 是 Capacitor 生成并纳入维护的原生外壳。

Host 通过公开 facade 注入 Ordinary、Space、Workbench Assets、Agent Notes 和 Managed Files 的窄 command/query 端口。connector 不调用 Panel `/api/*`，也不读取其他 feature 的 repository 或 SQLite 表。

## 配置边界

Relay 只读取：

- `AGENTARBOR_RELAY_HOST`
- `AGENTARBOR_RELAY_PORT`
- `AGENTARBOR_RELAY_DATABASE`
- `AGENTARBOR_RELAY_INVITE_CODES`
- `AGENTARBOR_RELAY_ALLOW_OPEN_SIGNUP`

桌面 Host 可读取 `AGENTARBOR_RELAY_PUBLIC_URL` 作为用户可修改的默认地址。移动构建通过 `VITE_AGENTARBOR_RELAY_URL` 注入默认地址；`.env.example` 只能使用 `https://relay.example.com`。正式域名、IP、邀请码、token、数据库路径和服务器凭据不得硬编码或提交。

官方部署默认关闭开放注册。邀请码只创建账户与首台桌面设备，Relay 只保存邀请码哈希。每账户限一台桌面和一台手机，手机 token 在桌面批准前不可用，撤销后立即失效。

## Relay 数据与 API

Relay SQLite 只拥有：

- `remote_accounts`
- `remote_invitations`
- `remote_devices`
- `remote_pairing_sessions`

开发迁移会删除早期 `remote_sync_documents` 与旧 pairing-as-account 表，不双读、不迁移业务内容。Relay 重启后只恢复账户和设备控制事实；对话、消息、命令、AI 输出、Space、笔记、资产和文件正文必须为零。

HTTP 根路径不提供网页。正式入口为：

- `GET /v1/health`
- `POST /v1/accounts/activate`
- `GET /v1/account`
- `PATCH /v1/account/handle`
- `POST /v1/pairings`
- `POST /v1/pairings/join`
- 配对状态、批准、设备列表与撤销接口
- `GET /v1/connect` 的 WebSocket upgrade

旧 `/health`、根 `/` 和 `/v1/sync/*` 均返回 404。

## 在线协议

所有帧携带 `protocolVersion: "remote-collaboration/v1"`。Relay 只在内存保存在线 socket 和等待接收确认的投递身份：

- 目标离线返回 `peer_offline`，发送端保留本地 outbox；
- 目标收到后返回 `message.received`，发送端才移除相应 outbox 项；
- 桌面 inbox 按稳定 `commandId` 去重，Ordinary 消息复用其作为 `submissionId`；
- `command.result` 明确返回 `applied | conflict | failed`；
- `run.delta` 只服务当前在线运行，正式投影由 `run.snapshot` 覆盖；
- `conversation.index` 同步全部索引，`conversation.page.request` 按需返回最近或更早的最多 50 条正文；
- `asset.snapshot` 与 `managed_folder.snapshot` 使用 `snapshotId / pageIndex / pageCount`，每页最多一个 512 KiB 文本对象，手机合并后再写本地缓存。

WebSocket 单帧上限约 1.1 MiB，慢消费者超过发送缓冲上限时断开。不能通过无限放大帧或 Relay 内存队列解决内容聚合；新增大对象必须先设计分页或分片。

## 本地存储

- Relay SQLite：仅账户与设备控制面。
- Desktop connector store：桌面 binding、outbox/inbox、notebook 映射和 command result。
- Desktop token：宿主凭据存储，不写普通配置或日志。
- Mobile IndexedDB：binding 的非秘密字段、pairing 状态、outbox、接收去重与展示缓存。
- Mobile token：Android Secure Storage；浏览器开发环境只使用 localStorage fallback。

手机缓存不是桌面业务恢复源。退出或撤销设备时必须清除 token、binding、outbox、回执和内容缓存。

## 命令与投影

手机可提交：

- `conversation.submit`
- `conversation.page.request`
- `run.cancel`
- `confirmation.decide`
- `space.create`
- `space.reference.add`
- `note.replace`
- `asset.replace_text`
- `managed_file.replace_text`
- `managed_file.create_text`
- `sync.snapshot.request`

所有写命令通过 owning feature；笔记、资产和受管文件使用版本/fingerprint CAS。只允许 `asset_folder`、`workbench_asset`、`managed_folder` 引用，文件路径必须相对且不能越界。

## Android 构建

当前配置：

- 包名：`dev.gustfeng.agentarbor`
- `minSdkVersion = 28`
- `compileSdkVersion = 36`
- `targetSdkVersion = 36`
- `versionCode = 302`
- `versionName = 0.3.2`
- `allowBackup = false`

构建命令：

```powershell
$env:VITE_AGENTARBOR_RELAY_URL='https://relay.example.com'
pnpm mobile:android:debug
```

正式地址只在构建环境中注入。APK 使用当前 AgentArbor 图标、系统 Secure Storage 和相机二维码扫描；浏览器 URL 不是产品入口。

## 验证

提交前至少执行：

```powershell
pnpm build:node
node --test dist/app/remote-collaboration/protocol.test.js dist/app/remote-collaboration/relay-store.test.js dist/app/remote-collaboration/relay-server.test.js dist/app/remote-collaboration/command-handler.test.js dist/app/remote-collaboration/desktop-feature.test.js
pnpm typecheck:mobile
pnpm test:mobile
pnpm typecheck:panel
pnpm build:panel
pnpm build:mobile
git diff --check
```

定向测试必须覆盖账户激活、handle 唯一修改、批准前 token 不可用、撤销、设备限制、peer offline、接收确认、重复命令、CAS 冲突、路径越界、内容分页，以及 Relay 重启后业务内容为零。

公网验证至少覆盖 TLS、反向代理 WebSocket、API-only 根路径、systemd 重启和 Android 网络切换。当前服务器上的其他业务端口不得修改；部署只更新独立 Relay 服务与对应反向代理路径。
