# 系统总览

## 架构图

```text
用户任务 / 文件 / 项目 / 网页
  -> Desktop Shell
  -> Task Soil
  -> Underground Cognitive Runtime
  -> Plan
  -> Aboveground Execution Runtime
  -> Fruits
  -> Governance Pipeline
  -> Global Soil
```

`Desktop Shell` 是统一产品入口。当前活跃实现路线先打磨默认普通桌面 Agent：消息输入、连续会话、模型工具循环、命令确认、运行事件、会话持久化和工作台结果展示先闭环。`Task Soil`、`Underground Cognitive Runtime`、`Plan`、`Aboveground Execution Runtime`、`Fruits`、`Governance Pipeline` 和 `Global Soil` 仍是长期产品架构边界；deep / Agent 集群不是废弃方向，但 deep 项目未重启前不做默认可见入口，也不主动扩展 deep 后端。

智能通道和 Shared Agent Kernel 横切这条主线。它们提供模型、工具、上下文、消息、守卫、trace、预算和权限能力，但不能替代产品语义。agent 的 `reason()` 承担目标理解、候选排序、是否继续探索、风险权衡和方向综合；`guard()` 只守结构、预算、权限、hard constraint 和包结构。

## Shared Agent Kernel + Two Product Runtimes

Shared Agent Kernel 包含：

- `AgentLoop`。
- `AgentTurnRuntime`。
- `ToolCenter`。
- `WorkspaceView`。
- `Mailbox`。
- `Guard`。
- `Trace`。
- Budget / Permission boundary。

Product Runtimes 包含：

- Underground Cognitive Runtime：负责方向智能，允许不确定、分叉、追问和停止。
- Aboveground Execution Runtime：负责执行智能，默认消费已成形 Plan，进入执行和验证。

二者共享底层能力内核，但业务语义不同。不能把它们写成两个完全割裂的技术栈，也不能为了简化把方向成形和执行落地混成一个无边界 runtime。

## 分层原则

- Desktop Shell 是唯一产品入口；用户不直接面对地下/地上两个入口。
- 默认普通 Agent 是当前活跃使用面；它不自动升级到 Underground，不派生 child/rootlet，不把普通工具循环包装成 deep flow。
- Task Soil 保存本轮任务材料，不能直接污染 Global Soil。
- Global Soil 保存治理后的长期偏好、Capability Asset、Path Bias、历史约束、失败模式和长期事实。
- Underground 负责目标成形、多路探索、动态派生 child agent、父层综合、裁决、追问或停止。
- Agent Fabric 是动态派生机制，不是独立产品入口；MVP 只允许一层 child。
- child/rootlet 输出默认是局部材料，不能直接进入 Plan。
- Plan 必须能暂停恢复、版本化、人类可读、审计复盘、跨进程消费，并防止 child output 直通执行。
- `.agentarbor` 是 Plan Package 的存储形态或目录名，不是独立产品概念树节点。
- Aboveground 负责执行、验证和成果交付；信息不足时发起 Nutrient Request，不自建地下探索集群。
- Governance Pipeline 决定 Run Memory 和 Experience Candidate 是否能晋升为 Capability Asset、Path Bias 或 Soil Update。
- Adapter 只做外部格式转换，不能定义核心产品模型。
- 命名必须和真实职责匹配；普通文件编辑、helper、adapter 或状态更新不能用 Agent、Plan、Handoff、atomic mutation 等过重名称。

## 目录对应关系

- `docs/`：人类可读指南和资料库。
- `.trellis/`：历史 Trellis 工作流和规范材料；`.trellis/tasks/` 不再作为当前开发任务、约束或上下文入口。
- `.agents/`：官方 Agent Skills 兼容层。
- `.codex/`：Codex 开发适配层。
- `.opencode/`：OpenCode 开发适配层。
- `.agentarbor/`：未来 Plan Package 默认存储目录，只在契约稳定后增量创建。
- `src/`：AgentArbor TypeScript 实现；当前下一阶段应围绕默认普通 Desktop Agent、工作台体验、工具循环、命令确认、运行投影和持久化推进，deep / Agent 集群保留为长期能力边界。

开发时不能把这些目录的职责混用。
